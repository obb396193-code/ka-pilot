## 7. 给后续前端实现者的交接顺序

1. 先以 `apps/ui-layout-demo/sidebar.html` 作为唯一视觉母版，不从旧 `apps/web` 页面继承视觉。
2. 阅读 `README.md`、`frontend-product-standard.md`、`前端视觉与体验审核清单.md`、`agent-workflow.md`。
3. 用 `capabilities.json` 查能力；需要多个候选时，用 `comparison-template.md` 在相同业务容器中真实渲染对比。
4. 先查 `source-cache/manifest.json`，只复制当前页面所需的公开官方源码；不要把全部缓存装入产品。
5. 等老板在字体页拍板后，再将字体、字重与数字规则接入视觉母版；MiSans 必须先过许可复核。
6. 功能代码以当前主线契约和 Task5 Cookie Session 为准；旧 `110f221` 分支不直接合并。`c5df265` 先由 root/接手人重新审计和跑全门禁。
7. 页面接 BFF 时保持指标由 Domain/API 给出，前端只做格式化；未接能力显示 loading/empty/error/forbidden/unavailable，不冒充完成。
8. 媒体写操作仍停在 ChangeSet 预览/确认边界；没有开放 execute Contract 前不做真实执行按钮。
