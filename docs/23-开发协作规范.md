# 开发协作规范（开工版）

> 2026-08-18 生效。蓝本＝ContentRadar 打法全套移植 + 本项目特化。

## 1. 分工定稿

| 角色 | 谁 | 管什么 | 只许动 |
|---|---|---|---|
| **老板** | 你 | 拍板、真数据验收、内网消息中转（zip→内网 agent） | 全部 |
| **arch** | 本会话 | 契约唯一出口、派活验收（SHA 逐条 ✅/❌）、整合 main、PRD/基线维护 | `packages/contract/`、`docs/` |
| **be（后端）** | Codex | `apps/worker` + `apps/dingtalk-gateway` + `apps/web/app/api/` + `packages/db` + `packages/domain` | 上述目录 |
| **fe（前端）** | 新开 Claude 会话 | `apps/web/`（除 api routes）：页面/组件/mock/视觉 | `apps/web/app`(非api)、`apps/web/components`、`apps/web/lib` |
| **内网 agent** | OS | a1 faas 部署三应用、看日志验干净启动、真数据联调 | 不进仓库 |

Codex 当前在跑 R-002 原型图——**图和后端并行不冲突**（生图是它的图像调用，B1a 是写代码）。

## 2. 协作机制（CR 打法移植清单）

| 机制 | 本项目用法 |
|---|---|
| **信箱** `docs/relay/inbox-{codex,fe,arch}.md` | 已在用。派活写对方信箱，处理完更新状态；有疑问标「有疑问」回抛不猜 |
| **台账** `docs/plans/工作台账.md` | 唯一事实源，已 131 条，继续 |
| **状态文件** | 每个开发批次建 `docs/plans/B{N}-状态.md`（从模板复制）：任务逐条列，做完一条更新一条，compact/重开会话先读它，**杜绝重复做已完成项** |
| **验收审计** | 交付方给 SHA → arch 逐条 diff 核对 ✅/❌ 列清（假完成是最大风险）；大面积机械改动 arch 亲自 grep 抽查 |
| **commit 前缀** | `[fe]` `[be]` `[arch]`；各自只 commit 自己目录（路径限定 `git commit -- <路径>`）；**main 由 arch 整合**，fe/be 各在自己分支 |
| **契约纪律** | 字段/端点/表名谁都不发明；改契约=给 arch 信箱提提议，arch 冻结后双方再动 |
| **视觉拍板** | fe 任何视觉产出先截图小样 → 老板批 → 才 commit；被否整颗回退不辩护 |
| **Mock≠真 API** | fe 按契约 mock 先行；**联调放行标准=真 payload 打真端点 E2E** |
| **部署验证** | deploy 成功≠服务起来：内网 agent 必看日志里干净启动序列 |
| **CR 新增可参考** | E2E 用系统 Chrome（channel:"chrome" 临时加跑完恢复）；前端命令必 cd 到 apps/web；npm 装包非沙箱跑 |

## 4. 前端开发流程（老板问的"先搭还是先定风格"）

**答案：三线并行，风格靠拍板不靠等。**

```
线1（现在开工）：工程骨架——Next.js 项目/路由树(按 PRD 2.2)/shadcn+D-CON token/
                 mock 层/布局壳(顶栏9项+页面容器)——这些不依赖视觉终稿
线2（Codex 在跑）：R-002 原型图 11 页 → 老板拍板视觉方向
线3（拍板后）：按定稿风格填充页面——B1c 数据页 → B2 工作台 → 依批次
```

理由：骨架和 mock 是"结构"，原型图定的是"皮"，两者不冲突；等图再动工浪费一周。**规矩：线 1 期间 fe 不 commit 任何"有视觉主张"的页面**（布局壳用最素的灰阶），视觉全部等原型图拍板后按图做，做完截图再拍板一次才 commit。
