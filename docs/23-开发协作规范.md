## 2. 协作机制（CR 打法移植清单）

| 机制 | 本项目用法 |
|---|---|
| **信箱** `docs/relay/inbox-{codex,fe,arch}.md` | 已在用。派活写对方信箱，处理完更新状态；有疑问标「有疑问」回抛不猜 |
| **台账** `docs/plans/工作台账.md` | 唯一事实源，已 131 条，继续 |
| **状态文件** | 每个开发批次建 `docs/plans/B{N}-状态.md`（从模板复制）：任务逐条列，做完一条更新一条，compact/重开会话先读它，**杜绝重复做已完成项** |
| **验收审计** | 交付方给 SHA → arch 逐条 diff 核对 ✅/❌ 列清（假完成是最大风险）；大面积机械改动 arch 亲自 grep 抽查 |
| **commit 前缀** | `[fe]` `[be]` `[arch]`；各自只 commit 自己目录（路径限定 `git commit -- <路径>`）；**main 由 arch 整合**，fe/be 各在自己分支 |
| **契约纪律** | 字段/端点/表名谁都不发明；改契约=给 arch 信箱提提议，arch 冻结后双方再动 |
| **视觉拍板** | fe 任何视觉产出先截图小样 → 老板批 → 才 commit；被否整颗回退不辩护 |
| **Mock≠真 API** | fe 按契约 mock 先行；**联调放行标准=真 payload 打真端点 E2E** |
| **部署验证** | deploy 成功≠服务起来：内网 agent 必看日志里干净启动序列 |
| **CR 新增可参考** | E2E 用系统 Chrome（channel:"chrome" 临时加跑完恢复）；前端命令必 cd 到 apps/web；npm 装包非沙箱跑 |

## 4. 前端开发流程（老板问的"先搭还是先定风格"）

页面和组件的详细执行门禁以 `docs/frontend/ui-assets/frontend-product-standard.md` 为准；UI 资产选择以 `apps/web/AGENTS.md` 与 `docs/frontend/ui-assets/agent-workflow.md` 为准。该规范明确 Storybook、ECharts、Design Tokens、Playwright 分别是组件试验台、图表引擎、主题变量层和自动验收工具，不是额外四套业务页面。

**答案：三线并行，风格靠拍板不靠等。**

```
线1（现在开工）：工程骨架——Next.js 项目/路由树(按 PRD 2.2)/shadcn+D-CON token/
                 mock 层/布局壳(顶栏9项+页面容器)——这些不依赖视觉终稿
线2（Codex 在跑）：R-002 原型图 11 页 → 老板拍板视觉方向
线3（拍板后）：按定稿风格填充页面——B1c 数据页 → B2 工作台 → 依批次
```

理由：骨架和 mock 是"结构"，原型图定的是"皮"，两者不冲突；等图再动工浪费一周。**规矩：线 1 期间 fe 不 commit 任何"有视觉主张"的页面**（布局壳用最素的灰阶），视觉全部等原型图拍板后按图做，做完截图再拍板一次才 commit。

**验收句（2026-09-05 起，每个批次必填）**：派活时写一句「合入之后，谁能在什么页面，用真实数据完成哪件以前做不了的事」。写不出来的批次标「基础建设」，可以做，但不计入"可用功能完成"，看板和缺口地图分开统计。交付顺序按三个可用版本推：**每天能看**（登录接入→真实账户→数据总表/筛选列/下钻/导出）→ **每天能处理**（队列→证据→处理/跳后台→记录→回收）→ **能复制做法**（SOP/工作流/Agent 编排/素材/知识库/团队复用）。

## 工作树与提交节奏（老板 2026-09-06 拍板，经 fe 转达）

- **工作树路径**：所有角色的 git worktree 一律放持久路径 `~/` 下（如 `/Users/aik/ka-fe-f006`、`/Users/aik/ka-be-r010`），**禁止放 `/private/tmp`**（机器重启即清空，2026-09-06 已发生一次，fe/Codex 工作树同时消失）。仓内 `.worktrees/` 也可，但必须在 `.gitignore`。
- **提交节奏**：每完成一个可交付单元立即路径限定 commit，不攒；未提交的改动视为随时可丢。
- **重建口令**：`git worktree prune && git worktree add /Users/aik/<name> <branch>`，随后 `npm ci`（或根 `scripts/install-all.sh`）。

## origin 备份规矩（老板 2026-09-07 拍板；本项目与 ContentRadar 不同）

- 远端 `origin` = **私有仓 `github.com/obb396193-code/ka-pilot`**，用途是**异地备份 + 给内网 OS 拉代码部署**。
- **只有 arch 推**：arch 每次合流后推 main；分支备份用 `--all`。be / be2 / fe **仍然不 push**，照旧本地路径限定提交，由 arch 合流。
- 推之前 arch 负责扫一遍不带真凭证（仓里只准 secret_ref 与空值占位）。原始内部资料仍只放 `private/knowledge-sources/`（gitignore，不进仓）。
- 给 OS 拉代码用 fine-grained PAT：Contents 只读、单仓、7 天，用完立即吊销。
