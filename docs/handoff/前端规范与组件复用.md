# 前端规范与组件复用

> 来源：KA Pilot（快手渠道投放经营平台）前端。2026-09-08 出稿。
> 用途：你要做的数据看板和这套形态很像。这份文档说明怎么直接复用已经打磨过的设计规范和组件，不用从零试审美。
> 配套文档：同目录的 `数据抓取指南.md`（数据从哪来）。

---

## 0. 一句话结论

**别让 agent 自己发挥审美。** 这套壳（侧栏 / 顶栏 / 卡 / 表 / KPI / 主题 / 状态态）是产品负责人逐页口头拍板打磨出来的，已经冻结成规范文件加可复制源码。agent 只要照抄加换数据，出来的东西就是同一水准；它一旦「自己想一版」，大概率退回到 AI 默认那种灰扑扑的卡片堆。

所以 agent 的定位是：**功能和它谈，视觉它没有决定权，只有执行权。**

## 2. 如果你的看板和我们不一样

大概率不一样。这一节说清哪些能原样拿走、哪些要改、哪些得自己加。

### 先说没有的

**没有图表库。** 起点包里一张图都没有，依赖里没有任何图表包。看板九成是表格加图表，表格给你了，图表你自己选。

建议 ECharts：配置驱动、能按需引入控制包体、能接主题桥跟着换色。主仓里 ECharts 和 Recharts 并存是历史遗留，别跟着抄，**只选一个**。

**没有侧栏导航。** 主仓有 shadcn 官方的侧栏件，要就去 `apps/web/components/ui/` 拿，同一套 style 直接兼容。

**没有数据层、没有登录。** 这两块和业务强绑定，给你反而是负担。

### 能原样拿走的（跟做什么业务无关）

| 拿什么 | 为什么通用 |
|---|---|
| `app/globals.css` 全套 token | 纯变量层，零业务耦合。三套主题模式、状态色、字体栈。这层也是「不灰」的根源 |
| `components/business/data-grid/` 表壳 | 看板九成内容是表格 |
| `data-grid/format.ts` 格式化器 | 金额、千分位、百分比、日期、缺数显 `−` |
| `state/page-state.tsx` 八态壳 | 任何有数据的页面都要这八种态 |
| `tabs/page-tabs.tsx` 页签收敛 | 子功能做页签不开独立路由，任何后台都适用 |
| `page-header.tsx` 页头与内容壳 | 结构通用，具体显示项要改，见下 |
| `docs/` 三份规范 | 视觉、数字、密度、动效规则，不挑业务 |

### 要改的

**页头那五件（空间 · 来源 · 数据日期 · 更新时间 · 口径）是我们的产物**，因为我们有多个数据源、切源会让同一个指标数字变化，所以必须常显让人看出是换源不是算错。

**你如果只有一个数据源，就只留数据日期和更新时间**，把空间和来源删掉。硬凑五件反而是噪音。

验收页 `app/demo-page.tsx` 里的 KPI 标签、表格列、状态枚举全是示例，看完就删。主色 18 个预设换成你的品牌色。

### 规则里哪些跨业务成立

这些和做什么无关，照做：

- **缺数显 `−` 不显 0**，分母 0 也显 `−`。这条对做 BI 的人比对我们更重要，因为看板最容易在这里骗人：把「没数」显示成 0，看板上就成了「这天成本为零」。
- **八态覆盖**，尤其 partial（覆盖不全）和 stale（数据过期）两态。只做「正常有数据」那条路径的看板，出问题时会安静地给错结论。
- 一种表格样式、真黑真白灰只做发丝线、状态色不参与配色、数字用等宽字形。

### 哪一条绑我们的架构

**只有「前端永不算数」这一条。** 它的前提是后端返回算好的指标。

- 你在 SQL 里算完再返回，这条同样成立，照做。
- 你打算在前端算，得自己判断。

这条的本质是**口径只有一处定义**，不是禁止前端做除法。如果同一个成本指标在三个页面各算一遍，早晚三个数不一样，而且没人知道哪个对。想在前端算就集中到一个地方算，别散在各页面。

## 3. 怎么开始

### 第一步：先跑起来看（不要跳过）

```bash
git clone https://github.com/obb396193-code/ka-ui-kit
cd ka-ui-kit
npm install
NEXT_PUBLIC_DATA_PROVIDER=mock npx next dev -p 3500
```

打开 `http://localhost:3500` 就是验收页：页头五件套、六个 KPI 卡、母版表格、右上角三套主题一键切、八种页面状态可切。

**这步别省。** 规范里写的「真黑真白不要灰」「点彩」「主色驯化」，光看文字复现不出来，看一眼页面就懂了。让 agent 也看。

看明白之后把 `app/demo-page.tsx` 和 `app/page.tsx` 删掉，换成自己的页面。

### 第二步：别 fork 主仓来改

主仓适合当参考，不适合当起点，理由具体：

- 主仓是 **monorepo**，含前端、后端 worker、钉钉网关、三个共享包。fork 过去会背上整个后端。
- `apps/web` **不能单独复制**。它通过路径别名读仓根的 `packages/contract`，假数据层直接引用契约里的 fixture。只拷前端目录会直接编译不过。
- 主仓 `private/` 目录有 93 MB 内部资料，clone 要全拖下来。
- 主仓正处于逐页精修期，改动很频繁。在它的分支上改会永久处于合并冲突状态。

### 第三步：起点用包，查用主仓

起点包和主仓解耦，但 token 和规范完全一致，做出来是同一个产品家族的东西。缺组件、想知道某个交互怎么实现的，回主仓 `apps/web` 翻对应文件照抄。

一句话：**起点用包，查回主仓抄。**

## 4. 必须照做的硬规则

这些是产品负责人拍过板、我们踩过坑的。违反其中任何一条，东西就「不像」了。

**底子和颜色**
- 真黑真白，**灰只做发丝线**。原话是「永远不要灰灰的」。AI 默认爱堆 `text-gray-500`，这是最大杀手。
- 三套主题模式同一套组件、只换 CSS 变量：黑白·点彩 / 黑白+彩 / 全彩。默认**黑白·点彩**，颜色只做点染（chip 一粒色点、图表一条点缀线）。
- **红绿黄是状态色，不进主色预设**。状态色只表状态，不参与主题配色。
- 主色一个 `--hue` 变量派生图表三色、按钮、选中态。切换开关放**顶栏右上角**，一点即换，不进设置页。
- 全彩模式要单色系：一个主色加中性色。多色卡片配标题色条等于廉价感，被否过两次。

**字体和数字**
- 字体栈 `Geist → PingFang SC → MiSans → Microsoft YaHei`。Mac 用苹方零下载，Windows 用 MiSans 兜底。
- 数字列和 KPI 必须 `font-variant-numeric: tabular-nums`，否则跳列。
- **前端永不算数**。CPA、达标率、Gap、环比、pacing 全部由后端给。前端只做格式化，走统一 formatter，禁止各页面手写 `toFixed()`。
- **缺数显 `−`，不显 0**。分母 0 也显 `−`。只有后端明确说「有数据且值为零」才显 0。这条是硬门禁，不是审美。

**表格**
- 全站**一种表**，照母版：勾选框列 / 名字一行（不放 ID 副行）/ 类型 chip / 带图标的状态 chip（绿勾、红叉、黄叹号、转圈、时钟、虚线圈）/ 行末 ⋮ 菜单 / 「已选 N 条，共 M 条」页脚加勾选后批量动作。
- 红绿状态**同时给文字或图标**，不能只靠颜色。
- 详情用**行内展开**（点名字在行下方展开），不是右侧抽屉。

**状态**
- 每个页面必须覆盖八态：`loading / empty / partial / stale / error / no-permission / demo / disabled`。只做「正常有数据」那条路径是不合格的。
- **不造真实感假数据**。没接口的地方标「示例」角标、降饱和、写明解锁条件。

**组件来源**
- **绝不自写组件**。原话是「自己写的会跟母版不一样」。先查资产目录，从官方源码复制，只写业务适配层。
- 同一能力多个库都有时，做成同业务容器**并排给人挑**，agent 不自选。

**动效**
- 只在能解释「什么变了」时用。即时反馈 100 到 180 毫秒，状态过渡 180 到 280 毫秒，布局变化 240 到 400 毫秒。
- 必须支持 `prefers-reduced-motion`。禁止 `transition: all`。
- 表格正文、错误文案、按钮标签**不做动效**。

## 5. 已经踩过的坑

| 坑 | 症状 | 解法 |
|---|---|---|
| 读地址栏参数的组件 | build 报错，dev 不报 | 包一层 `Suspense`，见起点包 `app/page.tsx` |
| TanStack Table 列显隐 | hydration 报错、控制台红字 | 初始列显隐必须走 `useGridTable({ initialColumnVisibility })`，不能在渲染中 `setColumnVisibility` |
| shadcn 面包屑 | 二级页 hydration 报错 | `BreadcrumbSeparator` 本身是 `<li>`，必须和 `BreadcrumbItem` **平级**，不能嵌在里面 |
| 示例角标 | 盖住内容自己的按钮 | 别用绝对定位压右上角，跟解锁说明放同一行 |
| React Flow 画布 | useEffect 死循环 | `setNodes` 回调里无变化时必须返回 `prev` |
| BlockNote 编辑器 | SSR 直接挂死 | 页面里必须 `dynamic(..., { ssr: false })`，它依赖 DOM |
| dev 日志放仓库里 | 页面 20 到 40 秒才出来 | 日志文件绝不能落在工作树里，会触发文件监听循环重编译。挪到仓库外后 300 毫秒 |
| AI Elements 命令行工具 | 装 streamdown 系依赖时卡死 | 别用它，直接 `curl https://elements.ai-sdk.dev/api/registry/<name>.json` 落文件，把 `@/registry/default/*` 改成 `@/components/*`，依赖手动装 |
| 重依赖首次编译 | curl 返回 000，以为挂了 | BlockNote、react-arborist、streamdown 首次编译要一到三分钟，不是挂 |

**主仓里有两个现存小问题，别跟着抄**：
- `package.json` 里有个 `"cn": "^0.2.5"` 是误装的无关包，真正的 `cn()` 在 `lib/utils.ts`。别装它。
- `echarts` 和 `recharts` 并存是历史遗留。新起项目**只选一个**，建议 ECharts，配置驱动、按需引入、能接主题桥。

**几件规范里提到但实际没做的，别当「已有」**：Storybook 没装、ECharts 正式图表层没建、tweakcn token 桥没实现、Playwright 视觉回归没配、错误上报没接。

## 7. 建议的推进节奏

1. **先跑起来看**。clone 起点包，装依赖，打开验收页。先看明白目标长什么样再动手。
2. **先只做壳**。删掉验收页，用假数据把导航、页头、一张表、六个 KPI 卡跑起来，确认视觉对了再往下做。
3. **再接数据**。看配套的数据抓取指南。
4. **每做一页看一眼**。这边就是这么做的：逐页看、口头改、改完提交。这个节奏比一次做完再返工快得多。

## 8. 两个仓怎么用

| 仓 | 用途 | 怎么用 |
|---|---|---|
| `obb396193-code/ka-ui-kit` | **起点** | clone 下来直接改，这是项目底座 |
