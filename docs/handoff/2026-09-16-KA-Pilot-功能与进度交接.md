## 1. 这个产品是什么

**一句话**：给淘宝 KA 渠道的信息流投放优化师用的投放工作台——把「每天手工导数据、拉透视、看谁超考核、去后台改」这套活，变成一个能自己取数、自己算口径、自己盯异常的产品。

| 项 | 内容 |
|---|---|
| 用户 | 一线优化师（主）、组长/负责人（看团队）、运营（看任务达成） |
| 北极星指标 | **考核达标**：真实 CPA vs 考核价，谁超了、为什么超、谁去处理 |
| 优化师三问 | ① 我今天要干什么 ② 这个户为什么不行 ③ 我改完有没有用 |
| 明确不做 | 大促战役（老板砍）、面向普通用户的工作流画布、通用 BI |
| 使用形态 | **不是 SaaS**。别人拿仓库地址 + 部署提示词，让自己公司的内网 agent 部署一套，绑自己的启航 userId，看自己的数据 |

产品定位与全量设计见 `docs/20-PRD-v1.md`（PRD v1.6 冻结版）和 `docs/17-功能全景-v2定稿.md`（13 个功能域、87 个功能点）。

## 2. 技术架构

### 2.1 四个进程

| 进程 | 起法 | 端口 | 干什么 |
|---|---|---|---|
| data-api | `cd apps/worker && npm run start:data-api` | 3101（内网部署）/ 3111（本地联调习惯用） | 所有业务读写 HTTP 接口，`/api/v1/**` |
| worker 主进程 | `cd apps/worker && npm run start` | — | 长驻：跑迁移、维护分区、消费 Job 队列（ETL 拉数、回填、质检） |
| worker-http | `cd apps/worker && npm run start:worker-http` | 3102 | 把「跑一轮 ETL」「发一轮钉钉」包成带令牌的 HTTP 触发口，给外部调度器调 |
| web | `cd apps/web && npm run build && next start` | 3000（内网）/ 3411（本地） | Next.js 15 前端 + BFF 中转层 |
| dingtalk-gateway | `apps/dingtalk-gateway` | — | 钉钉 Stream 机器人，消息转译到 data-api（**只通了「查数」一条**，见 5.5） |

### 2.2 请求链路与数据来源

```
浏览器 → web 的 BFF /api/internal/*  →  data-api /api/v1/*  →  ┬ 个人空间：我们自己的 PG
        （Next Route Handler，带内部令牌）                      └ 团队空间：KA Data（实时查，不落库）
```

**两种数据源，按空间类型自动绑定，前端不能选**（规则代号 DATA-ROUTE-001，实现在 `apps/worker/src/data/data-source-routing.ts`）：

| 空间 | 数据从哪来 | 落不落库 | 前提 |
|---|---|---|---|
| 个人空间 | worker 用**该用户自己的启航 userId** 调启航 `get_data`（账户日/离线/实时/小时四种 resource） | 落进我们 PG 的 `account_metrics_daily` / `account_metrics_hourly`，页面读库 | userId 已绑（`seed:qihang-identity`）、账户已授权、`worker:once` 跑过 |
| 团队空间 | data-api 每次请求**实时**发 SQL 给 KA Data（`dwd_account_daily` + `fact_conv_daily`） | 不落库 | `KA_DATA_ENABLED=true` + 地址 + reader token |

两边的账户昵称分组标签（优化师 / 转化目标 / 承接页 / 自定义段）都来自**我们自己库**里的昵称解析结果（`account_name_parses`），不来自数据源。

### 2.4 两条贯穿全项目的工程约定（踩过坑立的）

1. **「发出去的严、收回来的宽」**：前端对后端响应做镜像校验——后端多发字段不该让页面崩，但字段类型/枚举错了必须拦。镜像在 `apps/web/lib/data/canonical-query-rows.ts`。**教训**：镜像写成 `.strict()` 而后端加了新字段 → 整条响应判废、整页 502（2026-09-13 大盘就这么挂过一次）。
2. **真响应回放（A40 门禁）**：`apps/web/lib/data/fixtures/real-backend/` 放的是联调库上 data-api 的**原样响应**，测试把它们喂给前端镜像。前后端各自的测试都绿、只有真响应能抓出来的问题，靠这一层。后端改了发出的形状，要重取这些 JSON，**红了先改镜像，不许改 JSON**。

## 5. 后端现状

### 5.1 查询注册表（数据分析的心脏）

一个入口 `POST /api/v1/data/query`（旧语法别名 `POST /api/v1/query`），按 `queryId` 分发。注册表在 `apps/worker/src/data/query-registry.ts`。

| queryId | 查什么 | 个人源 | 团队源 |
|---|---|---|---|
| `account.summary` | 窗口合计（六卡） | ✅ | ✅（不支持 filters/taskId） |
| `account.trend` | 按天趋势（≤90 天） | ✅ | ✅ |
| `account.dimension` | 按单维度分组 | ✅ 六维 + `segment:<段>` | ✅ 仅优化师/目标/承接 + 段 |
| `account.table` | 分页明细 | ✅ | ✅ |
| `account.pivot2` | 两轴透视 | ✅ | ✅（同上限制） |
| `account.hourly` | 单日分小时 | ✅ | ❌ 不支持 |
| `account.detail` | 单账户明细 | ✅ | ✅ |
| `account.anomalies` | 平台侧异常（≤7 天） | ✅ | ❌ |
| `account.gap` | 差异对账 | ⚠️ 恒 503（源未配） | ❌ |
| `reconcile.account_daily` | 两源逐账户日对账 | 仅管理员诊断口 | 同左 |

可分组维度：固定六维 `account / task / biz / optimizer / goal / placement` + 昵称段 `segment:<段名>`。其余维度（资源位、代理类型、出价工具、UBP、扣量区间）会明确回 `DIMENSION_UNSUPPORTED` 并列出可用维度，不静默忽略。

### 5.2 HTTP 路由（约 70 个端点，BFF 一一对应）

分三层，都挂在同一个 data-api 进程：

- **壳层**：健康检查、两个查询入口、管理员对账、账户/任务/工作项列表、工作项与变更集详情、登录会话与空间切换。
- **r010 组**：账户静音、工作项忽略、管理员成员与授权、日历、ETL 运行记录与重跑、变更集 dry-run、设置变更日志、Agent 模型目录。另有 **7 个显式 501 占位**（停止测试、自治度升档、素材复刻与投放、AI 提效估时、月度决策、搜索动作）——这是有意为之：契约有、一期不做，前端不许假装成功。
- **r014 组**：账户池状态、日报、级联筛选项、知识库七端点、个人化（偏好/关注名单/视图/待办计数/负载/通知）、命名规则与昵称解析、自助改密、任务详情与页签（时间线/漏斗/考核价/就绪度/批量保存）、账户交接、能力注册表、分级决策、导出、全局搜索。

前端 BFF（`apps/web/app/api/internal/**`，70 个路由文件）只做转发 + 加内部令牌，不写业务逻辑。

### 5.3 ETL 与命令行

| 命令 | 干什么 |
|---|---|
| `npm run start`（worker） | 长驻：迁移、分区维护、租约恢复、消费 Job 队列 |
| `npm run worker:once` | **跑一轮抓数**（内网部署最常用）：一次性有界执行，超时强杀 |
| `npm run start:worker-http` | 把上面那条包成 HTTP 触发口（带令牌 + 防并发锁），给 cron/调度器调 |
| `npm run worker:diagnose` | 只读诊断：看队列、身份、授权快照，不连上游 |
| `npm run discover:accounts` | 只读：列出某媒体下该 userId 能看到的账户，用来生成授权清单 |
| `npm run outbound:once` | 排空钉钉出站队列（本轮不开） |
| `npm run auth:cleanup` | 清过期会话 |
| `packages/db`：`migrate` / `seed:bootstrap` / `seed:coefficients` / `seed:qihang-identity` | 迁移与初始化 |

Job 类型：`etl_full / etl_incr / backfill_historical / backfill_day / canonical_merge / data_quality_check`。⚠️ `apps/worker/src/r014/handlers.ts` 里给早报生成、导出渲染、定时推送留了槽，**目前是空的**。

### 5.4 数据库

- 迁移 **24 个**（001–031，编号不连续：013/014/016/017/021/024/026 是并行分支占过的空号，不是漏迁移）。自检方式：`select count(*) from pgmigrations` 必须等于 `ls packages/db/migrations | grep -cE '^[0-9]'`。

### 5.5 钉钉网关现状（重要：别高估）

- 通了：`帮助`、`/查数 <问题>`（建 Agent 会话 → 转结构化查询 → 调 `/api/v1/query` 回数）。
- **没通**：「创建任务」直接短路回「尚未开放」；任意自由文本走 Agent 意图，同样回「尚未开放」。
- **根因**：网关客户端调用的 `POST /api/v1/agent/sessions`、`/sessions/:id/query`、`/work-items/:id/reply` 这几个端点，**worker 侧根本没有实现**（全仓只有 `/api/v1/agent/models`）。所以「查数」那条链路在没有 Agent 会话端点的环境下也跑不通，属于待接。
- 出站（我们主动发钉钉）：持久化、去重、重试、发送模块、worker HTTP 触发口都已写好并合入，**但本轮部署故意不开**（不配 `OUTBOUND_WORKSPACE_ID`）。等数据分析内网验收通过再开。

## 6. 已知缺口与坑（接手必看）

### 6.1 真实模式下仍然读样例数据的地方（全站唯一一处）

`/tasks?tab=manage`「任务管理」：`apps/web/lib/fixtures/task-manage.ts:41` 直接同步导出 JSON，**没有走全站统一的 `isOk()` 开关**，所以真实部署下这个 tab 显示的是样例任务；而它的「保存」是真接口（`POST /api/internal/tasks/batch-save`）。**读假写真、保存后不重新拉**——这是最高优先级修复项。

其余所有页面的样例数据都被 `isOk()` / `IS_MOCK` / `operationalIsMock` / `FIXTURES_ENABLED` 这层开关挡住，真实模式下降级为空态，不会冒充真数据。

### 6.2 点了不会真的发请求的按钮（「假成功」）

fe 盘点了优化师日常会点到的三块（数据分析 / 账户池 / 任务列表），共 **34 条**，清单在 `docs/plans/2026-09-13-假成功清单.md`，分三批：

| 批次 | 判据 | 条数 | 处置 |
|---|---|---|---|
| A | 后端和 BFF 都已经在，纯接线 | 12（3 条已修，剩 9 条） | 已派前端整批接，数据分析页三条排最前 |
| B | 后端没有端点，要先加 | 11 | 内网联调结束后排给后端 |
| C | 产品决策没定 | 11 | 一律改成诚实占位（置灰 + 写清卡在哪），**不接** |

另有两处不在清单里但同样是假动作：**设置页改密码**（`password-form.tsx:34` 用 `setTimeout` 模拟，从不发请求，而后端 `POST /auth/password` 是有的）、**任务详情页头的改价/改卡/改阶段按钮**（`task-detail-page.tsx:319` 只弹 toast）。

### 6.3 比假成功更坑的：文案在撒谎

有些地方接口早就接好了，文案还写着「接口接入后生效（当前为示例）」——排查的人会被带偏。已确认两处：知识库编辑器的「本地示例，接口接入后同步」和知识库页头的同类说明，实际上知识库全通了。账户池测试台的「停止测试」也属这类（路由在，文案说没接）。**处理办法**：全仓搜「接入后 / 当前为示例 / 待接入」，逐句对照 `apps/web/app/api/internal/**/route.ts` 实际导出的方法。

### 6.4 其他

- **差异对账恒 503**：不是 bug，是对账源没配（内网有 `qihang_media_operation_log` 可做源，未接）。
- **小时数据只有个人空间有**：团队源（KA Data）没有小时口径。
- **`DATA_SOURCE_TIMEZONE` 要在 worker 和 data-api 两个进程都配**，不配则盯盘没有小时数据、血缘里时区为空。
- **QQ 浏览器布局错位**：Chrome / Edge / 夸克正常，QQ 浏览器单独有问题，未修。
- **早报/导出/定时推送三个 Job 槽是空的**（`r014/handlers.ts`）。

## 7. 环境与部署

### 7.1 本地开发

```bash
npm install                     # 仓库根，允许 postinstall
docker start db-postgres-1      # 或自己起一个 PG
cd packages/db && DATABASE_URL=<dsn> npm run migrate
npm run --silent seed:bootstrap -- '<JSON>'     # 建身份与空间，形状见 docs/evidence/proposals/seed/
cd ../../apps/worker && npm run start:data-api  # 3101/3111
cd ../web && npm run build && npx next start -p 3411   # ★ 用生产模式，dev 模式吃 3.5G 内存会把 PG 挤挂
```

前端要跑真实模式就设 `NEXT_PUBLIC_KA_DATA_PROVIDER` 为非 mock 值，并配 `KA_DATA_BACKEND_ORIGIN` + `KA_DATA_SERVICE_TOKEN`（与 data-api 的 `DATA_API_INTERNAL_TOKEN` 完全一致）。详见 `docs/runbooks/2026-09-07-本地联调环境.md`。

### 7.2 内网部署（给别人用的正式路径）

两份文档配合使用：
- `docs/deploy/部署提示词-数据分析真数.md` —— 步骤 0～11 的完整 SOP，直接发给对方的内网 agent
- `docs/plans/2026-09-13-发给OS-数据分析联调验收.md` —— 六个业务场景 + 四个 tab 的验收单、已知问题、回执格式

凭证纪律（**不要破坏**）：启航 userId、KA Data 地址与 token、登录密码只进受控 env 文件，聊天和回执里只写「已设置」「已取到 N 字符」，不回传原文，不进仓库。

### 7.3 CI 与前端产物

- GitHub Actions 两条：`gates`（全量测试）与 `build-web-standalone`（把前端打成预编译产物推到 `deploy/web-standalone` 分支）。
- 内网部署直接取那个分支的产物，里面的 `SOURCE_SHA` 必须等于要部署的 main 提交，否则部署的是旧代码。

### 7.4 门禁（合并前必过）

全量测试当前规模：domain 1726 / db 1922 / worker 2592 / 钉钉网关 36 / web 404 条，外加 tsc 与 eslint 零错误。
另有一份人工门禁清单 `docs/plans/2026-09-07-上线前门禁清单.md`（A1–A46），都是踩过坑立的条目，例如：真实模式下数据分析页不许出现 fixture、参数键名只许走统一构造函数、真响应回放必须覆盖、CSV 导出要带 UTF-8 BOM、合并前必须跑联调冒烟。

冒烟脚本的思路（脚本本身在 arch 的机器上，接手后自己重建一份）：对联调库发 19 个探针，**其中 5 个必须走前端 BFF**——只打后端会绕过前端镜像校验，2026-09-13 的大盘 502 就是这么漏掉的。
