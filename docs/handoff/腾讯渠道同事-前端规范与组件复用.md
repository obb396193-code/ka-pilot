# 给腾讯渠道同事：前端规范与组件复用

> 出稿：fe（KA Pilot 前端会话），2026-09-08。
> 用途：你要做腾讯渠道的数据看板 / BI，和我们这套（KA Pilot）形态很像。这份文档告诉你**怎么直接用我们已经打磨过的设计规范和组件**，不用自己从零试审美。
> 配套文档：`docs/handoff/腾讯渠道同事-数据抓取指南.md`（数据从哪来）。

---

## 0. 一句话结论

**不要让你的 agent 自己发挥审美。** 我们这套壳（侧栏 / 顶栏 / 卡 / 表 / KPI / 主题 / 状态态）是老板逐页口头拍板打磨出来的，已经冻结成规范文件 + 可复制源码。你的 agent 只要**照抄 + 换数据**，出来的东西就和我们一个水准；它一旦"自己想一版"，大概率退回到 AI 默认的灰扑扑卡片堆。

所以你的 agent 的定位是：**功能你和它谈，视觉它没有决定权，只有执行权。**

## 2. 怎么给你

### 先回答「给仓库地址让他复刻」还是「先部署出来再改」

**答案是分三步，两个都用，但用在不同环节。** 这两件事其实不冲突——「看」和「做」应该用不同的东西。

**第一步：让他先把我们的跑起来看（一定要做）**

我们的前端**在 mock 模式下能脱离后端独立运行**，不需要数据库、不需要后端、不需要任何凭证。中间件在 mock 模式下直接放行登录，假数据全部从仓里的 fixture 读。所以他 clone 下来装完依赖就能看到全站十二个页面的真实样子。

```bash
cd apps/web
NEXT_PUBLIC_KA_DATA_PROVIDER=mock KA_DATA_DEV_AUTH_CONTEXT_ENABLED=true \
KA_DATA_DEV_WORKSPACE_ID=00000000-0000-4000-8000-000000000024 \
KA_DATA_DEV_USER_ID=demo-user \
KA_DATA_DEV_ACCOUNT_SCOPE_JSON='[{"media":"KUAISHOU","accountId":"demo-account-07"}]' \
npx next dev -p 3401
```

登录页点「进入工作台」就进去了。

**这一步不能省。** 老板的核心顾虑是他的 agent 审美不够——而「看到目标长什么样」比任何文字规范都有效。规范里写的「真黑真白不要灰」「点彩」「主色驯化」，光看文字复现不出来，看一眼页面就懂了。让他和他的 agent 都看。

注意首次启动慢：BlockNote 和 streamdown 那几个重依赖首次编译要一到三分钟，页面暂时打不开不是挂了。

**第二步：不要在我们的仓上直接改（这是我的建议）**

理由是具体的，不是洁癖：

- 我们这个仓是 **monorepo**，里面有前端、后端 worker、钉钉网关、三个共享包。他 fork 过去会背上整个后端。
- `apps/web` **不能单独复制**。它通过路径别名读仓根的 `packages/contract`，假数据层直接 import 契约里的 fixture。只拷前端目录会直接编译不过。
- 仓里 `private/` 目录有 **93 MB 内部资料**，clone 要拖下来。
- **我们现在正处于老板逐页精修期，改动非常频繁**。他在我们分支上改，会永久处于合并冲突状态。

**第三步：给他一个抽出来的干净起点（推荐）**

我从 `apps/web` 里把和业务无关的那层摘出来，做成一个独立的启动套件（下面第 2 小节的 `ka-ui-kit`）。他拿这个当项目起点，和我们解耦，但 token 和规范完全一致，做出来就是同一个产品家族的东西。

**同时把我们的仓库地址给他当只读参考。** 他的 agent 遇到「这个表格我们是怎么做的」「这个状态壳长什么样」，直接去我们仓里找对应文件照抄。这正是老板说的「尽量从我们源码里拉取」——**参考用仓库，起点用抽出来的包。**

一句话总结：**看用我们的仓，做用抽出来的包，查还是回我们的仓抄。**

下面是三种方式的完整对比，供你判断。

### 方式一：直接给整个仓（最省事，但耦合）

你 clone 我们仓，在 `apps/` 下开一个 `apps/tencent-bi`，复用根目录的 `packages/contract`。
- 好处：token、组件、契约天然一致，我们改了你 `git pull` 就有。
- 坏处：你的提交和我们的混在一起，我们还在高频精修，你会不断遇到冲突。**不推荐现阶段这么做。**

### 方式二：抽一个「设计系统包」给你（推荐）

我从 `apps/web` 里摘出与业务无关的那层，做成一个可复制的启动套件给你，内容是：

```

├── docs/

│   ├── 前端视觉与体验审核清单.md          ← L1 自检清单

│   └── utils.ts              ← cn() 工具
```

### 方式三：只给文档，他自己实现

只给 L1 三份规范。省事但效果最差——规范里写的"12 预设主色""墨水版主色驯化""状态色只表状态"这些，靠文字描述复现不出来。**不推荐。**

## 3. 必须让他照做的硬规则（挑最关键的）

这些是老板拍过板、我们踩过坑的，你的 agent 只要违反其中任何一条，东西就"不像我们的"：

**底子和颜色**
- 真黑真白，**灰只做发丝线**。老板原话「永远不要灰灰的」。AI 默认爱堆 `text-gray-500`，这是最大杀手。
- 三套主题模式同一套组件、只换 CSS 变量：黑白·点彩 / 黑白+彩 / 全彩。默认**黑白·点彩**，颜色只做点染（chip 一粒色点、图表一条点缀线）。
- **红绿黄是状态色，不进主色预设**。状态色只表状态，不参与主题配色。
- 主色一个 `--hue` 变量派生图表三色 / 按钮 / 选中态。切换开关放**顶栏右上角**，一点即换，不进设置页。
- 全彩模式要单色系：一个主色 + 中性色。多色卡片 + 标题色条 = 廉价感，老板否过两次。

**字体和数字**
- 字体栈：`Geist → PingFang SC → MiSans → Microsoft YaHei`。Mac 用苹方零下载，Windows 用 MiSans 兜底。
- 数字列和 KPI 必须 `font-variant-numeric: tabular-nums`，否则跳列。
- **前端永不算数**。CPA、达标率、Gap、环比、pacing 全部由后端给。前端只做格式化，走统一 formatter，禁止各页面手写 `toFixed()`。
- **缺数显 `−`，不显 0**。分母 0 也显 `−`。只有后端明确说"有数据且值为零"才显 0。这条是硬门禁，不是审美。

**表格**
- 全站**一种表**，照母版 DataTable：勾选框列 / 名字一行（不放 ID 副行）/ 类型 chip / 带图标的状态 chip（绿勾·红叉·黄叹号·转圈·时钟·虚线圈）/ 行末 ⋮ 菜单 / 「已选 N 条，共 M 条」页脚 + 勾选后批量动作。
- 红绿状态**同时给文字或图标**，不能只靠颜色。
- 详情用**行内展开**（点名字在行下方展开），不是右侧抽屉。

**状态**
- 每个页面必须覆盖八态：`loading / empty / partial / stale / error / no-permission / demo / disabled`。只做"正常有数据"那条路径是不合格的。
- **不造真实感假数据**。没接口的地方标「示例」角标 + 降饱和 + 写明解锁条件。

**组件来源**
- **绝不自写组件**。老板铁律，原话「自己写的会跟母版不一样」。先查资产目录 → 从官方源码复制 → 只写业务适配层。
- 同一能力多个库都有时，做成同业务容器**并排给人挑**，agent 不自选。

**动效**
- 只在能解释"什么变了"时用。即时反馈 100-180ms，状态过渡 180-280ms，布局变化 240-400ms。
- 必须支持 `prefers-reduced-motion`。禁止 `transition: all`。
- 表格正文、错误文案、按钮标签**不做动效**。

## 4. 我们踩过的坑（直接给他，省他几天）

| 坑 | 症状 | 解法 |
|---|---|---|
| TanStack Table 列显隐 | hydration 报错、控制台红字 | 初始列显隐必须走 `useGridTable({ initialColumnVisibility })`，不能在渲染中 `setColumnVisibility` |
| shadcn 面包屑 | 二级页 hydration 报错 | `BreadcrumbSeparator` 本身是 `<li>`，必须和 `BreadcrumbItem` **平级**，不能嵌在里面 |
| React Flow 画布 | useEffect 死循环 | `setNodes` 回调里无变化时必须返回 `prev` |
| BlockNote 编辑器 | SSR 直接挂死 | 页面里必须 `dynamic(..., { ssr: false })`，它依赖 DOM |
| dev 日志放仓库根 | 页面 20-40 秒才出来 | 日志文件绝不能落在工作树里，会触发文件监听循环重编译。挪到仓库外后 300ms |
| AI Elements CLI | 装 streamdown 系依赖时卡死 | 别用 CLI，直接 `curl https://elements.ai-sdk.dev/api/registry/<name>.json` 落文件，把 `@/registry/default/*` 改成 `@/components/*`，依赖手动装 |
| 重依赖首次编译 | curl 返回 000，以为挂了 | BlockNote / react-arborist / streamdown 首次编译要 1-3 分钟，不是挂 |

**另外两个我们仓里现存的小问题，别跟着抄：**
- `package.json` 里有个 `"cn": "^0.2.5"` 是误装的无关 npm 包（真正的 `cn()` 在 `lib/utils.ts`），你别装。
- `echarts` 和 `recharts` 现在并存，是历史遗留。你新起项目**只选一个**，建议 ECharts（配置驱动、按需引入、能接主题桥）。

**还有几件我们也没做完的，别信规范里写"已有"：**
Storybook 没装、ECharts 正式图表层没建、tweakcn token 桥没实现、Playwright 视觉回归没配、错误上报没接。规范里提到这些是"应该做"，不是"已经有"。

## 6. 建议的推进节奏

1. **先决定交付方式**。我建议方式二（抽设计系统包）。你点头我就做，产出一个 `ka-ui-kit/` 给他。
2. **他先只做壳**。用假数据把侧栏 + 顶栏 + 页头 + 一张表 + 六个 KPI 卡跑起来，你看一眼像不像我们的。像了再往下做。
3. **然后接数据**。看配套的数据抓取指南。
4. **他每做一页你看一眼**。我们这边就是这么做的——老板逐页看、口头改、改完提交。这个节奏比一次做完再返工快得多。

## 7. 需要注意的一件事

我们这个 GitHub 仓库现在是**公开状态**（`private: false`），而 `private/knowledge-sources/` 下有 2194 个内部资料文件在里面。arch 最近那笔提交的说明写的是「私有仓当完整备份」，说明推的时候以为是私有的。

给同团队同事看没问题，但这个仓现在是全网可见。你要把仓库地址给他之前，建议先让 arch 把可见性改成 private 再发。
