## 一、指标体系（直接采纳为我们的指标字典底稿）

### ★新发现的整套「赔付」指标（v2.1 完全没有）

| 指标 | 公式 | 说明 |
|---|---|---|
| 赔付金额 compensation | 原始值 | 媒体赔付 |
| **赔付后现金消耗** | (cost − compensation) **/ 渠道折算系数** | **★老板澄清：1.09 不是税、不是通用常数——是该渠道的充值返点折算系数**（充 100 到账 109，账面消耗含返点虚增，除回去才是现金）。**每个渠道系数不同**（取决于各渠道返点政策），且可能随框架协议变化 → 实现上必须做成**渠道级可配置参数（含生效日期版本化，与考核价版本化同机制）**，绝不硬编码 1.09 |
| 现金赔付 | compensation / 1.09 | |
| **现金成本 cash_cpa** | (cost − compensation) / 渠道折算系数 / bi_volume | 真实单转化成本的权威公式（系数按渠道配置） |
| **业务赔付缺值** | (cash_cpa − target_cost) × bi_volume | 正值=超成本额——即我们「成本空间」的负数形式，两者统一口径时以此为准 |

### 扣量与归因细化（v2.1 只有 deduction_rate 一个字段）

- `attribution_volume`（归因量级）为独立概念
- 扣量比例 = deduction_count / attribution_volume
- GAP = media_conversions / bi_volume − 1
- **扣量前 GAP** = attribution_volume / bi_volume − 1（区分"扣量造成的 GAP"和"归因本身的 GAP"）
- 扣量比例区间维度：0-5% / 5-10% / 10-20% / >20%

### 转化链路比率（补全内网简版的漏斗）

唤端 wakeup → 潜客 potential → BI 量级；潜客率 = potential/wakeup；BI 转化率 = bi_volume/potential。

### ★投放健康度指标群（整组新增，需计划级数据→依赖 B2 结构同步）

空耗计划量占比｜空耗消耗占比｜0消耗曝光占比｜**冷启动通过率**（通过数/新建数）｜**新品跑出率**｜**新素材跑出率**｜**单计划 ARPPU**（总消耗/有消耗计划数）。

### 消耗分层（新增形式化）

计划 Tier1-5（≥1万/1千-1万/100-1千/0-100/空耗）＋素材 S/A/B/C（≥5万/1-5万/1千-1万/<1千），阈值可配。

### 环比字段约定（工程规范直接抄）

绝对值指标 (今−昨)/昨；**比率指标用百分点差值**；昨=0 今>0 返回 "NEW"；分母为 0 返回 null 展示 "−"；正红↑负绿↓。

## 二、8 维度体系（补两个新维度）

D1 **代理/自投（两级：大类→负责人）**——新维度，此前完全没有"代理"概念｜D2 业务｜D3/D4 任务（携带所属业务）｜D5 账户｜D6 资源位｜D7 出价工具｜D8 **是否 UBP/UAA/智投**——新维度。层级：业务→任务→账户；代理/自投→负责人。

## 三、语义层 API 设计（直接当我们数据服务的契约蓝本）

`query_type`: summary（大盘）/ dimension（8 维度之一）/ health（健康度）/ tier（分层）/ trend（7 日时序）；一份完整日报 = 12 次调用序列。入参含 filters、dimension_type；**返回结构 summary 与 dimension 完全同构（每行全量指标+环比）**——这个设计保证四角色同源，直接采纳。

## 四、权限模型（与 B1 裁决对齐并补充）

- 两角色：**渠道经理**（渠道级，可管多渠道）/ 优化师（账户级，channel 自动从授权账户推断不可指定）——渠道经理是新角色概念，对应我们的负责人视图
- 权限校验统一在数据层（MCP）完成，应用层不处理——与我们"库内 ACL"同构
- 基于 **mozi 权限系统**（=启航 userId 的身份体系，与 10 号文档 MOZI_USER_ID 环境变量对上了）
- 错误码规范：CHANNEL_UNAUTHORIZED / ACCOUNT_UNAUTHORIZED / NO_AUTHORIZED_ACCOUNTS

## 五、15 条实时盯盘规则（带阈值，直接入规则库候选）

**账户级 7 条**：ACC_001 消耗突增(1h 环比>50%)｜002 突降(>50%)｜003 预算将尽(>80%)｜004 已尽(≥100%)｜005 成本超支(>目标×1.2)｜006 严重超成本(×1.5)｜007 无消耗(连续 2h=0)。
**广告组级 8 条**：AD_001 空耗预警(>¥100 零转化)｜002 空耗严重(>¥500)｜003/004 超成本(×1.2/×1.5)｜005 CTR 骤降(>50%)｜006 CVR 骤降｜007 消耗突增(1h>100%)｜008 高消耗低转化(消耗 TOP10 但转化<均值)。
另：**cost_velocity（消耗速度）**与**estimated_daily_cost（预估日消耗=当前消耗/时间占比）**两个派生指标——与我们的断量倒计时、日内 pacing 同族，公式现成。

## 六、三表数据架构（库表设计参考）

主表 74 字段（8 业务维度+34 指标+环比）｜赔付表 22 字段（仅账户级以上）｜**素材表 85 字段（6 素材维度：名称/ID/制作商/AIGC 标识/规格/类型 + 25 项素材健康度）**。素材表的"制作商分析"和"**AIGC vs 非 AIGC 效果对比**"两个用例，与我们的 AIGC 下单平台内嵌正好呼应——素材闭环的分析端有了字段设计。

## 七、日报结构（12 模块 HTML + Executive Summary）

摘要区=6 卡片+异常事项汇总（按严重度排序、自然语言格式）→ 大盘 → 8 维度模块 → 扣量分析 → 健康度 → 分层。每维度模块统一结构：汇总卡片→数据表（异常行高亮）→图表（TOP10 柱状/成本 vs 考核对比）→异常摘要。**直接当我们自动日报的版式蓝本。**
