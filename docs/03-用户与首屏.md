# 四角色与首屏定义

> 建立：2026-08-13，来源：老板给出四角色首屏表 + 我的扩充
> 定位：这是**产品的骨架**。一个数据内核，四种视图；不是四个产品，也不是给所有人看同一张明细表。
> 铁律：每个角色打开产品，**第一屏就要看到属于他的结论**，不需要筛选、不需要下钻、不需要问人。

## 0. 老板原始定义（不改动）

| 角色 | 打开产品首先要看到什么 |
|---|---|
| 优化师 | 今天哪些账户要处理、为什么、建议动作、执行入口 |
| 运营 | 任务完成情况、Gap、异常归因、账户与渠道协同 |
| KA 负责人 | 各渠道效率、风险、资源分配、团队执行情况 |
| 更高层 | 核心目标、重要异常、AI 提效成果、需要拍板的问题 |

## 1. 四角色的本质差别

差别不在"看的数据不同"，在**要回答的问题不同、时间尺度不同、动作粒度不同**。

| 维度 | 优化师 | 运营 | KA 负责人 | 更高层 |
|---|---|---|---|---|
| 回答的问题 | 我现在该动哪个户 | 任务能不能达成、差在哪 | 钱和人该往哪投 | 这事值不值得继续投入 |
| 时间尺度 | 今天 / 实时 | 本周 / 本月周期 | 月度 / 季度 | 季度 / 年度 |
| 数据粒度 | 账户、计划、单元 | 任务 × 渠道 | 渠道 × 团队 | 部门整体 |
| 要的动作 | 直接执行调控 | 协调与追人 | 分配与决策 | 拍板与背书 |
| 看错的代价 | 一个户超成本 | 一个任务没达成 | 一个季度资源错配 | 战略误判 |
| 停留时长 | 长（工作台） | 中 | 短 | 极短（30 秒） |

**推论**：越往上，信息越要收敛成"结论 + 例外"，绝不能给明细表。给 KA 负责人一屏 50 行账户表，等于没给。

## 2. 逐角色首屏设计要点

### 2.1 优化师（工作台，日常长时间停留）

**核心是一条「今日待处理队列」**，不是看板。看板是给人看的，队列是给人干的。

每条必须四件套齐全，缺一条就不敢用：
1. **哪个户**（账户 + 任务 + 归属）
2. **为什么**（触发了什么规则、证据数字、和考核价差多少）
3. **建议动作**（改什么、改到多少、依据是什么）
4. **执行入口**（一键预览 → 确认 → 落到 kuaishou-cli）

配套：
- **优先级排序**：超成本起量 > 0 曝光 > 消耗断崖 > 衰退 > 机会扩量。今天只有 20 分钟也能先处理最要紧的三条。
- **处理状态**：已处理 / 忽略（记原因）/ 待观察。**忽略要留痕**，明天不再重复弹同一条。
- **效果回收**：改完之后 T+1 自动回来告诉你"这个动作生效了没"。这是 agent 和脚本的分水岭——脚本只会提醒，agent 要闭环。

### 2.2 运营（周期视角，横向协同）

**核心是「任务达成 × Gap 归因」**。
- 任务维度而非账户维度：这个任务本月目标 vs 当前进度 vs 按当前速度能否达成。
- **Gap 归因**：账面转化和 BI 转化差多少、差在哪个渠道/账户/时段——这是运营天天要解释、又最难解释的事。
- 跨渠道协同：同一任务在快手/抖音/腾讯的成本与量级对比，谁该加谁该收。
- 异常要给**原因候选**，不只给数字：出价改了 / 素材衰退 / 竞争加剧 / 归因口径变了。

### 2.3 KA 负责人（决策视角，短停留）

**核心是「渠道效率排名 + 风险清单 + 资源建议」**。
- 各渠道单位成本、达成率、趋势，一屏可比。
- 风险清单：本周期最可能没达成的任务、最可能超预算的渠道。
- 资源分配建议：钱从哪挪到哪，理由和预期收益。
- **团队执行情况**：谁处理了多少条建议、平均响应时长、处理后效果——这条要**极小心**，做成绩效监控会让优化师抵制整个产品。建议只对负责人展示聚合值、不做个人排名（详见 §4 风险）。

### 2.4 更高层（30 秒视角）

**核心是「三个数 + 一句话 + 需要你拍板的事」**。
- 核心目标进度：一个数、一个趋势箭头。
- 重要异常：最多三条，每条一句话。
- **AI 提效成果**：这是唯一一处产品要为自己举证的地方——本周期 agent 处理了多少条、节省多少人工工时、避免多少超成本损失。**AI Native 交差就靠这一屏**。
- 需要拍板的问题：预算追加、口径变更、资源冲突。

## 3. 一个内核，四种视图

四个角色的数字必须**同源同口径**，否则会出现"负责人看到的成本和优化师看到的不一样"，一次就失信、再也拉不回来。

架构含义：
- 底层：一份统一的事实表（媒体账面 + BI 真实转化 + 考核价 + 映射关系）。
- 中层：口径与规则引擎（成本空间、Gap、诊断规则），**唯一实现，不在前端各算一遍**。
- 上层：四套视图，只做聚合与呈现，不做计算。

## 4. 三个必须提前避开的坑

1. **绩效监控化**：一旦优化师觉得这是"监工工具"，产品就死了。第一批用户就是优化师，他们不用，上面看到的全是空数据。原则：**对个人只呈现帮助，对上层只呈现聚合**。
2. **权限混淆**：优化师只应看到自己的户，运营看自己负责的任务，负责人看全部。**多用户鉴权系统的第一需求不是登录，是数据可见范围。**
3. **首屏错位**：给谁看什么，在设计阶段钉死。任何"要不要在优化师首屏加个大盘趋势"的想法，先问"这能帮他决定动哪个户吗"，不能就不加。
