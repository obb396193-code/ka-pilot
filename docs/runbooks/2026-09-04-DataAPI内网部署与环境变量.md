# Data API 内网部署与环境变量

> 适用范围：`apps/worker` 的 `npm run start:data-api`。这是当前仓库 Data API 的部署入口说明；媒体写操作仍关闭。

## 0.0 内测拓扑定案（2026-09-07 OS 八条回收后）

- **FaaS 出网 443-only，任何 5432 都连不上（OS 实测）** → 内测 = **方案 A：整套跑沙箱**（web:3000 / data-api:3101 / worker HTTP 触发，PG = 沙箱 `postgresql://admin@127.0.0.1:5432/<db>`，trust 无密码仅内测）。沙箱重启 PG 不自启：部署脚本首步 `start_pg_tcp.sh`，data-api 启动探针连不上库拒启。
- worker 定时 = worker HTTP 函数 `POST /internal/worker/once`（`WORKER_TRIGGER_TOKEN`）+ autopilot cron 每 10 分钟。
- **应用与域名（2026-09-07 OS 回收）**：走 **aone-platform FaaS**（不是轻量 FaaS）建应用 `ka-pilot` → 自动带出 AONE 应用 + 代码仓库 + daily/pre/prod 三环境 + 域名 `ka-pilot.fn.taobao.net`（正式 `ka-pilot.fn.alibaba-inc.com`）。**建应用与发 daily 无外部审批**；发 pre/prod 走 CR + 流水线门禁（代码评审/安全扫描/可能人工审批），需老板提前物色技术同学/PE 当对接人。品牌域名走 `fs.alibaba-inc.com/#/ingressManage`，内测不用。
- **RDS 申请入口 = CloudCenter `cc.alibaba-inc.com/resource`（不是 Normandy CLI）**；必须归属一个 AONE 应用 + 云账号 uid；CC 强制多可用区、无免审批测试档。申请表与三个要找的人见 `docs/evidence/integration/2026-09-07-os-部署路径与RDS申请.md`。
- 正式化（FaaS + 内网 RDS）前置 = AONE 应用（走 aone-platform 建 ka-pilot 即得）+ 云账号 uid + CC 建库 + **一次 FaaS→RDS:5432 连通实测与出口 IP 是否固定**；个人云 RDS 公网端点已证不通。
- **★迁移编号有空洞是正常的，但升级必须一次跑到头**：并行开发下编号按批次预分配（013 团队快照 / 014 警报协作 / 015 已落 / 016 素材 / 017 P2 / 018 昵称解析），**先落地的不一定是编号小的**。`npm run migrate` 会按文件名顺序补齐所有未应用的，不要手工挑号。
  - 升级前后各跑一次 `SELECT count(*) FROM pgmigrations`，对得上仓库里 `packages/db/migrations/*.cjs` 的个数才算完。
  - **arch 联调实测踩到**：库停在 012 而仓库已有 015，9 条新端点全部 500（表不存在）。部署脚本必须在起服务前校验这一条，否则线上就是一片 500。
- **★前端必须用生产构建起，不许用 `next dev`**：dev 模式是「点到哪编译哪一页」，第一次点每页都要等（实测单页几百毫秒到几十秒，前端 agent 报过 899s）。生产构建提前编译好，实测**每页 5ms**。
  - 起法：`cd apps/web && npm run build && PORT=3000 npm start`（不是 `npm run dev`）。
  - 改代码后必须重新 build 才生效。
  - **换过路由名要先 `rm -rf .next`**：旧路由残留会让 build 报 `Cannot find module for page`（arch 实测踩到）。
- **★沙箱走 http 时必须设 `AUTH_COOKIE_INSECURE=1`（否则登录后立刻掉线）**：会话 cookie 默认带 `Secure`，浏览器在 http 上会直接丢弃 → 表现为「登录成功但读取会话失败」。沙箱 port-mapping 若给的是 https 就不用设；给 http 就必须设，**web 和 data-api 两侧都要设**（后端发 cookie、BFF 校验 cookie，成对生效）。
  - **正式环境（有 TLS）禁止设置该变量**，默认 Secure 才是对的。
  - arch 浏览器实测踩到（I-004）：curl 不校验该属性，只跑接口联调发现不了，必须真浏览器点一次。
- **★装依赖必须允许 postinstall（否则前端白屏）**：`apps/web` 的中文字体切片 `app/fonts/misans/misans.css` 由 `scripts/fonts/prepare-misans.mjs` 在 postinstall 生成且**不入仓**。没生成 → `app/layout.tsx` 编译失败 → **全站 500**。所以：
  - 装依赖用 `npm install`（仓库根，会跑 `scripts/install-all.sh`），**不要加 `--ignore-scripts`**；
  - 装完先自检：`ls apps/web/app/fonts/misans/misans.css`，不在就手动补跑 `node apps/web/scripts/fonts/prepare-misans.mjs`（正常输出「MiSans 就绪：300 个切片」）；
  - 这条已由 arch 在本地联调时实测踩到（I-003）。
- **worker 定时（定案）**：保留已实现的 HTTP 触发口 `POST /internal/worker/once`（`WORKER_TRIGGER_TOKEN` + 跨实例单飞锁）；**沙箱期由部署脚本挂后台循环** `while true; do curl -s -X POST -H "X-Worker-Trigger-Token: $TOK" http://127.0.0.1:3102/internal/worker/once >/dev/null; sleep 600; done`（沙箱无 crond，autopilot schedule 触发的是 agent 不是 HTTP，太重）。正式化切 FaaS 时只换触发源，代码零改动。备份脚本 `pg_backup.sh` 同样用后台循环调度。
- 凭证规矩：生成 → 落沙箱文件/config vars → 聊天只报"已设置"。
- **备份（方案 A 必做）**：每日 03:30 `pg_dump -Fc` → gzip → 上传公司 OSS（443 可达）`ka-pilot-backup/<date>.dump.gz`，保留 14 天；部署后做一次恢复演练（新库 pg_restore → data-api 探针通）。沙箱被回收 = 最多丢一天人产数据（任务/工作项/变更集/知识库/设置变更），指标数据可从启航/ka-data 重拉。
- **正式化并行**：老板走 Normandy 申请内网 RDS PG16（2C4G 起、50G、与 FaaS 同 VPC、pgcrypto+btree_gist、库 ka_pilot、迁移/运行两账号）；到手 OS 先做 FaaS→RDS:5432 连通实测，再谈迁移。

## 0. 内网拓扑与前置（2026-09-05 OS 回收后定案）

- **数据库**：产品自有 PostgreSQL 16 = 阿里云 **RDS PostgreSQL 16（最小规格）或 PolarDB-PG**，由老板走资源工单/控制台建（**9-6：工单预计过不了，候选=OS 沙箱 PG16 内测 / 个人阿里云 RDS 公网，待 OS 实测出网，老板待定**）；**不选 ADB-PG**（扩展白名单制，无 btree_gist）。CLI 不能建库。连接串形态 `pgm-xxxx.pg.rds.aliyuncs.com:5432/<db>`。
- **拓扑方案 B**（FaaS 请求触发/无状态，常驻进程会被回收）：`web` 一个 app；`data-api` 一个 app，设 `DATA_API_HOST=0.0.0.0`，只靠 `DATA_API_INTERNAL_TOKEN` 保护（内网网络策略再收口）；`worker` **不常驻**，用 `npm run worker:once`（tick + 消费到空 + 退出）由 a1 定时函数/autopilot cron 每 5–15 分钟触发。jobs 表 lease 保证容器回收后可重领。
- **构建**：a1 faas build.sh 构建期 `npm install` 走内网 registry（`registry.anpm.alibaba-inc.com`），自动 node 20；zip ≤2GB；不打 node_modules。仓库根级 `package.json`（R-013b）负责按 domain → db → worker/web 顺序安装。
- **FFmpeg**：镜像无；一期不部署素材链路。以后用 `imageio-ffmpeg` 静态二进制 + 单独打包 ffprobe。
- **出网**：`MATERIAL_SOURCE_ALLOWED_HOSTS=hwmov.a.kwimgs.com,tx2.a.yximgs.com`（素材 CDN，第四轮 + 本轮实证）。
- **https**：Session cookie 带 `Secure`，web 必须经 https 访问（a1 faas 域名默认 https；若内网走 http 反代，登录必失败）。
- **凭证红线**：任何 token/密码值**不得通过聊天/中转回传**（2026-09-05 一枚 `DATA_API_INTERNAL_TOKEN` 因回传作废）。OS 生成后直接 `config vars set`，只回传"已设置"。identityId（UUID）可回传。
- **ka-data 团队源**：`KA_DATA_BASE_URL` 是 owner 沙箱会话地址，重启即变（见 §3）；一枚 reader 可见全团队账户（已实证）。

## 1. 默认启动边界

- `KA_DATA_ENABLED=false` 是默认值。KA Data 是管理员备用诊断源，未配置它不得阻断健康检查、会话、启航主链、任务、账户和工作项只读接口。
- 只有服务端显式设置 `KA_DATA_ENABLED=true` 时，才必须同时提供 `KA_DATA_BASE_URL` 和 `KA_DATA_READER_TOKEN`。浏览器不能传或覆盖这个开关。
- `DATA_DIAGNOSTIC_ENABLED=false` 是默认值。角色（包括 admin）不会自动获得诊断权限；必须同时由服务端 allowlist 精确授权 workspace-local user。
- `INTERNAL_TEST_AUTH_ENABLED=false` 是生产默认值。内测登录只用于 BUC 接入前的受控内网试用。
- Data API 仅监听受控内网/localhost；浏览器经 Next BFF 访问，不能直接持有 `DATA_API_INTERNAL_TOKEN`。

| 变量 | 约束 | 说明 |

## 2.5 首次初始化与账户发现（R013 分批接入）

当前候选实现状态：`discover:accounts` 已通过本机假上游测试；`seed:bootstrap`（c7358fe）事务/CLI及真实PG→HTTP登录/切空间已验证，待arch复审；**未调用真实启航、未完成内网部署**。

在`packages/db`执行 `npm run --silent seed:bootstrap -- '<经过确认的JSON>'`，DATABASE_URL由部署环境注入；命令不自动迁移、不创建密码/会话、不修改既有角色/身份/授权。JSON形状见Domain bootstrapSeedSchema；全假数据示例提案在`docs/evidence/proposals/seed/bootstrap.example.json`，Contract fixture由arch落。部署时将identity_id替换为OS确认的实际身份，UUID引用须一致，不把秘密写进JSON。

先空grants初始化身份/个人与团队空间、成员；完成账户发现和人工确认后，再显式seed grants。新grant仅read，并只创建账户三键占位（name/status未知），不会默认全账户授权。团队不创建账户grant；同identity两个active personal或personal共享均拒绝。命令原子提交，失败整批回滚、退出1、固定错误；相同输入幂等重跑。输出inserted及解析出的workspace/user UUID，不输出provider subject。可选UUID省略时须保存输出，推荐使用全显式UUID输入。

计划顺序：migrate → seed身份/空间/成员 → 只读discover → 人确认清单后显式seed grants → 首次sync → start:data-api。没有显式账户grant仍被ACCOUNT_SCOPE_MISSING阻止同步，不支持all_accounts_in_workspace。

账户发现单独使用两个服务端变量，不需要DATABASE_URL：

| 变量 | 要求 |
|---|---|
| `QIHANG_BASE_URL` | 必填，启航get_data的HTTPS完整路径，不带用户名、密码、query或fragment；不自动回退默认地址 |
| `WORKER_SERVICE_QIHANG_USER_ID` | 必填，仅配置本人授权的启航身份；不传命令行、不输出到日志 |

在`apps/worker`中执行 `npm run --silent discover:accounts -- --media KUAISHOU`。`--silent`用于避免npm自身脚本标题污染JSON stdout；输出只含media/account_id/account_name/task_id/biz_name五字段。未知名称/任务/业务为null，不补假值。账户ID是实际授权数据，stdout按内部数据处理，不提交仓库。

- 只发GET account，50条/页、总量上限10000；可信总数恰好10000可完整，超限拒绝。必须所有页总数稳定、页码/行数对齐且账户不重复，才一次输出完整JSON；缺页、截断、跨媒体、坏字段全部失败，无部分清单输出。
- 单响应上限严格小于16MB、最终输出也严格小于16MB；30秒请求超时、不跟随重定向、不自动重试。失败只返回固定`Account discovery failed`和退出码1，避免泄漏上游URL、userId或body。
- 不写数据库、不创建grant、不发job、不调用媒体写。真实启航连通尚需OS验证；bootstrap三项初始化边界见inbox-arch P047。

### 2.6 单轮 Worker 操作（R013b候选；未在内网部署）

完成独立migration与初始化后，在`apps/worker`执行`npm run --silent worker:once`。该命令会入队并消费指定workspace的真实任务，**不要为了看页面在业务数据库运行**。无命令行参数；仅使用服务端部署配置：`DATABASE_URL`、`QIHANG_BASE_URL`（HTTPS完整get_data路径、无query/凭证）、`WORKER_ONCE_WORKSPACE_ID`（active personal UUID）、`WORKER_ONCE_MEDIA`（显式媒体）。`WORKER_ONCE_MODE=auto|full|incr`默认auto；`WORKER_ONCE_MAX_MS`默认600000（1至2147483647）；`WORKER_LEASE_SECONDS`默认60（1至3600）。

先tick，经DB解析本人membership/user/显式grants，再消费现有ETL/quality白名单；不使用`WORKER_SERVICE_QIHANG_USER_ID`兜底。没有候选正常退出0；blocked_auth不消费旧job且退出1；当前无可领取任务/达硬期限退出0。达到期限会终止child并等其退出，未完成job保留lease供下一次重领；尚未到retry时间的job也留下一轮，退出0不表示所有排队任务都已成功。运行错误/主动SIGINT或SIGTERM退出1，固定错误文本。

只输出jobId/jobType/status的JSON行，不输出payload、源身份、SQL或原始响应。不会自动migration、不会开启媒体写、不会全局恢复其他workspace任务。调度频率仍由部署scheduler配置；真实FaaS模板与OS内网验证待完成，不把本机隔离PG测试视为已部署。

### 2.7 单轮 Worker HTTP 触发（R013b / v1.7.7；本机合成联测，不是内网已部署）

在上述 2.6 配置基础上，用服务端 Secret 设置 `WORKER_TRIGGER_TOKEN`（32–512 位 `[A-Za-z0-9._~-]`；部署方可用 `openssl rand -hex 32` 生成并直接存 Secret，不在聊天/仓库/日志回传）。配置 `WORKER_HTTP_HOST` 默认 `127.0.0.1`，反向代理或受控容器入口需要时显式 `0.0.0.0`；`WORKER_HTTP_PORT` 默认 3102。运行 `npm --prefix apps/worker run --silent start:worker-http`。启动只监听，不入队、不需要 KA Data token；`GET /health` 只证明进程存活，不证明 PG/启航已连通。

- 唯一触发入口 `POST /internal/worker/once`，Header `X-Worker-Trigger-Token` 取服务端 Secret；空 body 或 `{}`，禁止 query/body 覆盖 workspace、media、身份、业务任务内容。无/错/重复 token 401，已有同 workspace 轮次 409 `WORKER_BUSY`；其他写路径不挂载。不要把 token 放 URL 或浏览器。
- 一轮复用现有 tick + scoped read-ETL consumer；只认 DB 的本人 membership/user/grants，不启用媒体写，不回退共享 userId。HTTP 结果 `status=completed|budget|blocked_auth`；`jobs.leased/done/failed` 是本轮 consumer 的领取次数/已提交完成次数/终态失败次数，不含 tick 重放旧状态、重试排队或授权阻断。`completed` 只表示本轮结束，不能当成所有异步任务成功或数据 ready。
- 同进程 busy + 同库/workspace PG session advisory lock。锁持有一条专用连接、无长事务；只有实际 child close 后才解锁。锁连接断开取消 child；父进程意外消失时 child 因 IPC disconnect 退出。截止终止后未完成 job 仍由原 lease/fencing 恢复，不假写 done/failed。启动多实例需同库同 workspace 配置，不能各用独立库绕锁。
- 请求断开不立刻取消后台轮次，重试会先遇 busy。按 arch P116 / OS 回收，沙箱无 crond，autopilot schedule 触发的是 agent 而非直接 HTTP；沙箱期由部署脚本挂后台循环：调用 localhost:3102 的上述 HTTP 口，完成或失败后 sleep 600 再调用。不是固定每十分钟完成一轮的承诺；HTTP 口保留，正式 FaaS 可换触发源。本批只登记方案，不启动循环、不执行真实任务。
- 循环从服务端 Secret 注入 token，禁止 shell tracing / verbose curl / token URL；部署实现应通过权限受控 header 文件或 stdin 配置传给 curl，避免把 Secret 展开进进程参数。网关/调用方等待时限必须覆盖 `WORKER_ONCE_MAX_MS`（默认 600000）加连接/解锁开销；部分 FaaS 的 HTTP 最长时限仍需 OS 实证，不能用本机结果承诺。关闭服务先停止触发循环再 SIGTERM，父进程终止 child 并等退出后关闭连接。
- 错误是固定文本与安全 requestId，不输出私有 SQL、DSN、源 body、token、qihang userId。合法 `x-request-id` 透传到响应 header/错误，非法值安全重建。成功体严格固定大小；请求体达到 1KiB 上限即拒绝。
- 本批没有部署实际内网服务、没有使用真实凭证。方案 A 的 PG 启动脚本、OSS 备份/恢复演练与正式内网 RDS 连通性仍按 §0.0/OS 门禁执行；OS §4 给的是 f.yml 结构说明，不声称已有可直接发布且验证过的 YAML。

## 3. KA Data 可选配置

**生产启动硬门（a77b224）**：部署设置`NODE_ENV=production`；Data API、Worker配置及KA reader工厂会在使用配置前拒绝任何`KA_DATA_DEV_*`变量，值为`false`或空串也拒绝。需删除整项测试变量，不是改值。错误只显示固定文本，不回显变量名/值；KA关闭时也不豁免。此项已通过本机子进程测试，未在FaaS部署。

| 变量 | 默认/约束 | 说明 |
|---|---|---|
| `KA_DATA_ENABLED` | `false` | 备用源总开关 |
| `KA_DATA_BASE_URL` | enabled 时必需，HTTPS origin | 固定的服务端上游地址。**内测期是 owner 沙箱会话地址，沙箱重启即变**：变更 = 让 owner 重取 port-mapping URL → 改 config var → 重启 data-api（运行期 origin 固定不热切）；正式前需稳定域名 |
| `KA_DATA_READER_TOKEN` | enabled 时必需，Secret | 只读共享凭证，不进浏览器和日志 |
| `KA_DATA_ACCESS_MODE` | `internal_trial_shared_reader` | 服务端访问模式 |
| `KA_DATA_TEAM_WORKSPACE_ID` | enabled 时必需，UUID | **一枚 reader ↔ 一个团队 workspace** 的服务端绑定（2026-09-05 arch 裁）；其他 team workspace 的读 → `503 SOURCE_UNAVAILABLE`；不接受浏览器 workspace 参数，不依赖 team grants |
| `KA_DATA_TIMEOUT_MS` | `15000` | 上游超时 |
| `KA_DATA_MAX_RESPONSE_BYTES` | `16777216` | 上游响应上限 |
| `DATA_DIAGNOSTIC_ENABLED` | `false` | 双数据诊断总开关；不是浏览器参数 |
| `DATA_DIAGNOSTIC_ENTITLEMENTS_JSON` | enabled 时必需，最多 1000 条 | 严格 `{workspaceId,userId}` allowlist；重复或非法 UUID 拒绝启动 |

普通 Session 无论角色，`data/query` 都由服务端固定为 `platform`，请求 body 不能开启 `ka_data/reconcile`。
只有总开关开启且当前 `(workspaceId,userId)` 命中 allowlist 时才保留诊断视图；此时若
`KA_DATA_ENABLED=false`，`ka_data/reconcile` 返回稳定 `422 VIEW_UNSUPPORTED`，不会调用共享 reader。
关闭状态不会伪造空数据，也不会阻断其他主链。

## 4. 内测登录配置

| 变量 | 默认/约束 | 说明 |
|---|---|---|
| `INTERNAL_TEST_AUTH_ENABLED` | `false` | 仅内测试用时显式打开 |
| `INTERNAL_TEST_AUTH_CREDENTIALS_JSON` | enabled 时必需，最多 1000 条 | 只保存 username、salt、scrypt verifier、identity UUID |
| `AUTH_SESSION_TTL_SECONDS` | 默认 `28800`，范围 60 秒到 7 天 | 登录和成功切换空间后的服务端会话期限 |

凭证 JSON 结构：

```json
[
  {
    "username": "trial.user",
    "passwordSalt": "base64url-salt",
    "passwordScrypt": "64-lowercase-hex-characters",
    "identityId": "00000000-0000-4000-8000-000000000000"
  }
]
```

禁止放 plaintext password、cookie、session token、BUC subject、启航 userId 或其他 Secret ref。

### 生成 scrypt 材料

下面命令从标准输入读取密码，不把密码写入命令历史；输入后按 `Ctrl-D`。参数与运行时一致：N=16384、r=8、p=1、输出 32 字节。

```bash
node -e 'const c=require("node:crypto");let p="";process.stdin.setEncoding("utf8");process.stdin.on("data",d=>p+=d);process.stdin.on("end",()=>{p=p.replace(/\r?\n$/,"");const s=c.randomBytes(16);c.scrypt(p,s,32,{N:16384,r:8,p:1,maxmem:33554432},(e,k)=>{if(e)throw e;console.log(JSON.stringify({passwordSalt:s.toString("base64url"),passwordScrypt:k.toString("hex")}));});});'
```

把输出与 username、identityId 组合后写入部署 Secret，不写入 `.env` 模板或 Git。

### 轮换

1. 生成新 salt/verifier，更新 Secret 中对应用户条目。
2. 重启 Data API，使新登录只接受新密码。
3. 如需立即踢出旧会话，在数据库侧撤销该 identity 的 active session；仅换 verifier 不自动撤销既有 session。
4. 验证错误密码与“密码正确但身份/工作区不可用”对外均返回相同 `401 UNAUTHORIZED`，避免凭证探测。

## 6. 钉钉 durable inbox（R009 P0-12，独立网关进程）

- 代码入口 `apps/dingtalk-gateway` 的 `npm start`。先在维护步骤执行并验证 migration 011，网关自身不再自动迁移。
- 既有 `DATABASE_URL`、`DINGTALK_CLIENT_ID/SECRET`、`KA_WORKSPACE_ID`、`KA_API_BASE_URL` 见该包 `.env.example`。新增必填 `GATEWAY_INBOX_KEY_HEX`：32 字节随机 AES-GCM key，64 位 hex，仅 Secret 注入；缺失/非法拒绝启动。
- 安全生成：`node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`。只在受控部署终端执行，将输出直接存 Secret，不贴聊天/日志/仓库。
- key 跨重启保持一致。轮换前停收件并 drain 已接收消息；旧 key 在 Secret 历史中受控保留以人工恢复死信。没有自动解密降级或多 key 猜测；丢 key 无法恢复旧消息。
- 入库的是加密 message（包括临时 sessionWebhook）与加密 reply checkpoint，AAD 绑定 workspace/provider/event/purpose。临时 webhook 过期后不会自动换群或换身份发结果；失败到达上限保留 dead 待排查。
- `attempts` 领取时递增，兼作 fencing generation：中断也消耗尝试数。按 arch 最新冻结，`processed=true` 为 done；`processed=false AND attempts>=max_attempts AND last_error='ATTEMPTS_EXHAUSTED'` 为 dead。最终显式失败立即设置耗尽标记并失效租约；崩溃由领取入口在租约到期后补标，尚存活的最后一次尝试不提前标 dead。dead 不自动清行或重置次数。
- lease 为120秒，失败退避2/4/8/16/32秒（代码有300秒上限），每 tick 一条，DB `SKIP LOCKED` 支持多实例。新进程不用原回调即可恢复；当前处理完成后响应 SIGTERM/SIGINT 停机。
- 查询成功 checkpoint 后，回复失败不重查业务。回复远程成功但本地未记 done 的窗口可能重复发送文本；钉钉 session reply 没有已证实的远端幂等协议，**不承诺 exactly-once 送达**。只读查询结果 checkpoint 前崩溃可重新查询。
- 目前只支持机器人 text；非文本/非法 envelope 不 ACK、不执行。卡片回调另批接线，不让文本 worker 领取 card event。
- **部署未完成项**：旧 `ProductApiClient` 的 Agent/query 端点和服务端身份桥接尚待 R010 接通，当前不得把“收件箱可恢复”当作“真实钉钉查数可用”。任务创建/Agent job 本批明确关闭；不创建媒体写操作，不接真实凭证测试。

## 7. 产品登录会话维护（R013b，部署方显式触发）

本命令只清理 `auth_sessions` 中过期或撤销严格超过 720 小时的记录；不是 Codex/Claude/OS 对话清理，也不删除账户和投放数据。默认不排定时任务，不提供浏览器 API。

- 服务端注入 `DATABASE_URL`、必填 UUID `SESSION_CLEANUP_WORKSPACE_ID` 与 `SESSION_CLEANUP_RUN_ID`。workspace 必须存在；不要求启航身份或媒体 grant。凭证仅用部署 Secret，不贴命令行日志。
- 每个新逻辑轮次生成一个新 run UUID（例如 `node -e 'console.log(require("node:crypto").randomUUID())'`）；同一次重试保留原 UUID。幂等已完成任务不会因重试重新删除后来新增的记录。清剩余数据需新逻辑轮次，不重置旧任务。
- `SESSION_CLEANUP_MAX_MS` 默认 60000，最大 600000，必须正整数。入口在 `apps/worker` 执行 `npm run auth:cleanup`。由部署方/外部 scheduler 决定频率。
- 只领取配置 workspace 的 `auth_session_cleanup`，不会领取媒体或其他工作项。单 job 最多删 1000 条；一轮最多处理 10 个同范围 job，不代表会连续创建十批。数据库时钟判定保留期，短事务检查 job 租约并锁行，跳过并发 session 锁。
- 父进程达到预算会停止子进程并等待退出；已提交批次不会回滚。崩溃留下的租约须到期恢复，重试仍遵守相同范围。返回 `round finished`/`round budget reached` 仅指本轮结束，不代表队列或历史 session 已清空；指定逻辑 job 的数据库状态才是完成依据。
- 错误只输出固定消息，不记录 session/token hash/identity/数据库错误。大表尚无保留期专用索引及规模性能实证；单条语句 5 秒、锁等待 2 秒、事务空闲 10 秒限制，不宣传无限规模吞吐。
- 首次启用前完成隔离 PG 验证并按部署流程复核保留期；此文档不表示已在内网运行清理。
