## 第一次联调结果（2026-09-07，main @ 1c622d0）

| 接口 | 结果 | 说明 |
|---|---|---|
| `GET /healthz` | ✅ 200 `{"ok":true}` | 只返进程存活，不漏配置 |
| `POST /auth/login` | ✅ 200 | 返身份 + 当前空间 + 两个空间；**团队空间 readOnly=true** 与 AUTH-001 一致 |
| `GET /auth/session` | ✅ 200 | 同上结构 |
| `GET /auth/workspaces` | ✅ 200 | |
| `GET /accounts` | ✅ 200 | `items:[]`、`dataState:"partial"`、`coverage.complete:false`、`dataAsOf:null`、`selectedSource:"qihang"` |
| `GET /tasks` | ✅ 200 | 同上 |
| `GET /work-items` | ✅ 200 | `dataState:"empty"`、`coverage.complete:true`（本来就没有，不是缺数） |

**三条关键行为验穿**：
1. **内部接口必须带服务令牌**（`Authorization: Bearer $DATA_API_INTERNAL_TOKEN`），不带一律 401——包括登录本身。浏览器不直连，走 BFF 加这个头。
2. **没同步过数据 ≠ 空**：账户/任务返回 `partial` + `coverage.complete:false` + `dataAsOf:null`，不是假装 `empty`。工作项才是真 `empty`。这是「缺数不补 0」在真接口上的第一次实证。
3. **空间读写权限**从 seed 的 membership 正确推出（个人可写、团队只读）。
