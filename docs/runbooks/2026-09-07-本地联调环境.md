**三条关键行为验穿**：
1. **内部接口必须带服务令牌**（`Authorization: Bearer $DATA_API_INTERNAL_TOKEN`），不带一律 401——包括登录本身。浏览器不直连，走 BFF 加这个头。

3. **空间读写权限**从 seed 的 membership 正确推出（个人可写、团队只读）。

### 验穿的正确行为（不用改）

1. **两层鉴权**：业务列表接口必须**同时**有服务令牌与会话 cookie；只带令牌 401。浏览器只走 BFF，BFF 加令牌，设计正确。
2. **空间切换**：切到团队空间后 `readOnly:true` 正确从成员关系推出。
3. **缺数不补 0**：未同步过的账户/任务返回 `partial` + `coverage.complete:false` + `dataAsOf:null`，不是假 `empty`。
4. **未登录拦截**：中间件 307 到 `/login`，不泄露业务页。

## I-007：重启前端必须按端口杀进程，不能按命令名（2026-09-08 踩到）
`next start` 起来后进程名是 **`next-server`**，`pkill -f 'next start'` 匹配不到；新进程因端口被占静默失败，**3411 上继续跑昨晚的旧构建**，新加的 BFF 路由全部 404，看起来像代码没生效。
正确做法：`lsof -ti :3411 | xargs kill` 再起；起完核对 **页面源码里的 build id 与 `.next/BUILD_ID` 一致**。
沙箱部署同理：重发版前先按端口杀旧进程，再校验 BUILD_ID。
