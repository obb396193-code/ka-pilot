# 006 账户复合外键停写迁移

## 部署条件

`006_account_media_foreign_keys` 使用 node-pg-migrate 的 `singleTransaction` 执行。
`ADD CONSTRAINT + VALIDATE` 的表锁会持有到六张表全部完成，因此它不是在线低锁迁移。

首次内网部署必须按以下顺序：

1. 在 API/Worker 启动前执行，或进入明确的停写维护窗口。
2. 确认没有 ETL、回灌、余额同步或广告小时写入。
3. 执行 migration；任一孤儿三元组在 DDL 前的六表预检中直接中止。
4. 迁移内部 `lock_timeout=5s`、`statement_timeout=5min`；无法及时取锁时失败退出，不无期等待。
5. 迁移成功后才启动服务，然后运行 Repository/HTTP smoke。

## 预检对象

`task_accounts`、`metrics_raw`、`account_metrics_daily`、`account_balance`、
`ad_metrics_hourly`、`ad_entities` 每行都必须命中
`accounts(workspace_id, media, account_id)`。

## 时长证据边界

仓库的 PostgreSQL 16 migration test 记录本机空载/小样本迁移时长，并以 10 秒作为回归上限。
该数字只是 CI 回归证据，不是生产 SLA；真实数据量下仍必须使用停写窗口。
