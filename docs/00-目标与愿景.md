# 投放 Agent · 目标与愿景

> 建立：2026-08-13　状态：**已填**　来源：老板口述 2026-08-14
> 规则：本文件只写"做什么、为什么"，不写实现方案。

## 1. 第一性原理：这件事的本质是什么

### 1.1 优化师一天的真实工作流

| 时间段 | 动作 | 本质 | 花多久 | 现在用什么 |
|---|---|---|---|---|
| 早上到岗 | **看昨日+今早账面数据**：各账户消耗、曝光、点击、转化数；排查异常账户、超成本、断崖 | 对账户和各任务的跑量情况建立感知 | 约 30-60 分钟 | 快手后台/Excel/启航 |
| 等数据刷新 | 等 FBI/小站后端 BI 数据刷新后，**做透视表**看每个账户的真实成本、Gap、异常 | 媒体账面 vs 后端真实转化的差异分析——这是真正做判断的数据基础 | 约 30-60 分钟 | Excel 手工透视 |
| **处理账户** | 根据数据决定怎么动账户（**策略因人而异，数据是共通的**） | 核心决策：该动哪个户、动什么、为什么 | 约 2-3 小时 | 经验 + 手工操作 |
| 执行动作 | 优质账户复制/拷贝扩量；超成本账户删除关闭垃圾计划；调价、调时段、调预算 | 把判断变成投放平台上的实际动作 | 分散在全天 | 快手后台/CLI |
| 新任务处理 | 看上面派发的新任务和新测试 → 开户测试 → 看能不能增加跑量 | 扩量探索 | 不定 | 开户流程 |
| 素材迭代 | 看跑量视频是什么 → 下单给设计师 → 再回来测试；有些任务涉及测品 | 素材供给侧 | 不定 | 设计沟通 + 测试 |
| 大盘观察 | 同渠道别人跑的什么类型账户、什么品、什么视频、什么策略好；其他渠道跑的怎样 | 竞争情报 + 跨渠道学习 | 不定 | 手工搜集/同行交流 |

**关键词：迭代起来，日常维护。** 不是一次性的活，是每天重复的循环。

### 1.2 现在的痛在哪

| 痛 | 说明 |
|---|---|
| **每天重复看数据做透视表** | 快手后台数据是扁平的（没有按任务筛选区分），需要手工做透视、加筛选逻辑才能按任务/业务线/biz_name 等维度看。同一件事每天花 1-2 小时手工做 |
| **账面 vs 真实的数据差** | 媒体账面转化 vs 后端真实转化有 Gap，需要手工对，对不上就是一笔糊涂账 |
| **处理策略因人而异** | 每个优化师判断方式不同，没有标准——AI 可以辅助给策略建议，但具体操作还得人来 |
| **素材反馈链路长** | 看跑量素材 → 找设计师 → 再测试，中间有等待和沟通成本 |
| **跨渠道/大盘信息靠手工搜集** | 别人跑什么好、什么策略有效，全靠问和看，没有结构化的情报来源 |

### 1.3 为什么现在能用 agent 解，以前不能

以前：数据分散在多个平台（快手后台、BI、Excel），取数靠手工导表，分析靠手工做透视表。每一步都是人盯着屏幕做的"搬运"。

现在：奇航 get_data 接口能把多维数据批量拉出来，agent 能自动化取数和基础分析，FaaS 能把结果存下来做持久化看板——**搬运的部分可以被自动化，判断的部分有 AI 辅助**。

但判断不会完全被取代：具体怎么动账户、动什么，是优化师基于经验+上下文+实时情况做的决策。AI 的价值是**把数据准备好、把异常标出来、把建议给出来**，让人做决策更快而不是替人做决策。

## 2. 我们要做什么（产品定义）

### 2.1 一句话定义

**一个面向 KA 部门全角色的投放提效平台**：自动拉取账户数据、标注异常、给出诊断建议、支持任务分发与协作，让优化师少做重复劳动、让管理者一眼看清大盘。

### 2.2 服务对象

**全部门能用的平台，团队用。** 不是个人工具。

| 角色 | 用它来干什么 |
|---|---|
| 优化师 | 看今日待处理账户、看建议、执行动作、看效果回收 |
| 运营 | 看任务达成、Gap 归因、跨渠道协同 |
| KA 负责人 | 看各渠道效率、风险、资源分配 |
| 更高层 | 看核心目标进度、AI 提效成果、需拍板的事 |

（详见 `docs/03-用户与首屏.md`）

### 2.3 明确不做什么

| 不做 | 理由 |
|---|---|
| 不做投放平台本身 | 快手/抖音/腾讯已有后台，我们不替代 |
| 不做素材生产工具 | 设计师有自己的工具链，我们只负责"看到什么素材跑得好" |
| 不做 BI 数据仓库 | BI 是基础设施层，我们只做 BI 数据的可视化和判断 |
| 不替优化师做最终决策 | AI 给建议，人拍板——这是产品定位不是技术限制 |
| 一期不做跨渠道 | 先在快手渠道验证，跑通后再扩展 |

### 2.4 素材拆片明确要求

**目标状态**：在“商品素材”域支持用户选择或导入一条视频，按时间轴拆出镜头/片段，并结构化识别钩子、卖点、人群、节奏、CTA、画面与声音证据；拆解结果继续服务相似素材查找、复刻方案、设计 brief 和投放效果对比。

**当前状态**：KA 平台尚未实现。ContentRadar 已有可复用的媒体下载、转写、视觉指纹、镜头切点、CTA 时间轴和拆解管线，本地已有一套质量较高的完整拆片提示词。正式开发前必须先确认“视频文件从哪里取得”：用户上传、内部素材库/对象存储、媒体素材接口或可访问的播放地址至少打通一种；没有稳定视频输入时不得把该功能标成可用。

## 3. 目标（分阶段）

| 阶段 | 目标 | 完成的判据 | 状态 |
|---|---|---|---|
| **阶段一：打通数据，自己用** | 账户数据自动拉取、存储、可视化；异常账户自动标注；诊断建议生成 | 老板本人每天用它替代手工看数据和做透视表，省时 ≥1 小时/天 | 进行中（等 FaaS 连通性验证） |
| **阶段二：团队用起来** | 任务分发、多角色视图、效果回收闭环；更多同事开始使用 | 至少 3 个同事每天主动使用；KA 负责人能看到大盘视图 | 未开始 |
| **阶段三：全部门平台** | 跨渠道（抖音/腾讯/百度）、AI Native 成果可汇报、推广到部门级 | 部门会议上有一次用这个产品做投放复盘；AI 提效数据有据可查 | 未开始 |

## 4. 愿景（终局形态）

优化师早上打开产品，看到的不是一堆数字，而是**"今天你该处理这 3 个账户，原因是什么，建议怎么做，点一下就能执行"**。

运营打开产品，看到的是**"这个任务本月目标完成率 87%，差在快手渠道的 XX 账户，原因是 XX"**。

KA 负责人打开产品，看到的是**"各渠道效率排名、最可能出问题的地方、钱该往哪调"**。

更高层打开产品，看到的是**"核心目标进度、AI 帮部门省了多少人工、需要你拍板的一件事"**。

**早上 5 分钟做完日常巡检，而不是 2 小时。判断有依据，动作有闭环，结果可追溯。**
