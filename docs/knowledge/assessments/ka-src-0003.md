## 1. 原始资料摘要

资料覆盖四层内容：

1. 快手磁力引擎的用户与流量版位、素材规格、出价目标、定向、学习期、预算和对象数量限制；
2. 最大转化、起量工具、程序化创意、UAA/AUAX、原生广告、DMP 等媒体产品；
3. 内部业务、渠道、转化回传事件、回传工具和内部命名规范；
4. 返点、赔付、余额/充值、素材审核红线和格式要求。

它是一份“媒体能力字典 + 内部业务映射 + 商务/素材规范”的混合汇编，不是单一来源、单一时点或正式接口契约。

### 2.2 关于当前 KA 产品

## 3. 合理推断

- 这份资料可以成为快手 adapter 与 Capability Registry 的发现清单，帮助定义“媒体支持什么、在什么条件下可用、有哪些限制”。
- 内部命名规范可支持确定性的账户名称解析器，把业务、设备、版位、出价目标等标签回填为结构化维度。
- 素材格式和审核要求可用于基建前预检，减少提交后拒审，但必须先由官方资料核验并版本化。
- 媒体产品、限额、学习期和赔付政策变化快，若没有 `verified_at/effective_from/source_url`，很快会变成过期知识。

以上为推断，待 arch 与业务/安全审查。

## 4. 宣传性表达

以下内容带明显营销或未经范围限定的概括，不能作为产品事实：

1. **媒体能力目录**：已有 Capability Registry 概念，缺产品级 eligibility、白名单、限额、适用对象、版本和证据字段。
2. **基建校验**：已有参数预览和 dry-run，缺官方规格/对象上限的可更新规则包。
3. **学习期联动**：已有宽松阈值，缺按出价/优化目标区分的媒体状态映射。
4. **内部业务映射**：任务和 field mapping 有容器，缺业务—考核—事件—媒体目标的受控字典。
5. **素材治理**：已有素材域，缺重复素材风险、规格和审核红线的机器校验。
6. **媒体产品选择**：已有策略分析，缺“何时可推荐/何时禁用某媒体产品”的经验证知识。

## 11. 与现有设计冲突的地方

1. 原文把固定返点系数写成当前口径；当前 Contract 明确系数必须按渠道和生效日期版本化。
2. 原文对象层级名称与当前 `campaign/unit/creative` 归一化模型不完全一致，需要 adapter 映射，不能直接替换 canonical 类型。
3. 原文把媒体产品、内部业务、商务政策和素材规范混在一个文档中；当前知识资产要求按来源、权限和证据层级拆分。
4. 原文包含通过调整/增加/减少回传实现竞价或赔付目标的描述；这些行为不能自动进入产品能力、规则或 Agent 指令，必须先过安全、合规和业务责任方审查。
5. 原文中的开屏图片/视频规格标签疑似互换，不能直接生成校验规则。
6. 原文多个学习期表格字段残缺，不能成为正式状态机。
7. 原文媒体规模、用户画像、性能基准和产品限制缺时点，与知识库可追溯/可废弃要求冲突。

## 12. 可以直接借鉴的内容

1. 媒体能力按“产品类型—名称—说明—适用条件—限制—来源”建目录。
2. 基建参数按版位、素材类型、出价目标、定向和媒体产品形成可检索矩阵。
3. 学习期状态映射到产品生命周期，并影响告警阈值和允许动作。
4. 素材上传前做格式、尺寸、时长、大小和审核风险预检。
5. 账户命名按版本化规则解析为结构化标签，解析结果允许人工校正。
6. 返点、赔付和余额类型分别建模，不用单一“消耗”覆盖所有现金口径。
7. 所有媒体限制记录 source URL、核验时间、适用版本和 supersedes。

## 13. 不建议照搬的内容及原因

1. **不直接发布内部编号、系统链接和命名枚举**：权限与业务敏感度高。
2. **不把媒体营销文案和画像当策略事实**：缺样本、周期和可复现证据。
3. **不把 CTR/CVR/CPM 区间当告警阈值**：不同业务、版位、素材和时期不可直接比较。
4. **不硬编码媒体规格和对象限额**：平台更新后会误拦或漏拦。
5. **不直接采用残缺学习期表格**：状态、条件和目标对应不完整。
6. **不把回传调整做成默认工具或自动化节点**：涉及数据真实性、媒体政策、赔付和审计风险。
7. **不从内部汇编稿反向宣称官方能力**：必须回到媒体官方文档逐条验证。

## 14. 对 PRD 的影响

当前不修改冻结 PRD。建议下一版候选：

- 在既有 Capability Registry 增加媒体能力元数据、资格/限制和证据版本；
- 在基建 dry-run 增加素材规格、对象数量和产品资格预检；
- 将账户命名解析器从“方向”明确为可配置、可回滚的结构化规则；
- 将媒体学习状态作为生命周期信号，不直接替换业务生命周期；
- 回传相关内容单独进入安全/合规审查，不进入普通功能排期。

## 15. 对后端架构的影响

不在本批修改 Contract。若批准，建议扩展既有统一资产/能力模型，而不是新造执行引擎：

- capability metadata：media、object types、input schema、eligibility、limits、risk level、source、verified_at、effective window；
- preflight rules：素材规格、数量上限、白名单和互斥产品，规则版本随 changeset 固化；
- mapping assets：媒体对象→canonical、内部业务→任务/指标、账户命名→结构化标签；
- policy gate：高风险回传类能力默认 `disabled/deny`，只有明确法务/安全批准才可登记可用状态；
- 所有媒体变化通过新 revision/supersedes 发布，不覆盖历史运行证据。

## 16. 对前端产品设计的影响

- 不新增一级导航；媒体能力放在基建、账户详情和操作工具箱的上下文入口。
- 参数选择器只展示当前账户/媒体有资格使用的能力，并说明来源、核验日期和限制。
- dry-run 同时展示格式错误、对象限额、白名单缺失、互斥能力和预计影响。
- 学习期/冷启动状态显示“媒体状态”和“业务生命周期”两列，避免概念混用。
- 敏感内部业务映射和高风险能力仅在授权治理页可见，不在普通搜索联想中曝光。

## 17. 对 Agent、工作流、知识库的影响

- **Agent**：只能引用 approved 的媒体能力 revision；未知或过期时回答“待核验”，不能补全参数或限制。
- **工作流**：能力节点运行时固定 capability revision；资格、权限和预检每次执行前重查。
- **基建**：用资料生成候选字段和校验规则，不直接生成可执行计划。
- **知识库**：原文保持 confidential；未来只发布经拆分、审查的派生知识卡，媒体官方事实与内部业务映射分开。
- **安全策略**：回传调整相关段落不得进入产品内 Agent 默认召回、自动化模板或示例提示词。

## 18. 建议动作：融合 / 补证 / 仅参考 / 不采用

总体建议：**拆分后补证，选择性融合**。

- 融合候选：媒体能力目录结构、基建预检、学习期映射、命名解析、素材审核候选。
- 补证：全部媒体规格/限额/产品/学习期/赔付/返点事实，以及内部业务事件映射。
- 仅参考：用户画像、版位效果区间和营销说明。
- 不采用：未经批准的回传调整能力、固定商务系数、把内部链接/编号发布给普通用户。

## 19. 建议优先级

- **当前优先级 A**：安全/合规审查回传相关内容；确认原文访问范围。
- **一期 P1 候选**：把已获官方证据的快手能力/限制加入 Capability Registry 和基建 preflight。
- **一期 P1 候选**：账户命名解析与业务映射先做只读标签建议，人工确认后生效。
- **后续 P2**：媒体能力浏览、版本变更提醒和多渠道扩展。
- **不排期**：未经审查的高风险回传工具、把历史版位基准用于自动调控。
