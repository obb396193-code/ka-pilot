## 1. 原始资料摘要

资料从术语字典出发，描述预算、出价、素材、赔付的调控原理，并继续展开：

- 优化师日常基建、盯盘、调控、复盘和日报工作流；
- 账户/广告监控条件、调价/关停/扩量/维稳动作；
- 账户结构、基建规模、母体复制、素材和选品裂变；
- 出价与回传、商品、素材、承接页的测试和效果回收。

它是“业务术语 + 操作经验 + 规则候选 + 策略 SOP”的混合稿，不是已批准规则库，也不是实验或因果验证报告。

## 3. 合理推断

- 这份资料是理解优化师真实工作和形成安全规则候选的高价值输入，比泛化产品文档更接近业务现场。
- 其中大部分阈值属于经验参数，应建成“规则候选 + 适用范围 + 证据 + 版本”，而不是全局默认值。
- 商品、素材、承接页测试已经体现“假设—基建—观察—回收”雏形，可为 `ka-src-0001` 的实验编排补充业务场景，但仍缺随机化、对照和污染控制。
- 原文同时包含正常优化经验和高风险回传/赔付做法，若不分区，进入 Agent 知识库会产生严重误用风险。

以上为推断，待 arch、业务和安全审查。

## 4. 宣传性表达

以下属于经验性绝对化或缺少证据的表达：

- 大预算更容易获得平台优先流量；
- 提预算“最多没效果，不会有坏处”；
- 降预算、降价或暂停会“打死广告”；
- 某一转化数即可稳定判断广告能否放量；
- 复制成熟账户必然缩短冷启动、降低试错；
- 媒体推荐商品天然具备跑量与转化优势；
- 多账户测试或一户一承接即可保证结果客观、精准。

这些可以形成待验证假设，不能成为默认规则说明。

## 5. 未证实项

1. “新户、主力账户、主力广告、爆量素材”等阈值是否为当前统一业务口径。
2. 预算、出价、冷启、关停和上新建议在不同任务/版位/生命周期的真实效果。
3. 赔付门槛、时间和不赔付场景的当前媒体政策。
4. 监控时间点、波动阈值、调价幅度和每日次数是否来自回放/试验。
5. 大规模基建数量建议是否满足当前媒体限额、素材供给和成本约束。
6. 母体复制、素材裂变、商品裂变的增量效果和内卷/污染风险。
7. 商品、素材、承接页测试周期和结论标准是否统一、是否存在幸存者偏差。
8. 内部报表、素材平台和商品平台的数据字段、权限、时效和可接入性。
9. 回传相关策略是否获得媒体、业务、安全和法务允许。

## 6. 对我们产品是否有帮助

**非常有帮助，但必须以“安全拆分后的候选知识”使用。** 价值主要在：

- 提供优化师一整天的任务链和对象关系；
- 提供从指标异常到原因、动作和观察窗的规则候选；
- 提供基建、商品、素材、承接页的策略资产原型；
- 暴露当前产品尚缺的策略版本、适用条件、证据等级和实验污染标记；
- 明确哪些业务经验可能带来安全、合规和自动化风险。

## 8. 已包含能力

1. 数据巡检、异常工作项、告警分级和钉钉触达。
2. 指标→原因→建议→变更集→回收的主闭环。
3. 预算、出价、暂停、基建等原子能力和权限/审计门。
4. 冷启动阈值联动、主力广告集中度和素材疲劳候选。
5. 矩阵基建、优质户复制和复刻血统。
6. 商品/素材池、标签、拆解、相似查找和回测方向。
7. 日报、多维策略分析、效果复盘和案例库。

## 9. 部分包含能力

1. **术语治理**：已有指标合同，缺业务术语、定义责任方、适用媒体和版本。
2. **规则候选治理**：已有规则表和历史效果方向，缺导入候选→回放→审查→启用的完整门。
3. **策略资产**：已有工作流/案例，缺策略假设、适用条件、版本、证据和失效条件。
4. **商品/素材测试**：有对象与效果回收方向，缺可用数据源和实验对象。
5. **承接页**：可借任务/账户承载，但没有 landing-page entity、绑定历史和效果归因。
6. **实验编排**：有测试 SOP 和显著性提示，缺对照、随机化、主指标、观察窗和污染检测合同。

## 10. 缺失能力

1. 安全知识分类：`allowed_for_advice/allowed_for_execution/forbidden/quarantined`。
2. 规则候选的来源、样本、回放结果、适用范围、批准和废弃版本。
3. 策略卡：目标、触发条件、动作、风险、观察窗、证据、适用/禁用条件。
4. 商品/素材/承接页实验对象与 control/treatment 表示。
5. 承接页版本、账户绑定历史和效果归因。
6. 操作冲突检测：近期人工改动、多个规则同时命中、媒体学习期、赔付/动态产品互斥。
7. 对高风险回传/赔付内容的产品级拒绝策略与审计规则。

## 11. 与现有设计冲突的地方

1. 原文多处直接给出调价、加预算、关停、复制等动作；当前写操作必须先形成变更集并由风险门决定是否确认/执行。
2. 原文把固定时间点、金额和倍率写成普适 SOP；当前规则应按任务、生命周期、业务日历和历史基线版本化。
3. 原文“提预算不会有坏处”等绝对判断与 What-if、影响上限和回滚理念冲突。
4. 原文以推断的扣量公式计算“真实成本”；当前产品已有真实转化字段，确定性口径以 Contract 为准，不从扣量比例反推替代。
5. 原文存在改变或伪装转化回传、以满足赔付或竞价目标的做法；这与数据真实性、媒体政策、审计和产品安全边界冲突，不能进入默认 Agent 知识或自动执行。
6. 原文的“多账户并行”“一户一承接”仍可能受账户、素材、定向和时段差异污染，不能直接宣称实验结论精准。
7. 原文对素材测试同时出现 1–2 天和 1–2 周等不同周期，说明它是多来源经验汇编而非统一规范。
8. 原文建议对劣质素材直接删除；当前应保留历史资产、运行证据和废弃状态，不能破坏可追溯性。

## 12. 可以直接借鉴的内容

1. 术语卡采用“定义—公式—来源—粒度—适用范围—版本”的结构。
2. 把优化师工作拆成基建、盯盘、调控、复盘、商品/素材/承接测试五类工作流。
3. 将监控条件和动作分开：条件可先上线只读告警，动作需独立风险审查。
4. 把“观察/维稳/干预/升级”做成明确状态，而不是所有异常都自动改价。
5. 母体复制记录母子血统、差异参数、观察窗和效果回收。
6. 商品、素材、承接页测试统一记录假设、基建、标签、指标、结论和下一轮方向。
7. 规则忽略、人工修正和 T+1/T+7 结果反哺策略版本。
8. 素材标签按商品、利益点、风格交叉分析，为下轮设计 brief 提供输入。

## 13. 不建议照搬的内容及原因

1. **禁止把高风险回传/赔付做法转成产品说明、规则或工具**：可能违反数据真实性、媒体政策和内部控制要求。
2. **不把固定阈值直接作为默认规则**：缺少回放、样本和适用范围。
3. **不把“预算只升不降”等经验绝对化**：会产生过度消耗风险。
4. **不自动执行大规模复制和高数量基建**：需媒体限额、素材供给、冲突和预算上限预检。
5. **不把经验测试当统计实验**：必须允许“不可判定”，并记录变量污染。
6. **不自动删除低效素材或历史计划**：采用 deprecated/paused，保留证据和回滚链。
7. **不向普通知识库用户暴露内部报表/案例链接和敏感策略**。
8. **不让 LLM 自行解释或修改公式**：确定性指标继续由领域层计算。

## 14. 对 PRD 的影响

当前不修改冻结 PRD。建议下一版候选：

- 增加“安全知识用途”字段，区分可解释、可建议、可执行和禁止内容；
- 在规则中心增加 candidate→backtested→reviewed→enabled 生命周期；
- 将策略/打法沉淀为带证据和失效条件的版本化资产，不只存文章；
- 在商品素材域增加承接页对象/绑定历史，前提是数据源可得；
- 将测试 SOP 对接 `ka-src-0001` 的实验编排候选，但先支持草案/人工确认，不做黑盒自动实验；
- 明确高风险回传内容不进入产品能力范围。

## 15. 对后端架构的影响

不在本批修改 Contract。若批准，建议复用现有规则、工作流和资产表扩展：

- knowledge policy：用途等级、风险类别、允许角色、可否进入 Agent 默认召回；
- rule candidate：source document/revision、scope、thresholds、backtest metrics、reviewer、enabled revision；
- strategy version：hypothesis、preconditions、actions、guardrails、observation window、evidence、invalidated_at；
- landing page：版本、账户绑定区间、指标和 lineage；
- execution policy：高风险能力 denylist、人工动作冲突、限额和不可逆标记；
- 所有规则与策略运行固定版本，效果回收不覆盖原定义。

## 16. 对前端产品设计的影响

- 规则候选页展示来源、适用范围、历史回放、误报/漏报、风险等级和审批状态。
- 策略卡将“经验描述”转成条件、动作、护栏、观察窗和证据，禁止一键从文章发布自动执行。
- 调控建议卡显示近期人工操作、学习期、数据新鲜度和冲突规则，默认生成变更集草稿。
- 商品/素材/承接页测试用同一实验草案结构，显示变量差异和污染警告。
- confidential 原文不出现在普通全文搜索结果；只有获准派生卡进入相应角色知识视图。

## 17. 对 Agent、工作流、知识库的影响

- **Agent**：允许总结业务流程、解释 approved 术语和生成规则草稿；禁止提供或执行高风险回传/赔付规避建议。
- **工作流**：所有动作复用 capability policy、changeset、dry-run 和确认门；资料中的阈值仅能作为未审查候选。
- **规则**：先运行 Shadow Mode/历史回放，再由人批准；不能因资料标“日常规则”就启用。
- **实验**：Agent 可生成测试草案，但必须明确变量、样本、观察窗、污染和不可判定状态。
- **知识库**：原文保持 confidential 且不进入默认召回；只发布安全审查后的拆分派生卡，并保留 `document_id/hash/citations`。

## 18. 建议动作：融合 / 补证 / 仅参考 / 不采用

总体建议：**安全隔离后拆分融合**。

- 融合候选：术语结构、优化师工作流、规则候选治理、策略卡、商品/素材/承接测试流程。
- 补证：所有阈值、操作效果、平台政策、数据源、基建规模和实验结论。
- 仅参考：预算/出价/素材的经验解释和裂变方法。
- 不采用：回传伪装/人为增减以影响赔付或竞价、无确认写操作、固定阈值全局生效、自动删除历史资产。

## 19. 建议优先级

- **立即 A 级**：安全/合规审查高风险回传和赔付内容；在检索策略中隔离原文。
- **一期 P1 候选**：安全术语卡、规则候选生命周期、Shadow Mode 回放和策略卡格式。
- **一期 P1 候选**：将已验证的巡检条件作为只读告警候选，不自动执行。
- **后续 P2**：商品/素材/承接页实验草案与效果回收，依赖数据源。
- **不排期**：高风险回传工具化、未经证据的全自动调控和大规模复制。

6. 哪些监控阈值进入历史回放候选，首发规则是否保持不变？
