## 1. 原始资料摘要

资料把 AI 投放产品拆成两个相互独立的平台：

- 白盒平台面向优化师，以人工策略、模板化基建、规则和人工指令执行为主，解决执行效率；
- 黑盒平台面向渠道管理，从自然语言目标理解、实验设计、智能基建、实时调控到自动复盘形成策略闭环，解决策略验证效率；
- 资料认为两者的本质差异是决策权归人还是归 AI。

本文是一份产品定位与能力设想，不是接口说明、统计方案、上线证明或效果数据。

## 2. 已确认事实

### 2.2 关于当前 KA 产品设计（已实读本仓文档）

- 当前产品是一套面向优化师、运营、渠道负责人和高层的 KA 投放经营工作台，不是两套平行平台（`docs/20-PRD-v1.md` §1.1/§1.2）。
- 当前冻结定位明确“不替人做最终决策”，一期不做跨渠道（`docs/20-PRD-v1.md` §1.4）。
- 已设计矩阵批量基建、变更集、确认门、规则、工作流、T+1 回收和自动复盘（`docs/17-功能全景-v2定稿.md`、`docs/20-PRD-v1.md`）。
- 已设计自治度三档：仅建议→确认后执行→自动+事后汇报；自动档受准确率、失败降档、金额上限和动作类型限制（`docs/20-PRD-v1.md` §3.9）。
- 已设计测品矩阵的“样本够不够/差异是否显著”标注，但没有完整实验对象、对照组和流量分配契约（`docs/17-功能全景-v2定稿.md` 域六；本仓对实验关键词检索未发现完整定义）。

## 3. 合理推断

- 我们的产品更接近“可控自治灰盒”：白盒执行底座上叠加 Agent 诊断、有限自治和效果学习，决策权按风险与历史准确率渐进释放。
- 将白盒和黑盒拆成两套独立平台会重复建设账户、数据、基建、执行、审计和效果回收底座；在当前团队与阶段下，单平台按角色/自治度呈现更合理。
- “AI 实验编排”有产品价值，但应作为现有任务对象和工作流之上的新能力，而不是把产品整体改造成不可解释黑盒。

以上是基于当前 PRD 与资料的产品推断，尚未经 arch 审查。

## 4. 宣传性表达

以下表述具备愿景或营销性质，原文没有给出实现与效果证据：

- “说一句话→系统全自动跑完→看结论”；
- “AI 充分理解哪些策略已经被验证”；
- “无需人工干预的长期稳定投放”；
- “确保实验结论的统计有效性/纯净度”；
- “全渠道覆盖”；
- “how 的部分全部交给 AI”。

这些可以作为目标描述，不能直接转写为已验证产品能力。

## 5. 未证实项

1. 对方白盒/黑盒是否真实上线、服务哪些团队、实际采用率与效果。
2. 快手等媒体是否提供足够的实验分组、稳定流量或随机化控制能力。
3. 所谓“成熟策略”如何定义、版本化、判定适用条件和处理环境变化。
4. AI 实时调控使用什么因果/序贯统计方法，如何保证结论有效。
5. 全渠道是否具备统一对象、指标、写接口和权限。
6. 自动追加预算、提价、关停的权限、风险限额、回滚与责任归属。
7. 黑盒产出的结论如何被审计、复现和沉淀为下一轮策略。

## 6. 对我们产品是否有帮助

有帮助，主要价值不是“照搬两套平台”，而是暴露出当前设计中一个真实断点：我们的策略分析、自动基建、工作流、效果回收和知识库已经存在，但缺少把它们串成“假设→实验→结论→策略资产”的实验对象与流程。

资料也提供了清楚的角色语言：优化师关注执行效率，渠道管理关注策略验证效率。这个区分可用于角色视图和功能叙事。

## 8. 已包含能力

1. 面向优化师的执行提效底座：数据、队列、矩阵基建、原子操作、批量操作。
2. 规则与指令两条执行路径，并有变更集、dry-run、确认、审计和回收。
3. 自然语言生成规则/报表/工作流草稿，但发布或写操作受确认门控制。
4. Agent 诊断、建议、历史评测、Shadow Mode 和有限自治。
5. T+1/T+7 效果回收、自动报告、Deep Research 和知识库沉淀。
6. 多角色视图放在同一任务/账户/数据底座之上。

## 9. 部分包含能力

1. **成熟策略识别**：已有多维策略分析和效果历史，但没有“策略版本—适用条件—证据样本—失效条件”的正式资产。
2. **长期托管**：已有规则、定时工作流和自动档，但自动档只允许受控防御动作，不是黑盒长期全权托管。
3. **智能新基建**：Agent 能生成草稿、复制母户和组合矩阵，却不能自动把一个业务目标转为可审查实验方案。
4. **实验效果分析**：有显著性标注和效果回收，但回收对象是动作/任务，不是预注册实验。
5. **渠道管理决策**：已有 pacing、负责人视图和资源建议，但尚未形成目标→实验组合→组合结论的交互。

## 10. 缺失能力

建议把缺失能力定义为“AI 实验编排”，至少包括：

- `experiment` 对象：目标、假设、唯一主变量、适用媒体、业务对象和负责人；
- 实验臂：control/treatment、基线策略版本、差异字段；
- 分配：样本对象、流量比例、随机化/匹配方法和污染检查；
- 指标：主指标、护栏指标、观察窗、最小样本和可检测差异；
- 规则：开始条件、暂停/安全终止、统计停止、最大预算/周期；
- 执行：生成基建变更集、人工审批、固定工作流版本、执行对账；
- 分析：序贯统计/固定窗选择、结论置信度、局限和不可判定状态；
- 沉淀：实验报告、策略版本、适用条件、失败原因和引用证据。

## 11. 与现有设计冲突的地方

1. 原文黑盒把最终决策权交给 AI；当前 PRD 明确“不替人做最终决策”，只能通过受控自治逐级放权。
2. 原文允许 AI 自动追加预算和提价；当前自动档只允许防御性动作，进攻性动作不自动执行。
3. 原文宣称全渠道；当前一期只做快手。
4. 原文把两类平台完全独立；当前产品采用一内核、多角色视图，共用数据、权限、执行和审计。
5. 原文同时要求统计有效实验和实时动态调控，若无专门方法会产生统计冲突。

## 12. 可以直接借鉴的内容

1. 用“执行效率”和“策略验证效率”区分角色价值，而不是只按页面功能描述。
2. 新方向测试时锁定一个主变量，其他维度优先复用有证据的成熟策略。
3. 把老基建/新基建分开管理：老基建关注稳定托管，新基建关注学习价值。
4. 实验结束后自动回收、生成结论并反哺下一轮，而不是只展示数据。
5. 自然语言目标先生成可审查方案草稿，降低渠道管理写实验文档和催执行成本。

## 13. 不建议照搬的内容及原因

### 13.1 不拆两套产品

重复建设底座和权限，角色协作会在两套系统之间断裂。建议同一平台按角色和自治度呈现。

### 13.2 不承诺“AI 全权决策”

广告写操作涉及预算、效果和责任归属；在能力、评测、数据质量和回滚未成熟前，纯黑盒不可审计。

### 13.3 不把实时调控直接叫实验优化

如果 AI 根据中途表现任意关组、加流或改价，分组暴露概率和环境会改变，常规 A/B 结论出现选择偏差、提前停止偏差和不可复现问题。

正确做法是：

- 区分探索期与利用期；
- 测量窗口尽量固定分配；
- 预先登记主指标、护栏、最小样本和停止规则；
- 安全护栏触发时标记“安全终止”，不能硬出胜负结论；
- 若采用 bandit/序贯试验，必须记录每次分配概率并用相应统计方法，不能套普通显著性检验。

### 13.4 不把全渠道写成一期能力

各媒体对象、指标、流量机制和写权限不同，先在快手验证实验对象与闭环，再决定适配层。

## 14. 对 PRD 的影响

当前不修改冻结 PRD。建议 arch 将以下内容作为“待补证的路线图候选”：

- 在投放任务下增加实验对象，而非新增一级导航或独立黑盒平台；
- 将“测品显著性”升级为实验结果模块；
- 将策略分析结果转为带版本和证据的策略候选；
- 明确 Experiment Copilot 只生成方案草稿，写操作仍走变更集/确认/自治度门。

是否进入下一版 PRD 取决于媒体能力、统计方案和业务试点补证。

## 15. 对后端架构的影响

若批准，需要独立立项设计，不在本批修改 Contract。可能新增：

- `experiments`：目标、假设、主变量、状态、预算、观察窗；
- `experiment_arms`：control/treatment 与策略版本；
- `experiment_assignments`：账户/计划/流量分配、分配概率、污染标记；
- `experiment_metric_specs`：主指标、护栏、样本和停止规则；
- `experiment_observations`：固定口径观测；
- `experiment_decisions`：AI/人工决策、证据、审批和停止原因；
- `strategy_versions`：由 approved 实验结论生成的策略资产。

执行仍复用现有工作流版本、变更集、幂等、冲突锁、审计和效果回收，不新造第二套执行引擎。

## 16. 对前端产品设计的影响

建议放在“投放任务详情”内的“实验”页签或任务创建流程，不增加“黑盒平台”一级入口：

1. 自然语言目标输入；
2. AI 生成实验草案卡：假设、变量、control/treatment、预算/样本/周期、指标与风险；
3. 可视化差异审查，人工确认后创建基建变更集；
4. 运行页同时展示投放状态和实验有效性（污染、样本不足、安全终止）；
5. 结论页必须允许“不可判定”，显示局限、引用和下一步；
6. 负责人看组合实验进度，优化师看具体执行和异常。

## 17. 对 Agent、工作流、知识库的影响

- **Agent**：增加 Experiment Planner，只输出结构化草案和解释；不能绕过权限、统计校验和确认门。
- **工作流**：实验发布时固定工作流版本；基建、同步、观察、停止、回收复用现有可靠执行内核。
- **策略中心**：将多维分析发现转为“实验候选”，不能直接升级成成熟策略。
- **自动基建**：根据批准的实验臂生成变更集，锁定非实验变量并记录差异。
- **效果回收**：从动作级 T+1/T+7 扩展为实验观察窗与主/护栏指标，但保留原动作回收。
- **知识库**：approved 实验报告可发布为知识；策略资产记录来源实验、适用条件、样本和失效条件。

## 18. 建议动作：融合 / 补证 / 仅参考 / 不采用

总体建议：**补证后选择性融合**。

- 融合候选：实验对象、单变量锁定、成熟策略作为基线、自动回收与策略沉淀。
- 先补证：快手分组/流量能力、对象稳定性、统计方法、业务试点和权限。
- 仅参考：白盒/黑盒角色叙事和两类价值表达。
- 不采用：两套独立平台、无边界 AI 全权决策、把动态调优直接当普通 A/B、一期全渠道承诺。

## 19. 建议优先级

- **当前一期**：不新增实验编排开发；先完成快手数据、诊断、变更集、确认执行和 T+1 回收真实闭环。
- **近期研究优先级 A**：补证快手 MAPI/内部执行能力、实验统计规则和最小业务试点，输出 experiment schema 草案与 Shadow Mode 方案。
- **后续产品优先级 P2 候选**：Experiment Copilot 先以“方案草稿+人工确认+固定分配”上线。
- **更后期**：只有评测、数据和媒体能力足够时，研究受控自适应分配；不默认演进为全权黑盒。
