## 结论先行

资料有用，但用途是“跨渠道对象模型、Capability Registry、后续 adapter 和实验编排取证”，不是把 815 篇结构化接口文档一次性接入产品。对当前 KA 产品的定位判断不变：我们是“可控自治灰盒”，不是无确认门的黑盒代投。

官方 Scope 清单证明存在 4 个 AB 实验工具路径，但未发现它们各自的公开请求/响应详情页；因此只能证明“公开 Scope 资料声明有这类能力”，不能证明账户已授权、Contract 可用或已可接入。

## 2. 已确认事实

1. [巨量引擎商业开放平台](https://open.oceanengine.com/labels) 公开返回投放、账户、素材、人群、转化、报表、工具、千川、本地推、星图等多产品线文档。
2. 业务 API 需要开发者应用与 OAuth 2.0；账户、数据范围和 Scope 需授权，部分权限还需平台审核或白名单。
3. 公开“接口清单（Scope 权限点）”文档 `1699352157034496` 列出 AB 实验工具：`/tools/ab_test/create/`、`/tools/ab_test/update/`、`/tools/ab_test_list/get/`、`/tools/ab_test_info/get/`。
4. 公开目录包含 4 类 RTA 实验报表路径，可用于后续核验实验效果回收。
5. 官网文档站的 `/skiff/api/doc/client/*` 是网站实现接口，未被官方承诺为稳定业务 Contract，不得成为产品运行依赖。

## 3. 合理推断

- 巨量引擎对象层级、素材/人群/转化资产和报表能力可帮我们抽象跨媒体 provider schema。
- Scope 中出现 AB 实验工具，说明未来可优先研究“媒体原生实验 adapter”，但不证明其已满足我们对随机化、分层、污染检测和显著性的全部要求。
- 1,103 篇中非快手一期业务占多数，适合“按问题检索”而不适合默认全量召回。

## 4. 宣传性表达

官网中“智能投放”“智擎”“全量能力”等名称只能作为官方产品/导航名称，不能推导为“AI 已能代替渠道管理做全流程决策”。

## 5. 未证实项

- 4 个 AB 路径的当前请求/响应 Contract、授权门槛、帐户可用性和运行结果。
- 媒体是否保证随机分流、分层互斥、稳定样本、统计显著性和实验污染检测。
- 公开 hidden/历史页面是否仍可用。
- 当前公司主体是否已申请对应 Scope/白名单。

## 6. 对我们产品是否有帮助

有，但分三档：

- 直接帮助：跨渠道对象字段、权限状态、错误/限制、报表粒度、实验能力取证。
- 条件帮助：巨量渠道 adapter、媒体原生 AB 实验、智能投放工具；等跨渠道路线图和账户授权到位再做。
- 背景参考：千川、本地推、星图、MUI、企业号、轻代码、群峰等非当前 KA App 信息流主链路。

## 7. 对应现有功能

| 官方能力 | KA 当前设计 | 映射判断 |
|---|---|---|
| 账户/项目/广告/创意 | 账户资源、基建管理、Capability Registry | 对象模型可借鉴，渠道字段必须留 provider extension |
| 实时/离线报表 | 数据分析、策略中心、效果回收、报告 | 可用于粒度/口径/分页限制设计，不替代现有数据主链路 |
| AB 实验 Scope | 工作流、测品跟踪、显著性标注、效果回收 | 只是媒体 adapter 候选，尚不是我方完整实验引擎 |
| 智能投放/诊断/管家 | 策略分析、规则引擎、自治度滑块 | 媒体建议可作为 evidence，不直接越过变更集/确认门 |
| 官方术语、Scope、限制 | 知识库 | 审查后按媒体分区发布，带版本与引用 |

## 8. 已包含能力

- KA 设计已有账户结构、自动基建、策略中心、工作流、变更集/确认门、T+1 效果回收、知识库和 Capability Registry。
- 已设计“测品跟踪 + 实验显著性标注”，但不等于已实现媒体原生 AB 编排。

## 9. 部分包含能力

- 自由工作流画布能承载实验节点，但缺 experiment definition、variant、traffic allocation、guardrail、sample/statistical decision 模型。
- 效果回收能承载实验结果，但现阶段重点是操作后 T+1，不是严格对照实验的分析计划。
- 策略中心已支持多维分析，但尚未形成“假设→方案→实验→结论→下轮策略”的独立实验状态机。

## 10. 缺失能力

1. 媒体原生 AB 的可执行 Contract 和账户授权实证。
2. 跨渠道统一 experiment/variant/control/traffic/metric/guardrail schema。
3. 试验前样本量/最小可检测差异，试验中污染与停止规则，试验后显著性/不确定性。
4. 实验运行时对媒体自动优化的开关、冻结和异常中止协议。

## 11. 与现有设计冲突的地方

- 一期“快手单渠道”与全量接巨量冲突：本轮不改一期。
- 无人确认的黑盒实时调控与“AI 给建议、人拍板、写操作走变更集”冲突。
- 媒体原生自动优化会改变实验内部状态，若与我方实时调控同时开启，可能污染因果解释。

## 12. 可以直接借鉴的内容

- provider 对象层级、授权/Scope 状态、字段枚举和频控/限制的建模方式。
- 结构化主接口与正文引用路径分开存储。
- 实验能力作为 provider capability，而不是写死在单一媒体页面。
- hidden/下线/灰度能力保留证据但默认不召回。

## 13. 不建议照搬的内容及原因

- 不照搬全部媒体后台信息架构：我们是 KA 经营平台，不是媒体后台替代品。
- 不照搬资金转账/退款/钱包写操作：超出当前产品边界且风险高。
- 不将“智能”品牌名当成 AI 策略闭环证据。
- 不使用官网抓取实现接口做生产运行依赖。

## 14. 对 PRD 的影响

本轮不改冻结 PRD。建议 arch 仅裁决两个后续候选：

1. Capability Registry 补 provider/media/version/scope/whitelist/authorization/runtime verification/endpoint evidence 字段。
2. P2 实验编排补一级实验状态机与统计治理，媒体原生 AB 只是 adapter 之一。

## 15. 对后端架构的影响

- provider adapter 必须区分 `documented / authorized / white_listed / wrapped / runtime_verified / product_enabled`。
- experiment orchestration 与 execution/change-set 分层：实验层决定设计和冻结策略，执行层仍走幂等、预览、确认、回查。
- 引入 experiment lock：正常运行时禁止未声明的自动调价/调预算；guardrail 触发可中止，但要标记数据截断。

## 16. 对前端产品设计的影响

- 实验卡需显示：假设、唯一变量、对照/实验组、分流、主指标、guardrail、样本进度、污染状态、中止原因。
- “媒体原生 AB”与“KA 自建对照”分开显示，不伪装能力等价。
- 调控操作显示“实验冻结/允许/guardrail 例外”，避免用户在实验中误改唯一变量。

## 17. 对 Agent、工作流、知识库的影响

- Agent 可生成实验草案和风险提示，不可将未补证 AB 路径当成已可调用工具。
- 工作流新增实验节点时，必须绑定固定 definition version、指标快照和变更治理。
- 知识库按媒体/产品线/文档状态分区；hidden 和未审查内容不进入默认可执行召回。

## 18. 建议动作

`fusion + evidence_required`：

- 融合对象模型、权限状态、实验治理概念。
- 对 AB 路径、媒体自动优化、帐户授权做后续补证。
- 资金写、非当前业务产品线和 hidden 历史内容只参考。

## 19. 建议优先级

- P0：不改快手一期边界；完成资料治理与检索。
- P1：将 provider capability 状态字段纳入架构裁决，但不开发巨量 adapter。
- P2：跨渠道前实证 OAuth/Scope/账户，再开发按价值排序的 adapter 和 AB 能力。
