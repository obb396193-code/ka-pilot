## 1. 原始资料摘要

该资料包把多个内部知识源聚合为本地快照，覆盖：

- 用户增长知识库的 43 条摘要索引及少量全文；
- O2/Aone FaaS、Next.js、BUC 等部署与研发资料；
- AIStudio LLM/API、模型和接入资料；
- 项目管理方法、SOP 与模板；
- 国际广告历史白皮书；
- EVO（一休）实验生命周期、流量规划和 A/B 操作资料；
- Panama 业务 wiki 与 FBI 嵌入/数据处理资料。

它是“发现线索的资料集”，不是一个统一版本、统一责任方、统一权限、统一证据等级的正式知识产品。

## 2. 已确认事实

### 2.1 包体与安全

- 原包共 729 个 ZIP entry，其中 671 个文件、58 个目录；解压内容字节数为 2,407,997。导读所称“约 730 篇”实际把目录和文件 entry 混在一起，不能理解为 730 篇有效文章。
- 分组文件数：O2 380、AIStudio 139、项目管理 57、广告白皮书 57、EVO 19、Panama 15、用户增长 3，另有 1 份导读。
- 质量扫描发现 22 个零字节文件、42 个小于 100 字节的文件、11 个含 NUL 字节的文件、44 个文件落在 11 组重复内容中。
- 原包没有路径穿越、符号链接、加密 entry 或重复路径。
- 项目根目录的独立 `INDEX.md` 与压缩包内 `INDEX.md` hash 完全一致，只作为重复副本，不另分配 `document_id`。
- 原包含签名资源 URL 中的访问标识和签名形状，不能直接进入资料库。canonical 生成时清除了 128 处 access-key query、128 处 signature query、1 处 AK ID 形状和 3 处 named-secret assignment；清除后 671 个文件凭证形态复扫为 0。
- canonical manifest 逐文件记录相对路径、hash、字节数和是否被凭证清除器修改；校验器会复核归档和全部子文件，不只校验 manifest。

### 2.2 对产品研究有直接价值的内容

- EVO 资料明确区分实验设计、流量规划、配置与指标、联调、发布、分析、人工决策和结果报告；“推全/下线”仍由业务方结合结果操作。
- 用户增长摘要索引确实列出追踪归因、SaaS 广告投放、程序化运营、看板、人群、RTA/OCPX/DPA 等历史方案，但多数只有搜索摘要，不是完整原文。
- FBI 文档描述后端 SDK 嵌入、账号与权限覆盖、下载权限和加密参数等模式；其中示例技术栈与当前 KA 产品并不相同。
- O2 与 AIStudio 文档可作为内部部署和模型通路的发现入口，但本轮没有验证这些接口、版本、网络条件或权限仍然有效。

### 2.3 当前 KA 设计

- 当前一期取数主通路是奇航 `get_data`，不是 FBI 拼接链路；FBI/BI 只可能作为口径补充或后续嵌入候选。
- 当前产品已设计 Next.js Web/API、Agent/Worker 分离、矩阵基建、Capability Registry、工作流、效果回收、知识库和受控自治。
- 当前只设计“测品显著性标注”，尚无完整实验对象、实验臂、分配、污染检查和实验决策契约。

## 3. 合理推断

- 该包对“寻找内部已有轮子”很有价值，尤其是实验治理、程序化投放对象、追踪归因、报表嵌入和内部部署约束。
- EVO 的流程证明“实验设计”和“实时自动调控”应是两个可组合但独立治理的层：实验可以成立而不要求 AI 中途自动改流量；人工决策是一个合法基线。
- 145201 摘要与 `ka-src-0001`、`ka-src-0004` 相互印证：当前产品真正的缺口不是批量基建，而是“假设→实验→效果→策略资产”的正式对象。
- 包内大量旧资料、空文件和重复文件说明后续应按主题提升子文档，而不是把整个目录直接向量化。

以上为研究 Agent 推断，待 arch 审查。

## 4. 宣传性表达

导读中的以下表述不能当作事实：

- “总计约 730 篇”；
- 43 篇只有摘要也“足够知道每篇讲什么”；
- 某份内部文档就是“全套”或可以直接决定技术选型；
- “你的部署平台”“你的大模型通路”“可直接套”等定性。

这些是打包者的导读判断，不是当前架构或可用性验证。

## 5. 未证实项

1. 每篇子文档的作者、责任团队、正式/草稿状态、更新时间和当前有效性。
2. O2、AIStudio、FBI、EVO 接口和权限在 2026-08-20 是否仍可用。
3. 包内模型清单、SDK 版本、限额、网络条件和登录方式是否已变更。
4. 用户增长 43 条摘要对应全文是否准确、完整，是否允许项目或产品引用。
5. 广告白皮书中的媒体/结算结论是否仍适用于当前 KA 快手场景。
6. EVO 是否支持快手媒体对象的真实随机化、账户/计划分组或流量分配。
7. FBI 嵌入是否满足当前产品权限、前端技术栈、下载控制和数据口径。
8. 包内 `PUBLIC` 目录名是否只是内部空间标签；不能据此推断可外发许可。

## 6. 对我们产品是否有帮助

**有帮助，但价值在“选题与补证导航”，不是整包成为正式知识。** 优先价值：

1. 用 EVO 资料补强 AI 实验编排的流程边界；
2. 用历史 SaaS/程序化投放摘要校对业务对象和基建依赖；
3. 用 FBI/O2/AIStudio 资料建立架构核验清单；
4. 用项目管理资料改善后续拆解和评审方法；
5. 验证多文件资料包需要 manifest、逐文件 hash、凭证清除和子文档提升机制。

## 8. 已包含能力

1. 当前产品已覆盖批量基建、账户/素材/出价组合、运行状态、失败重试和效果回收。
2. 当前产品已有工作流版本、Agent 帮编、规则、自治度和写操作确认链。
3. 当前产品已有数据分析、报告、知识库和内部应用嵌入的产品容器。
4. 当前资料库已有权限、证据、审查、hash 和发布门，能承接包内子资料的逐篇治理。

## 9. 部分包含能力

1. **实验**：有显著性标注与回收，没有假设、实验臂、分配和污染治理。
2. **策略资产**：有策略分析和案例库，没有由实验批准生成的版本化策略。
3. **归因**：有媒体回传和双口径方向，没有完整多触点追踪归因平台。
4. **报表嵌入**：有数据分析页和内部应用嵌入设想，未确认 FBI SDK 方案适用。
5. **内部 LLM**：已有 Agent 架构，尚未把包内 AIStudio 资料验证为当前 Provider Contract。

## 10. 缺失能力

1. 多文件包的子文档提升队列：候选→独立 ID→补证→评估→审查。
2. 完整 experiment schema、固定分配、污染标记、主/护栏指标和不可判定状态。
3. 内部平台文档的版本/可用性自动复核与失效提醒。
4. FBI/O2/AIStudio 能力的当前实证矩阵，而不是历史文档摘录。
5. 摘要索引与全文之间的引用关系和授权状态。

## 11. 与现有设计冲突的地方

1. 导读把 FBI 视为看板复用优先路径；当前一期数据真相明确以奇航 `get_data` 为主，不能改回 FBI 依赖。
2. 包内 FBI 示例主要是 Spring Boot/HSF；当前 Web/API 是 Next.js，不能把示例依赖直接复制进架构。
3. 包内部分 LLM 模型和 SDK 名称明显属于历史快照；不能覆盖当前 Provider 选择。
4. 整包内容权限混杂；当前知识库要求 ACL 继承，不能因聚合后统一放宽。
5. 普通 A/B 的固定测量与中途任意自动调流仍存在统计冲突；EVO 的人工决策流程不能被误读成黑盒自动调控依据。

## 12. 可以直接借鉴的内容

1. EVO 的阶段化实验状态：设计→流量规划→配置→联调→发布→分析→决策→报告。
2. 实验发布前进行白名单/埋点/分流均匀性检查。
3. 实验结论允许推全、下线和不可继续，而不是强制 AI 给赢家。
4. 程序化创建广告时显式处理父子层级、数量限制、长任务和部分结果。
5. FBI 文档强调自定义账号、查询权限、下载权限和安全参数，说明嵌报表不能只做 iframe。
6. 文档包 manifest、逐文件 hash、可检索提取目录和子文档独立审批模式。

## 13. 不建议照搬的内容及原因

1. **不整包向量化或发布**：混有空文档、重复、旧版本、基础设施细节和不同权限。
2. **不把摘要当正式证据**：摘要无法支持接口、统计或产品现状结论。
3. **不复制历史模型/API 清单**：版本漂移快，必须回到当前内部平台或官方文档核验。
4. **不把 FBI 改成一期主数据链**：与当前数据通路实证冲突。
5. **不把实验流程等同自动调控**：需要预注册停止规则或专门序贯/bandit 方法。
6. **不在 Git 或产品知识库保留签名资源参数**：所有访问标识和签名必须只由凭证系统管理。
7. **不因目录名含 PUBLIC 就对外发布**：许可边界仍未知。

## 15. 对后端架构的影响

- 资料库校验器增加 bundle manifest、逐文件 hash、archive hash 和凭证扫描。
- 若实验候选获批，仍复用现有任务、workflow version、changeset、效果回收和知识库，不另造执行引擎。
- FBI/O2/AIStudio 只可通过 adapter/provider 接入；版本、权限、网络、下载和审计要有能力矩阵。
- 任何 signed URL、AK/SK、app secret 只能保存 `secret_ref`，不能进入数据库正文、向量索引或日志。

## 16. 对前端产品设计的影响

- 产品知识库未来需要显示来源包、子文档、审查状态和版本关系，但不能让普通用户浏览整个 confidential 包。
- 实验页可借鉴阶段状态和联调检查清单；不应展示“AI 已自动决定”而缺少证据。
- FBI 报表若后续嵌入，必须有权限/下载/水印/失败态，不只嵌一个页面。
- 基础设施和项目管理资料只应进入管理/研发权限视图，不进入优化师默认搜索。

## 17. 对 Agent、工作流、知识库的影响

- **Agent**：先按 catalog/assessment 选主题，再定向检索 `extracted/`；禁止整包灌入上下文。
- **实验 Agent**：可从 EVO 生成实验草案和检查清单，决策仍走人工/自治度门。
- **工作流**：实验联调、发布、观察、决策和报告可映射为固定版本节点。
- **知识库**：包级记录永不直接发布；每个要发布的子文档必须独立 ID/hash/ACL/审查。
- **安全**：canonical 只使用清除凭证后的内容；原下载包不进入正式 storage。

## 18. 建议动作：融合 / 补证 / 仅参考 / 不采用

总体建议：**包级仅参考，子文档分批补证后融合**。

- 融合候选：EVO 实验生命周期、程序化创建的层级/限额/长任务治理、报表权限检查清单、多文件资料治理。
- 补证：快手实验能力、FBI/O2/AIStudio 当前接口、43 条摘要全文与授权。
- 仅参考：历史广告白皮书、项目管理方法、旧模型清单。
- 不采用：整包发布、摘要当正式事实、历史接口直接进架构、签名 URL 入库。

## 19. 建议优先级

- **立即 A**：维持 confidential 隔离；原下载包不得成为 canonical；子文档发布前逐篇提升。
- **一期**：不因本包新增生产能力；只将实验联调/状态作为研究补证。
- **后续 P2 研究**：Experiment Copilot、FBI 嵌入备选、内部 Provider/部署能力实证。
- **不排期**：整包产品知识库导入、无审查自动召回和历史技术栈直接迁移。
