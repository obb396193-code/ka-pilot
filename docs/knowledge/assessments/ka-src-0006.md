## 1. 原始资料摘要

Excel 用结构化表单生成 `ks-create-ad-script` 的自然语言基建指令，包含：

- 单条“指令生成器”；
- 20 行“批量创建模板”；
- 素材、参考账户、任务、投放时段等“常用配置库”。

可配置基建组数、账户/任务、参考账户/计划/广告组、出价、素材库、落地页、文案库、设备、过滤、时段和资源位，并拼成可复制的执行指令。

## 2. 已确认事实

### 2.1 文件结构与安全

- 工作簿有 3 个 sheet：`指令生成器`、`批量创建模板`、`常用配置库`，各有 1 个表格对象。
- 文件没有 VBA 宏、外部链接 part 或 OLE 对象；凭证形态扫描为 0。
- 文件含真实内部任务/账户标识、素材/落地页/文案配置和可直接影响投放创建的参数，因此仍属于 confidential。
- 默认基建组数为 100；批量模板预置 20 行，部分素材/时段配置硬编码。
- 指令可在账户 ID、任务 ID 等关键字段为空时继续生成，没有阻断式必填校验、媒体限额预检、预算总额预览、权限检查、dry-run、幂等键或执行回执。
- 模板含名为“伪装参数”的配置。该参数与 `ka-src-0004` 中已隔离的高风险回传/赔付内容存在关联风险，本评估不把它转述为可执行方法。

### 2.2 公式核验

- 原始文件的公式没有 cached value。
- 通过 Artifact Tool 和隔离 LibreOffice 重算，8 个查找单元格均显示 `#NAME?`：`C8/C10/C11/C12/C14/C15/C16/C22`。Microsoft Excel 目标环境尚未实测，因此结论是“跨引擎复现异常，需作者在目标环境补证”，不是断言所有 Excel 版本必然损坏。
- `C8` 和 `C19` 在对应下拉值被清空时会自引用，存在循环引用风险。
- 批量页即使账户/任务为空也会生成完整句式，说明“成功生成字符串”不等于“参数完整可执行”。

### 2.3 当前 KA 设计

- 当前设计已经有矩阵批量基建、Prompt Compiler、Capability Registry、基建控制台、状态机、逐对象失败重试、定时基建和实际对账。
- 所有媒体写操作必须走 changeset→dry-run→确认→执行→效果回收；不能因 Excel 生成了指令就绕过。
- 当前产品定位是可控自治灰盒；这份 Excel 本身属于典型白盒自动化资产：策略和参数由人决定，工具负责拼装。

## 3. 合理推断

- Excel 很可能是把优化师常用参数和 CLI 提示词固化成临时操作台，证明一线确实需要“配置库 + 批量创建 + 指令预览”。
- 参数集合可直接帮助定义 `create_ad` capability 的表单 schema 和 Prompt Compiler 输入，但 Excel 自身不应成为生产执行合同。
- 当前 KA 产品不是缺少这类白盒功能，而是需要把它升级为有类型、有权限、有预检、有回执和可审计的结构化执行链。

以上为推断，待 arch/业务/security 审查。

## 4. 宣传性表达

模板中的以下暗示没有证据支持：

- “自动生成的完整指令（直接复制使用）”；
- “选模板后三个字段一起填”即代表配置一定有效；
- “其他默认”足以描述未显式参数；
- 批量创建 100 组是安全、合理的默认值。

字符串完整不等于权限、限额、素材资格、预算和媒体约束完整。

## 5. 未证实项

1. 作者、责任方、创建日期和当前使用团队。
2. `ks-create-ad-script` 接受的正式参数合同、版本和真实执行语义。
3. 工作簿在 Microsoft Excel 中的公式与下拉是否正常。
4. 常用配置库中各 ID、落地页、时段和业务命名是否仍有效。
5. 默认 100 组和 20 行批量规模是否符合媒体/账户当前限额。
6. “其他默认”实际展开的字段和值。
7. 高风险参数是否合法、获谁批准、能否进入任何自动化链路。
8. 生成指令后是否还有人工复核、dry-run、失败重试和效果回收。

## 6. 对我们产品是否有帮助

**有帮助，主要作为白盒基建需求样本和字段词典。** 它能补充：

- 优化师真正希望批量填写的字段；
- 常用配置库/套餐复用需求；
- 单条与批量两种交互；
- 指令预览和参考账户复制的使用心智；
- 当前线下工具在安全、验证、版本和回执上的缺口。

## 8. 已包含能力

1. 参数化单条与批量基建。
2. 素材、任务、参考账户、时段和资源位配置复用。
3. 参考对象复制和自然语言指令预览。
4. 当前产品已设计比 Excel 更完整的执行状态、权限、确认、重试与回收链。

## 9. 部分包含能力

1. **配置套餐**：当前有模板/资产概念，尚需明确版本、责任人、适用任务和失效时间。
2. **Prompt Compiler**：已有方向，需把 Excel 字段映射成正式 schema 和编译测试。
3. **参考账户复制**：已有血统方向，需明确哪些字段继承、哪些必须重新确认。
4. **批量矩阵**：已有设计，需加入总创建量、预算暴露和媒体限制预检。

## 10. 缺失能力

针对该操作样本，现有设计/合同后续需补证：

- `create_ad` 的完整字段、必填关系、枚举、单位和版本；
- 套餐资产的 owner、revision、适用范围、引用对象和废弃状态；
- 生成前的账户权限、媒体产品资格、素材/落地页可用性、数量限额和预算暴露校验；
- 编译结果的结构化 diff，而不只是一句话；
- 对高风险参数的 denylist/quarantine；
- UAT 样本和失败回执。

## 11. 与现有设计冲突的地方

1. Excel 鼓励“直接复制使用”；当前写操作必须预览并确认。
2. Excel 使用自然语言作为最终载体；当前应以结构化 capability payload 为事实源，自然语言只是解释层。
3. Excel 允许缺字段仍生成；当前需要 schema 阻断。
4. Excel 使用硬编码真实配置；当前需要权限化、版本化资产引用。
5. Excel 的 100 组默认值和“其他默认”与限额/可审计原则冲突。
6. 高风险参数不得进入 Capability Registry、Agent 默认知识或工作流节点。

## 12. 可以直接借鉴的内容

1. 字段集合和业务命名，用作 schema 访谈清单。
2. 单条生成器 + 批量矩阵 + 常用配置库的三层交互。
3. 下拉选套餐后联动填充相关素材/参考对象字段。
4. 生成前提供人类可读预览。
5. 参考账户/计划/广告组作为显式 lineage，而不是复制后丢失来源。

## 13. 不建议照搬的内容及原因

1. **不复制真实 ID 到产品默认模板**：会跨人/跨环境误用。
2. **不使用自然语言字符串作为执行合同**：难以校验、版本化、幂等和审计。
3. **不保留“其他默认”**：默认值必须逐字段、带版本并可见。
4. **不把 100 组作为默认**：应由媒体限额、预算和用户明确选择决定。
5. **不接受空关键字段仍可生成**：必须在编译前失败。
6. **不产品化“伪装参数”**：在安全/合规明确批准前永久隔离。
7. **不把当前公式当可靠实现**：跨引擎异常和循环引用风险未解决。

## 14. 对 PRD 的影响

本批不修改冻结 PRD。下一版候选只建议补充：

- 基建管理的参数 schema、配置套餐版本和总影响预览；
- Prompt Compiler 输出“结构化 payload + 人类解释 + diff”，而不是仅文本指令；
- 参考对象 lineage 与套餐引用；
- 高风险参数 denylist 和空字段阻断。

这些是现有基建能力的验收细化，不是新增白盒平台。

## 15. 对后端架构的影响

- Capability Registry 为字段提供类型、枚举、必填条件、默认版本、权限、媒体限制和风险等级。
- Compiler 输入输出均存结构化 JSON；自然语言可重建但不作为事实源。
- 每次批量创建先生成 changeset，计算对象数、预算暴露、冲突和幂等键，再由执行器逐对象处理。
- 配置套餐独立版本化，引用时固定 revision；真实 ID 不进入公开模板。
- denylist 在 compiler 与 executor 双重阻断，不能只靠 Prompt 约束。

## 16. 对前端产品设计的影响

- 表单可延续“参数设置/批量矩阵/常用套餐”的心智，但必须显示必填、单位、来源、权限和失效状态。
- 预览页显示将创建多少对象、涉及哪些账户、每个字段 diff、预算/数量上限和风险提示。
- 缺账户、任务、素材等关键字段时禁止生成可执行 changeset。
- 常用配置库默认只展示当前用户有权使用的资产；真实 ID 可按权限遮蔽。
- 高风险/隔离字段不出现在普通界面、快捷模板或 Agent 建议里。

## 17. 对 Agent、工作流、知识库的影响

- **Agent**：可把用户意图编译成 schema 草稿并解释缺字段；不能直接输出高风险参数或绕过确认。
- **工作流**：基建节点引用固定 capability/version/preset revision，运行前模拟并冻结版本。
- **知识库**：Excel 原件不进入默认召回；可在审查后派生一份去 ID、去高风险字段的“快手基建参数字典”独立资产。
- **效果回收**：创建完成只是执行成功，后续仍要绑定 T+1/T+7 效果与母体 lineage。

## 18. 建议动作：融合 / 补证 / 仅参考 / 不采用

总体建议：**字段与交互融合，文件本体仅参考，高风险内容不采用**。

- 融合：参数字段、单条/批量/配置库结构、参考对象 lineage、预览心智。
- 补证：CLI 正式合同、目标 Excel 公式、媒体限额、套餐有效性和执行流程。
- 仅参考：当前硬编码配置、自然语言示例和 Excel 公式实现。
- 不采用：直接复制执行、空字段生成、100 组默认、“其他默认”、高风险参数工具化。

## 19. 建议优先级

- **立即 A**：保持 confidential；高风险参数进入 deny/quarantine；不进入开发或产品 Agent 默认知识。
- **一期 P1 验收细化**：将字段映射进基建 schema、必填校验、总影响预览和 changeset。
- **后续 P2**：版本化配置套餐、参考对象 lineage 和经过审查的参数字典。
- **不排期**：修复并继续使用 Excel 作为生产执行主入口；高风险参数自动化。
