## 结论先行

这批资料**对产品有直接帮助**。MAPI 是快手官方媒体能力底座，`kuaishou-cli` 是其中一小部分接口的命令封装；奇航仍是一期既定数据主链路，两者不是替代关系。产品后续缺少的官方能力，可以按需补 CLI/adapter 壳，但不能把“官方有接口”直接等同“当前账户可用”。

当前 KA 产品设计已包含账户资源、计划/组树、矩阵基建、变更集、确认门、效果回收、素材、工作流和知识库，因此产品方向不需要因这批文档重构。真正缺的是：把这些官方能力逐项落实为“当前账户是否授权、当前执行通路是否封装、当前版本是否验证”的运行时能力矩阵。

截至 2026-08-20，官网未登录可访问的 DSP 当前版目录覆盖账户、投放、报表、素材、资产、原生广告、工具、线索、DMP、SPI、资金等 15 个一级分组。当前 381 篇的 59/249/73 只是机器初筛，且已发现操作/风险误判，不是产品路线图或逐接口批准。资料仍**没有补证原生 A/B 实验对象、随机分流或统计显著性能力**。媒体原生 `auto_build`、`auto_adjust`、`auto_manage` 不能与我方实验编排混为一谈。

## 1. 原始资料摘要

本资料是对快手磁力引擎开放平台截至抓取日、未登录公开可访问 DSP/MAPI 当前版与旧版菜单的快照，不代表快手全站、登录后、白名单或未索引能力的绝对全量。覆盖：

1. MAPI 注册、scope、token 生命周期、授权账户发现；
2. 广告主信息、余额和流水；
3. 广告计划、广告组、广告创意的创建/查询/修改；
4. 广告主、计划、组、创意和素材报表；
5. 图片、视频上传与查询、创意审核；
6. 应用/接口/账户维度频控和创建限制；
7. 官方文档内部版本、路径、方法与数量限制冲突；
8. “实验”关键词的官方站内检索结果。
9. 当前 381 条能力的产品相关性、路线图、风险和 CLI 覆盖矩阵；
10. 旧版 291 篇正文，用于 v1/v2/gw 路径兼容与废弃识别。

本轮没有登录，没有获取 token，没有调用媒体业务接口，没有验证本公司账户的 scope 或白名单。

## 2. 已确认事实

### 2.1 官方能力事实

- MAPI 是快手商业广告体系的官方开放接口平台，面向广告主、代理商和第三方服务商。
- scope 明确拆分 `report_service`、`account_service`、`ad_query`、`ad_manage` 等权限。
- access token 官方说明有效期为 1 天，refresh token 为 30 天；刷新会替换新旧 token。
- 可拉取 token 下授权广告主 ID；页面声明单页最大 200。
- 计划、组、创意均有官方创建、查询、状态修改接口；组另有预算和出价修改接口。
- 计划/组/创意状态接口的 `put_status=3` 具有删除语义，并可能级联删除下级对象。
- 创建计划页包含 `auto_adjust`、`auto_build`、`auto_manage`，其中自动基建明确标注白名单能力。
- 实时报表覆盖账户、计划、组、创意；支持日/小时粒度，目标接口页包含分页和对象 ID 数量限制。
- 素材接口覆盖图片/视频上传与查询；视频列表包含审核、质量、重复度、跑量分、标签、来源等字段。
- 创意审核详情可返回商业/社区审核状态、拒绝原因、限流原因和修改建议。
- 接口频控可按应用、接口和广告账户维度交叉生效；官方页写默认 AppID QPM=2000。
- 当前新版完整目录包含 381 个唯一文档，其中 352 个可提取 endpoint；旧版另有 291 个唯一文档。
- 当前本机 `kuaishou-cli` 版本标识三方冲突：zip 1.0.2、PKG-INFO 1.2.0、代码/UA 1.2.1；base URL 为快手 MAPI，声明 25 个 endpoint 常量，其中 23 个存在命令路径，2 个未暴露命令。
- CLI 25 个 endpoint 路径均能与当前官方文档精确匹配；23 个命令路径中 21 个 HTTP 方法对齐，2 个冲突。因此只能确认“CLI 是 MAPI 的静态封装子集”，不能确认 23 个全部可正确调用。

### 2.2 当前产品事实

- 冻结 PRD 已规划 Capability Registry、账户树、基建管理、变更集、确认门、工作流、T+1 回收、素材和知识库。
- 当前数据主链路是奇航 `get_data`，并非产品服务直接持有快手 MAPI token；现有 `kuaishou-cli` 真实 token 由沙箱代理注入。
- 当前奇航数据维度止于账户和广告，计划/组/创意结构与媒体写能力仍依赖执行侧同步/封装。
- 验收基线中绝大部分相关页面和闭环仍标为“未开发”，不能把设计存在写成运行时已具备。

## 3. 合理推断

- MAPI 可以成为快手 provider 的能力上限来源，CLI 只是当前执行壳；但某接口“公开存在”不等于公司账号“已授权且已封装”。
- 对一期价值最高的不是直连报表替换奇航，而是补齐账户授权发现、计划/组/创意结构同步、素材审核以及变更后媒体态回查。
- 计划页的媒体原生自动基建/自动调控/智能投放，与我们的矩阵基建和自治度滑块不是同一层：前者是快手内部算法开关，后者是我方治理和编排。
- MAPI 能构造多个计划/组并分别拉数，但没有原生随机分流证据；只能先称“运营测试/准实验”，不能承诺严格 A/B 因果结论。

## 4. 宣传性表达

官方注册说明中的“自动化、智能化工具”“显著提升人效”“全链路归因与优化”是能力定位，不是本产品的实现或效果证据。评估不把这些表达转写为“接入即实现全自动优化”。

## 5. 未证实项

1. 本公司开发者身份、AppID 和各广告账户实际拥有的 scope。
2. `auto_build`、`auto_adjust`、`auto_manage` 的白名单覆盖、算法行为和可解释性。
3. 已完成 CLI 静态覆盖审计，但 23 个命令路径中已确认余额/流水 2 个 GET/POST 方法冲突，且 23 个的授权与运行结果均未逐条验证。
4. 官方文档发生冲突时，生产服务当前接受的路径、方法和数量上限。
5. MAPI 实时报表与奇航 `get_data` 在时效、口径和结算字段上的一致性。
6. 是否存在未公开、白名单或其他产品线的实验分流能力。
7. 媒体原生自动调控是否会跨实验组共享学习、改变流量或污染对照。

## 6. 对我们产品是否有帮助

有，价值分三档：

- **直接价值**：Capability Registry、对象树同步、基建 preflight、变更集执行/回查、素材审核、权限健康。
- **条件价值**：MAPI 实时报表作为结构/口径校验或奇航缺维度补充；必须先验证权限、口径和数据稳定性。
- **研究价值**：快手原生自动基建/调控/智投、异步长周期报表、程序化创意、素材智能能力。

机器矩阵位于 `docs/knowledge/datasets/ka-src-0007-capability-coverage.jsonl`。每条标记 `official_state / authorization_state / cli_status / http_method_alignment / runtime_verification_state`。`operation/risk/roadmap_phase` 是未逐条人工审查的初筛，已知“上传被祖先目录关键词误标删除”“获取授权列表被误标写操作”等假阳性，不得当作产品批准结论。

## 11. 与现有设计冲突的地方

### 11.1 不构成方向冲突

MAPI 的存在不要求替换奇航主读取链路，也不要求把产品改成黑盒。它更适合作为快手执行/结构/素材能力的官方来源。

### 11.2 需要消解的接口冲突

- 汇总限制页仍写 v2 老路径，新目标页已使用 `gw/dsp` 路径。
- 计划总数在不同官方页分别写 1000 和 500。
- 广告主资质信息页头方法写 POST，而同页 curl 样例写 GET。

因此“官方文档=绝对一致契约”不成立。Capability Registry 必须允许 `official_conflict`，没有探针结果时禁止进入 production-ready。

### 11.3 与实验设计的潜在冲突

`auto_adjust`、`auto_build`、`auto_manage` 会让媒体改变基建或投放行为。若同时做固定 control/treatment 实验，可能造成：

- 组间流量和学习过程不稳定；
- 测试变量之外的基建/出价/素材发生变化；
- 中途关组或加预算导致传统固定样本检验失效；
- 媒体算法共享学习边界不透明。

实验模式下应默认冻结这类媒体黑盒开关，或把它们本身作为唯一测试变量；动态调控实验必须改用预注册的序贯检验/多臂老虎机方案，不能沿用普通 A/B 显著性文案。

## 12. 可以直接借鉴的内容

1. scope 到能力的显式映射，进入 Capability Registry 和授权健康页。
2. 授权账户列表作为“当前 token 可见账户”发现源，和内部账户池做差异检测。
3. 对象级 read/write 分开注册；删除类动作标明级联影响。
4. 目标接口的分页、批量上限、日期范围、金额单位进入 preflight。
5. 创意审核拒绝/限流原因和修改建议进入素材审核看板。
6. 视频质量、重复度、跑量分等字段进入素材策略分析候选。
7. 官方页面版本、更新时间、documentId 和 hash 进入知识资产更新追踪。

## 13. 不建议照搬的内容及原因

- 不直接复制官方 curl 样例：样例含凭证形态、旧方法或示例参数，且同页可能自相矛盾。
- 不把汇总限制页硬编码为生产上限：页面较旧，且与新接口页冲突。
- 不在产品服务保存快手 secret/token：继续使用既定凭证托管和原运行身份绑定。
- 不默认开启 `auto_manage/auto_build/auto_adjust`：白名单、黑盒行为和实验污染均未证实。
- 不让 Agent 自动执行删除、关停、改预算或改出价：继续走预览、确认、幂等、回查和回收。
- 不用 MAPI 实时报表直接替换奇航：缺当前账户权限、字段口径与稳定性验证。
- 不把多计划/组构造等同严格 A/B：缺随机分流和稳定流量证据。

## 14. 对 PRD 的影响

本次**不修改冻结 PRD**。建议 arch 仅裁决是否在下一版候选中补充：

- Capability Registry 条目必须带 `official_document_id / doc_version / doc_updated_at / scope / whitelist / risk / limit / verification_state`；
- provider 能力状态支持 `official_conflict`；
- 实验计划需声明是否冻结媒体原生自动化开关；
- 官方资料只在 approved 后进入产品知识库默认可信范围。

这些是现有功能的证据化和安全收口，不是新增一级产品模块。

## 15. 对后端架构的影响

建议形成四层，不直接让业务代码拼 MAPI 请求：

```text
官方文档证据
  → provider capability manifest
  → adapter/CLI command + read-only probe
  → changeset / workflow / scheduler
  → media-state verification + T+1 recovery
```

后端需要：

- 每个能力单独记录 read/write/delete 风险、scope 和白名单；
- 使用执行队列做 QPM/日限额、账号级公平调度和指数退避；
- 创建类自建 idempotency key；修改前读 from，执行后回查媒体态；
- 删除类显式列出级联对象；
- 所有 job 固定 credential owner，不允许刷新失败后切换他人身份；
- 报表数据带 source、granularity、freshness、window 和口径版本；
- 文档冲突或未探针能力不得标 production-ready。

## 16. 对前端产品设计的影响

- 操作工具箱只展示当前账户“已授权且已验证”的能力，禁用项显示缺 scope/白名单/未封装/文档冲突原因。
- 变更集预览展示媒体上限、金额单位、批量数量、级联删除和目标接口版本。
- 账户设置页展示 MAPI 授权健康、token 剩余生命周期和需要重新授权的任务；不显示 token 值。
- 素材页展示审核、限流、质量、重复度等字段，并对废弃/待确认字段加数据质量标记。
- 实验/测试页面展示“媒体原生自动化是否冻结”，避免用户以为结论天然纯净。

## 17. 对 Agent、工作流、知识库的影响

### Agent

- 检索官方资料后只能提出能力候选，必须再查询运行时 Capability Registry。
- 不得因页面存在就宣称“账号可用”；回答中应区分 `documented`、`authorized`、`wrapped`、`verified`。
- 高风险写操作只生成 changeset 草稿，不直接调用 MAPI。

### 工作流

- 节点来源应是 registry 条目，节点执行前检查 scope、白名单、版本和限额。
- 文档更新导致 endpoint/limit 变化时，已发布工作流固定旧版本并进入待迁移，不静默漂移。
- 实验工作流默认冻结媒体自动化；选择启用时要求实验方法另行审批。

### 知识库

- `ka-src-0007` 当前可供研发/审查引用，但必须显示“未审查”。
- 批准后可发布无凭证的结构化官方摘要和引用，不建议发布完整网页镜像。
- 381 条能力矩阵可作为产品知识库的机器附件候选；672 份完整快照仍留在项目资料区，默认不把整站镜像复制进产品正文。
- 后续复抓使用同一 `document_id` 更新 revision/hash；重大结构变化可新建版本并建立 supersedes 关系。

## 19. 建议优先级

### 一期 P0/P1

1. 从业务 owner 复核通过的少量高价值项录入 provider capability manifest，状态先设 `documented_unverified`；不把机器初筛 59 条整体视为一期范围。
2. 优先补 CLI 的核心断点：campaign update/status、unit budget、creative update/status/review、四层实时 report；已有 23 条先修正 2 个 HTTP 方法冲突再做回归验证。
3. 在授权测试账户上做只读探针：授权列表、账户信息、campaign/unit/creative list、审核、报表最小调用。
4. 把 scope、QPM、日期范围、批量上限和删除级联纳入 preflight。
5. 继续保持奇航为一期读取主链路；MAPI 先补结构和执行回查。

### 后续路线图

1. 素材质量/审核/重复度接入素材策略分析。
2. 异步长周期报表和多源对账。
3. 媒体原生自动基建/智投能力的白名单试点与 Shadow Mode。
4. 官方文档定期复抓、diff、变更告警和自动 deprecated。
5. 若业务仍需实验编排，另补媒体流量机制与统计协议，不从本批 MAPI 证据直接推出。

### 不建议做

- 在一期改成产品服务直存 MAPI token。
- 为追求“全接口覆盖”一次性封装所有 MAPI。
- 让 Agent 绕过确认门直接写媒体。
- 用官方老汇总页覆盖新目标接口页。
- 把 `auto_manage` 当作我方黑盒 AI 决策闭环的已实现证据。
