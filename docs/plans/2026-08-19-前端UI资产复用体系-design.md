# 前端 UI 资产复用体系设计

> 日期：2026-08-19  
> 状态：老板已确认方向；本文是资产治理与接入设计，不代表各组件已经安装  
> 适用范围：`apps/web`，不涉及 ContentRadar 或其他产品线

## 1. 目标

建立一套“先查成品、复制官方源码、再做业务适配”的前端生产方式：

1. 开发新页面或细节交互前，先从完整目录中确认官方是否已有成品。
2. 运行仓只复制当前需求实际使用的源码，不把所有上游源码一次性塞进项目。
3. 页面骨架、通用组件、复杂数据组件和动效都优先采用成熟官方实现。
4. 本项目主要自写业务数据适配、权限/状态映射和必要的页面组合，不重复发明已有 UI。
5. 以 tweakcn token 体系为核心，预留运行时多风格切换，不复制多套页面。

## 2. 已确认的分层

| 层级 | 主来源 | 在投放平台中的职责 | 使用强度 |
|---|---|---|---|
| 页面壳与基础结构 | shadcn/ui + Blocks | Sidebar、Sheet、Tabs、Card、Form、Table、Dashboard 页面骨架 | 全局默认 |
| 细节组件与交互颗粒 | coss/ui Components + Particles | 日期/范围选择、Command、组合框、字段组、Dialog、Drawer、按钮组、空态、菜单等 | **优先高频使用** |
| 复杂数据工作台 | ReUI | Data Grid、组合筛选、列配置、虚拟滚动、Kanban、Event Calendar | 数据密集页优先 |
| KPI 与经营看板版式 | Tremor Blocks | KPI、趋势、比较、报告和管理驾驶舱的版式参考/源码 | 看板页按需 |
| 高级视觉组件 | Aceternity UI | Bento、背景、聚光、卡片、营销/欢迎页高级交互 | 克制使用 |
| 微动效 | Magic UI、React Bits | 数字、文字、状态、局部反馈和少量高识别动效 | 偶尔使用 |
| 多风格主题 | tweakcn | 颜色、字体、圆角、阴影、明暗主题和预设管理 | **核心能力** |
| 业务图表 | ECharts | 大盘、趋势、漏斗、归因树和复杂交互图表 | 业务图表默认 |

### 2.1 coss/ui 的正式定位

coss/ui 不是“只有特殊场景才用”的候选库，而是本产品的**细节组件优先库**。

开发日期筛选器、日期范围、Command、Autocomplete/Combobox、Field/Fieldset、Dialog/Drawer、Menu/Context Menu、按钮组、空态等细节前，必须先查 coss/ui 的 Components 与 Particles。存在合适成品时直接复制官方源码，适配项目 token、中文文案和业务数据；不自行重写同类组件。

coss/ui 基于 Base UI，现有 shadcn New York v4 基于 Radix。两者可以在同一 React/Next.js 项目中共存，但不能让同名文件互相覆盖，也不能在一个底层 primitive 内随意混装两种交互 API。

## 3. 资产进入运行仓的方式

```text
完整官方目录（只保存元数据）
        ↓ 查找与预览
官方 Registry / 官方源码
        ↓ inspect + 许可证核验
复制到来源隔离目录
        ↓ token、中文、可访问性和业务接口适配
业务页面组合
        ↓ 验证与登记
可复用本地资产
```

完整目录解决“官方到底还有什么”；按需复制解决依赖膨胀、许可证失控和上游更新不可追溯。二者同时保留。

## 4. 目录边界

建议目标结构：

```text
apps/web/
  components/
    ui/                     # shadcn/Radix 基础组件，不被第三方覆盖
    coss/                   # coss/Base UI 细节组件与 Particles
    reui/                   # ReUI 复杂数据组件
    blocks/                 # 页面级 Blocks，按来源再分子目录
      shadcn/
      tremor/
    motion/
      aceternity/
      magic-ui/
      react-bits/
    business/               # 本项目薄适配层，只放业务语义
  lib/
    ui-assets/              # 来源、版本、兼容性和资产检索元数据
  styles/
    themes/                 # tweakcn 主题 token 包
```

约束：

- `components/ui/` 只保留 shadcn 主底座；coss 组件即使上游默认写入 `components/ui/`，引入后也要移动并修正到 `components/coss/`。
- 页面可以同时组合 shadcn 容器和 coss 细节组件。
- 一个复合组件内部若以 coss/Base UI 为行为底座，就沿用 Base UI 的 `render`、事件和 portal 规则，不套 Radix 的 `asChild` 规则。
- `components/business/` 不复制第三方实现，只对统一 props、数据状态、权限和产品文案做薄封装。
- 不建立“万能 Button/万能 Dialog”二次抽象；来源不同就显式导入，避免隐藏行为差异。

## 5. 完整目录的数据模型

每个上游项目生成一份可检索目录，至少记录：

| 字段 | 含义 |
|---|---|
| `source` | shadcn、coss、ReUI 等来源 |
| `upstream_name` | 上游组件/Block 原名 |
| `kind` | primitive、particle、block、template、theme、motion |
| `category` | table、form、navigation、feedback、date、chart 等 |
| `preview_url` | 官方预览页 |
| `source_url` | 官方 Registry 或源码页 |
| `install_command` | 精确到单组件的命令 |
| `foundation` | Radix、Base UI、无头组件或纯 React |
| `license` | 许可证与附加条款 |
| `dependencies` | 直接依赖与可能的重型依赖 |
| `project_fit` | 对投放平台的推荐场景 |
| `theme_ready` | 是否完全使用 CSS variables/token |
| `last_verified` | 最后核验日期 |
| `upstream_ref` | tag/commit/registry 版本 |
| `local_status` | catalogued、approved、vendored、adapted、deprecated |
| `local_path` | 已复制时的本地路径 |

目录是发现索引，不等于安装清单。`local_status=vendored/adapted` 才表示源码已进入运行仓。

## 6. 引入流程

### 6.1 开发前

1. 先按需求语义查资产目录，例如“日期范围”“列筛选”“空态”。
2. 打开官方 preview，确认交互与风格，不凭名称判断。
3. 优先顺序：coss 细节成品 → shadcn 基础组件/Block → ReUI 复杂数据 → Tremor 看板 → 其他动效库。
4. 记录没有采用的接近候选及原因，避免下一次重复评估。

### 6.2 复制源码

1. 使用 `shadcn view`/Registry JSON 或上游官方 Code 面板先检查将写入的文件和依赖。
2. 一次只加入当前需要的组件或 Block，不执行第三方全量安装命令。
3. 保存来源 URL、核验日期、上游 ref、许可证和原始安装命令。
4. 将生成文件移到来源隔离目录，统一项目 import alias；不覆盖同名 shadcn 文件。

### 6.3 允许修改

- 允许：中文化、尺寸/密度、token、图标、响应式、项目数据 props、加载/空/错状态、可访问性修正。
- 尽量不改：底层键盘交互、焦点管理、portal、ARIA 关系和受控/非受控状态契约。
- 需要大改行为时：保留 vendored 原件，在 `components/business/` 建薄适配，不直接把上游组件改成业务专用件。

### 6.4 验证门

每个引入资产至少验证：

- TypeScript、ESLint、production build；
- 键盘操作、焦点回收、Esc、点击外部关闭；
- loading / empty / error / disabled / readonly；
- light / dark 及所有已发布主题；
- 1366px 桌面、1440px 桌面和移动端基本响应式；
- Base UI portal 层级与现有 Radix overlay 不冲突；
- 大数据量下的渲染和交互性能；
- 源码来源与许可证台账已登记。

## 7. 多风格切换

多风格不复制页面，只切换 token 和少量可控的密度/动效变量。

```html
<html data-theme="new-york-neutral"
      data-density="compact"
      data-motion="subtle">
```

### 7.1 三个独立维度

- `data-theme`：颜色、字体、圆角、阴影、表面层级；来自 tweakcn 预设并经项目语义 token 映射。
- `data-density`：`compact | comfortable`；控制表格行高、控件高度和间距，不改变数据结构。
- `data-motion`：`none | subtle | expressive`；控制 Aceternity/Magic/React Bits 的启用强度，并尊重 `prefers-reduced-motion`。

### 7.2 首批风格方向

| 预设 | 视觉特征 | 推荐场景 |
|---|---|---|
| New York Neutral | 中性、紧凑、稳定 | 默认工作台 |
| Data Dense | 更紧凑、弱阴影、高信息密度 | 完整数据总表、账户池 |
| COSS Minimal | 大留白、细边框、清晰字段层次 | 筛选器、表单、设置页 |
| Warm Operations | 暖中性色、较柔和表面 | 日报、知识库、长阅读 |
| Dark Command | 深色、高对比、命令中心感 | 值守、警报、Agent 抽屉 |
| Bento Soft | 柔和卡片、有限渐变和动效 | 工作台摘要、欢迎/空态 |

ECharts 颜色、tooltip、网格线和字体必须通过同一语义 token bridge 读取，避免页面换主题而图表不换。

## 8. 各来源使用边界

### shadcn/ui

- 主底座与页面骨架；继续保留当前 `new-york-v4`。
- Blocks 直接复制官方源码后改业务数据，不把截图当源码重画。
- Registry 支持 inspect/search/add，用它作为所有兼容 Registry 的入口。

### coss/ui

- 细节组件第一检查点；优先使用当前维护的 Base UI 版本和 Particles。
- 官方支持 shadcn CLI 单组件安装和手工复制；不使用 `@coss/ui` 或 `@coss/style` 全量覆盖现有项目。
- 额外语义 token（info/success/warning 等）通过映射补齐；Base UI portal 根节点使用隔离 stacking context。
- `apps/ui` 源码为 MIT；仓库其他目录存在 AGPL，复制前必须核对目标文件确实来自 MIT 范围。

### ReUI

- 负责复杂数据交互，不再在普通 Table 上手写一套 Data Grid。
- 引入前核实其 Radix/Base 变体和 TanStack 依赖，选择与页面组合最少冲突的版本。

### Tremor

- 主要复用 KPI/报告/驾驶舱的 Block 结构与视觉组合。
- 业务图表运行时仍以 ECharts 为主；如果 Block 强依赖其他图表库，保留布局并替换图表实现。

### Aceternity、Magic UI、React Bits

- 只在能提升识别、反馈或信息理解时使用，不在高频表格滚动区堆叠持续动画。
- 页面同时最多一个主要视觉动效；动效必须可关闭并提供 reduced-motion 路径。
- Aceternity Pro 资产不得作为本项目公共组件库再分发；购买前单独核许可证。

### tweakcn

- 是主题生产和预览工具，不是只看配色的网站。
- 导出的 token 进入版本化主题包；主题发布必须经过组件展厅和核心页面回归。
- UI 组件读取项目语义 token，不能把某一 preset 的颜色硬编码进组件。

## 10. 验收标准

1. 开发者能在一个入口查到所有已选官方来源“有什么、长什么样、如何安装、能否商用、是否已经接入”。
2. 新页面需求有明确的资产检索记录；已有合适成品时不再手写同类组件。
3. coss 日期选择器作为首个样板完整走通：官方源码、独立目录、token 适配、业务薄封装、主题/键盘/响应式测试。
4. 至少六种主题可在同一页面运行时切换，布局和功能不分叉。
5. 任何第三方源码都能追溯到来源、版本、许可证、安装命令和本地修改说明。
