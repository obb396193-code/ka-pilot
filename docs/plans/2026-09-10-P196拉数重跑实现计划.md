# P196 ETL Rerun Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 落地arch v1.9.12/19/20管理员重跑入口，保持原job取数范围与凭证归属，重复请求返回已有活动job。

**Architecture:** Session approved admin → strict空body/十进制runId → live membership锁 → 原run/job行锁 → audit查重 → JobRepository.enqueue与audit同事务。仅创建数据库job，不启动worker或媒体写；不修改原job/run，原凭证为空则保持空，不改成管理员。未知/损坏跨空间来源拒绝。

**Tech Stack:** TypeScript、Zod、node:http、pg、Vitest；复用JobRepository与r014 live membership锁。

---

## 已批准设计/取舍

采用arch已批准的新job+audit方案，不改原job状态，不建立第二张队列/映射表。sourceRunId直接十进制BIGINT，避免JS Number精度丢失；jobId是UUID。管理员可治理当前空间，不把其个人账户清单替换原job范围。保留原payload原样（不接请求覆写），worker启动时仍负责原凭证/权限复核。

## Task 2 DB可靠新job（先红）

- Create `packages/db/src/etl-run-rerun-repository.ts`、`packages/db/test/etl-run-rerun-repository.test.ts`；Modify exports。
- live锁批准admin，原run/job锁串行同源并发；允许job done/failed/blocked_auth，拒绝活动原job；限定六类ETL，不借此执行changeset/任意job。
- workspace必须一致；payload是对象、workspaceId一致，原owner（若非null）必须属于原workspace；run kind与job type相符；16MiB在PG投影前拒绝。
- active重跑由同源audit+jobs读取（queued/leased/running），冲突返回已有UUID；已结束可再建新的job。通过同run行锁与READ COMMITTED后续新statement看见先提交audit。
- JobRepository.enqueue用同client，audit仅sourceJobId/jobId，失败整体回滚。原scope/actor/owner不覆写；不复制旧lease/attempt/error状态。
- PG合成反例：三个终态、活动态、跨空间、admin撤权、owner跨空间、类型错配、大ID、并发双请求、audit失败回滚、原row不变、有效租约。
