# 异步规则证据读取 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让已冻结的受限规则AST支持真实异步DB/接口证据读取，保持与同步解释器相同判真语义。

**Architecture:** 复用condition-tree解析器与求值器，先完整校验并复制树，再枚举唯一(metric,windowHours,dayOffset)证据计划，顺序await读取并严格解析，最后用同一个解释器求值。无假值预跑、无LLM/eval/动态SQL；缺数不短路，限额仍4096观察、128叶子、深度8。

**Tech Stack:** TypeScript、Zod、Vitest。executing-plans技能本会话不可用，按本计划逐项本地执行；不远程上传、不派子Agent。

---

### Task 1：RED与冻结语义测试

Create `packages/domain/test/condition-tree-async.test.ts`。测试同步/异步同fixture parity、缺数any/not、连续日期动态阈值唯一读取、无限CPA、非法树零读取、非法证据拒绝、await期间树与返回对象被修改不漂移、reader错误不泄露、4096上界。运行 `cd packages/domain && npx vitest run test/condition-tree-async.test.ts --maxWorkers=1`，预期新增函数不存在而红。

### Task 2：共享解析与异步读取

Modify `packages/domain/src/condition-tree.ts`。抽取evaluateParsedTree(root, reader)，同步函数仅parse再求值。新增evaluateConditionTreeAsync(input, reader)：parseTree→递归collectRequests（Map JSON三键去重）→逐个await reader的请求副本→observationSchema与daily window校验→evaluateParsedTree读取已验证快照。reader异常固定安全错误，不把原始上游body带到消费者；不对缺源注入0。

### Task 3：门禁与交审
