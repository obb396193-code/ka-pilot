# B15 拆片语义与抽帧解耦设计

> 日期：2026-08-21
>
> 状态：老板已确认
>
> 基线：`be/b14@e9edd5d`

## 1. 已确认的产品语义

“拆片”不是把视频裁成多个 MP4。KA 产品的一期拆片由三条互补但独立的证据链组成：

1. **文稿拆解**：视频只做一次云 ASR，得到完整文稿；按老板 Obsidian 中的拆片提示词，输出钩子、故事结构、卖点推进、受众、节奏、CTA、复刻公式等多个有顺序的语义段。
2. **视觉抽帧**：FFmpeg 检测镜头切换，为每个镜头抽取中点代表帧，并生成 Hook、全片和逐镜头帧墙供页面集中浏览。
3. **证据对齐**：有句级时间戳时可以输出逐句时间表和文稿到镜头的精确映射；只有整段 ASR 时，不伪造秒点，只展示“文稿按语义顺序拆解 + 视觉按真实镜头时间展示”。

实体裁片、导出多个 MP4、自动剪辑不属于本批范围。

## 2. 采用方案

采用“**双时间轴、延迟对齐**”方案：

- 视觉时间轴以 FFmpeg 的真实 `shot.startMs/endMs` 为真相，始终可以显示和跳转。
- 文稿结构使用不带时间的有序 `semanticSections`，整段 ASR 也允许拆成多个语义段。
- 只有 `segment` 精度字幕才能产生 `segments`；`whole_video` 必须返回空的 `segments`，并标记 `alignmentStatus=unavailable_whole_video`。
- 不用视觉镜头边界猜文稿句子出现时间，也不用语义段顺序伪造镜头内容。

未采用：

- **把整段文稿压成一个全片 `other` 段**：诚实但失去拆片的主要业务价值，已被老板否决。
- **按镜头数量平均切文稿**：会制造虚假对齐，优化师可能据此下错误结论。
- **等待带时间戳 ASR 再开发**：阻塞当前可用的文稿诊断和抽帧展示，不符合一期先做诊断的裁决。

## 3. 领域契约

拆片结果升级为版本化结构：

- `alignmentStatus`
  - `exact_transcript_timing`：字幕段自带真实起止时间；
  - `unavailable_whole_video`：只有整段全文，不能逐句定位。
- `semanticSections[]`
  - `order`：从 1 连续递增；
  - `role`：hook/problem/body/proof/selling_point/turn/cta/other；
  - `title`、`description`；
  - `evidenceIds`：整段 ASR 时必须引用全文字幕证据，不包含时间承诺。
- `segments[]`
  - 保留为“有真实字幕时间依据的叙事时间段”；
  - `segment` 字幕时必须无缝覆盖全片；
  - `whole_video` 字幕时必须为空。
- 既有 `summary/hook/sellingPoints/audiences/rhythm/cta/replicationSuggestions/uncertainties` 继续保留，并纳入证据校验。

这样既兼容已经实现的精确字幕能力，也不会让无时间戳 ASR 阻断语义分析。

## 4. 抽帧与帧墙

保留当前已实现能力：

- `scene > 0.15` 记录视觉事件；
- `scene > 0.30` 形成硬切镜头边界；
- 每个镜头按中点抽一张代表帧；
- Hook 帧墙最多 15 格；
- 全片帧墙最多 36 格；
- 抽帧失败保留占位状态，不移动镜头编号。

本批补齐 ContentRadar 已有而 KA 尚缺的**逐镜头帧墙**：

- 每页 6 列、最多 36 个镜头；
- 镜头超过 36 个时生成多页；
- 每页记录 `artifactRef/fromShotIndex/toShotIndex/frameCount/status`；
- 使用已抽出的代表帧生成，不重复解码视频；
- 缺失帧使用本地生成的占位图，确保帧墙槽位和镜头编号稳定。

帧墙只是展示证据，不发送给模型。真实投放帧外发仍受 B13 的受信任多模态 Provider 门禁约束。

## 5. 数据流

```text
sourceRef
  -> 领取短期素材 URL
  -> 立即下载并计算内容 SHA
  -> FFprobe/FFmpeg
       -> 真实镜头时间轴
       -> 逐镜头代表帧
       -> Hook/全片/逐镜头帧墙
  -> 平台字幕或单次云 ASR
       -> segment: 有时间字幕
       -> whole_video: 完整文稿
  -> 版本化拆片 Prompt
       -> 多段 semanticSections
       -> 有时间字幕才生成 segments
  -> 严格 Schema、证据引用和指纹校验
```

## 6. 错误与降级

- 单张抽帧失败：保留 placeholder，其他镜头继续。
- 逐镜头帧墙某页失败：保留页级 unavailable 状态，不把整个拆片任务判失败。
- 整段 ASR：语义报告正常完成；精确逐句时间表显示不可用。
- Agent 输出虚假秒点、非连续 `order`、未知证据或未知字段：fail-closed。
- Prompt、Schema、Provider/model/profile 任一变化：分析缓存失效并重跑；FFmpeg 与 ASR 确定性 checkpoint 可继续复用。

## 7. 测试与完成判据

1. 整段文稿可合法输出至少两个 `semanticSections`，且不含虚假时间。
2. 整段文稿若输出任何 timed `segments` 必须被拒绝。
3. 有时间字幕仍能输出完整、连续、覆盖全片的 `segments`。
4. 逐镜头帧墙按 36 个一页稳定分页；失败帧不导致编号位移。
5. 真实 FFmpeg 烟测能生成代表帧、Hook/全片/逐镜头帧墙。
6. Prompt 明确“拆片不是裁 MP4”，并保留老板原提示词的语义拆解目标。
7. 不修改公开 Contract、DB migration、前端和 ContentRadar 原仓；未做的真实多模态、IdeaLab、OS 通路继续如实标注。
