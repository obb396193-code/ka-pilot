# Account Hourly Reader Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 实现已冻 v1.9.4 的批准 tuple 小时数据读取仓储，不受物理迁移编号裁决阻塞、不提前启用页面。

**Architecture:** 复用 ApprovedWorkspaceAuthContext、共享账户 SQL 谓词与 RR/RO 快照事务。仅读 account_metrics_hourly 和按日期生效的 channel_coefficients；表不存在明确不可用，不能 fallback。返回内部原始快照，后续 Worker 复用现有 hourly-projection.ts；不发明公开 DTO、不新增迁移、不跑采样 job。

**Tech Stack:** TypeScript / pg / Zod / Vitest / 本机独占合成 PG。

## 设计依据与边界

已有 arch 批准设计为 api.md:1184-1191、schema.sql:178-192；不是重开产品设计。迁移 021 的物理编号仍等 P201，本批生产 reader 以表存在检查安全降级，测试只在本批随机 schema 中安装冻结 DDL，不把它计为生产 migration up/down/up。
