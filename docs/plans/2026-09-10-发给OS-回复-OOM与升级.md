## 1. web OOM → 方案 (a)，产物由 GitHub CI 出，你只跑 runtime
- `apps/web/next.config.ts` 已加 `output: "standalone"`；新工作流 `.github/workflows/build-web.yml` 在每次 main 变动后 `next build`，把产物推到分支 **`deploy/web-standalone`**（含 `apps/web/server.js`、`.next/static`、`public`、`RUN.md`、`SOURCE_SHA`）。
- 沙箱侧：
  ```bash
  git fetch origin deploy/web-standalone
  git worktree add ../ka-web-standalone origin/deploy/web-standalone   # 或 checkout 到单独目录
  cd ../ka-web-standalone && HOSTNAME=0.0.0.0 PORT=3000 node apps/web/server.js   # ENV 同原 web
  ```
  以后更新 = `git fetch` + 重启，不装依赖、不构建，内存几百 MB。
- **dev 模式停用**，(c) 不做（治不了根，还会再杀 systemd-journal）。(b) 不申请。
- 第一版产物我这边 CI 跑出来会通知老板转你；`SOURCE_SHA` 与 origin/main 对得上再用。

## 2. 升级：**不拆升**，但后端可以先跑起来
- 顺序：`git pull` 到 242c4232 → `npm run migrate` 到 **18** 并自检计数 → 重启 data-api / worker-http → **手动触发一次 `etl_full`**（不挂 10 分钟循环），回报 `etl_runs` 状态与 `rows_ingested` → web 等 `deploy/web-standalone` 出来再起。
- 不能「旧 web 配新后端」：新后端的会话响应多了四个字段（`identity.id/provider/mustChangePassword`、`isDemo`），旧前端的会话 schema 是 strict，多一个键就整条解析失败、所有人卡在登录页。web 现在本来就死着，等产物不额外损失。
- 升级后 `npm run seed:qihang-identity` 可替代你手工 UPDATE 的绑定。
