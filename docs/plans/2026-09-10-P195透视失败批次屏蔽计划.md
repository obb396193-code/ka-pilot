# P195 Pivot Failure Readability Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让个人 canonical 透视及其规则取证不把已记录失败的 tuple-day 旧数当可用，同时保留预期缺数行。

**Architecture:** 复用 P179 的 `etlBatchReadableSql("metric")`，仅加入 daily LEFT JOIN 的 ON。不会在 WHERE 丢掉 expected 行，不自行删除 canonical、不新增状态或开启 Full/Incr 半成功。P178 授权审计过程中发现的独立一致性修复，不包装成新发现的越权。

**Tech Stack:** TypeScript、PostgreSQL、Vitest；既有 PlatformPivotRepository / EtlBatchFailureRepository。

---

## Task 1：真实 PG 先红

- Modify: `packages/db/test/etl-batch-readability.test.ts`
- 使用套件原有随机 workspace / 明确本机测试库 / 自主迁移。
- 先读两户均 observed，记录一户失败后仍应返回两条 expected：失败户 observed=false、cost missing、computedAt=null；另一户保留10。同号其他媒体/空间不受影响。
- 匹配 Raw 恢复但 canonical 未重算时仍 missing；重算后恢复。
- 摘掉共享屏蔽 SQL 的测试代理应能复现旧数回流，作为负对照，不改生产 SQL。
- Run（packages/db，显式本机 TEST_DATABASE_URL）：`npm test -- --run test/etl-batch-readability.test.ts`；新正向在旧实现应红。
