# 内测 Mac / Windows 适配测试计划（arch 2026-09-09）

## 0. 先分清「是前端还是部署」——内网浏览器控制台粘这一段（F12 → Console → 回车）
```js
(()=>{const r=performance.getEntriesByType('resource');const bad=r.filter(x=>(x.responseStatus&&x.responseStatus>=400)||(x.transferSize===0&&x.decodedBodySize===0&&/_next\/static/.test(x.name))).map(x=>x.name.split('/').slice(-2).join('/')).slice(0,8);
return {视口宽:innerWidth,缩放:devicePixelRatio,被套在框架里:window.top!==window.self,样式表数:document.styleSheets.length,字体:document.fonts.status,构建ID:(document.documentElement.innerHTML.match(/<!--([A-Za-z0-9_-]{15,})-->/)||[])[1]||'未见',失败或空的静态资源:bad}})()
```
| 结果 | 判定 | 归谁 |
|---|---|---|
| `视口宽 < 1290` 且资源无失败 | **我们壳的最小宽问题**（F8-10 在修） | fe |
| `被套在框架里: true` | 沙箱预览把页面套进了它自己的框，视口被压窄；Mac 宽屏也会变形 | OS：给裸地址或新窗口打开 |
| `样式表数 = 0` 或 `失败或空的静态资源` 有 `_next/static/...` | **部署问题**：静态资源没起来 / 代理改了路径 / 构建产物不完整 | OS |
| `字体: loading` 超过 5 秒 | MiSans 切片慢（走公网代理） | fe 预载 + OS 看 TTFB |
| `构建ID` ≠ 沙箱 `.next/BUILD_ID` | 服务的是旧构建（改了代码没重建/没重启） | OS |

**结论先行**：目前老板看到的「变形」我已在本地 1093px 复现，主因是壳（见 `docs/evidence/ui/2026-09-09-1093px/`）；部署侧只剩「是否套框」「静态资源是否全 200」「构建 ID 是否最新」三项待 OS 报。

## 1. 测试矩阵（内测期每次前端大改后过一遍）

## 2. 通过标准（任一不满足 = 不通过）
1. 页面不出现横向滚动条；表格只在自己的容器内滚。
2. 页头、KPI 卡、状态卡、筛选条不被裁切、不叠字、不折成三行以上。
3. 侧栏折叠/展开后内容区随之重排，无遮挡。
4. 字体 3 秒内稳定（Win 上切换一次可接受，反复跳动不行）。
5. 弹层/抽屉在 1093 宽度下可关闭、可滚动到底。

## 3. 怎么测（三层，从便宜到贵）
- **L1 自动**：`scripts/ui/overflow-check.mjs`（headless Chrome + CDP）跑 1093/1280/1440 三档 8 页，溢出全 0 才算过。fe 每次交付附结果；OS 在沙箱对部署版跑一次（把 URL 改成 `http://127.0.0.1:3000`、cookie 用内测账号登录后的 `ka_session`）。后续进 CI（Actions 的 ubuntu 自带 Chrome）。
- **L2 半自动**：Chrome DevTools 设备工具栏，把宽度拨到矩阵五档，逐页截图对照。fe 交付附 1093 三张。
- **L3 真机**：内测同事各自机器上按 §0 自检 + 走一遍「登录→账户池→任务详情→数据分析→工作台」，把自检 JSON 和一张截图发到群里。清单做成一页本地 HTML 勾选（同请教清单做法）。

## 补（2026-09-10）：浏览器版本下限
四浏览器矩阵加一列「版本 ≥119？」（Chrome/Edge）。测试前先 `chrome://version` 记版本；<119 的机器不测排版，先记为「版本不达标」，等主色静态兜底再测。Windows 机型宽度档以 **1078px**（1366@125% 减滚动条 15px）为准。
