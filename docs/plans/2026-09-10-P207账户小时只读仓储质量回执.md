## 本批实现与边界

- `AccountHourlyReadRepository.read(auth, request)` 仅读冻结的账户小时表，不读广告小时、Raw 或日表兜底。auth 严格 personal/explicit_accounts，team/非法/重复 tuple 拒绝；筛选必须由上游已批准 context 承载，request 不接受另一份 accountIds。
- SQL 按 workspace+media+共享 `accountScopeClause` 在读取正文前过滤；返回行再核三键、日期、小时和重复。空授权/仅其他媒体授权无 DB IO，绝不扩大成全 workspace。
- RR/RO 快照内查表、读小时行、读按 ds 生效的最新系数。仅读 requested 前一小时至末小时的真实 0..23 样本；缺行仍缺行，hh24 不冒充 hh23。
- 保存累计 cost/转化/预算等字段的 null 与 0，源 last_sync_time 与本机采样 sampled_at 独立返回，`sourceRunId` 用 decimal string 保精度。`complete` 仅读库存值，不用查询当前时间生成 freshness。
- 系数无记录/只有未来版本时 null；multiply/divide 不混用；同日最新版本歧义 AMBIGUOUS_VERSION，非法值 UPSTREAM_INVALID_RESPONSE，不任取、不默认1。
- 可信 DB `COUNT OVER` 与行在同一语句；真实总数恰好10000可返回，10001或count与实际返回不符拒绝。响应按字段有界，增量估算 JSON UTF-8，达到16MiB同样拒绝。构造器仅允许收紧阈值，不允许超过16MiB。
- 未安装小时表明确 SOURCE_UNAVAILABLE；数据库故障不输出 SQL/上游 body/密码文本，超时57014映射 UPSTREAM_TIMEOUT。

**这是内部原始快照，不是公开 SourceQueryResult。** 不声明 coverage完整/新鲜/ready，不产生 projectedDayCost/cashCost 等派生数。下一环节复用现有 Domain 投影与公开 envelope，仍须接 ETL 与实际表。

## 性能/安全自审

- 最多一次表检查、一次有界行查询、一次最多2条系数查询，固定3次，无逐户数据库roundtrip；共享SQL tuple谓词有界授权最多1000。查询耗时仍受既有15s statement/5s lock timeout控制。
- 大numeric文本在SQL端做128byte限制，缺失与超限分别null/invalid，不把超限伪装成0。计数超过JS安全整数拒绝；不引入任意SQL或表达式执行。
- 所有数据为合成fixture；没有真实账户/媒体写、队列消费、OS请求、部署、push。
- 磁盘约3.0GiB，未过arch8GiB全包门，未跑五包全量/构建，也未清理用户缓存。Worker仅类型/lint兼容验证，不冒称其完整test绿。
- 本批按 writing-plans 拆任务、code-quality-checker 验证；沿用arch既有设计，不另开产品权限决策。
