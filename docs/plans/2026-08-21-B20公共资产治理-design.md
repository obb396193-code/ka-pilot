# B20 公共资产治理领域底座设计

> 状态：设计冻结，进入纯 Domain TDD。
>
> 需求依据：REQ-112/113/114、验收 14.10、老板终裁“个人草稿→团队共享→已验证→官方资产→已废弃”。

## 1. 本批目标

为报表、工作流、策略、对象组和知识资产提供同一套可复用的治理语义，使每个业务模块不再各自发明共享、认证、官方和废弃规则。

本批只实现确定性领域内核，不接数据库、公开 API、权限系统或前端。UI 首期仍可只展示“我的/共享”，底层完整保留五段状态，避免后续迁移返工。

## 2. 核心模型

### 2.1 不可变资产版本

每次修改公共资产都创建新版本，不直接改写已共享版本。版本包含：

- workspace、资产 ID、版本 ID、递增版本号；
- 类型：report/workflow/strategy/object_group/knowledge；
- owner、维护人、定义指纹、变更说明；
- 适用范围和显式依赖；
- 来源：原创、复制或新版本，带来源版本引用；
- 创建时间和完整生命周期事件。

复制只复制来源引用，不复制作者权限或凭证；本模型也不承载任何 credential 字段。

### 2.2 五段生命周期

严格前进：

`draft → shared → verified → official → deprecated`

- `verified` 必须绑定当前版本最近一次通过的验证记录；
- `official` 只能从 verified 晋级；
- `deprecated` 需要原因，可指向替代资产版本；
- 同一事件完全相同可幂等重放，事件 ID 冲突或越级流转失败；
- 不设计隐式回退。修订公共版本应新建 draft 版本，旧版本保持可审计。

### 2.3 验证与使用事实

验证记录由外部真实执行产出，本内核只校验和归一：

- passed/failed；
- 验证人、时间、证据引用；
- 成功次数/总次数或显式业务效果摘要；
- 当前定义指纹，防止旧结果替新版本背书。

使用人数和频次由显式 usage facts 聚合：按用户去重、记录总使用次数和最近使用时间。无事实时返回 0，不由 Agent 猜测。

## 3. 输出

治理摘要统一提供：负责人、维护人、版本、状态、适用范围、依赖、来源、最近验证时间、成功率、使用人数/频次、替代版本和废弃原因。

所有输出稳定排序、深冻结并带 SHA-256 指纹，供后续 Repository、API、列表筛选和 Agent 引用。

## 4. 安全边界

- 不判断调用者是否有权晋级；公开 API 后续必须在调用 Domain 前做 workspace/角色权限校验。
- 不发明“成功率达到多少才算已验证”的业务阈值；是否 passed 由验证流程显式给出。
- 不执行资产定义，不读取报表/工作流/策略内容。
- 不改冻结 contract、migration、runtime 和前端。
- 替代版本只校验引用形态与非自指；是否真实存在、是否兼容由 Repository/服务层验证。
