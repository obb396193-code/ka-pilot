# R010a2 复合规则解释器 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 实现已冻结P098受限条件树的确定性解释，不让OR/NOT掩盖缺数。

**Architecture:** Domain纯函数校验AST，收集每叶子每业务日的metric/window证据与动态阈值，再统一执行三态比较。无eval/SQL/模型调用；数据窗口由可信reader提供，当前默认窗保留null，不擅自解释成24h。输出是内部解释结果，不是公开explain已上线。

**Tech Stack:** TypeScript、Zod、既有MetricValue/RatioValue、Vitest。

---

依据：api.md P098/metrics.md「规则条件树语义」，fixtures/rules/list.json。执行技能不可用，按本计划直接TDD。

### Task 1: AST与证据边界

- 新建`packages/domain/src/condition-tree.ts`与`packages/domain/test/condition-tree.test.ts`；Domain index仅末尾be块追加。
- 先写RED：权威三条规则可解析，深度8/叶子128，空组/无叶子/未知字段/表达式阈值/cost/循环拒绝；任意命中不能短路掉其他叶子的缺数。
- 结构只支持all/any/not（同节点多组AND）；not=NOT(OR)。叶子有限数值阈值或assessment_price，六比较运算符。指标名只作标识，不执行文本。
- 取数请求保留metric/windowHours/dayOffset；无窗口为null，consecutive_days按每个业务日单独判断。累计超过4096次观测拒绝，防超大连续天参数耗尽内存；不是业务最大天数承诺。

### Task 2: 解释、缺数与窗口

- reader返回MV/RV及daily/hourly粒度；present-invalid直接拒绝。日累计证据不能用于非24倍数小时窗。
- assessment_price同窗同日作为额外requiredMetric读取，不用字面值表达式；reader负责已冻结逐日转化加权价格，不由解释器猜价格。
- 任一missing/error/undefined→整条pass=null；+infinite CPA合法比较有限阈值，不转0。每个连续业务日均成立才叶子成立。
- 用cache按metric/window/day去重取证，仍保留每处叶子解释；缺数不可用any/not消掉。
