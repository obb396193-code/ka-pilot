# 前端视觉规范、审核与复用仓库设计

> 日期：2026-08-20
> 状态：老板已批准 A 方案；字体、数字、布局和动画使用“推荐基线 + 可调整 token”，不冻结单一审美答案。

## 目标

在现有 UI 资产体系上补齐三件事：

1. 把文字、数字、布局、密度和动画从零散原则补成前端可执行的推荐基线。
2. 建立前端完成后的独立审核模板，既审数据与行为，也审美观、内容、排版和动效。
3. 把可跨项目复用的介绍、目录、规范、合法源码缓存和离线展厅整理成独立私有 GitHub 仓库。

## 决策

### 1. 规范不是审美铁板

规范分三层：

- **硬门禁**：数据正确、权限、写操作确认、敏感信息、键盘/焦点、许可证等不可妥协。
- **推荐基线**：字号范围、行高、间距、密度、数字精度、动画时长和缓动作为默认起点。
- **可调整层**：真实页面验证更清晰、更协调时，可以修改语义 token；修改需同时复核桌面/移动、多主题和至少三个典型页面，并回写理由。

不把某款字体、某个字号或某条动画参数写死到组件里。规范控制层级和一致性，不替代设计判断。

### 2. Storybook、ECharts 与离线展厅各司其职

- **Storybook**：项目自己的组件工作台。每个 KPI、筛选器、表格、弹窗和 Agent 消息用 stories 展示不同 props 与状态，不进入生产 bundle。
- **ECharts**：产品运行时的数据图表引擎，只负责趋势、对比、分布、漏斗等可视化。
- **UI 资产展厅**：第三方来源选型墙，用于比较 17 家官方代表组件，不等于项目自己的组件库。

三者不能互相替代：ECharts 不能展示完整表单/弹窗状态，Storybook 也不负责第三方全量目录发现。

### 3. 动画只服务理解

Motion Primitives 与 Animate UI 继续选择性准入。文字/数字动画只用于：

- KPI 确认性更新；
- Agent 流式或工具执行状态；
- 操作成功反馈；
- onboarding、空态或少量强调信息；
- 展开、折叠、切换和层级变化。

表格正文、长文、错误信息、权限提示、关键操作标签和高频实时数据禁止使用炫技文字动画。所有动画支持 reduced motion，优先 transform/opacity，可被用户输入打断。

### 4. 审核分为硬门禁与视觉评分

审核顺序：契约/数据 → 状态 → 信息层级 → 内容与数字 → 排版布局 → 组件一致性 → 动画 → 响应式/无障碍 → 性能/来源。

- P0：禁止合并/上线。
- P1：本批次应关闭；否则需明确批准。
- P2：普通体验问题。

视觉评分只辅助比较，不能抵消数据错误、越权或写操作风险。审核输出必须带页面、视口、主题、状态、截图/录像、文件行号和复审状态。

### 5. GitHub 复用仓库按许可证白名单导出

目标仓库名：`frontend-ui-asset-kit`，默认 private。

包含：

- 项目无关的 UI 资产介绍、目录、指南、规范、审核模板、决策模板；
- 机器可检索 catalog/capabilities/coverage/source health；
- 离线展厅和合法可再分发的预览/源码；
- 许可证、来源、ref/hash 和排除清单；
- 给其他前端 Agent 的入口说明。

排除：

- 投放 Agent PRD、契约、内部数据、内部角色信箱和公司专属决策；
- Pro/Ultimate/会员源码；
- React Bits、Animate UI 等 Commons Clause 限制源码；
- Aceternity 等逐项许可证尚未确认的源码；
- 许可证只写“待核验”的公开仓库样例；
- 任何密钥、token、真实账户信息和本地绝对路径。

源码白名单首批仅允许明确 MIT/Apache-2.0 且路径边界已核验的 shadcn、coss apps/ui/origin、ReUI Free、Tremor、Magic UI Free、Vercel AI Elements、Kibo UI、Dice UI、Motion Primitives、tweakcn。受限来源只输出元数据、官网链接和使用边界。

## 验收

- 新规范明确区分硬门禁、推荐基线和可调整层。
- Storybook/ECharts/展厅不再混淆。
- 数字、日期、文字、布局、密度、动画都有可执行检查项。
- 审核模板可以直接复制给每个页面使用，并生成通过/有条件通过/不通过结论。
- 导出包不含项目敏感信息、受限源码、付费源码或绝对本地路径。
- 导出包内所有允许的本地链接有效，许可证 manifest 与物理文件一致。
