# B19 月度结算单内核设计

> 日期：2026-08-21
> 产品依据：验收 7.3、PRD 3.7、老板需求 REQ-110
> 边界：纯 Domain；不接 DB/API/导出/钉钉/Agent，不替业务发明字段与容差

## 1. 目标

把优化师每月手工拼结算表的确定性部分变成可复算、可校验、可冻结的领域模型：每期选择一个不可变模板版本，导入离线结算事实，计算派生字段，显示缺数/公式/返点差异，人工修正必须形成前值一致的审计链；冻结后的旧单不受新模板影响。

## 2. 为什么不是自由 Excel 公式

- 自由公式字符串难校验、可注入、无法稳定回放。
- 采用受限表达式树，只允许字段引用、有限常量与 add/subtract/multiply/divide。
- 不内置 `/1.09`、返点率、差异阈值或固定列；这些都属于模板版本输入。
- Agent 未来只解释差异或起草模板，不参与数字计算。

## 3. 模板

模板包含：

- template ID/version/name、币种/单位说明、创建人和规范时间；
- 1~50 个有显式 order 的字段；字段类型为 text/date/number/money/rate；
- 字段来源为事实键或受限公式；公式字段只能产出 numeric 类型；
- required、allowCorrection 两项显式控制；
- 0~50 条有显式 order 的对账检查；检查比较两个 numeric 字段，容差模式为 absolute/relative/either，容差值必须由模板给出，严重度为 block/warn；
- 稳定排序、严格未知字段拒绝、深冻结和 SHA-256 fingerprint。

## 4. 事实与预览

- 一次运行固定 template fingerprint、结算期起止日、scope、`offline_settlement` 数据口径和 dataCutoffAt。
- 最多 1000 行；每行由稳定 sourceFactId/rowKey 和最多 200 个标量事实组成。
- 完全相同 sourceFactId 重试幂等；同 ID 内容冲突失败；rowKey 必须唯一。
- 每行按模板取事实/算公式；缺 required、类型不符、公式除零/循环等形成阻断 issue，不输出伪数。
- 检查结果明确 matched/mismatch/undefined；只有模板标为 block 的 mismatch/undefined 才阻止冻结。

## 5. 人工修正与冻结

- 修正事件绑定 rowKey+fieldKey，带 from/to、理由、操作者、规范时间和 evidenceRef 可选；字段必须 allowCorrection。
- 事件按 correctedAt+correctionId 稳定执行；fromValue 必须与当时值严格相等，防并发覆盖；完全相同 correctionId 幂等，冲突失败。
- 预览输出 `blocked|ready_to_freeze`、逐行值/来源、检查与 issue、事实/修正/template fingerprint。
- 只有无 blocking issue 的预览可冻结；冻结记录确认人/时间与 preview fingerprint，形成新 fingerprint。
- 冻结是值快照，不在未来模板更新或事实重拉时静默变化；勘误应产生新运行/版本，不覆盖旧单。

## 6. 不做

- 不定义每个月到底有哪些字段、返点公式和容差；由运营模板版本提供。
- 不实现 DB/API/Excel/PDF/钉钉推送、工作项转换或权限。
- 不接真实离线数据源；调用方以后从奇航 offline/语义层提供事实。
- 不做税务、发票或财务会计规则，不把内部经营结算模型冒充财务系统。
