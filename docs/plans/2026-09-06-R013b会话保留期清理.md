# R013b 会话保留期清理实施计划

**Goal:** 落实 inbox-codex 的 R013b 追加：删除失效超过 30 天的产品登录会话 auth_sessions，不处理投放业务记录，也不是清理 Codex/Claude/OS 的对话。

**Architecture:** 后台维护 job 复用 JobRepository / JobConsumer 与现有租约，不增加浏览器写 API。目标 workspace 仅取受信部署配置和 job row；缺 workspace 拒绝，不靠个人媒体 credential/grants 执行维护。保留期使用数据库时钟，不接收浏览器或 payload 传来的任意 cutoff。

**Tech Stack:** TypeScript、PostgreSQL、Vitest、现有 Worker runtime。

状态：下一独立子批计划，尚未实现；不与 KA BI 修复代码提交混合。

1. 新 `packages/db/src/session-cleanup-repository.ts` + unit / real-PG test：参数严格 uuid、固定 30 天、有限 batch；按 `(active_workspace_id, expires_at/revoked_at)` 筛选，只删除 expires_at 或 revoked_at 严格早于 DB 当前时间减 30 天的记录。有效、未到期、刚过期/刚撤销、恰好边界、其他 workspace 全保留。返回计数，不返回 token hash、identity、cookie、provider subject。
2. 同一短事务内检查 job id / workspace / type / running lease token 与有效租约，并锁 job；过期 worker 不得在新 executor 之后删记录。批次稳定排序、有限锁等待、statement timeout；失败 rollback。session switch/revoke 的并发更新不得让新活动会话误被删除。
3. 新 `apps/worker/src/auth/session-cleanup-handler.ts` + 测试：仅接受服务端维护 job，拒绝 payload 自报 workspace/cutoff/token；固定安全错误，旧租约保留 LostJobLease 语义，重放安全；注册实际 runtime，不包装 withQihangIdentity，不调用媒体。
4. 单独受控维护入口/排队 service：复用既有队列，不改 ETL tick 的媒体授权语义；不能为了清 session 放宽 worker:once 的空 grant 防线。无媒体凭证仍能维护，不启动全局 daemon，不领取别的 job。部署触发频率交配置/外部 scheduler，不承诺固定业务频率；单轮工作量和时间有界，未清完留后续轮次。
5. 真实 PG：旧过期、旧撤销、恰好边界、仍有效、跨 workspace、两 worker 同时领取/陈旧 fence、重放、批次上限、session 切换竞态；测试只用随机合成用户/会话。SQL 不删除 accounts/users/workspaces/业务记录，无 CASCADE。
6. 定向先红后绿；Domain/DB PG/Worker 全量、typecheck/lint、coverage、安全审计；独立代码 SHA + 回执 SHA。runbook 只新增本人维护命令节，交接明确默认不自动运行、未在真实内网部署验证。

在实现前继续核对迁移/索引与既有 session 锁顺序；发现需要新 Contract 列或 migration 编号先问 arch，不侵占 013–017。公开 v3 细口径仍按 P058/P061 待裁，本维护子批不替其拍板。
