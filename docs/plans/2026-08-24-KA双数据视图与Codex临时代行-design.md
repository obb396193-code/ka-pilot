# KA 双数据视图与 Codex 临时代行设计

> 日期：2026-08-24  
> 状态：老板已确认方向；目标为实现、内网联调、部署并可用；Claude 后续复审不阻塞交付
> 适用范围：KA Data / 自建数据主线 / 对账视图，以及 Claude 暂不可用期间的临时协作

## 1. 已拍板目标

1. **KA Data 是运营权威数据源**：先做一版部门成员可以直接查看和使用的运营权威视图。
2. **自建数据体系继续作为产品主线**：奇航 get_data、我方 ETL、确定性计算、诊断与执行闭环继续建设，不因 KA Data 可用而停止。
3. **一套产品支持两版数据并可对账**：不是复制两套页面，而是在相同页面、筛选和业务对象下切换数据视图，并提供差异比较。
4. **内部试用不被多人权限方案阻塞**：一期允许使用已确认可用的共享只读通路；每人独立授权、数据范围和正式服务身份进入后续治理，不倒逼当前试用停工。
5. **Claude 暂不可用期间采用方案 2**：由两个独立 Codex 任务分别做临时审查和可复用纵向切片；Codex 继续做到功能实现、真实内网联调、部署和可用验收。Claude 恢复后逐项复审，前端允许重做，但不作为当前部署前置门。

## 2. 为什么不是两套产品

复制两套页面会造成筛选、指标定义、交互和后续功能分叉。正式产品采用统一的业务对象、页面和组件，只在数据适配层切换来源：

```text
页面 / 报表 / Agent / 工作流
            ↓
      Canonical Query Contract
            ↓
  ┌─────────┼─────────┐
  │         │         │
KA Data   自建主线    对账引擎
Adapter   Adapter    Reconcile
```

统一状态：

```ts
type DataViewMode = "ka_data" | "platform" | "reconcile";
```

- `ka_data`：运营权威版，优先用于跨媒体、商品、素材、广告组、BI 转化和历史经营分析。
- `platform`：自建主线版，优先用于奇航实时/离线数据、异常诊断、账户动作和效果回收。
- `reconcile`：同筛选条件下并列展示两边数值、差值、差异率、口径说明和可解释原因。

## 3. 页面交互

### 3.1 全局数据视图切换

数据相关页面顶部统一提供“数据视图”选择器：

- `运营权威版 · KA Data`
- `平台主线版 · 自建数据`
- `对账比较`

切换时保留日期、媒体、任务、账户、商品等可兼容筛选；目标来源不支持的筛选或指标显示“该数据源暂不提供”，不得静默换字段或用 0 代替。

### 3.2 必须随数据出现的来源信息

所有 KPI、图表、表格和导出都携带：

- 数据源徽标；
- 数据截止时间或分区日期；
- 口径/数据集版本；
- 覆盖媒体、日期与对象范围；
- 是否截断、降级、补洞或部分产出；
- 对账模式下的匹配率和未匹配对象数。

### 3.3 对账视图

对账不是把两边数据混成一个数，而是保留来源：

老板于 2026-08-24 裁决采用方案 A：`reconcile` 只并列展示 KA Data 与自建主线原值，不生成第三个“统一主数”，不静默选择一边覆盖另一边。`ka_data` 和 `platform` 单模式各自只展示本来源数值；KA Data 标记为运营权威版，当日实时诊断、小时 pacing、执行前检查和效果回收仍使用 platform。详见 `docs/decisions/2026-08-24-双数据对账主数语义.md`。

| 对象/指标 | KA Data | 自建主线 | 差值 | 差异率 | 原因/状态 |
|---|---:|---:|---:|---:|---|
| 账户 A / 消耗 | — | — | — | — | 待真实数据填充 |

差异原因至少区分：时间尚未对齐、实时/结算口径不同、账户 ID 未映射、字段定义不同、分区未完整、数据源异常和真实业务差异。未知原因必须显示“待核查”，不能由 LLM 编造。

## 4. 数据权威矩阵

权威不是“一边包打天下”，而是按业务用途定义：

老板于 2026-08-24 进一步冻结逐指标/场景权威矩阵：跨媒体经营、历史运营、商品/素材/广告组/BI 分析默认 KA Data；当日实时、小时 pacing、异常诊断、账户/广告下钻、执行前检查和动作效果回收默认 platform；考核价、返点、赔付和现金成本按来源分别版本化，禁止跨来源混算。详见 `docs/decisions/2026-08-24-双数据逐指标权威矩阵.md`。

| 场景 | 默认来源 | 说明 |
|---|---|---|
| 跨媒体经营分析 | KA Data | 运营维护、权限完整，先作为部门查看版 |
| 商品/素材/广告组/BI 转化分析 | KA Data | 使用其现有事实表与维表能力 |
| 今日实时巡检、小时 pacing、广告下钻 | 自建主线 | 奇航实时接口及已验证的分片/小时语义 |
| 结算与历史离线分析 | 两边并存 | KA Data 为运营权威版，自建离线口径继续保留并对账 |
| 账户写操作及效果回收 | 自建主线 | 经 Capability Registry、确认门和执行器完成 |
| 现金、返点、考核等公式 | 分视图版本化 | KA Data 版使用其维护公式；主线版用我方版本化规则；禁止无来源混算 |

## 5. KA Data 接入边界

内部一期可以使用共享只读凭证，但实现上必须明确标记为 `internal_trial_shared_reader`，且只放服务端 Secret/config，不进浏览器和仓库。

浏览器、Agent 和报表设计器不得直接提交任意 SQL。产品后端建立 Query Registry：

- 每个查询有固定 ID、参数 Schema、允许的数据源和最大范围；
- 服务端只拼装白名单字段、维度、筛选与排序；
- 原始结果进入来源层，映射后进入统一 Contract；
- 记录 SQL 模板版本、数据集版本、执行耗时、截断标志和 trace；
- 10,000 行/16MB 等上游边界必须被产品识别并提示，不得把截断结果当全量。

账户 ID 存在不同命名空间时，使用独立映射表和匹配状态；未匹配对象不强行 join。

## 6. Codex 临时代行分工

### 6.1 根任务 / 集成方

- 维护需求基线、设计、计划、台账和交接包；
- 保护当前 `fe/f001` 脏工作区，不在其上继续混改；
- 审计两个 Codex 任务的实际文件、SHA、测试和截图；
- 只把通过门禁的候选标为 `candidate_integrated`；
- 生成 Claude 恢复后的完整复审包。

### 6.2 临时审查任务

- 只读审查现有后端、契约、数据口径、安全与可靠执行；
- 特别审查双数据视图、Query Registry、对账语义和 Runtime Executor；
- 输出问题、证据、严重级别和修复建议，不直接充当 Claude/arch 终裁；
- 状态只能从 `draft` 到 `codex_prechecked`。

### 6.3 临时前端任务

在独立 worktree/`codex/fe-vertical-slice` 分支实现一个可复用纵向切片：

```text
工作台
  → 数据分析（含三态数据视图切换）
  → 账户详情
  → 异常诊断
  → 变更预览与确认
```

交付范围包括：统一 API/mock 层、来源徽标与新鲜度、数据视图切换、对账表、加载/空/错误/无权限/部分数据状态，以及切片页面。业务逻辑、数据适配与视觉组件分层，便于 Claude 后续重审或换皮。

本批次不追求一次做完全部页面，也不得把纵向切片冒充完整前端。

## 7. Claude Code 上下文如何迁移到 Codex

### 7.1 不能原样迁移聊天外壳

Claude Code 的 JSONL 和 Codex 任务使用不同的会话存储、工具事件与运行协议。`copy-cloud-session` 只适用于同一类 Claude Code 本地会话“换 session ID 续聊”，不能把 Claude Code JSONL 直接注册成 Codex 原生任务。

禁止直接改 Codex 内部数据库或伪造 thread ID：即使能显示，也不能保证附件、工具结果、父子消息、权限和隐藏状态正确。

### 7.2 采用可审计上下文包

原始会话只读保留：

- 源文件：`/Users/aik/.claude/projects/-Users-aik/9960860c-e50b-4a3f-a47f-26fccbb7a236.jsonl`
- 行数快照：2,785
- SHA-256 快照：`63716acd17e018e864b728be08a74c5602472d41897da20e422bc60320bd1f51`

新 Codex 任务不吞整份大 JSONL，而是收到分层入口：

1. `AGENTS.md`、目标、PRD、原始需求基线和工作台账；
2. 与自己角色直接相关的 relay 信箱；
3. Claude 会话索引，记录关键消息行号和对应结论；
4. 当前分支、SHA、脏工作区状态和禁止触碰范围；
5. 未决问题、内网部署门、待 Claude 后续复审项和双轴状态词典。

需要核查细节时，新任务可只读检索原始 JSONL；不得把其中较早、已被老板后续推翻的结论当成当前事实。

## 8. 状态与验收

交付与审查使用两条独立状态轴：

```text
交付：draft → implemented → integrated → deployed_internal → runtime_verified
审查：codex_prechecked → claude_review_pending → claude_approved | changes_required
```

`claude_review_pending` 不阻塞 `deployed_internal/runtime_verified`。任何临时 Codex 产出都不得标“Claude 已审”或“架构已冻结”；但通过 Codex 预审、自动门禁和真实内网验收后，可以如实标注“内网已部署/已验证”。Claude 恢复后复审包必须包含：需求映射、commit 范围、测试、截图、部署版本、真实联调证据、已知缺口、临时审查报告、被否决方案和原 Claude 会话证据入口。
