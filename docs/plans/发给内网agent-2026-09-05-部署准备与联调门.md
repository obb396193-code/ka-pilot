一、环境准备（6 问，回答 + 能做的直接做）

1. PostgreSQL 16
   产品用自己的 PG（不是 ka-data、不是 SQLite）。内网给 FaaS 应用配 PG 的路径是什么（a1 配套 / RDS / ADB-PG / 其他）？申请要多久？
   硬要求：能执行 CREATE EXTENSION pgcrypto 和 btree_gist（要么预装，要么给的账号有权限）。给我：申请路径、连接串形态（host:port/db 的样子，不要密码）、两个扩展是否可用。
   能申请就直接申请一个 daily 用的库。

2. Node 20 + 依赖安装
   仓库是 5 个独立 package（apps/worker、apps/web、apps/dingtalk-gateway、packages/db、packages/domain），apps 通过 file:../../packages/xx 依赖 packages，安装顺序 domain → db → worker/web。
   问：FaaS 构建阶段能不能跑 npm ci（走 tnpm 或内网 registry）？不能的话，我们把 node_modules 打进 zip（会到几百 MB），你确认 zip 大小上限和哪种方式可行。Node 版本请给 20.x。

3. 进程拓扑（最关键）
   一套产品要跑 3 个进程：
   - web：next start，对外端口（用户浏览器访问）
   - data-api：npm run start:data-api，只监听 127.0.0.1:3101（web 的 BFF 通过内部 token 调它）
   - worker：npm start，ETL 循环，无端口
   问：a1 faas 一个应用能否跑多进程（有没有 Procfile/supervisor 之类）？如果不能，就要拆 3 个应用，data-api 得改监听 0.0.0.0 靠 token 保护——告诉我你环境支持哪种，我按你说的改配置。

4. FFmpeg / ffprobe
   运行时镜像里有没有？没有能不能装？素材拆片链路要用，一期部署可以不带，但要知道能不能有。

5. Secret / 配置注入
   config vars 明文可读你之前实证过，daily 阶段接受，正式前再换。下面这张表，请你确认"谁给"这列，能自己生成的直接生成放进 config vars：

   | 变量 | 谁给 | 说明 |
   |---|---|---|
   | DATABASE_URL | 你（PG 建好后） | 三个进程共用 |
   | DATA_API_INTERNAL_TOKEN | 你生成 | ≥32 位随机；data-api 侧 |
   | KA_DATA_SERVICE_TOKEN | 同上一行同一个值 | web BFF 侧，两边必须一样 |
   | KA_DATA_BACKEND_ORIGIN | 拓扑定了再填 | 同机 = http://127.0.0.1:3101 |
   | INTERNAL_TEST_AUTH_ENABLED | true | 内测登录开关 |
   | INTERNAL_TEST_AUTH_CREDENTIALS_JSON | 你按 runbook 生成 scrypt | 用户名/密码老板给你；identityId 你生成 UUID 后**回传给我**（seed 要用） |
   | AUTH_SESSION_TTL_SECONDS | 28800 | 默认即可 |
   | WORKER_SERVICE_QIHANG_USER_ID | 老板本人的奇航 userId | 一期绑老板身份拉数（B10 结论：不冒充服务身份） |
   | QIHANG_BASE_URL | 不用设 | 代码默认 https://qh.alibaba-inc.com/qihang/api/rta_auto/tmp/get_data |
   | KA_DATA_ENABLED / KA_DATA_BASE_URL / KA_DATA_READER_TOKEN | 先不设 | 团队空间第二阶段，等二.2 有答案 |
   | IDEALAB_ASR_ENABLED / IDEALAB_AK | 先 false | 等老板申请 AK |
   | AGENT_ENABLED | false | 一期关 |
   | DINGTALK_* / KA_API_* | 先不设 | 网关第二阶段 |
   | NEXT_PUBLIC_KA_DATA_PROVIDER / KA_DATA_DEV_* | 一律不设 | 那是本地 mock 用的，线上出现即错 |

   生成 scrypt 的命令在 runbook 第 4 节（node 一行脚本，从 stdin 读密码，不进历史）。

二、四项只读核证（只读、不写、不借 token）

1. 8 维透视的 ad 级字段名
   产品"维度透视"要 8 个维度：任务｜业务｜账户｜代理/自投｜资源位｜出价工具｜UBP｜扣量区间。
   已知 ad_realtime 有 task_id / biz_name / account_id / account_deduction_rate_h（前三个和扣量有了）。缺四个：**资源位、出价工具、代理商/自投、UBP**。
   请从 kuaishou-cli 的 campaign list / unit list / creative list、ks-data-queryer 的 account 行、qihang-ks-cli 的 kuaishou-task get 返回里，找出承载这四个维度的字段：给**字段名 + 枚举值全集 + 在哪个接口哪一层**，不要数值。哪个维度所有接口都没有，就明确写"无数据源"，我们前端就显示空态不猜。

2. ka-data（团队空间的主数据源，老板已拍板）

   d. 一枚 reader 能不能看到全渠道所有人的账户？团队空间要"所有人可看只读"，这条决定我们能不能用一个 token。
   e. 同日同户对平：老板给你 1 个账户 + 1 个 D-2 日期。你分别跑 奇航 account_offline 和 ka-data 对应查询，回一张表：字段名 | 奇航有/无 | ka-data 有/无 | 相等/不等/差异百分比。**不贴值**，只贴等不等。

三、部署流程（等老板给 zip；先看一遍能不能做）

zip = main@某个 SHA（我会写在 zip 名里）。步骤：
1. 解压 → 按一.2 装依赖
2. 在 packages/db 跑：DATABASE_URL=... npm run migrate（001→011 一次跑完，空库没有前置检查问题）
3. 跑 seed（zip 里会带 seed 脚本和一份 JSON：identityId = 你在一.5 生成的那个、个人空间、团队空间、成员关系；没有 seed 登录会失败，这是代码现状不是你的问题）
4. 起 data-api → 探针：curl 127.0.0.1:3101/healthz 要 200；带 Bearer 不带 cookie 打 /api/v1/auth/session 要稳定 401
5. 起 web → 浏览器用内测账号登录 → 能进工作台
6. 起 worker → 触发一次 etl_full → 账户池页出现真实账户（老板 userId 名下的）
7. 回一份脱敏烟测报告：只报 route / status / requestId / 行数 / 覆盖 / 耗时，**不报指标值、账户 ID、token、完整 URL、SQL、上游 body**
