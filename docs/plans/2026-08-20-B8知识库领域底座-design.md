## 1. 本批目标

B8a 先把知识文档的“内容真相和安全引用”做成可测领域内核，为后续复制 ContentRadar 的 BlockNote 编辑器、文档树、@双链、反链面板、报告归档和案例库提供稳定语义。

本批只做：

1. BlockNote `{blocks: [...]}` 严格信封与受限 JSON 验证；
2. 递归纯文本投影，供搜索索引使用；
3. 按文档 ID 的 wikilink 提取、去重和安全替换计划；
4. KA 业务对象引用提取（任务/账户/报告/工作流 Run/变更集/数据集/商品/素材）；
5. 来源、可见性、资产生命周期与 Agent 搜索引用的内部类型；
6. 权限、目标解析和搜索的抽象端口，不绑定 PostgreSQL/OSS/向量库。

## 2. 已核对的 ContentRadar 现状

本次已只读核对 ContentRadar 当前源码、迁移和真 PG 集成测试，不依赖历史汇报：

- `KnowledgeEditor` 使用 BlockNote，真相信封是 `{blocks:<BlockNote 块数组>}`，裸数组不是正常写入形态。
- 前端停笔约 500ms 后整篇 PATCH，串行保存，飞行中新稿覆盖 pending，即单客户端 LWW，没有 CRDT。
- 自定义内联形状为 `{type:"wikilink", props:{itemId,title}}`；`itemId` 是真相，`title` 只是显示缓存。
- 后端保存时递归投影所有 `text` 叶子，wikilink 还投影 `props.title`，使被链文档标题可搜索。
- 保存时按当前正文全量替换本文出链；重复边去重，非法 UUID、自链、跨 workspace 或已删除目标不建边。
- 反链就是查 `target=当前文档` 的 source 文档，并且显式带 workspace 条件。
- 文档树用 `react-arborist`，同级排序用 `fractional-indexing/generateKeyBetween`；后端只保存 position，不自研排序算法。
- ContentRadar 现有实现会静默忽略坏链。KA 底层将保留“不建边”的安全结果，但返回结构化拒绝原因，便于数据健康和排障。

## 3. 真相模型

### 3.1 正文真相

```text
KnowledgeDocumentEnvelope
└─ blocks: BlockNote JSON[]
```

- 外层只允许 `blocks`，拒绝裸数组和未知顶层字段。
- B8a 不复制 BlockNote 整套块 Schema；只验证 JSON 安全、大小/深度/节点数上限，以保留 BlockNote 前向兼容。
- 自定义 `wikilink`/`business_ref` 节点由提取器单独严格解析；坏引用不影响其他正文保存，但不进链接图。
- 指纹来自规范化后的完整信封，供事件幂等、索引去重和审计使用。

### 3.2 纯文本投影

- 递归收集 key 为 `text` 的字符串叶子。
- `wikilink.props.title` 额外加入投影；`itemId` 不进用户可搜文本。
- 保留文档遍历顺序，去掉空白项，用换行组合。
- 投影是派生数据，不得反向覆盖 blocks 真相。

### 3.3 文档双链

```text
source document --wikilink(itemId)--> target document
```

- 提取阶段输出候选 ID 和坐标路径，去重后稳定排序。
- 非法 ID 和自链在纯函数阶段拒绝。
- 目标解析端口只返回“当前 workspace 可用/不可用”，不区分“他租户存在”与“不存在”，避免用 UUID 探测跨租户资源。
- 替换计划输出 `acceptedTargetIds` 与 `rejected[]`，上层事务再执行“删旧出链+插入新出链”。

### 3.4 KA 业务对象引用

自定义内联形状：

```json
{
  "type": "business_ref",
  "props": {
    "objectType": "account",
    "objectId": "internal-or-media-id",
    "label": "账户显示名",
    "snapshotVersion": "optional",
    "dataCutoffAt": "optional ISO time"
  }
}
```

首批 `objectType`：`task|account|report|workflow|workflow_run|dataset|changeset|product|material`。

- `objectId` 是受限 opaque ID，不假设所有媒体对象都是 UUID。
- `label` 只是显示缓存，不作对象真相。
- `snapshotVersion/dataCutoffAt` 使报告、诊断和案例可回到当时证据，不用当前态篡改历史结论。
- 引用只在解析端口确认同 workspace 且当前用户可读后才可用于搜索反查和 Agent context。

## 4. KA 特有增量

### 4.1 来源和可见性

内部来源类型：

- `manual`：用户手写文档/SOP/口径；
- `ai_report`：日报、周报、复盘、诊断、结算等 Agent 生成报告；
- `report_snapshot`：报表/图表数据快照；
- `workflow_case`：工作流 Run、变更集和 T+1 效果自动聚合的案例；
- `lesson`：忽略原因、失败 pattern、错题本；
- `imported`：外部 SOP/文档导入。

可见性只表达访问面：`private|team`。`official` 不是可见性，而是统一 `assets` 治理状态之一。

资产生命周期复用现有方向：`draft→shared→verified→official→deprecated`。B8a 只建模，不更改 `assets` 表。

### 4.2 自动归档和运行废气

B8a 不实现归档 Worker，但底层需支持未来输入：

- 报告归档：文档引用 report/task/account，带 config version 和 data cutoff；
- 案例卡：引用 work item/workflow run/changeset/account/task，结构是问题→动作→结果；
- 错题本：来源 `lesson`，默认 `private`，成本高于目标/执行失败/忽略原因保留证据引用；
- SOP：用户手写，可经统一资产治理升为 verified/official。

### 4.3 Agent 搜索引用

Agent 不直接获取整库文档，搜索端口返回受限 citation：

- document ID/title/revision；
- fragment ID/text 和 score；
- source/visibility；
- 已授权 business refs；
- data cutoff/snapshot version；
- 稳定引用键，用于诊断结论 evidence 回锚。

权限裁剪必须在搜索端口内完成，不能先把跨权文本给 Agent 再要求模型忽略。

## 5. 保存与并发语义

- 前端后续可复制 ContentRadar 的 500ms 停笔+串行 pending 保存，避免同一客户端响应乱序覆盖新稿。
- KA 是多用户部门产品，不应把“纯 LWW 无冲突提示”直接复制到团队共享文档。公开 API 应由 arch 裁决 revision/ETag/If-Match 或等价乐观锁。
- B8a 仅产出稳定内容指纹和解析结果，不假设数据库 revision 字段已存在。
- 不引入 CRDT；实时多人协同编辑不是首版必需。

## 6. 前端复用与后端移植边界

### 后续 FE 可独立复制/改造

### B8a 用 TypeScript 移植语义，不照抄 Python

- 信封验证、纯文本投影、wikilink 提取、全量出链替换计划。

- 结构化坏链诊断，不复制“静默忽略”。

ContentRadar 原仓只读，本项目独立实现，不共享运行时代码和数据库。

## 8. 验收标准

1. 裸数组、未知顶层字段、非 JSON、过深/过大/过多节点全部拒绝。
2. 合法 BlockNote 块原样保留，稳定内容指纹不受 object key 顺序影响。
3. 纯文本投影包含正文 text 和 wikilink title，不包含 ID/props 噪音。
4. 双链按 itemId 去重，自链/坏 ID/目标不可用有结构化原因，不建边且不泄露跨租户目标存在性。
5. 业务对象引用严格类型、受限 ID、去重，时间/快照字段校验。
6. 搜索 citation 必须带 workspace/user 权限上下文、revision 和证据引用，无权文本不得进 Agent。
7. 新模块 tests/coverage/type/lint/audit 通过，contract/migrations 相对 B7 零差异。
