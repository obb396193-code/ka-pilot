# B4 任务经营内核设计

> 日期：2026-08-19
> 状态：老板已批准契约安全内核路线
> 分支：`be/b4`

## 目标

交付任务经营的确定性事实层：pacing、考核价版本、任务—账户有效期、任务日指标与日报事实数据集。报告“12 模块”只消费事实集，不在契约未冻结时固化展示 DTO。

## 方案

1. 直接实现任务 API+日报 12 模块：会猜 task 主键、模块字段和日历语义，不选。
2. 等启航抽查和 Claude 契约：会阻塞已明确的数学与版本仓储，不选。
3. 领域事实先行：日历天 pacing 纯函数+版本化仓储+报告事实集，外部 task source 和展示模板走适配器。选用。

## 领域计算

`computeTaskPacing` 输出目标进度、时间进度、最近最多 7 个完整数据日均速、预计完成量/完成率、缺口、剩余完整日需日均、预算进度。日期统一 `YYYY-MM-DD`，`asOf` 代表已完整结算的数据日，剩余天数不含 asOf；节假日/大促等业务日历调整后续由调用方传入有效日序列，不在函数里猜。

不自动生成“加预算/降目标/挪量”结论：这些依赖账户容量和策略数据。

## 仓储

- TaskRepository：租户隔离查询任务、按有效期挂账户、拒绝同任务同账户重叠区间；
- AssessmentPriceRepository：正数校验、版本追加、按日期取生效版本，保留 changed_by/evidence_url；
- TaskMetricsRepository：按任务关系有效期聚合 canonical，返回任务日事实；
- DailyReportAssembler：组合任务 pacing、全局指标、异常计数、数据截至时间，输出稳定事实集，不渲染文案/PNG。

## 边界

- 启航 task_id 准确性未核验：Repository 接收外部 taskId，不负责来源；未来改自维护 ID 时接口形态保持；
- task_accounts 当前 UNIQUE 缺 workspace_id，查询和写入必须显式 workspace，并向 arch 提契约修正；
- 考核价改动后的通知/确认已读需 B2 通知契约；
- 报告 12 模块顺序、角色裁剪、知识库归档和钉钉模板待冻结；
- pacing 目前为日历天事实，业务日历/小时 pacing 后接。

## 验证

覆盖日期边界、零目标/零剩余日、7 日均速、超额完成；PostgreSQL 覆盖版本生效、租户隔离、区间重叠、任务日聚合；报告装配覆盖缺数据透明性。四包质量门禁继续执行。
