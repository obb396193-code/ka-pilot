# KA 投放经营平台产品设计 v0.2

> 日期：2026-08-14  
> 状态：产品讨论版，待老板、Claude、Codex共同评审  
> 用途：统一产品定位、对象边界、功能架构、页面结构和概念原型范围；不是已上线功能说明，也不是接口承诺。  
> 数据声明：文档和原型中的账户、人员、金额、任务、商品、素材和指标均使用虚构脱敏信息。

## 1. 产品定义

### 1.1 一句话定位

**以投放任务为中心，把数据、诊断、账户、商品素材、投放策略、工作流执行、协作和效果回收连成闭环的 KA 投放经营控制台。**

Agent 负责理解、分析和编排；确定性引擎负责计算、规则和状态；Multica/OS 负责受保护媒体能力的执行；人负责最终判断和写操作确认。

### 1.2 产品目标

- 优化师：早上 5 分钟完成日常巡检，减少手工导表、透视和逐户排查。
- 运营：围绕投放任务看到准备、执行、跑量、素材和阻塞情况。
- KA 负责人：看到团队经营、目标差距、渠道效率和需要协调的资源。
- 更高层：看到核心目标、业务风险、AI 提效和需要拍板的事项。
- 部门：沉淀可复用的指标、策略、工作流、报告和案例资产。

### 1.3 不做什么

- 不替代媒体投放后台。
- 不自建底层 BI 数仓，但建设供产品、Agent、报表和告警共用的投放语义层。
- 不把产品做成通用 Dify、n8n、Superset 或低代码平台。
- 不让 Agent 直接承担确定性指标计算和工作流状态管理。
- 不绕过媒体写操作的预览、确认、审计和对账。
- 不替代专业素材制作工具；产品负责选品、选素材、拆解、复刻方向、测试编排和效果回收。

## 2. 设计原则

1. **任务中心化**：任务是串联账户、策略、素材、预算、工作流、数据、待办和报告的主对象。
2. **行动优先于看数**：默认先告诉用户今天该处理什么，再提供完整分析。
3. **官方方案先用，用户能力逐层开放**：直接使用 → 保存个人视图 → 复制修改 → 高级自由搭建。
4. **同一内核，角色化首屏**：不是四套系统，而是同一数据和对象底座的四个默认入口。
5. **Agent 是全局能力，不是产品主页**：自然语言是入口，结构化资产和动作才是产物。
6. **投放策略与执行工作流分离**：策略决定怎么投，工作流负责把动作连续完成。
7. **写操作必须可预览、可确认、可追踪、可对账**。
8. **先做可信闭环，再做自由平台**：可靠执行和数据口径优先于空白画布。

## 3. 用户与默认入口

| 角色 | 默认入口 | 第一问题 | 核心动作 |
|---|---|---|---|
| 优化师 | 我的工作 | 今天哪些任务和账户最该处理 | 诊断、处理、确认、观察、复盘 |
| 运营 | 任务经营 | 哪些任务准备不足或目标有差距 | 配置任务、协调账户素材、派发工作 |
| KA 负责人 | 团队经营 | 哪些业务风险最高、资源该怎么调 | 派发、调整资源、查看效果回收 |
| 更高层 | 经营简报 | 目标进度怎样、哪些事需要拍板 | 看结论、看风险、看 AI 提效 |

用户可以切换视图或保存自己的首页，但首次进入不面对空白画布。

## 4. 核心对象模型

### 4.1 业务对象

| 对象 | 定义 | 关键关系 |
|---|---|---|
| 投放任务 | 一次业务目标或投放项目的经营主线 | 关联策略、账户、商品、素材、预算、工作流和报告 |
| 账户 | 媒体账户及其生命周期、容量、余额和归属 | 从属于或服务于一个或多个任务 |
| 广告对象 | 计划、广告组、广告、创意等媒体层对象 | 从属于账户和任务 |
| 商品 | 被测试、放量或淘汰的业务商品 | 关联任务、素材、账户和表现 |
| 素材 | 视频、图片、文案及拆解片段 | 关联商品、任务、广告和效果 |
| 投放策略 | 关于版位、投法、出价、RTA、预算、商品素材组合和阶段打法的业务方案 | 被任务选择，由工作流读取参数 |
| 工作流 | 对查数、开户、充值、基建、执行、等待、监控、推送和效果回收的可恢复执行图 | 被任务 SOP 或自动化规则调用 |
| 自动化规则 | 在满足数据和安全条件时触发工作流的规则 | 关联任务、对象选择器和已发布工作流版本 |
| 工作项 | 人或系统需要处理的一件事 | 来源于异常、派发、工作流或 Agent |
| 运行实例 | 一次工作流的真实运行 | 固定工作流版本、执行身份、输入、状态和证据 |
| 变更集 | 一次媒体写操作的具体前后差异 | 绑定目标快照、数据时间、确认人和有效期 |
| 报告/结算单 | 对任务、账户和周期结果的结构化输出 | 复用官方指标和字段模板 |

### 4.2 数据分析对象

```text
Entity（任务/账户/广告/商品/素材）
  → Metric（消耗/转化/实际成本/考核价/达成率）
  → Dimension（日期/渠道/负责人/阶段/版位）
  → Segment（冷启动/超成本/低消耗/起量）
  → Dataset View（面向场景的认证数据视图）
  → Question/Chart（一次查询和可视化）
  → Dashboard（多个分析组件）
  → Bookmark（个人筛选和分析状态）
```

普通用户和 Agent 只使用认证语义层，不直接拼接物理表或修改官方指标口径。

### 4.3 资产空间和生命周期

适用于报表、看板、策略、工作流、对象组和知识案例：

```text
个人草稿 → 团队共享 → 已验证 → 官方资产 → 已废弃
```

资产必须记录：

- 所有者与维护人；
- 来源：原创、复制或引用；
- 适用范围与不适用条件；
- 版本、变更说明和依赖；
- 最近验证时间；
- 使用人数和使用频次；
- 替代版本与废弃原因。

不同资产采用不同验证标准：

- 策略：样本量、成本、跑量和适用条件；
- 工作流：成功率、失败类型、恢复能力和效果回收；
- 报表：数据准确性、指标口径和刷新稳定性；
- 对象组：对象范围、动态/固定模式和权限有效性。

## 6. 功能设计

### 6.1 我的工作

- 今日待处理队列：对象、原因、证据、建议动作、截止时间、优先级。
- 待确认变更集：媒体写操作前后差异、影响范围和有效期。
- 运行中任务：开户、充值、基建、监控、报告等长流程阶段。
- 效果回收：执行前基线、观察窗、执行后变化、改善/无效/恶化。
- 快捷筛选：任务、账户、异常、优先级、来源、处理状态。
- 角色化概览：优化师看个人帮助，负责人看聚合阻塞，不做个人绩效排名。

### 6.2 投放任务

- 任务库：目标、预算、RTA、考核价、渠道、版位、阶段、负责人、账户数。
- 任务准备度：账户、充值、商品、素材、策略、基建、权限是否齐备。
- 目标差距树：消耗、量、成本、转化、账户、素材等差距来源。
- 任务 SOP：开户到监控工作流的业务阶段视图。
- 任务时间线：配置变更、策略版本、工作流运行、人工动作和效果回收。
- 任务对象组：固定快照与动态选择器分开。

### 6.3 数据分析

- 官方经营看板：优化师、任务、负责人和更高层默认视图。
- Explore：在认证数据视图上选择指标、维度、筛选和时间范围。
- Question/Chart：保存一次分析，供看板、告警、报告和 Agent 复用。
- Dashboard：官方、团队、个人看板。
- Bookmark：保存筛选和分析状态，避免复制大量相似看板。
- 自助报表设计器：高级模式下组合表格、趋势、透视、漏斗、分布和说明卡片。
- 查询保护：必填时间、数据量预估、粒度冲突、预览、超时、最大行数和异步查询。
- 数据健康：来源、刷新时间、覆盖率、缺失、补洞状态、口径版本和可用性。

### 6.4 投放策略中心

策略解决“这个任务应该怎么投”，包括：

- 广告版位与资源位；
- 投放方式、出价方式和 RTA 配置；
- 账户结构与预算分配；
- 起量、放量、稳定和衰退阶段打法；
- 商品、素材、人群和时段组合；
- 换品、换素材、换版位和停投条件；
- 历史相似任务表现和 Agent 建议。

策略页包含：

- 官方打法库、团队已验证策略、个人策略；
- 适用条件、不适用条件和数据证据；
- 策略版本比较；
- 绑定到投放任务；
- 运行后的真实结果回收；
- Agent 生成策略草稿和对比方案，不直接替用户拍板。

### 6.5 账户池

- 账户归属、状态、余额、预算、容量、生命周期和健康度。
- 可开户、待充值、待基建、冷启动、起量、稳定、衰退和异常账户池。
- 账户与任务匹配建议。
- 批量操作入口，但写操作必须进入变更集确认。
- 操作历史、冲突提示和执行后回查。

### 6.6 商品与素材

- 商品池：在测、可放量、起量、稳定、衰退、淘汰。
- 素材池：表现、生命周期、疲劳度、关联商品和账户。
- 素材拆解：前 3 秒、卖点、人物、场景、节奏、CTA 和镜头结构。
- 素材复刻：生成复刻方向、变体矩阵、测试任务和效果对比。
- 商品 × 素材组合分析。
- 相似素材、相似商品和跨任务复用建议。
- 不替代设计制作工具，负责方向、任务、素材资产和结果闭环。

### 6.7 自动化

自动化包含四个层次：

1. 原子能力：查数、计算、开户、充值、基建、改价、暂停、通知等。
2. 工作流：唯一可视化执行画布。
3. 自动化规则：定义何时、对谁、在什么边界下触发工作流。
4. 运行中心：状态、确认、重试、对账、效果回收和审计。

第一版节点控制在十类左右：

```text
手工/定时/事件触发
查询数据
确定性计算
筛选与条件分支
Agent 分析
生成变更集
人工确认
Multica 执行
等待与重新查数
待办/钉钉/报告
```

工作流状态：

```text
DRAFT → VALIDATED → TESTED → PUBLISHED → ACTIVE

CREATED → QUEUED → RUNNING → WAITING_CONFIRMATION
        → SUCCEEDED / PARTIAL_SUCCESS / FAILED / TIMED_OUT / UNKNOWN
```

可靠执行要求：

- 运行固定在启动时的工作流、节点、工具和指标版本；
- 工作流所有者、发起人、执行身份和确认人分开；
- 凭证只保存引用，不写入流程定义；
- 查数、AI、媒体写和创建类节点使用不同重试规则；
- Multica 异步执行出现 UNKNOWN 时先对账，禁止盲目重发；
- 对账户和广告对象增加写操作冲突锁；
- 服务重启后能够恢复等待和长运行实例；
- 用户确认的是具体变更集，不是抽象的“执行工作流”。

自动化规则需要解释“为什么没有触发”：

- 数据未刷新；
- 样本不足；
- 正在冷却；
- 达到每日调整上限；
- 与其他写操作冲突；
- 权限不足；
- 等待确认。

### 6.8 报告与结算

- 日报、周报、月报、任务复盘和管理简报。
- 月度结算单：按期次模板选择字段，自动取数和校验。
- 模板版本管理：不同月份字段变化不覆盖旧结算单。
- 生成前检查缺失字段、口径和数据时间。
- 导出、定时生成、钉钉推送和证据快照。
- Agent 可以生成叙述、异常解释和会议摘要，数字来自确定性数据层。

### 6.9 Agent

统一使用一个产品内 Agent Runtime；默认 Claude，模型通过 CCSwitch 类网关配置，不建设多个运行时。

四种触发形态：

- 后台 Agent：摘要、归因、运行监控和异常聚合。
- 全局 Agent 抽屉：跨对象复杂任务。
- 页面/表内助手：自动携带页面、筛选和选中对象。
- 创建助手：生成策略、报表和工作流草稿。

上下文优先级：

```text
用户明确选择对象
→ 当前表格选中行
→ 当前筛选范围
→ 当前页面对象
→ 当前对话历史
→ Agent 自主搜索
```

同一对话保留上下文；新建对话默认清空。每次查询、分享和执行重新鉴权。

Agent 输出采用“结论—证据—动作”结构，并展示：

- 对象范围和时间范围；
- 数据模式：实时引用或固定证据快照；
- 使用的指标、数据视图和查询依据；
- 哪些是确定性计算，哪些是模型推断；
- 可检查的报表配置、工作流草稿或变更集 Patch；
- 全部接受、局部接受、拒绝和回滚。

### 6.10 钉钉消息网关

独立部署消息网关 FaaS：

```text
钉钉 Stream
→ 消息接收
→ 身份映射
→ 意图与卡片事件路由
→ 产品业务 API / 工作流引擎
→ 必要时调用 Multica
→ 模板渲染
→ 推送、更新和重试
```

暂不设计群数据范围治理；本版只定义产品能力和交互模式。

卡片动作分级：

| 级别 | 示例 | 卡片行为 |
|---|---|---|
| L0 只读 | 查数、刷新、生成报告 | 点击直接运行 |
| L1 低风险 | 创建待办、静默告警、保存草稿 | 卡片确认后运行 |
| L2 媒体写 | 改价、改预算、暂停、基建 | 卡片展示变更集，确认后运行 |
| L3 高影响 | 大批量关停、大额预算调整 | 卡片看摘要，跳 Web 查看完整明细后确认 |

按钮回调必须校验用户、权限、状态、有效期、变更集 Hash 和幂等键；对象或参数变化后原确认失效。

## 8. 权限、可信与治理

权限采用“主体—资源—关系—动作”模型：

- 主体：用户、组织组、服务身份；
- 资源：任务、账户、数据视图、报表、策略、工作流、运行、对话和对象组；
- 关系：负责人、协作者、查看者、编辑者；
- 动作：查看、编辑、发布、执行、确认、重试、分享和查看原始日志。

审计分层：

1. 业务动作账本；
2. 工作流节点运行记录；
3. Agent Trace；
4. 受限查看的原始 OS 日志。

媒体写操作补齐：目标快照、前后 Diff、影响范围、批量上限、幂等、冲突锁、紧急停止、执行后回查、可逆回滚或不可逆补偿。

## 10. 视觉与交互方向

- 桌面端 16:10，企业级高密度工作台，不做聊天框首页。
- 白色/极浅冷灰底，深海军蓝文字，电光蓝主色，青绿色成功，琥珀色风险，珊瑚红异常。
- 左侧紧凑一级导航，顶部全局对象与时间筛选，主体使用 12 栏网格。
- 信息层级：结论与动作优先，图表和证据其次，底层日志按需展开。
- 卡片边框轻、阴影弱、圆角克制；避免大面积渐变、玻璃拟态和装饰性插画。
- 表格支持冻结、密度切换、行内趋势、批量选择、右侧上下文抽屉。
- Agent 使用右侧抽屉或浮动入口，不抢占主工作区。
- 所有写操作先形成可阅读的变更集，再出现确认按钮。

## 11. 分阶段范围

### P0：核心闭环

```text
今日待处理
→ 查看异常证据
→ 表内 Agent 分析
→ 形成操作预览
→ 确认执行
→ Multica 执行与对账
→ T+1 效果回收
```

同时完成：任务库、官方指标和数据视图、数据健康、操作账本、角色化首页、首批官方工作流模板、钉钉查询和卡片确认。

### P1：个人与团队生产力

- 个人视图和自助报表；
- 复制官方工作流和 Agent 辅助编排；
- 账户池、商品素材、策略资产；
- 报告与结算单；
- 运营任务经营和负责人会议简报；
- 公共资产审核与版本。

### P2：验证后平台化

- 完整自由工作流画布；
- 完整自助 BI 布局器；
- 大规模公共资产池；
- 自动策略规模运行；
- 素材拆片、复刻谱系和跨渠道统一；
- 必要时引入更强的持久执行底座。

## 12. 成功指标

- 优化师每日主动打开并完成一次核心闭环；
- 早巡检耗时从 1—2 小时下降到 5—15 分钟；
- 异常从发现到处理的平均时间下降；
- 媒体写操作有完整预览、确认、执行和效果证据；
- 官方指标与现有可信来源保持一致；
- 同一工作流和策略能被不同任务复用；
- 产品使用数据用于改进产品，不形成个人绩效排行榜。
