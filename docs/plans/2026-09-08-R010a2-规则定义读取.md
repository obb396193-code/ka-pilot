# 规则定义读取 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 从真实alert_rules读取指定账户/日期的规则定义及适用性，为explain提供可信的定义来源。

**Architecture:** 复用AUTH判别上下文和v1.9 scope Schema；个人先tuple grant、团队workspace readonly；RR/RO内查询规则+同账户有效task_accounts，union匹配冻结三类scope。内部ruleId保留BIGINT字符串；只输出显式字段，不把无condition_tree或非法scope变成默认规则。

**Tech Stack:** TypeScript/PostgreSQL/Zod已有Domain/Vitest。executing-plans不可用，按此计划本地逐项TDD；Coze远程导流超出本项目授权，不上传。

---

### Task 1：Domain内部目标及计划

Create `packages/domain/src/rule-definition.ts` / `test/rule-definition.test.ts`；新增内部strict目标(ruleId/media/accountId/ds)与定义字段校验，scope复用be2的alertRuleScopeSchema而不改其文件；新增conditionReadRequests纯规划入口复用parseTree，只有非null条件树才校验；未知树保留null。新导出仅追加本人index块。

### Task 2：Repository（先RED再实现）

Create `packages/db/src/rule-definition-repository.ts` / `test/rule-definition-repository.unit.test.ts`。read(auth,target)先校验与授权再connect，BEGIN RR/RO+固定statement_timeout；SELECT规则白名单/字节计数（exact16MiB拒绝，不传超大payload）；WHERE workspace/id，LIMIT2防异常；第二查询账户存在及有效task/biz union，所有参数绑定，日期含首尾。缺规则null，缺账户/越权typed error；commit前再验证输出，失败rollback/release。无真实指标/判真/写入/HTTP。

### Task 3：真实PG与交审

Create `packages/db/test/rule-definition-repository.test.ts`，显式localhost55432 ka_*_test：全局/tuple/任务/业务名、前后生效日期、同ID跨媒体/空间、空grant、team、非法scope、缺树、不存在、大ID；合成fixture局部清理。Domain全量/DB定向真实PG+unit/type/lint/Worker类型与规则回归；磁盘允许范围内门禁，独立SHA和P143报告。

**后续不是本批完成项：** 指标、freshness/readiness、mute/dedup、公开explain/BFF及生产扫描provider；此读取只证明规则定义与作用范围，不推断已触发或数据新鲜。后续组合指标时必须将定义与指标放同一个RR快照，不把两次独立read当同快照。
