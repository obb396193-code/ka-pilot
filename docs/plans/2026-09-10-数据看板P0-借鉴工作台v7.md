# 数据看板 P0（借鉴同事「快手投放账户工作台 v7」的优化师视角）— arch 2026-09-10

老板拍板：**P0 最高优先**——先让「数据分析」能按优化师视角看出数据，覆盖 v7 已做的三块（数据概览 / 任务管理 / 标签定义）的功能，架构不抄（我们是 PG + 契约 + BFF，不是 Flask/SQLite）。

## 0. 老板三问的答案
1. **两条取数路**：团队空间 = ka-data（`dwd_account_daily` 等，经 `/api/query`）；个人空间 = 启航授权账户（`account_realtime`/`queryDataReport`）。两条都落成同一套账户×天事实 + 账户维度。
2. **账户昵称 → 维度**：每个账户带 `account_id` + `account_name`；治理后台「归属清洗」按媒体的命名规则把昵称切段（优化师/业务/资源位/版位/转化目标…），进 `account_dimensions`，数据分析的交叉表和日报的维度模块就按这些切。**快手规则 v1 已做**（seed 灌了、归属清洗页能编辑/干跑/重解析）；**腾讯规则 v1 草案**见 `2026-09-10-腾讯账户昵称清洗规则v1草案.md`（两处待优化师确认）。
3. **在哪看**：个人 / 团队用左下角空间切换；数据分析页 = 大盘 + 交叉表；账户池 = 单账户。**缺的是 v7 那种「优化师 → 任务大类 → 细分 → 账户」的钻取视角和两行 KPI**，这就是本批。

## 2. 派单
- **Codex P-210（数据 API）**：① `dimension_type` 加 `optimizer|goal|placement`；② `filters` 加 `optimizer|biz|resource_position|goal`（多值数组）；③ summary 加 `bi_conv`（考核 BI 数）、`bi_cash_cost`（现金花费/考核BI数）、`over_cost`（现金花费 − Σ 当日考核BI数×当日生效考核价；正=超）；④ `GET /api/v1/data/filters?window_from&window_to&media&optimizer[]&biz[]` 回 cost>0 的级联选项（下游随上游收窄）；⑤ fixtures：`data-query/summary-v1922.json`、`data-query/dimension-optimizer.json`、`data-query/filters.json`。排在 F-OS-004 之后、024 之前（P0）。
- **be2 Q-039（清洗闭环）**：① 规则段加 `anchor`（锚点：命中该段后其余段按相对位置）与 `matchLongest`（enum 最长别名命中）；② `GET /admin/account-names` 每行带 `parsed`（各段值）、`failedSegments[]`、`raw`（原昵称），status=partial/failed 的能直接给 fe 做「未归属样例」；③ `PUT naming-rules` 后自动干跑本空间全部昵称回命中率。排 Q-037 之后（P0）。
- **fe F8-19（概览优化师视角）**：两行 KPI + 环比、趋势双轴、任务大类表现（展开细分）、优化师三级钻取（BI 按消耗占比分摊）、资源位环图。契约 fixtures 先行（v1.9.22），后端未到用 fixture 先做页。
- **fe F8-20（筛选与导出）**：月历区间 + chips、级联多选（`/data/filters`）、账户 ID 多值、CSV 导出、骨架屏 + stale-while-revalidate。
- **fe F8-21（清洗闭环 UI）**：归属清洗 tab：未归属样例列表 → 点样例的某一段加进规则对应段的别名 → 干跑命中率 → 重解析；腾讯规则可选媒体 TENCENT。
- 序：fe F8-15 ⑥⑦（1 小时的活）→ **F8-19 → F8-20 → F8-21**；Codex F-OS-004 → **P-210** → 024；be2 Q-037 → **Q-038 → Q-039**。
