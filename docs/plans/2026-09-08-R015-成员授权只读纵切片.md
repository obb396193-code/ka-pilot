# Admin member access read Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 接通当前空间成员和成员授权两条真实GET，不暴露跨空间身份档案或凭证。

**Architecture:** Domain strict schema复用arch成员/授权fixture；DB同RR/RO读取membership、identity和当前workspace session时间，team分支不查grants；Service再次核对workspace和目标identity。主HTTP使用既有Session+bearer，BFF直接导入schema；admin权限前置，未知query/写方法拒绝，exact16MiB。

**Tech Stack:** Zod / pg / Node HTTP / Next BFF / Vitest。

---

1. `packages/domain/src/admin-members.ts` + `test/admin-members.test.ts`：先以缺模块RED验证fixture；严格日期/UUID/字段/重复，成员1000和grants1000哨兵；meta未知时间null。
2. `packages/db/src/admin-members-repository.ts` + unit/PG：当前workspace参数化查询，member/目标identity不在本workspace返回NOT_FOUND；join user必须带workspace；isActive取membership配置，不冒充整个登录链状态；grantsCount是本空间存储授权计数，team固定0且授权列表空。只读显式列，不读subject/Secret/token_hash。joinedAt按上海日期格式化真实created_at；lastSeenAt只取当前绑定本workspace的Session最大真实last_seen_at，不用全局最后登录。
3. `apps/worker/src/admin/members-service.ts`、`r010/admin-members-routes.ts`、http/data-api注册：GET两个端点；admin前置，严格输出scope，安全错误；新增HTTP与实际PG反例包括外空间同identity/team忽略grant/空/撤销/错误/溢出。
4. `apps/web/lib/data/admin-members-{bff,server}.ts` 和两个Next GET：只服务端origin/token+session；无浏览器scope；共享Domain响应，不手抄。
5. 定向测试/覆盖、三包type/lint、新BFF定向type/lint；磁盘<8GiB按规则不跑全量。质量报告和P151回执，代码/文档独立SHA。没有executing-plans技能则本人TDD，不另开agent或上传外部平台。

公共成员创建/改权/停用以及团队管理写接口不是本批内容，仍保留总目标。GET只在当前workspace管理，不擅自引入全局管理员跨个人空间浏览。
