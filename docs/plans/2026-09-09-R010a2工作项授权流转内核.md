# Authorized Work Item Transition Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 为已冻结开始处理/忽略/拒绝语义补 Session 授权、事务锁和审计内核，不开放 HTTP 或媒体写。

**Architecture:** 新内部 command schema，只接受 workItemId/action/reason。Repository 从锁内工作项取实际三键，以 ApprovedWorkspaceAuthContext 及数据库有效成员/身份/账户授权双重校验，再更新状态并同事务写 audit_log。旧内部 transition 不替换；新网络入口将来只能接安全方法。

**Tech Stack:** existing Domain state machine, Zod, node-postgres, Vitest, synthetic PostgreSQL.

## Task 1: Domain command

创建 `packages/domain/src/work-item-command.ts` 与对应 test，末尾be export。
先写失败测试：strict discriminated request，action 只含 start_processing/ignore/reject；reject 必须非空 reason，禁止输入workspace/media/account/user或mute参数。result仅内部状态回执，不代替未收口公开fixture。
执行 `npx vitest run test/work-item-command.test.ts`，先缺模块红，再实现。

## Task 2: Repository

新 `packages/db/src/work-item-command-repository.ts`、`test/work-item-command-repository.test.ts`；不改be2文件。
`apply(auth, command)`：personal且显式scope非空→BEGIN短事务→FOR UPDATE真实工作项→批准tuple→FOR SHARE活跃workspace/user/member/identity/grant/account→assertWorkItemTransition→UPDATE状态及原因→INSERT审计→COMMIT。
team/无账户项先拒绝，不把“个人无账户可读”外推为可写。派发/升级需收件人和通知，暂不以状态替换冒充完成。
失败固定typed code；不在返回/日志夹带SQL、上游body、凭证。事务失败ROLLBACK，成功路径不碰媒体、queue或account_mutes。
