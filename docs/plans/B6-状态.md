## 三种推进方式

### 方案 A：全部停止等 Claude

- 优点：不会扩大待审代码量。
- 缺点：语义层、日报事实和 Agent 内核已经具备，完全停工会浪费现有安全开发空间。
- 判断：不推荐。

### 方案 B：继续 B6 契约安全内核（推荐）

只实现可替换内部能力：

- 对已有语义查询结果做报表组件数据装配的纯函数；
- 表格、KPI、趋势、柱状等组件的输入校验和缺数状态；
- Gap 对账与样本量护栏；
- Agent 生成“内部报表草稿”后的安全校验、证据引用和降级；
- 报表生成 Worker 的内部端口、幂等与失败留痕测试。

明确不做：公开 DTO、Schema 迁移、共享/官方资产权限、schedule 语义、真实 PNG/PDF/钉钉发送、缺失维度策略结论。

### 方案 C：只做整合与质量加固

- 重新跑 B1a-B5 全量测试、迁移和安全扫描；整理 merge/review bundle。
- 风险最低，但新增业务价值有限，而且最终整合仍需 Claude/arch。
- 判断：适合作为 B6 内核完成后的收尾，不适合代替 B6。

## 当前建议

选择方案 B，继续到 B6 的“内部报表与分析内核”完成后停在公开契约之前。B7 工作流、真实 OS/Multica 和 Web/SSE 集成不应在 Claude 未裁决时继续扩张。
