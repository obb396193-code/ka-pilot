# 旧 PRD（AdAgent 源头版）借鉴笔记

> 2026-08-18。来源：老板提供的历史 PRD（2024-05 团队模拟会议版，AdAgent/R001-R010 规则的源头）。
> 处理原则：只淘可借鉴的，过时部分（外部 SaaS 定位/商业化/裂变/Excel 上传主路径/低代码方案）全部过滤。
> 以下 9 条为 v2.1 未覆盖或未写细的增量，开发时并入对应模块。

## 采纳清单

1. **原因子类→建议映射表**（并入规则引擎/诊断）：每类异常按原因细分并各配建议——超成本的子类：点击率下降(环比>20%)→测新素材｜转化率下降→查落地页/定向｜竞争加剧(同类成本升>10%且自身出价未变)→适度提价或错峰｜定向过窄(展现降+成本升)→放宽。不起量子类：出价低/预算少/素材差/定向窄/版位差，各配建议。这套"子类字典"是 Agent 诊断 JSON 里 possible_reasons 的现成枚举。

2. **欠成本诊断**（新规则）：转化成本 < 目标×(1-阈值) 且量足——**不是好事，可能出价过低拿量困难**。与"优质潜力"区分：优质=成本低+量在涨；欠成本=成本低+量上不去。补进规则库。

3. **LLM 建议安全约束**（并入 Agent 输出规范）：硬约束写进 prompt+出口校验——**建议出价调整幅度≤20%、预算调整≤50%**，防大模型生成极端建议。与自治度滑块互补（滑块管执行权，这条管建议本身的边界）。

4. **大模型降级方案**（并入值守设计）：LLM 调用失败/超时/格式错 → 降级展示规则引擎预设的通用建议话术，不留空白。每条规则配一句"解释话术"兜底（R001 式："新计划探索期超成本，样本不足建议止损"）。

5. **ETL 剔除零消耗日**（并入 ETL 工程细则）：算均值/环比时剔除因新建或暂停导致的零消耗日，防基线被拉歪。

6. **跨账户对比基准的统计口径**（并入跨账户模式识别）：基准=按消耗**加权中位数**或分位数（防大户拉偏）；**日消耗<100 元的账户不参与对比**（标"数据不足"）；对比框架用分位数（前 20%/均值/后 20%）。

7. **双层标签体系+组合筛选**（并入账户池）：自动标签（阶段/效果/风险，系统打）+人工标签（测试/业务/优先级，用户打）；价值在**组合筛选**——例："衰退期+优质账户"=需要抢救的好户。

8. **时段质量规则**（规则库候选）：凌晨消耗占比>40% 且凌晨转化质量<白天 50% → 建议收缩时段。配合 hh 小时数据可实现。

9. **建议幅度的预期效果附注**（并入 What-if 预演）：每条建议附"预计成本降至 X"——用统计（历史弹性）算，不用 LLM 算，与既有铁律一致。

## 二次重读补捞（2026-08-18，老板重发全文后）

10. **起量期样本量规则**：新计划前 3 天成本允许 ±50% 波动；超支<50% 且转化<10 →"样本不足，观察至 20 个转化再判断"；超支>50% 且转化>10 → 才判异常。**给冷启动阈值联动（优化师路#12）补上了具体数字**。

11. **异常检测算法选型**：消耗突降用 3-sigma（历史 7 天基线）、成本突增用 EWMA（指数加权移动平均）。给"统计基线异常检测"（v2 已有）的具体实现候选。

12. **数据异常预警**：单日消耗 > 历史均值 5 倍 → 标"数据异常"（可能是回传/录入错误），**标记不删除**——并入数据健康模块。

13. **提示词知识库三层架构**：系统角色定义（固定）→ 场景化模板（按异常类型，含分析步骤）→ 动态数据注入（模板引擎填实时数据）。这就是我们 Agent 诊断 prompt 的组织方式，与 Devix 文章的诊断 Skill 模式互补。
