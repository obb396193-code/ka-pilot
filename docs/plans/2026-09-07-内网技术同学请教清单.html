怎么开这个会

顺序是有意的：先让对方进入语境，再问，最后留时间捡盲点。

  1. 先给 3 分钟背景，别让对方猜。一句话定位 + 一条主流程 + 一张页面截图。

    「给投放优化师做的经营助手——把启航和 BI 的数据拉进自有库，算成本达标和差距，给出建议和一键操作，人确认后再写回媒体。全站页面已铺完、后端在接接口，现在卡在部署和身份权限。」

  2. 带着「我们已经实测过什么」去。对方不用从零解释，省一半时间。清单在本页最后。
  3. 问「你们怎么做的」，不是「能不能帮我们做」。前者拿到方案，后者拿到「排期再说」。
  4. 每个问题都要落到三样之一：文档链接、具体人名、一句可执行的结论。当场记在下面的框里。
  5. 按 A → F 顺序走。A 组是命门，问不完不要往下。
  6. 最后 5 分钟问盲点：我们哪里做错了、有没有别的团队在做同样的事。
  7. A1 是全场最重要的一个问题。他答不了就追问「该问谁」，拿到人名也算成功。
A 组 · 命门

部署与数据库

实测：FaaS 出网只开 443，5432 和 3306 全被过滤，连不上沙箱里的 PostgreSQL，也连不上公网 RDS。已查证：RDS 申请入口是 CloudCenter 不是 Normandy，必须归属一个 AONE 应用加云账号；走 aone-platform 建应用能一步拿到 AONE 应用和带产品名的域名，建应用与发 daily 无外部审批。所以下面只问还没答案的。

B 组

身份、多租户与数据权限

内测用自建账号密码，正式要接 BUC。更麻烦的是数据范围：FaaS 里没有用户身份注入，现在只能在配置里写死一个人的启航 userId，所有人看到同一份数据。

C 组

数据源

团队版数据全靠 ka-data；它没有版本号，近三天的日期每天重建，我们只能靠每行的构建时间戳猜批次。

D 组

工作流与 Agent

对方的强项，这组是取经。我们自己做了：可视化画布 + 十类节点 + 版本发布 + 运行实例 + 人工确认门 + 失败重试 + 未知结果人工核查。

E 组

写链路与合规

我们把「预检 → 确认 → 执行」三段自己做了一遍，想知道公司有没有现成的。

G 组

发布与上线流程

已知：建应用和发 daily 无外部审批；发预发要变更单加流水线；发正式门禁最严，可能人工审批加发布窗口。这组问细节，部署时要用。

F 组

组织与先例

性价比最高的一组，留在最后 5 分钟问。

我们能给对方什么

别只索取，这几样他们未必系统测过。
