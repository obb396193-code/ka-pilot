# R010 静音与试运行 BFF Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> 子技能不可用，按用户长期目标授权本地执行。

**Goal:** 为已接主服务的静音、ignore+mute、source-off dry-run提供浏览器同源POST适配；不改页面、组件或媒体执行。

**Architecture:** 固定三种路径与strict request/response；复用内部API的配置、cookie、Headers、requestId与16MiB响应读取。新变更入口要求同origin+JSON并拒cross-site Fetch Metadata；浏览器不能传服务令牌/scope，服务端只注入批准cookie+token。无重试，传输失败不声称回滚。

**Tech Stack:** Next Route Handler、TypeScript、Zod、node:test、Worker Vitest/PG。

### Task 1：RED

- 新 `apps/web/lib/data/r010-command-bff.test.ts`：三路径、严格body、CSRF、cookie、header隔离、状态/envelope/requestId、UTF8请求限制、exact16MiB、超时、上游原文隐藏。
- `node --test lib/data/r010-command-bff.test.ts` 应在实现前因缺模块失败。

### Task 2：实现

- 新 `r010-command-contracts.ts` 镜像已冻静音schema（永久Domain parity测试），错误码扩NOT_FOUND/INVALID_STATE/FROM_VALUE_CHANGED；dry-run成功态当前不可映射，不把旧record当成功。

- 新 `r010-command-server.ts` server-only wrapper及三条Next route；不新增确认/执行路由。
