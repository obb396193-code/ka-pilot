# B16 素材相似度与复刻谱系领域底座设计

> 日期：2026-08-21
> 状态：基于已冻结 PRD 的内部实现设计
> 产品依据：PRD 3.16 `REQ-052`、验收基线 6.3/6.6；老板已明确要求“拆片 + 相似查找 + 复刻谱系”
> 边界：只做 `packages/domain` 纯函数，不冻结公开 API、数据库、任务、页面或 Embedding Provider

## 1. 要解决的问题

B15 已把素材拆成可校验的钩子、卖点、人群、节奏、CTA 和语义段。下一步需要把这些结果变成：

1. 可稳定索引的相似度画像；
2. 可解释的两两相似度结果；
3. 明确记录“谁复刻自谁”的谱系边；
4. 在证据不足时拒绝伪造一个看似精确的相似度分数。

“内容相似”与“复刻关系”不是一回事：相似度是计算结果，复刻谱系是用户或系统明确记录的事实关系。两者必须分开。

## 2. 方案比较

### A. 结构化字段确定性评分（本批采用）

- 输入只来自已经校验的 B15 拆片结果和视觉摘要；
- 钩子类型、语义段角色序列、卖点、人群、节奏、CTA 分项比较；
- 文本用面向中英文的稳定字符 n-gram 集合，不依赖外部分词服务；
- 输出分项得分、实际参与权重、缺失项和解释；
- 输入相同则画像和结果指纹相同。

优点：可复现、低成本、可离线测试、不受模型漂移影响。缺点：对同义改写的识别弱于语义向量。

### B. 纯 Embedding 相似度（本批不选）

语义召回更好，但需要冻结模型、数据外发、成本、版本、向量库和重算策略；目前会跨越 Claude/架构契约边界。

### C. 确定性召回 + Embedding 重排（后续推荐）

长期效果最好：先用 A 低成本召回候选，再在受信任 Provider 边界内重排。本批先把 A 做成可作为 fallback 和基准线的领域能力。

## 3. 相似度画像

画像版本独立于拆片 Schema 版本。画像包含：

- `materialVersionId`：素材版本的稳定内部标识；
- `teardownFingerprint`：绑定具体拆片产物，防止静默漂移；
- `profileVersion` 与画像 `fingerprint`；
- `hookKind`；
- 有序的 `semanticRoleSequence`；
- 卖点、人群、节奏、CTA 的规范化 token 集；
- 视觉节奏的确定性值：平均镜头长度、Hook 视觉密度、硬切密度。

画像不放消耗、转化率、GMV、账户或投放人。内容相似度不能偷渡效果评价，也不能把公司业务数据变成索引特征。

## 4. 可解释评分

固定六个组件：

| 组件 | 默认权重 | 算法 |
|---|---:|---|
| 结构 | 0.20 | 语义角色序列的顺序相似度 |
| 钩子 | 0.15 | 类型相同为 1，不同为 0 |
| 卖点 | 0.25 | 文本 token Jaccard |
| 人群 | 0.10 | 文本 token Jaccard |
| 节奏 | 0.20 | 文本节奏 + 镜头长度/密度数值相似度 |
| CTA | 0.10 | 文本 token Jaccard |

规则：

- 组件两侧都有可比较信息才参与；缺失组件不计 0，而是从分母移除并在 `missingComponents` 中展示；
- 至少三个组件且参与原始权重不少于 0.50，才输出 `scored`；否则输出 `insufficient_evidence`，不提供总分；
- 总分是参与组件的加权平均，保留四位小数；
- 每个组件返回原始权重、是否参与、得分和稳定解释码；
- 相同素材版本与相同画像指纹直接得 1，但仍返回完整分项，不走隐藏捷径。

这套分数只表达“内容结构相似”，不表达素材质量、跑量概率或复刻价值。

## 5. 复刻谱系

谱系边是不可变事实，包含：

- `sourceMaterialVersionId` / `derivedMaterialVersionId`；
- `method`：`script_rewrite`、`structure_adaptation`、`visual_remake`、`mixed`；
- `sourceTeardownFingerprint`：记录复刻决策所依据的源分析版本；
- `createdByUserId`、`createdAt`；
- 可选的 `note`；
- 稳定 `fingerprint`。

禁止：自己复刻自己、非法/空标识、未来时间、伪造 SHA、未知字段。领域对象深冻结。数据库将来应以该 fingerprint 或业务组合键防重复，但本批不替契约方决定表结构。

## 6. 错误与安全边界

- 对外只抛稳定错误码：`invalid_profile`、`invalid_comparison`、`invalid_lineage`；
- 不在错误信息回显原始文稿、素材标识或业务数据；
- 限制文本长度、token 数、语义段数量和数组规模，防止大输入拖垮同步路径；
- 所有结果深冻结；任何 fingerprint 都使用字段顺序固定的 canonical JSON。

## 7. 本批不做

- 向量模型、向量库、模型重排；
- 相似素材列表的数据库查询和分页；
- 素材上传、自动生成、自动投放；
- “跑得好所以相似”的效果归因；
- 公开 API/Contract、migration、Job、前端页面；
- 自动认定复刻关系。谱系必须由明确操作或可审计流程创建。

## 8. 验收

1. 同一内容键序变化不改变画像/比较指纹；语义段顺序变化会改变结构分；
2. 中文同段文本、部分重合、完全不同有单调结果；
3. 缠绕缺失数据时返回 `insufficient_evidence` 而非 0 分；
4. 评分解释可直接支撑以后页面展示“钩子相同/卖点部分相似/节奏不同”；
5. 谱系拒绝自环、非法 SHA、未来时间和非法标识；
6. Domain 全量测试、typecheck、lint、coverage 与复杂度门禁通过。
