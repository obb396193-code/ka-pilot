# P192 Work Item List Authorization Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 按 arch v1.9.11 让工作项列表使用 Q027 共享矩阵，并保持输出侧 scope 守卫。

**Architecture:** count/page 同一 RR/RO snapshot 引用 workItemScopeClause。任务型行额外投影内部 taskScopeAccount（同 workspace/task 的一个真实获授 tuple），Service 用它校验非本人任务型行；证据不进入公开 DTO。账户型不能用本人分支绕过 tuple，团队保留任务型但排除纯私人项。详情另交独立批次。

**Tech Stack:** TypeScript, PostgreSQL, Vitest, existing shared authority helpers.

---

### Task 1: 先红测试

Files: `packages/db/test/work-item-list-repository.test.ts`、`apps/worker/test/work-item-list-service.test.ts`。
1. 真 PG 加同号跨媒体/跨 workspace、授权任务、仅本人任务、无授权任务、空 grant、team 排私人和分页反例。
2. Service 加内部 tuple 证据通过/跨媒体拒绝、team 任务可见/私人不可见。
3. Run: 在 `packages/db` 运行 `npm test -- --run test/work-item-list-repository.test.ts`（TEST_DATABASE_URL 为独占本机合成库）；在 `apps/worker` 运行 `npm test -- --run test/work-item-list-service.test.ts`。本仓根不是 npm workspaces，命令必须在各包执行；旧实现应红。

### Task 2: 最小共享接线

Files: `packages/db/src/work-item-list-sql.ts`、`work-item-list-repository.ts`、`apps/worker/src/work-items/work-item-list-service.ts`。
1. CTE 使用 `workItemScopeClause("$3", "$4", "item", "$2")`，额外拒绝半空 tuple；count/page 不另写权限矩阵。
2. 同查询 LATERAL 限定 workspace/task + personal + shared accountScopeClause，稳定 C 排序 LIMIT 1 返回 task_scope_media/task_scope_account_id；不是新公开字段。
3. Repository 映射成 `taskScopeAccount: {media,accountId}|null`，非法/半空证据拒绝；Service 验证授权 tuple，最终 itemFor 不输出证据。
4. 更新旧 SQL 字面测试为共享 helper 断言，更新内部 fixture 的显式 null。
