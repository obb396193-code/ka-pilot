# 新 UI 来源入库与实时预览展厅设计

> 日期：2026-08-19
> 状态：老板已选择 A 方案并确认实施顺序

## 目标

先把 Vercel AI Elements、Kibo UI、Dice UI、Animate UI、Motion Primitives 的官方能力、规范、许可证和高频公开源码准备完整，再为整个 UI 资产体系制作一组真正可操作的离线实时预览。完成后 UI 资产准备阶段收工，交前端 Agent 按页面选择和适配。

## 老板确认的范围

- 不追求把 5,996 条既有目录和所有新增条目全部编译运行。
- 每家官方来源挑 1–3 个最能表现自身特性的公开组件或组合，能点击、输入、切换、展开，不用截图冒充运行效果。
- 付费源码、仅元数据、会员墙和无法合法取得源码的条目不渲染，继续显示目录、权限和免费替代。
- 先完成五库正式入库，再实现实时预览；不与前端当前 F-001R 页面改动混在一起。

## 方案比较

### A. 高频代表组件离线实时预览（已选）

为每个来源挑代表能力，使用官方源码和本地依赖预编译成静态 bundle，由展厅在 sandboxed iframe 中运行。

优点：能真实操作、完全离线、加载体积可控、能跨来源对比。缺点：需要维护精选清单和构建兼容层，不能覆盖所有目录项。

### B. 全部公开源码实时渲染（未选）

为所有公开目录项建立运行环境。覆盖面最大，但会带来上千条构建、Radix/Base/Motion/Tailwind 多版本冲突、巨大体积和持续升级成本，不适合本项目。

### C. 在线嵌入官网（未选）

直接 iframe 官方页面。开发最快，但很多官网禁止嵌入，离线失效，页面改版不可控，也不能证明本地源码可用。

## 实施顺序

### 阶段 1：五库正式入库

1. 从官方 Registry、文档和仓库抓取完整能力目录；每个条目保留官方 URL、预览、源码入口、依赖、许可证、访问层级和核验日期。
2. AI Elements、Kibo、Dice 建正式 catalog 和官方使用/主题/修改/可访问性指南。
3. Animate UI、Motion Primitives 建完整能力索引与许可证边界，但只把少量代表源码加入高频缓存。
4. 更新 source health、catalog index、capability index、coverage、showroom、Obsidian 和 Agent 入口。
5. 高频源码只缓存公开且合法取得的官方源码；不触碰 `apps/web` 运行时。

### 阶段 2：离线实时预览

建立 `docs/frontend/ui-assets/live-previews/`：

```text
live-previews/
  manifest.json
  README.md
  frames/
    <preview-id>/
      index.html
      preview.js
      preview.css
```

每个 frame 是已经编译的 classic/IIFE JavaScript 和本地 CSS，不含 CDN、远程字体、ES module import 或运行时 fetch。展厅只加载相对路径，并使用 `sandbox="allow-scripts"` 隔离，禁止预览组件导航主页面或访问展厅数据。

## 代表能力选择

目标总量约 25–40 个，不以凑数为目标：

| 来源 | 代表能力方向 |
|---|---|
| shadcn | Sidebar/Sheet、基础表格或 dashboard 结构 |
| coss current | Date Picker、Command/Combobox、Drawer/Field 细节 |
| coss Origin | 仅展示 current 没有且仍有参考价值的 legacy 能力 |
| ReUI | Data Grid、Filters/列配置 |
| Tremor | KPI、Filter Bar、图表/报告组合 |
| Aceternity | Bento、Spotlight/背景效果 |
| Magic UI | Number Ticker、Marquee、Border Beam |
| React Bits | Counter/Text、轻背景或卡片动效 |
| tweakcn | 同一组件即时切换 3–5 个代表主题 |
| AI Elements | Conversation/Message、Prompt Input、Reasoning/Tool/Sources |
| Kibo UI | Gantt、Kanban、Editor/Dropzone 中可稳定编译的代表项 |
| Dice UI | Data Grid、File Upload/Time Picker 中可稳定编译的代表项 |
| Animate UI | Button/Dialog/Icon 等克制状态过渡 |
| Motion Primitives | Text/Number/Disclosure 等微交互 |

若某来源的官方组件需要无法离线满足的后端、付费资源或浏览器能力，则选择同来源下一项代表组件，并在 manifest 记录原因；不得自己重画一个“近似版”冒充官方组件。

## 数据与状态

`manifest.json` 每项至少记录：

- `id/source/official_asset_id/title/capability_ids`
- `official_url/source_url/license/upstream_ref`
- `source_cache_paths/build_inputs/build_hash`
- `render_status`：`live`、`blocked-paid`、`blocked-missing-source`、`blocked-incompatible`
- `frame_path/interaction_notes/theme_support/verified_at`

展厅卡片显示“实时预览”“官方预览”“源码”“许可证”和无法运行原因。`live` 只表示预览 bundle 已验证，不表示已经安装进产品运行时。

## 样式与主题

- 组件行为和结构来自官方源码；预览 harness 只提供演示数据、容器尺寸、中文标签和事件结果面板。
- 颜色通过预览专用语义 token 适配，保留一个“官方默认”模式；Kibo/Dice/AI Elements 另提供项目主题模式，证明可换色但不改变行为。
- 动效必须支持 `prefers-reduced-motion`；数据表和数字不得持续无意义运动。

## 失败与安全边界

- 预览构建不得从非官方镜像补源码，不得执行付费 payload。
- iframe 禁止 `allow-same-origin`、表单提交和顶层导航；所有演示写动作只更新本地假状态。
- bundle 构建失败必须记录依赖/兼容原因，不能降级成自己手写的仿制组件。
- 展厅在 `file://` 打开时不得产生外部网络请求、控制台 error 或横向溢出。

## 验收

1. 五库目录计数可重复生成，新增/减少都会触发 stale check。
2. 正式准入三库和选择性准入两库的目录、指南、许可证、缓存与运行时状态不混报。
3. 每个已选来源至少有一个实际可操作的代表预览；没有合法公开源码的来源明确阻断原因。
4. 所有 live frame 可在断网和 `file://` 下运行，零外部请求。
5. Playwright 检查展厅打开、预览切换、至少一条交互、键盘焦点、桌面/移动端和 console。
6. 展厅、桌面副本、canonical Obsidian note 与外部 `vibemotion` 笔记同步并校验 hash。

## 完成边界

完成本设计不等于把第三方组件安装进产品。最终交接给前端的是：可查目录、官方规范、合法源码缓存、代表组件实时预览、选择流程和质量门禁。产品运行时仍由前端按具体页面从中选择并登记安装。
