# 首次内网只读纵切片 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 以干净控制分支冻结前后端唯一 Contract，完成 `ka_data / platform / reconcile` 只读纵向切片，并达到可审计的内网部署条件。

**Architecture:** `codex/integration-control` 只承载需求、Contract 冻结、派活、验收和集成记录；后端从累计代码线 `codex/b22-idealab-asr-provider` 建独立实现分支，前端继续使用隔离的 `codex/fe-vertical-slice`。后端先交可执行 Contract 与受控查询 API，前端再按同一 Contract 收口；两边分别验收通过后才进入候选集成，禁止直接合并 `fe/f001` 脏工作树。

**Tech Stack:** TypeScript、Node.js、PostgreSQL、Zod、Vitest、Next.js App Router、Playwright。

---

## 固定边界

- 首次部署只读；所有媒体写入口、Runtime/Multica 执行入口必须关闭。
- 浏览器只能提交 `queryId + params + dataView`，不得提交 SQL、表名、列名或自由表达式。
- `reconcile` 不生成混合值，必须并列保留 KA Data、platform 原值及两侧 lineage。
- workspace/user/account scope 由服务端认证上下文注入，不相信请求体。
- 恰好命中 2,000、10,000 行或 16MB 也按疑似截断处理；partial/truncated 不参与全量总计。
- 当前 Claude 为后续复审席位，不是实现、联调和部署前置门。
- 原子能力、操作工具箱和工作流保持 PRD 全量范围；后续选单个写能力做 canary 只用于验证执行链路，不构成功能范围裁剪。
