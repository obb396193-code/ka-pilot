# P182 健康读取授权质量回执

## 交付

代码 **58db9dce**，对应 arch P-178 全域自查中的 PlatformHealthRepository。
候选账户来自当前 workspace 主账户与已批准账户的并集，统一通过
`accountScopeParams/accountScopeClause` 后再关联指标。保留 RR/RO、workspace/media/account/date
关联和读取后的分母/时间一致性守卫；空 grant 仍空，team 只读当前空间。

本轮查到的是一处重复授权实现，**不是新复现的公开数据泄漏**。
全仓调用核查仅发现 repository 本体和测试，当前没有 Worker/public 调用、也未从 DB index 导出。
因此这是内部读取能力的授权收敛，不宣称修复已上线健康页或已完成 HTTP 链路。
未授权账户不会加入缺数分母；获授但尚未同步主表的账户仍保留在分母中。

## 查询成本

独占库事务内新增2000个合成账户、仅1个获授，`EXPLAIN (ANALYZE,BUFFERS,FORMAT JSON)` 后 ROLLBACK：
planning 2.492ms / execution 3.925ms；accounts Index Only Scan 2000行，UNION去重后共享谓词滤掉1999行。
这是实测的代价：相比原先个人直接以grant为总体，会多扫描当前workspace候选账户。
不承诺大空间生产SLA；此reader未接公开runtime，上线前须按实际规模评估，不能用该合成耗时冒充生产性能。
关联查询仍一次、RR/RO不变、无新增业务锁或媒体调用。
