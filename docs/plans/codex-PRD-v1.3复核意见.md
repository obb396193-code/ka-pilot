## 二、剩余六处精确修改

### 1. 九项导航仍有旧七项版本

`§2.1` 第一张总表是九项，但紧接着的 ASCII 和编号表仍只有：工作台、投放任务、数据分析、账户资源、商品素材、报告、钉钉中心，缺**自动化、知识库**。

处理：直接用九项终稿替换 ASCII；编号表补成 1～9，二级结构与上方总表一致。不要同时保留“摘要版七项”。

### 2. 页面清单未完全承接导航

- 导航明确有“卡片管理”，但页面清单没有 `/dingtalk/cards`；
- `Agent/OS 运行监控` 是用户可见 Run 列表，却放在 `/admin/runs`。建议用户运行页为 `/runs` 或 `/automation/agent-runs`；管理员原始日志权限在页面内部控制，治理后台只保留跨用户审计视图；
- R-004 称“补 9 路由”，实际新增 8 行。

### 3. 安全红线仍写每用户凭证进 config vars

§3.16 已正确规定“每用户凭证进 Secret 服务，config vars 仅应用级密钥”；§6 仍写“凭证只进 config vars”。

处理：§6 统一改为“每用户凭证仅存加密 Secret 服务并在数据库保存 reference；config vars 仅应用级密钥；审计全留痕”。

### 4. 充值协作旧审批文案仍存在

§3.10 仍写“调价单/充值申请/批量操作提交指定人批”，与 §3.16 的“不含审批字样、不构成门槛”不一致。

处理：改为“调价单/批量操作可自愿提审；申请充值是协作请求，仅通知和回执，不进入 approvals，不阻断充值动作”。

### 5. SQLite 运维要求仍与三单元网络库冲突

§4.1 和开放问题已正确写 SQLite 仅本地开发；§3.13 仍要求“SQLite 每日 dump 外部存储”。

处理：改为“本地 SQLite 不承载 daily 数据；daily 起必须使用网络 PostgreSQL；PostgreSQL 自动备份并做恢复演练”。

### 6. 旧拓扑和旧目录应删除，不应继续作为开发结构示意

`§4.1.1` 仍展示单应用 Agent/Multica、第二个网关和网关 Chromium；`§4.2` 在三应用结构下面继续列 `apps/web/server/etl|agent|dingtalk|db`。虽然加了“历史/旧版”标签，但本文声明是开发唯一依据，开发目录不能同时出现两套归属。

处理：历史拓扑移出 PRD 或只保留外部依赖清单；代码树按三个应用展开真实目录，删除旧 `apps/web/server` 模块树。

## 三、结论

上述均为删除/替换旧行，不需要再扩功能或重做 126 条统计。arch 修完后回派同一个 R-004，Codex 只做六个 `rg`/diff 检查；全部消失即可标记“可冻结进契约”并立即开始 R-002。
