# 17 库官方源码比较墙设计

> 日期：2026-08-20
> 状态：老板已选择 A 方案

## 目标

把现有离线展厅从“5 个新库有实时预览”扩展为“17 条产品线各有一个明确位置”。每家展示 1–2 个最能体现自身特性的官方能力，让老板和前端 Agent 能直接比较视觉语言、交互密度、适用场景和接入边界。

完成形态为 **16 个真实公开源码实时预览 + 1 个付费锁定卡**：React Bits Pro 没有可合法取得的公开源码，因此只展示官方定位、能力摘要、许可状态与官网预览入口，不仿写、不绕会员。

## 老板确认的 A 方案

- 在总览页增加“17 库官方源码比较墙”，不是只展示新加的 5 个库。
- 17 家各占一个独立卡位，按基础组件、数据业务、动效视觉、Agent、主题系统分组和筛选。
- 16 家使用已经公开、许可证允许本地审阅的官方源码真实运行；React Bits Pro 显式锁定。
- 每家只选 1–2 个代表能力，不把 7,056 个目录条目全部编译，也不把截图冒充组件。
- 预览用于选型，不代表已安装进 `apps/web` 产品运行时。

## 17 个卡位

| 产品线 | 代表方向 | 展示状态 |
|---|---|---|
| shadcn | Command / Calendar / Dashboard primitive | 实时公开源码 |
| coss current | 日期范围、Autocomplete 或细节型 Base UI 控件 | 实时公开源码 |
| coss Origin | current 没有的 legacy 交互或复合控件 | 实时公开源码 |
| ReUI | Data Grid、Filters 或列配置 | 实时公开源码 |
| Tremor current | KPI、分析卡与报表组合 | 实时公开源码 |
| Tremor legacy | 旧版 Metric/Card/Chart 视觉语言 | 实时公开源码 |
| Aceternity UI | Spotlight、Bento 或空间背景效果 | 实时公开源码 |
| Magic UI Free | Marquee、Number Ticker 或 Border Beam | 实时公开源码 |
| Magic UI Pro | 只采用官方明确公开的 3 条源码之一；若构建不成立则锁定说明 | 条件实时 |
| React Bits Free | 文字、背景或轻量交互动效 | 实时公开源码 |
| React Bits Pro | Pro 能力摘要与官方预览入口 | 付费锁定，不缓存源码 |
| tweakcn | 同一小型数据界面切换代表主题 token | 实时公开 token |
| Vercel AI Elements | Conversation / Sources | 复用现有实时预览 |

最终代表项以官方公开源码能稳定离线构建为准。若首选项有付费、缺源码或依赖不兼容，必须换同品牌另一个公开代表项并记录原因，不能手写近似版冒充。

## 信息架构

比较墙放在展厅总览的高优先级区域，提供：

- 组别筛选：全部、基础组件、数据业务、动效视觉、Agent、主题系统。
- 状态筛选：实时预览、付费锁定。
- 每张卡固定展示：产品线名称、风格一句话、适合的项目场景、代表能力、许可证/访问层级、缓存状态、官方条目 ID。
- 卡片内直接运行 iframe，另提供“官方预览”“源码/目录”“使用规范”入口。
- 组件按进入视口后加载，避免 16 个 frame 同时执行；筛选后仍保留键盘焦点和可见状态。

比较墙回答“这 17 家看起来和用起来有什么区别”；原有全量清单继续回答“官方具体有哪些条目”。二者不混为一张巨表。

## 源码与证据规则

1. 只允许使用官方 Registry、官方 GitHub 仓库或官方发布包中公开可取得的源码。
2. 优先复用 `docs/frontend/ui-assets/source-cache/` 已缓存且有 SHA-256 的源码。
3. 为 shadcn、coss Origin、Tremor legacy、Magic UI Pro 公开子集补充最小代表源码缓存；每项保留官方 URL、上游 ref、许可证和文件 hash。
4. 已有 5 库 frame 保留其官方源码输入，统一迁移到 17 卡 manifest，不重新手写组件。
5. React Bits Pro 不生成 bundle、不产生本地源码路径；只记录 `blocked-paid`、官方预览和最接近的免费候选。
6. harness 只可提供脱敏演示数据、容器、中文业务标签、主题 token 和交互结果面板，不得改写官方核心结构或行为。

## 离线运行架构

继续沿用现有安全模型：

```text
showroom.html
  └── sandbox="allow-scripts" iframe
        ├── 内联已编译 CSS
        ├── 内联 IIFE JavaScript
        ├── 官方组件源码
        └── 仅本地假数据的 preview harness
```

- `file://` 双击可打开，不依赖开发服务器、CDN、远程字体或运行时 fetch。
- frame CSP 禁止外部网络；iframe 不开放 `allow-same-origin`、表单提交或顶层导航。
- manifest 记录 `source/official_asset_ids/license/source_cache_paths/build_hash/render_status/frame_path`。
- 每个 frame 独立编译和隔离，避免 Base UI、Radix、Motion、Tailwind 等版本相互污染。

## 失败处理

- 官方源码或依赖缺失：构建失败并标 `blocked-missing-source`，不得静默换成项目自写版本。
- 许可证不允许缓存：标 `blocked-paid` 或 `blocked-license`，只展示官方链接和合法免费替代。
- 编译环境不兼容：标 `blocked-incompatible`，记录具体依赖，再选择同品牌另一公开代表项。
- hash、manifest、frame 或展厅不同步：stale check 必须失败，禁止交付旧副本。
- 任何 live frame 出现远程请求、控制台错误或 `file://` 空白，都视为未完成。

## 自动验收

1. manifest 必须有 17 个唯一产品线记录，预期 16 个 `live`、1 个 `blocked-paid`。
2. 每个 live 记录都能反查 catalog、公开访问状态、许可证、缓存路径和文件 hash。
3. React Bits Pro 不得出现本地 bundle、frame 或 source-cache 文件。
4. 所有 live frame 的 body 在 `file://` 下非空，且至少一个代表交互可执行。
5. Chrome 在 1440px 桌面和 390px 移动端检查：零横向溢出、零 console error、零外部请求。
6. 分组/状态筛选、卡片链接与键盘焦点可用；`prefers-reduced-motion` 时动效降级。
7. 仓库展厅、桌面离线包、canonical Obsidian note、外部 `vibemotion` 笔记和 F-004 前端交接保持一致。

## 非目标

- 不渲染全部 7,056 项。
- 不强行让 17 家都展示同一个组件；各家展示最能体现特色的能力。
- 不安装第三方源码到产品运行时，不改前端 Agent 当前页面实现。
- 不绕过登录、license key、Pro 会员或付费下载。
- 不把官方截图、仿制 CSS 或 AI 重画当成真实源码预览。

## 完成边界

完成后，老板可以在一个离线 HTML 中直接看 17 条产品线的差异，前端 Agent 可以同时查全量目录、官方规范、许可证、代表源码和免费替代。实际页面选哪一家、是否安装、如何映射项目 token，仍由前端按 PRD 和同业务容器对比后决定。
