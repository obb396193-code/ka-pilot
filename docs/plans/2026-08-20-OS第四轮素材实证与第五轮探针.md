# OS 第四轮素材实证与第五轮只读探针

> 日期：2026-08-20
>
> 状态：第四轮结论为 OS 真实执行/文档/源码回传的证据快照；第五轮尚待老板复制给内网 OS Agent 执行。
>
> 边界：本文件不代表 KA 产品已经接通素材、商品、承接页或字幕数据。

## 1. 第四轮已确认事实

### 1.1 广告对象与结构枚举

- `get_data` 只有 `account`、`account_offline`、`account_realtime`、`ad_realtime` 四类 resource，没有 ad list。
- `kuaishou-cli unit list --advertiser-id` 的分页真实生效，`total_count` 可用；`creative list --unit-id` 也可分页，但只覆盖自定义创意。
- 程序化 `auto_build` 广告不应被 `creative list` 当成完整广告清单；`creative_id` 与 `ad_realtime.ad_id` 是否同域仍未验证。
- 对“有过投放数据的广告”，可按账户、按日期查询 `ad_realtime` 后对 `ad_id` 做跨日并集；这不是全广告资产清单，不能覆盖创建后从未投放的程序化广告。

### 1.2 数据接口分页边界

- MAPI 的 unit/creative/material list 使用真实分页 envelope。
- `get_data` 数组接口不支持分页，`pageNum/pageSize` 会被静默忽略；无 `accountIds` 的 `ad_realtime` 会在 2000 行静默截断。
- 产品后端必须先枚举账户，再按账户小批次拉取；UI 必须把该集合标注为“有投放数据的广告”，不得标成“账户全部广告”。

### 1.3 视频素材通路

- `kuaishou-cli material list --kind video` 返回账户素材库真实分页数据，包含 `photo_id`、视频 `url`、`cover_url`、时长、宽高、状态等字段。
- 抽样 URL 是带签名参数的公网 CDN 直链；OS 沙箱内实测 HEAD 200、HTTP Range 206，无需 Cookie/Referer。
- 单账户素材库可达 50 万量级，不适合整库全量同步。产品应按账户/商品/任务按需检索，后台只做增量元数据缓存和已选素材持久化。
- MAPI 真 token 仍由 OS 沙箱代理注入：产品不能自己枚举素材；应由 Source Bridge 在 OS 内执行 CLI，把最小元数据和短期 URL 回传。
- 产品 Worker 拿到 URL 后负责下载、校验、入自有对象存储和拆片。签名 URL 不能作为长期素材主键，TTL 仍未验证。

### 1.4 尚未证实

- 程序化广告的完整 ad list。
- `creative_id == ad_realtime.ad_id`。
- 素材签名 URL 的 TTL。
- 产品 FaaS 运行时能否直连 kwimgs/yximgs CDN。
- `qihang-cli material list --item-ids` 的真实商品样本、字段与分页。
- 商品资料、承接页/DP、平台字幕的查询能力与稳定关联键。

## 2. 对产品设计的直接影响

1. 商品素材域拆成两层：
   - 素材索引层：OS Source Bridge 负责枚举、查询、权限与短期 URL 获取；
   - 媒体处理层：KA Worker 负责立即下载、对象存储、抽帧、字幕/云 ASR、LLM 拆解。
2. 视频主键优先使用来源类型 + `photo_id` + 来源账户；签名 URL 只是可刷新 locator，不得去重或长期引用。
3. 大库采用“搜索/筛选后入库”，不做 50 万素材逐账户全量下载；只下载用户发起拆片、策略命中或任务已关联的素材。
4. 拆片默认链路冻结为：平台字幕优先；无字幕时走 API Key 云 ASR；再走多模型网关做校正和结构化分析；不引入本地 ASR。FFmpeg 抽帧仍在 Worker 本地执行。
5. 商品和承接页在第五轮之前继续标“数据源待证实”，不能把素材的 `photo_id/url` 推断成商品或落地页数据。

## 3. 第五轮只读探针（可直接复制给 OS）

```text
上一轮已经确认：material list 能返回视频 url/cover_url/photo_id 等字段，视频 URL 在 OS 沙箱内可直接 HEAD/Range 下载；get_data 的 ad_realtime 无分页且会在 2000 行静默截断；creative list 不覆盖程序化 auto_build 广告。这些不用重复测试。

这轮只查三件事：商品、承接页/DP、平台字幕。全部只读，不创建、不修改、不上传、不授权；只使用当前身份本来有权限的数据。请把“真实执行 / 源码确认 / 文档确认 / 推断 / 未验证”分开标记。回传可用对象别名，但必须保留字段名、类型、envelope、分页和对象关系；不要回传 token、Cookie 或完整签名 URL。

一、先做工具面和源码/文档发现
1. 检查 qihang-cli、kuaishou-cli 及已安装广告/素材 skill 的 --help、SKILL.md、connectors 和源码，搜索以下能力与同义字段：
   product/item/goods/commodity/offer、landing/page/dp/deeplink/click_url/target_url/h5/scheme/miniapp、subtitle/caption/asr/transcript/ocr/text。
2. 列出所有可能相关的只读命令/resource：命令、参数、返回对象、是否分页、权限来源。若无能力要明确写“工具面不存在”，不要凭后端可能存在就推断可用。

二、商品数据真实探针
3. 不让我提供真实 item_id。请先从当前身份已有权限的账户/任务/unit/素材元数据里，只读发现 1 个合法商品 item_id 或等价商品标识；如果发现不了，写清查过哪些路径和缺口，不要猜 ID。
4. 若找到合法商品标识，最小范围执行一次 qihang-cli material list --item-ids（或实际存在的等价只读命令），只拉第一页小 pageSize。回答：
   - envelope、total/page/pageSize/hasNext 是否真实；
   - 商品本身是否返回 title、主图、类目、价格/库存/状态、店铺/业务、item_id/SKU 等字段；
   - 还是只返回与商品关联的素材，商品信息仅有 item_id；
   - 素材字段是否含 URL、POSTER_URL、ITEM_PIC_URL、视频/图片类型、创建/更新时间、来源池。
5. 验证稳定关联键：item_id 能否关联 task_id、account_id、unit_id、ad_id、photo_id/material_id；哪些是响应直接给出，哪些只能另外查询拼接。
6. 如有 product/item list/detail/search 能力，再各做一次最小只读探针；没有就明确没有。

三、承接页 / DP 数据真实探针
7. 在 unit、creative、material、campaign、task、product/item 的 list/detail 返回和源码字段定义中查找承接页相关字段：landing_page_url、click_url、target_url、deeplink、dp、scheme、h5_url、miniapp、universal_link、download_url 等。
8. 对一个当前有权限的最小对象执行只读 list/detail，回答：
   - 能否拿到用户最终点击后的承接页地址，还是只能拿到商品/素材地址；
   - 地址属于淘宝商品页、活动页、唤端 deeplink、下载页还是媒体中转链接；
   - 是否带签名/短期参数、是否需要 Cookie/Referer/BUC、OS 沙箱 HEAD/GET 是否可达；
   - 是否存在页面标题、商品 ID、页面类型、审核状态、创建/更新时间等结构化字段；
   - 能否用稳定键关联 account/unit/ad/material/item/task。
9. 若承接页只藏在 create/update 请求参数或 skill Prompt 里、没有只读回查接口，要明确标记“可写入但不可回读”，并贴字段名来源，不执行写操作。

四、平台字幕与文案提取
10. 检查 material/creative/ad/detail 以及视频元数据是否返回 subtitle/caption/transcript/asr/ocr/text 字段或字幕文件 URL。区分：
    - 视频内烧录字幕（只有画面，没有字幕轨/文本）；
    - 平台独立字幕/文案字段；
    - 创意标题/广告文案（不是语音转写）；
    - OS/skill 临时调用 ASR 生成的文本。
11. 若存在平台独立字幕或文案接口，用一个当前授权样本做最小只读查询，保留字段名和时间戳结构，回答语言、分句、start/end 时间、标点、说话人、下载权限和有效期。
12. 若不存在独立字幕，明确回答“只能下载视频后走云 ASR”；不要调用本地 Whisper/本地 ASR，也不要下载模型。若 OS 已有带 API Key 的云 ASR skill/CLI，只列能力、provider、输入输出和凭证变量名（值不回传），本轮不跑大文件。

五、URL 有效期与产品侧下载补证
13. 对同一个素材，间隔 5~10 分钟重新调用一次 material list，比较 URL 是否完全相同、签名参数是否变化；只回传哈希/参数名/可推断时间字段，不能回传完整 URL。这个只能判断短时刷新行为，不能把 10 分钟稳定误写成真实 TTL。
14. 如果当前环境能在“已有 FaaS 日常实例”内做无部署、无改配置的只读 curl，则对一个素材 CDN 做 HEAD + Range 0-1023，回传状态码/长度/content-type；如果需要创建应用、部署或改配置，直接跳过，不做写操作。

六、按产品可用性总结
15. 最后给三张矩阵：
    A. 商品字段：字段名/类型/来源/粒度/真实执行状态；
    B. 承接页字段：字段名/页面类型/是否可访问/稳定关联键/真实执行状态；
    C. 字幕字段：平台字幕/广告文案/烧录字幕/云 ASR 四类分别是否可用。
16. 明确给出：
    - KA 产品现在能做深到什么程度；
    - 必须经 OS Source Bridge 的步骤；
    - 产品 Worker 可独立完成的步骤；
    - 仍需平台开放的最小能力。
```

## 4. 第五轮回收后的裁决点

- 若能得到商品字段和稳定 `item_id`：商品池可以从占位升级为真实索引，并设计商品→素材→广告→任务效果链路。
- 若只能按 item_id 查关联素材：商品池仍需人工/其他数据源维护基础信息，但素材检索可正式落地。
- 若能回读承接页：可增加承接页资产、页面类型、审核态与投放效果关联；若只能写不能读，则只做基建表单参数，不做承接页资产库。
- 若有平台独立字幕：直接进入拆片证据层；若只有烧录字幕，则平台字幕不可用，必须走云 ASR 或后续 OCR，不能把广告文案冒充语音原文。
