# 找部门后端/平台同学请教：问题清单与开会方法（arch 2026-09-07）

> 对方画像（老板给的）：做过 Scale OS / OS agent，懂工作流编排，懂内网数据权限与 BUC 多租户，熟奇航等内网产品。
> 目标：**用他们的既有答案换掉我们的试错**。一个卡点问对了能省一到三周。

## 一、开会方法（决定这会有没有用）

1. **先给 3 分钟产品背景**，别让对方猜：一句话定位 + 一条主流程 + 一张页面截图。
   - 一句话："给投放优化师做的经营助手——把奇航/BI 的数据拉进自有库，算成本达标和差距，给出建议和一键操作，人确认后再写回媒体。"
   - 一条主流程：拉数 → 算达标/差距 → 生成工作项 → 人确认 → 变更集写回媒体 → 观察结果。
   - 现状一句话："全站页面已铺完、后端在接接口，卡在**部署和身份权限**。"
2. **带着"我们已经实测过什么"去**（见 §四），对方不用从零解释，省一半时间。
3. **问"你们怎么做的"，不是"能不能帮我们做"**。前者拿到方案，后者拿到"排期再说"。
4. **每个问题都要落到三样之一**：文档链接 / 具体人名 / 一句可执行的结论。当场记下来。
5. 顺序按 §二 的 A→B→C 走，**A 组问不完不要往下**，那是命门。
6. 最后留 5 分钟问"盲点"：我们哪里做错了、有没有别的团队在做同样的事。

## 二、问题清单（按价值排序）

### A. 部署与数据库（**最卡，必问**）

已知（OS 2026-09-07 实测/查证，别再问）：FaaS 出网只开 443，5432/3306 全被过滤；RDS 申请入口是 CloudCenter 不是 Normandy，必须归属一个 AONE 应用 + 云账号 uid，CC 强制多可用区无免审批档；走 aone-platform 建应用可一步拿到 AONE 应用与带产品名的域名，建应用与发 daily 无外部审批。

| # | 问题 | 为什么问 | 想拿到 |
|---|---|---|---|
| A1 | **FaaS 的出口是不是固定网段？在哪个 VPC？** | 这是"FaaS 到底能不能连 RDS 的 5432"唯一的未知；出口 IP 不固定，白名单方案直接不成立。OS 测不到（ipify 不可达） | 网段/VPC，或该问谁 |
| A2 | 有没有**已经在 FaaS 里连内网 RDS 5432** 的产品？怎么打通的（VPC 内网直连 / 安全组网段 / 白名单）？ | 有先例就照抄，没有就得换架构 | 产品名 + 打通方式 |
| A3 | **云账号 uid 怎么拿？我们 BU 的云账号管理员是谁？** 有没有**现成的 AONE 应用**可以直接挂一个内测 RDS？ | 建 RDS 的两个硬前提，我们都没有 | 人名 + 现成应用名 |
| A4 | 走 **aone-platform 建应用**有什么坑？成本归属、安全扫描、集团治理会带来多少负担？轻量 FaaS 和它怎么选？ | 我们准备建 `ka-pilot`，想知道建完要背什么 | 经验判断 |
| A5 | 让产品**长期跑在沙箱**里现实吗？回收策略是什么？ | 内测方案 A 的寿命 | 能撑多久的经验值 |
| A6 | 要开一个 **OSS bucket** 存数据库备份，走什么流程？也要云账号吗？ | 沙箱被回收会连本地备份一起丢，异地备份卡在这 | 流程 + 是否同样卡云账号 |

### B. 身份、多租户与数据权限（**正式化必经**）

现状：内测用自建账密；正式要接 BUC。更麻烦的是**数据范围**——现在 FaaS 里没有用户身份注入，只能在配置里写死一个人的奇航 userId，**所有人看到同一份数据**。

| # | 问题 | 为什么问 | 想拿到 |
|---|---|---|---|
| B1 | BUC 接入的**最新标准流程**？（我们查到的是 scaffold-id 10 + NextAuth）现在还是这套吗？有没有坑？ | 一期不自建账号体系 | 最新文档 + 已知坑 |
| B2 | BUC 登录后，怎么拿到**这个人自己的数据权限范围**？奇航/数仓那边认 BUC 身份吗，还是要另做映射？ | 这是"多人可用"的前提 | 有没有现成的身份映射服务 |
| B3 | 我们要做**负责人视图**（看下属的账户和任务）。组织架构、上下级关系有没有可调用的服务？ | 自己维护一张成员表会和 HR 数据脱节 | 组织服务的名字/接口 |
| B4 | 奇航取数是**裸 userId 参数、无 token 无签名**。正式产品应该用什么身份调它？有没有服务身份/代理授权/OpenAPI 那一套？ | 现在等于长期借一个人的身份，不可持续 | 正规调用方式 |
| B5 | 内部产品的**数据权限**一般怎么落？（我们做的是账户级授权表）公司有没有统一的权限中心？ | 避免自建一套将来要拆 | 权限中心是否存在 |

### C. 数据源（奇航 / ka-data / 数仓）

| # | 问题 | 为什么问 | 想拿到 |
|---|---|---|---|
| C1 | ka-data 是**官方数仓还是临时服务**？长期能依赖吗？有没有更权威的口径源？ | 团队版数据全靠它 | 定位 + 负责人 |
| C2 | 它**没有版本号**、近三天的 ds 每天重建。数仓侧有没有**快照/分区就绪**语义（比如"这一天的数据已封版"）？ | 我们只能靠 updated_at 批次猜，做同步很别扭 | 有没有就绪标记 |
| C3 | 消耗、转化这些指标，公司**权威口径**在哪张表/哪个服务？返点系数、现金口径谁维护？ | 我们现在把系数写在自己配置里 | 权威源 + 维护方 |
| C4 | 奇航的取数接口有没有**官方 SDK/网关**，还是就这一个裸接口？限流是多少？ | 我们在裸调，怕哪天被限 | 限流数值 + 官方通道 |

| # | 问题 | 为什么问 | 想拿到 |

| D1 | 你们做 Scale OS 的**工作流引擎**，编排、重试、幂等、人工确认是怎么设计的？有没有可复用的组件或服务？ | 可能不用自己维护一套 | 组件名/是否开放 |
| D2 | 长任务的**执行语义**：怎么保证一个任务不被两个实例同时跑、崩溃后怎么恢复、结果未知怎么办？ | 我们用租约+围栏+一次只读核查，想对一下 | 他们的模式 |

| # | 问题 | 为什么问 | 想拿到 |

## 三、我们能给对方什么（别只索取）

- 一份**内网能力实测清单**（奇航双口径、写链路 14 项、FaaS 出网端口、CDN、ASR 格式），他们可能也没系统测过。
- 快手 MAPI 出价字段的**实测枚举**（三个字段不是一个分类轴，官方文档没说清）。
- 一个**契约驱动 + 多 Agent 并行开发**的实践样本（如果他们对 AI 协作开发感兴趣）。

## 四、别问的（已经实测过，问了浪费时间）
