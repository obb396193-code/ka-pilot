# 看板多值筛选 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 P211 多值 OR/跨维 AND 筛选接入个人 summary/trend/table/dimension，保留账户日和日考核口径，不只筛显示行。

**Architecture:** 同一 RR/RO 快照读取可信账户日、有效 task/biz 与命名证据，生成内部限定 accountDays；共享 Semantic SQL 在原 workspace/accountScopes 授权之内再取交集。lineage/expected/考核/展示查询都用同一交集。浏览器只传业务 filters，永不传内部 accountDays。

**Tech Stack:** 现有 TypeScript/Zod/pg/Vitest、SemanticQueryRepository、PlatformWindowQuery、PlatformDimensionQuery。

## Task 1：过滤内核与限定账户日

- 新 `packages/domain/src/dashboard-filters.ts`、`test/dashboard-filters.test.ts`：五字段 optimizer/biz/resource_position/goal/task_id 多值，OR/AND/空/非法值测试先红后绿。resource_position 与 placement 同义；biz 取实际当日 task 大类，不猜昵称。
- `packages/db/src/semantic-query-types.ts` 增内部 accountDays；`semantic-query-support.ts` 参数化匹配，同步 workspace/tuple/day 验证。`semantic-query-repository.ts` 对筛后 expected 做真实 SQL count/date proof，WindowAssessment 使用 eligible day count。
- 独立真实 PG 证明同账户跨任务日不会被全窗口多算，缺日仍 missing，空交集不回退全范围。

## Task 2：同快照解析

- 新 `packages/db/src/dashboard-account-days-repository.ts` 与单元/PG测试：生成授权范围的31天以内网格，三键读取有效 task/biz（不读取或猜测指标），不依赖有消耗才决定查询授权；后续指标/覆盖沿用失败批次屏蔽SQL，10001/16MiB保护。
- Worker 新 `data/dashboard-filter-scope.ts`：复用自查10的命名事实与历史规则，匹配 filter 后输出 accountDays，返回命名缺失警告。同RR，固定批量读取；不得 N+1 或只返回 accountIds 丢日期。

## Task 3：公开查询接线

- Registry 仅在 summary/trend/table/dimension 加 `params.filters`；legacy `/query` filters 通过同一个语法 adapter，所有新字段不能悄悄丢掉。KA尚无筛选实现时明确 unsupported，不能静默忽略。
- PlatformWindowQuery/DimensionQuery/PlatformDataSource 各同RR注入范围解析，expected、lineage、考核、比较窗口重新按各窗口过滤。
- 实际 PG+HTTP 证明 optimizer→biz→task→account 下钻、filter之间AND、同字段OR、跨media/workspace、缺字段错误、未知filter拒绝、源失败/大小门；复跑旧数据HTTP与三包类型/lint、Web测试。
