# 双布局真实前端 Demo 设计

> 日期：2026-08-20  
> 状态：老板已确认  
> 性质：独立可运行的前端样机，不修改 Claude 当前 `apps/web`

## 1. 目标

制作两个可以真实打开、点击和响应式查看的投放 Agent 首页 Demo，用同一套脱敏业务数据比较两种成熟布局：

1. 侧栏版：以 shadcn `dashboard-01` 官方结构为主要骨架。
2. 顶栏版：优先采用许可证清晰的成熟顶栏/Navigation Menu 官方源码与模式。

它们不是截图稿，也不在同一画面中做左右拼接。用户后续可以分别打开页面、操作并自行截图。

## 2. 已确认边界

- 两个完全独立入口：`sidebar.html` 和 `topbar.html`。
- 侧栏版页面内不出现“切换到顶栏版”的按钮、链接或说明。
- 顶栏版页面内不出现“切换到侧栏版”的按钮、链接或说明。
- 两版内部可以共享业务数据、图表、KPI、表格和状态组件代码，但共享关系不得出现在视觉界面中。
- 两版都支持三种首页角色模式：优化师、KA 负责人、综合首页。
- 角色切换只改变业务视角和模块权重，不切换页面导航形态。
- 不覆盖、不整理、不提交 Claude 当前未完成的 `apps/web` 页面改动。
- 所有业务数据明确为脱敏演示数据，不连接真实投放平台，也不提供真实写操作。

## 3. 实现形态

在独立目录建立一个真实 React 前端样机，采用多页面构建：

```text
独立 Demo
├── sidebar.html  → 侧栏版入口
├── topbar.html   → 顶栏版入口
├── src/sidebar/  → shadcn dashboard-01 外壳
├── src/topbar/   → 成熟顶栏外壳
└── src/shared/   → 脱敏数据、业务卡片、图表、表格与 Agent 抽屉
```

使用多页面入口而不是页面内布局切换，可以保证打开和截图时不会看到另一种方案，也避免通过隐藏按钮或 query 参数制造混乱。

## 4. 两套视觉方案

### 4.1 侧栏版

主要复用 shadcn `dashboard-01` 的官方页面组织：

- Sidebar / SidebarProvider；
- SidebarHeader、SidebarContent、SidebarFooter；
- 顶部页面标题与全局动作区；
- KPI Card；
- Chart 容器；
- Data Table、Tabs、Dropdown、Sheet、Badge、Skeleton；
- 桌面折叠侧栏与移动端抽屉行为。

业务适配只负责把通用 dashboard 文案和示例数据替换为投放任务、账户、消耗、转化、CPA、风险和待办。

### 4.2 顶栏版

优先从 coss Origin 的 MIT Navigation Menu、shadcn Navigation Menu 与公开数据产品模板中选择兼容的正式源码模式；数据区域优先复用 Tremor Raw/Blocks 与 shadcn 成熟组件。若某个完整 App Shell 属于 Pro、Commons Clause 或许可证未确认范围，只保留元数据，不复制源码。

顶栏版结构：

- 第一层：品牌、八个业务入口、全局搜索、数据更新时间、通知、用户；
- 第二层：当前业务域的二级导航、对象选择器和时间范围；
- 主体：宽屏数据看板，不再保留任何左侧导航栏；
- 移动端：顶栏收进抽屉或菜单，不退化成桌面侧栏版。

## 5. 三种角色模式

### A. 优化师工作台

- 今日需要处理的异常账户；
- 今日消耗、真实转化、真实 CPA、Gap；
- 待执行/待确认动作；
- 任务进度与账户明细；
- Agent 诊断入口。

### B. KA 负责人看板

- 整体目标完成率、预算与风险；
- 团队/任务表现排名；
- 超成本、断量和数据延迟分布；
- 需要负责人拍板的事项；
- 渠道和资源分配视图。

### C. 综合首页

- 上半部分展示经营大盘；
- 下半部分展示个人行动队列；
- 同时保留数据证据和 Agent 建议，但控制信息密度。

三种模式共用同一事实数据，避免切换后数字相互矛盾。

## 6. 首页内容与交互

两个版本都至少包含：

- 角色模式切换；
- 日期范围、投放任务、账户或负责人筛选；
- KPI 与同比/环比语义；
- 消耗与真实 CPA 趋势；
- 异常账户/任务队列；
- 数据表格及排序/筛选样张；
- 数据更新时间、过期与无数据状态；
- Agent 右侧抽屉；
- 亮色/暗色模式；
- 桌面与移动响应式。

演示交互不伪造后台写成功：涉及预算、出价、上下线等动作只允许打开预览或确认界面。

## 7. 组件复用原则

1. 先用已缓存或可从官方公开 Registry/仓库合法取得的源码。
2. shadcn、coss、Tremor 等上游组件保留来源、许可证和必要依赖记录。
3. 自写范围仅限业务数据映射、模块组合、响应式外壳和少量缺失胶水代码。
4. 不反推预编译 bundle，不绕过会员，不复制 Pro/Ultimate/Commons Clause 受限源码。
5. 同能力存在多个候选时，使用相同中文数据、宽度和状态做内部比较后再选择。

## 8. 验收

- 两个入口均可独立启动、刷新和直接访问。
- 任一入口的可见页面中都不存在另一布局的切换入口。
- A/B/C 三种角色切换后，KPI、队列和页面重点真实变化。
- 桌面端至少验证 1440×900；移动端至少验证 390×844。
- 页面无横向溢出，控制台无错误，键盘焦点可见。
- 金额、百分比、CPA 与日期使用 `Intl.*` 和等宽数字。
- reduced motion、加载、空、错误、过期、无权限状态可验证。
- 每个采用的第三方组件能够追溯到上游来源与许可证。

## 9. 非目标

- 不接真实 API、认证或数据库。
- 不替代正式 PRD 和数据契约。
- 不把 Demo 直接认定为最终产品皮肤。
- 不把两个入口合并成布局切换器。
- 不修改 Claude 当前前端批次。
