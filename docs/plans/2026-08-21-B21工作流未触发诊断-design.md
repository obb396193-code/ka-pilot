# B21 工作流“为什么没触发”诊断内核设计

> 状态：设计冻结，进入纯 Domain TDD。
>
> 依据：自动化运行中心验收 5.6，以及老板已确认的七类解释：数据未刷新、样本不足、冷却中、每日上限、操作冲突、权限不足、等待确认。

## 1. 目标

把调度器每次判断的门禁结果变成稳定、可检索、可解释的诊断快照，而不是只在页面显示“未运行”。同时兼容现有 Workflow Runtime 已建模的 trigger/version/capability/manual pause/condition 等阻断原因。

## 2. 模型

- 绑定 workspace、workflow、固定版本、trigger、evaluation ID 和评估时间；
- checks 带显式顺序、reasonCode、outcome（passed/blocked/not_evaluated）、证据引用和可选 retryAt；
- 至少一个 blocked → blocked，第一条 blocked 是 primary blocker；
- 无 blocked 但有 not_evaluated → incomplete；全部 passed → eligible；
- blocked 自动映射稳定 nextActionCode，只给动作类型，不生成自然语言结论；
- blocked 必须有 evidence ref；需要等待的原因可带 retryAt，且必须晚于评估时间；
- 检查序号连续、reasonCode 不重复，输入排序不影响指纹。

## 3. 边界

- 本批不实现 Scheduler、Trigger、DB、API 或运行中心页面；
- 不自行判断数据是否新鲜、样本是否足够、权限是否通过，只有对应执行器能产出 check fact；
- 不发明冷却时长、日上限和样本阈值；
- 不把 diagnostic 当 workflow run，eligible 也不代表已执行。
