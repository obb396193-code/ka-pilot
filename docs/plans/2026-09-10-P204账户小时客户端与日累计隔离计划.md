# P204 账户小时客户端与日累计隔离 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 按v1.9.4接通账户实时查询的hh参数，并避免分小时Raw替代日累计或错误解除全天失败标记。

**Architecture:** 沿用现有QihangClient参数校验/重试、query observation、Raw审计与共享失败守卫。新增account_realtime可选hh，0..24本地校验；小时Raw不作为日canonical输入，只有未传hh或明确24才是日累计输入/恢复依据。迁移号待P201裁决，不创建小时表、不启动采样调度，不提前开放Full/Incr容错。公开DTO不改；账户小时批次失败暂不支持降级为partial，必须fail-stop，后续Task3接完整私有覆盖事实时再放行。

**Tech Stack:** TypeScript、Vitest假fetch、pg真实合成库。

2. 扩`packages/db/test/etl-batch-readability.test.ts`：新小时Raw不能替换旧日Raw；小时补采+重算不能解除日失败；hh24恢复；同ws/media隔离继承原测试。先跑红。
3. 最小实现：`qihang/client.ts`、`etl/query-observation.ts`、`etl/batch-failure.ts`；`etl-batch-readability.ts`提供日输入谓词并在Raw读取/失败恢复两处复用。现有广告小时差分路径不变。
4. 跑Worker Qihang/ETL与DB失败读取定向回归、两包type/lint、cache audit。小于8GiB磁盘不做全包/构建，不清用户文件。
