# B6 分析与报表契约安全内核设计

> 日期：2026-08-19
>
> 分支：`be/b6`
>
> 上游：B5 `53ea264`
>
> 状态：老板已批准按“契约安全内核”继续；本设计不修改冻结契约，不触碰前端。

## 1. 目标

在 Claude/arch 尚未裁决报表公开 DTO、共享权限、定时语义和缺失策略维度时，完成以后不会白做的后端内核：

- 将已有语义层事实装配为 KPI、趋势、分组表/柱图所需的结构化数据；
- 计算 Gap 对账，不让模型心算；
- 对策略矩阵执行样本量护栏并输出结构化胜出项；
- 严格校验 Agent 生成的报表草稿，禁止 SQL、Shell、URL、任意表达式和预计算数字；
- 提供幂等、可失败留痕的报表生成 Worker 内部端口。

## 2. 为什么不直接实现 `report_configs.config`

冻结 Schema 只有 `config JSONB`，公开 API 也只有 `/reports/configs` 和 `/reports/render` 的轮廓。尚未冻结：

- config 的精确字段、版本、组件和布局 Schema；
- `is_shared` 与统一 `assets` 的关系；
- schedule 的时区、失败补偿、订阅和幂等语义；
- 导出任务和报表快照的持久化位置；
- Agent 草稿与前端自由画布配置是否同构。

直接把任意一版 JSON 写入数据库，会让实现反向定义契约。B6 因此先引入内部 `ReportExecutionPlan`：它只表达“查询什么、装配什么”，不表达前端布局、共享、发布和定时。未来公开 DTO 只需编译为该执行计划。

## 3. 架构

```text
未来 Web/Agent 报表草稿
        │
        ▼
严格草稿解析器（unknown → ReportExecutionPlan）
        │  禁任意 SQL/Shell/URL/表达式/预计算数据
        ▼
ReportFactsSource
        │  只读 B1c summary/trend/dimension
        ▼
报表装配器 ──→ KPI / trend / breakdown 数据集
        │
        ├── Gap 对账纯函数
        └── 策略矩阵样本护栏纯函数
        ▼
ReportArtifactSink（内部端口）
        │
        └── 幂等保存/失败摘要；真实存储等契约后接
```

## 4. 组件设计

### 4.1 内部执行计划

位置：`packages/domain/src/report-plan.ts`。

固定内部版本 `b6-internal-v1`，只允许：

- scope：日期范围和 B1c 已支持的 task/account/owner/media 筛选；
- KPI：summary 数据源 + 单指标；
- 趋势：trend 数据源 + 单指标；
- 分组表/柱图：dimension 数据源 + `account|task|biz` + 指标列表 + limit；
- 最多 24 个组件，组件 ID 唯一；标题和筛选字符串有限长；日期严格有效。

禁止接受：layout、schedule、sharing、SQL、formula、script、URL、HTML、预计算 rows/value。Zod `.strict()` 使所有未知字段 fail-closed。

### 4.2 统一事实与组件数据装配

位置：`packages/domain/src/report-dataset.ts`。

输入是已经过语义层计算的 summary/trend/dimension 事实。装配器只做：

- 从白名单指标目录取值；
- 保留 `finite|infinite|undefined|missing`，不把缺失改成 0；
- KPI 输出单值；趋势输出日期序列；分组输出 key/label/metrics；
- 每个组件带 `ready|empty|missing` 和 `dataCutoffAt`；
- 一个组件缺事实时局部降级，不让整份报表伪成功或全部失败。

指标比率继续来自 B1c `MetricSummary.ratios`，不得平均行级 CPA/CTR。

### 4.3 Gap 对账

位置：`packages/domain/src/gap-reconciliation.ts`。

输入只接收有限非负的媒体转化与真实转化，输出：

- signed difference = media conversion - real conversion；
- Gap = media conversion / real conversion - 1，保留零分母状态；
- `matched|mismatch|undefined|missing`；
- evidence fields，供 Agent/报告引用。

不在本批发明“正常 Gap 阈值”或财务结算口径。

### 4.4 策略矩阵样本护栏

位置：`packages/domain/src/strategy-analysis.ts`。

上游以后可以提供版位、出价方式等观察数据；当前内核只接收通用 row/column key，不假设字段已落库。按 PRD 冻结护栏：

- 独立账户数 `<3`：insufficient；
- 总消耗 `<100`：insufficient；
- 真实转化为 0 时真实 CPA 保留 infinite/undefined；
- 只有 eligible 且 CPA finite 的 cell 才参加“最低真实 CPA”比较；
- 并列按稳定 key 排序，保证重跑一致。

本批不生成自然语言打法结论，只输出结构化 winner 和排除原因。

### 4.5 B1c 数据适配

位置：`packages/db/src/report-facts-source.ts`。

适配器复用 `SemanticQueryRepository` 的 summary/trend/dimension，只读、不造新 SQL 口径。相同 scope/dimension 查询去重；每次都要求 workspaceId。它将 DB 类型转换为领域统一事实，不改变比率。

### 4.6 报表生成 Worker

位置：`apps/worker/src/reports/`。

Handler 流程：

1. 校验 workspace、reportId、requestedBy 和生成时点；
2. 从 `ReportPlanSource` 读取 unknown 草稿并严格解析；
3. 从 `ReportFactsSource` 读取权威事实；
4. 装配数据集；
5. 用 workspace/report/config hash/asOf 生成稳定 idempotency key；
6. 调 `ReportArtifactSink.saveOnce()`；
7. 返回 generated/duplicate 和安全摘要。

端口不指定存 PostgreSQL、OSS 还是知识库。失败只记录稳定错误码和安全消息，不回显草稿全文或凭证。

## 5. 错误处理

- 未知字段/非法指标/非法维度/重复组件：整份执行计划拒绝。
- 权威事实缺失：组件返回 missing/empty，不捏造数字。
- 单个 dimension 查询失败：FactsSource 明确失败，Worker 不保存半成品为成功。
- Artifact 幂等冲突：返回 duplicate，不重复发送和渲染。
- workspace 泄漏：任何 Source 返回不同 workspace 都 fail-closed。
- 真实外部服务：本批没有调用，因此不存在 fake 结果冒充联调。

## 6. 测试策略

- Domain：非法草稿、未知字段、组件约束、缺数态、ratio 状态、Gap 零分母、策略样本护栏、稳定 winner。
- DB：真实 PostgreSQL 下 summary/trend/dimension 适配、租户隔离、查询去重和多任务歧义传递。
- Worker：成功、重复、非法草稿、跨租户、Facts 失败、Sink 失败、稳定幂等键。
- 全量：四包 tests、coverage、typecheck、lint、audit、复杂度和 `git diff --check`。

## 7. 明确不做

- 不修改 `packages/contract/` 和迁移；
- 不实现 Web API Route、SSE 或前端设计器；
- 不持久化公开 report config；
- 不做共享/官方资产状态流；
- 不做 cron、PNG/PDF/Excel、钉钉推送；
- 不查询当前不存在的版位、出价方式、负责人维度；
- 不接真实模型、Multica/OS 或 Secret 服务。

## 8. B6 完成标准

- 内部执行计划有严格、可测试、fail-closed 的 Schema；
- 三类组件从 B1c 事实稳定装配；
- Gap 和策略矩阵不由 Agent 计算；
- Worker 重试不重复保存产物；
- 新增代码行覆盖率不低于 80%，全仓门禁不下降；
- 状态、证据、契约差异和 Claude 审查项全部留痕。
