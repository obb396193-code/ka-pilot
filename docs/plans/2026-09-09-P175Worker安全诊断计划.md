# P175 Worker安全诊断 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** F-OS-003提供可定位阶段的安全stderr和部署只读自查，不再只显示Worker once failed；不改变HTTP响应合同、不泄漏原始错误/URL/凭证。

**Architecture:** 内部typed阶段码贯穿child→strict IPC→supervisor→CLI固定formatter。常规job失败仍由原consumer记录，不改队列重试语义。独立diagnose入口只在RR/RO事务读环境/空间/授权和队列计数，不起worker、不领取或重排任务、不测真实媒体。

**Tech Stack:** Node child_process/pg、Worker zod、Vitest真实子进程及本人PG隔离库。

## Task1：安全阶段错误

- 新 `apps/worker/src/scheduling/worker-once-failure.ts`：固定枚举+Error+formatter+stage wrapper，unknown→UNEXPECTED_FAILURE，绝不输出error.message/cause/stack。
- 改 `worker-once-protocol.ts` 新增strict failure IPC；`worker-once-supervisor.ts` 区分spawn、IPC、terminal、counts、child exit、kill失败，仍close之后才settle，不把kill失败当结束。
- 改 `worker-once-child.ts` 包住tick/prepare/consumer/cleanup；外层只发送typed failure。`worker-once-cli.ts`配置失败和授权阻断输出固定码；`worker-once-process.ts`日志只写安全formatter，HTTP envelope不变。
- 新定向测试先红：spawn原错误带secret、malformed IPC、非零退出、无terminal、各child阶段、未知错误不透传；真实子进程坏配置/坏DB失败输出无URL。原13个supervisor及HTTP/实际once PG回归。

## Task2：只读自查命令

- 新DB `worker-once-diagnostics-repository.ts`（RR/RO、有界统计）及PG测试；新Worker `worker-once-diagnose.ts`、package.json `worker:diagnose`。
- 只返回配置合法性、DB可读、workspace状态、active身份链/缺qid/缺grant计数、当前media的ETL队列状态计数（due/等待/阻塞/耗尽/租约）；不返回qid、payload、last_error、DB URL。
- 明确未检查奇航网络/数据，不能把自查成功当ETL成功。真PG创建合成queued/blocked/leased，前后行全等证明只读；未配置/连接失败输出安全码。
- 更新唯一runbook本人诊断命令；先代码独立SHA再留痕，type/lint/audit，磁盘>=8GiB才全量。

执行子技能不可用，沿用老板持续授权在本人worktree逐项实施；不派未授权子agent、不生图、不push。
