# 内部先例与账号复用

> 建立：2026-08-13，来源：老板口述
> **这份文档记的是目前为止信息价值最高的一条线索：部门里已经有业务侧的人做成了同类事。**

## 1. 线索原文

> 内部有个运营做了个产品，他的产品能直接调用 OS 去查询数据返回给他的产品。不知道用的啥方法，反正就是可以用 token 权限，但好像不是拿到 token。
> 多用户鉴权，不确定能不能直接复用已有账号体系。

## 2. 为什么这条最重要

**它把三个假设一次性证伪了：**

| 原假设 | 先例证明 |
|---|---|
| 业务侧拿不到数据通路 | 拿到了，而且是运营（非技术部门） |
| 外部产品调 OS 查数据可能不可行 | 已经在跑 |
| 得靠我们自己摸索 | 有人踩过坑，答案是现成的 |

**行动含义：去问那个人，比问 OS 十轮都快。** OS 只能告诉我们"平台理论上有什么"，那个运营能告诉我们"实际怎么批下来的、卡在哪、花了多久、找了谁"。这是几周和一下午的差别。

**博弈含义（要点）**：有先例＝有判例。将来跟技术部门要权限时，"业务侧已经有人这么做了并且在跑"比任何论证都好用。

## 3. 「有权限但不持有 token」是什么机制：候选排序

老板说"可以用 token 权限但好像不是拿到 token"。这句话的技术含义是**凭证不在他的产品里**。可能的机制按可能性排：

| # | 机制 | 表现 | 可能性 |
|---|---|---|---|
| 1 | **应用身份鉴权（AppKey/Secret 或 mTLS）** 走内部网关 | 应用注册后，调用方以"我是哪个应用"被识别，权限挂在应用上，代码里没有用户 token | 高。这是阿里内部服务间调用的常规形态，也最符合"有权限但没 token" |
| 2 | **服务端代理 / BFF** 由后端持凭证 | 产品前端只调自己后端，凭证只在后端环境变量里，开发者感知不到 | 高 |
| 3 | **数据服务 API**（dataworks 数据服务 / FBI 开放接口） | 申请数据集权限，调用时用应用身份，不碰媒体 token | 中高。这条最干净，绕开媒体侧 |
| 4 | **autopilot webhook** | POST 一个带 token 的 URL 触发 agent，结果异步回写 | 中。URL 里其实有 token，但用起来"不像拿 token" |
| 5 | **Multica Open API + 应用凭证** | 应用注册后按需换短期 token，不留长期凭证 | 中 |
| 6 | MCP / 网关中转 | 中间层持凭证 | 低 |

**不确定就是不确定**，这里不猜结论。三个机制（1/2/3）对我们都是好消息，因为都不需要借任何人的个人 token——和 05 文档确立的原则一致。

## 4. 账号体系复用：三种可能，都要问

需求本质不变（见 03 文档）：**要的是数据可见范围，不是登录界面。** 但"复用已有账号"有三种完全不同的做法：

| 方案 | 含义 | 优点 | 风险 |
|---|---|---|---|
| A. 公司 SSO（BUC/域账号） | 员工用工号登录 | 最正规、自带组织架构（上下级关系可喂给任务分发）、零密码管理 | 需申请接入 |
| B. 复用 OS/Multica 账号 | 用户已在 OS 有身份，直接沿用 | 用户零新增账号、与技术侧体系天然集成 | 绑死在 Multica；外部应用能否验证其身份未知 |
| C. 复用启航的账号/权限体系 | 账户基建原属启航，账户归属关系在那里 | **能直接拿到"谁管哪些广告账户"** ——这正是数据可见范围要的东西 | 启航是传统 SaaS，未必有对外鉴权接口 |

**我的倾向：A 做登录 + C 做数据可见范围。** SSO 解决"你是谁"，启航的账户归属解决"你能看哪些户"。两者是不同问题，不该用一个方案硬凑。B 只在 A 走不通时考虑，因为绑死在 Multica 上会失去独立性。

## 5. 下一步（按 ROI 排）

1. **★ 找那个运营聊**（问题清单见 `docs/plans/问运营先例清单.md`）。当前最高 ROI 动作。
2. 发探针 B 给 OS（已成稿），两条线并行不冲突。
3. 拿到先例细节后，直接对照修订 05 文档的主路径——**如果他的方法比 a1 faas 更轻，就走他的路，不重复造。**

## 6. 一个要老板自己判断的问题

去问这个运营，等于让部门里第一个人知道你在做同类产品。他可能是：
- **盟友**：愿意分享踩坑经验，甚至将来一起推。
- **同赛道竞争者**：AI Native 的成果位置有限，他也在争。

我给不出答案，因为这取决于你对这个人的了解。但建议：**问路子和流程，别一上来讲你的产品蓝图。** "我想查点数据做分析，你当时怎么申请下来的" 这个问法既能拿到全部关键信息，又不暴露产品意图。等你手里有东西了再谈合作，谈判位置完全不同。
