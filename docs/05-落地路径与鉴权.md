# 落地路径与鉴权（关键突破）

> 建立：2026-08-13，来源：OS agent 三轮问答（含实测 `a1` 二进制）
> 这份文档回答的是全项目最卡的问题：**产品跑在哪、数据怎么合法拿到、用户怎么登录。**

## 1. 先确认一件事：OS 拒绝借 token 是对的

OS 明确拒绝导出 MULTICA_TOKEN / 业务 CLI 凭证给外部产品，理由是这些是绑定沙箱会话 + agent 身份 + 具体任务的短期凭证，转借会绕开按身份审计的设计、泄露风险不可控、大概率违反使用条款。

**我认同，而且我们不该要。** 建立在借来的凭证上的产品：随时因 token 过期或轮换而全线瘫；一旦被发现就是"业务侧绕权限"，博弈直接输掉，比慢几周严重得多。

**结论：架构必须建立在「我们自己的合法服务身份」上。** 这不是妥协，是唯一能拿去谈的形态。

## 2. 四条路径与判断

OS 给出的可行路径：

| 路径 | 机制 | 我的判断 |
|---|---|---|
| **A. a1 faas 部署内部应用** | `a1 faas`（阿里内部统一研发 CLI，实测 v0.2.46）建应用 → build → deploy，拿 `ACCESS_URL`；正式链路走 AoneFaaS 函数组 + 代码仓库 + `a1 faas publish <env>`；配套 config vars / logs / health / metrics | **★主路径。** 应用有自己的身份、自己申请数据源凭证、边界清楚、在公司体系内合规、天然可给多人用 |
| B. Multica issue/评论 | 外部产品建 issue / @agent，agent 用自己凭证查，结果回写评论/附件，外部再读 | 只适合偶尔查、能接受异步；不能做产品主链路 |
| C. autopilot webhook | `multica autopilot trigger-add --kind webhook` 生成 `/api/webhooks/autopilots/{token}`，POST 触发一次 agent run | **是触发不是请求-响应**，异步、无同步返回值；且 OS 不确定 POST body 能否传参进 run 上下文。适合事件驱动，不适合查数据 |
| D. port-mapping | 沙箱内服务映射临时公网 URL | 只在会话存活期有效，仅开发期调试可用 |

**采用 A 为主路径，D 做开发期验证，C 留给未来的事件驱动场景，B 不用。**

## 3. 为什么 A 一举解决三个难题

**① 凭证问题** → 应用以自己的服务身份申请快手 MAPI / FBI 数据权限，不借任何人的 token。
**② 合规问题** → 之前担心"产品跑在沙箱外＝在 mitmproxy 审计体系之外处理公司数据"。跑成内部 FaaS 应用，数据不出公司基建，这个担忧基本消解。
**③ 多用户问题** → 内部应用可以接公司统一登录（BUC/域账号 SSO）。**我们不该自己造账号体系**——自建密码库不仅是重复劳动，还是合规风险。用域账号登录，还自带组织架构（谁是谁的上级），正好喂给 04 文档的分发功能和数据可见范围。

## 4. 硬约束（OS 明确说的）

- `a1 faas deploy` 目前**固定发布到日常环境（daily）**，不是生产入口。生产要走 AoneFaaS 函数组 + `a1 faas publish <env>`，需确认权限与流程。
- `a1 faas register` 当前被临时禁用。
- `create aone-platform` 有跨系统副作用（新建代码仓库 + 新建应用），OS 会强制二次确认应用名、Code group、project、脚手架。
- **这一步会留下组织足迹**：建了仓库和应用，项目就从"私下捣鼓"变成"公司里有登记的东西"。博弈上是好事（成果可见、可汇报），但意味着不再隐身。**需要老板拍板时机**。

## 5. 修订前面的结论

| 原结论 | 修订 |
|---|---|
| 02 文档：卡点＝kuaishou-cli 能否拷到沙箱外用 | **不再是主路径。** 正解是 FaaS 应用申请自己的数据源权限，而不是搬别人的 CLI 二进制 |
| 02 文档：产品跑沙箱外有审计合规隐忧 | 走 FaaS 后基本消解 |
| 03 文档：要做多用户鉴权登录系统 | **改为接公司 SSO（BUC/域账号），不自建账号体系。** 需求本质仍是数据可见范围，不是登录本身 |
| 01 文档：先做出来再博弈 | 次序不变，但"做出来"的形态更清晰：先在 daily 环境跑起来给自己和身边人用，拿实效去谈生产环境和数据权限 |

## 6. 仍未解决的核心问题

1. **FaaS 应用能不能拿到快手 MAPI 读权限**，走什么流程、谁审批、多久。
2. **FBI / BI 真实转化能不能给应用身份开权限**——业务价值地基，仍是最大未知。
3. FaaS 能不能托管**前端**（Next.js / 静态站点），还是只能后端函数。若不能，前端另找托管。
4. 有没有配套**数据库**（RDS/Tair）可申请。产品要存工作项、状态、历史快照，无库则无产品。
5. 出网策略：FaaS 应用能不能访问快手公网 API。
6. 是否复用 Multica issue 做任务底座（见 04 文档 §6.4）。

以上进探针 B。
