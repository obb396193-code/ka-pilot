- `autopilot create --mode create_issue` → `trigger-add --kind webhook` → `curl POST 带 JSON body` → HTTP 200 返回 run_id → run 完成生成 issue → agent 评论含 `RESULT_JSON:` 行 → `multica issue comment list` 完整读回。

## 2. 外部读取凭证 ✅ 矛盾解开

- `mcn_` **真实存在**（`multica login --help` 明示；前会话只查了 `auth` 子命令所以没看到——两会话都没撒谎，查的面不同）。token 三态：`mat_` 运行态 / `mul_` 用户 PAT / `mcn_` Cloud Node PAT。
- 签发在 Multica Web 端（CLI 只消费）；有 `/api/tokens/current/renew` 端点=有有效期可续期，时长未文档化。
- **决定性证据**：钉钉网关 config vars 实读 → `MULTICA_TOKEN` 前缀 **`mul_`**（用户 PAT）+ SERVER_URL + WORKSPACE_ID 三件套即可跑 `multica issue` 全套命令。
- **定案：产品 FaaS 侧沿用 `mul_` 用户 PAT**（既成先例），`mcn_` 作为正式化升级项。
- ⚠️ 安全：`a1 faas config vars get` **明文可读**，DINGTALK_CLIENT_SECRET 当前裸存——正式版评估密钥管理（进红线待办）。
