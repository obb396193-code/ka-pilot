## 2026-08-20：奇航 `get_data` 双口径只读探针

### 已确认

| 口径 | 实证结论 | 产品用途 |
|---|---|---|
| 当天实时 | `account_realtime` / `ad_realtime` 命中当天数据，且 `last_sync_time` 显示分钟级同步新鲜度 | 实时监控、日内诊断、异常判断；页面展示“更新于”时间，不用于结算 |
| 离线结算 | 本次探针中 D-1 尚未产出、D-2 命中 | 晨报、结算、对账；运行时动态探测最新已产出分区，不硬编码 T-1 或 T-2 |

- 两条口径不是互相替代：当天运营看实时，结算对账看离线；产品界面必须显式展示口径、数据日与更新时间。
- `get_data` 为内网 HTTP GET，显式传入合法 userId；四个 resource 均返回结构化 JSON，日期使用 `YYYYMMDD`。
- 当前一期主取数路径按老板拍板走**奇航 `get_data`**。BI 后台拉取保留为备用/增强路径；当前尚未完成产品侧接入和等价性验证，不作为一期阻断。
- 详细脱敏证据与代码适配见 `docs/evidence/integration/2026-08-20-qihang-readonly-os-probe.md` 和 `docs/evidence/B10-真实奇航只读适配报告.md`。

### 仍未确认

- `account_realtime` 传历史日期是否被服务端正式支持。本次只真实执行了当天；最新版 `rta-data-queryer` 明写历史日 realtime 补洞，`ad-hourly-monitor` 也明确查询今日与昨日 realtime，证明这是官方 Skill 的实现预期，但仍不能替代服务端实测。
- 离线分区的正式产出 SLA、部分产出/完整产出状态、跨日查询语义、`hh` 边界和服务端上限。
- BI 后台的正式应用接入方式，以及其字段与奇航口径逐字段、逐数据日的等价关系。
- 本项目 Worker/FaaS 携带合法身份完成 Qihang→Raw→Canonical→质量检查的同链 trace。

## 1. 写链路 ✅ 全链路打通（最关键）

- `autopilot create --mode create_issue` → `trigger-add --kind webhook` → `curl POST 带 JSON body` → HTTP 200 返回 run_id → run 完成生成 issue → agent 评论含 `RESULT_JSON:` 行 → `multica issue comment list` 完整读回。
- **3a 动态传参成立**：webhook POST body 完整进入 agent 上下文（内嵌进 issue 描述的 JSON 代码块，字段无丢失）。**推翻 09 报告"trigger_payload 实测为 None"的旧结论**——FaaS 每次 POST 不同 payload，agent 都收得到，不必固定 prompt。

## 2. 外部读取凭证 ✅ 矛盾解开
