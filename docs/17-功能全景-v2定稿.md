# 功能全景 v2 定稿

> 建立：2026-08-17　状态：**老板已过口头版，本文为定稿归档；发 Codex 复核 + 内网实证后开工**
> 演进：13-合并版 v1 → 八路审查（15-总汇）→ 老板两批处置（台账 #100/#101）→ 值守设计（16）→ 本稿。
> 分级：S＝脊柱（最先构建）｜A＝闭环增强｜B＝沉淀放大。**不分排期全都做**，S/A/B 只是构建依赖顺序。
> 标注：✅ 数据/通路已验证｜⚠️ 数据源待验证｜🤖 依赖 Multica/agent 执行链路（统一前置＝写链路实证）。

## 0. 已锁定的全局裁决

| 裁决 | 内容 |
|---|---|
| 对象模型 | 投放任务为主线；任务→资源（账户/商品/素材）→打法→执行→结果→产物 |
| B1 多租户 | 每人登录绑自己的奇航 userId，各拉各的数据；库内 ACL 管可见范围（负责人无奇航权限也能看大盘） |
| B5 自治度滑块 | 每类自动动作三档：仅建议→确认后执行→自动+事后汇报；高档靠历史准确率达标解锁（Devix 文章生产判例）；夜间单日累计影响金额上限，失败率>50% 自动降档 |
| B7 任务主键 | **待老板核验**：奇航 task 数据准→直接用奇航 task_id；不准→自己维护。核验方式＝抽几个任务对比接口返回与实际认的数 |
| 计算分层 | 取数（agent/skill）｜口径计算聚合（我方代码，确定性）｜判断建议（LLM+规则兜底）｜渲染（我方）。agent 永不算数 |
| 采纳门 | 构建次序≠暴露次序。写权限一期只给老板；个人行为数据零上行；建议分两层放（先事实后建议）；数字与后台/BI 对平才对第二人开放 |
| 大促战役 | **不做**（老板拍板砍） |
| 审批 | ＝主动提审（自愿提交给指定人批，非超阈值强制），寄生钉钉卡片，配默认授权与超时转授权 |
