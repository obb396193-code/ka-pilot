# P2 大件设计 + 策略方案对象（2026-09-06 arch；老板 9-6 拍"功能想清楚就先做前端"，推翻 9-5 下午"先不设计"）

## 一、"策略中心的可保存方案"是什么

你 8-14 说"策略是投放广告策略：这个任务用哪个版位、哪种方式跑量好"；8-24 说"策略中心做的是不同版位、不同任务、不同出价的账户数据分析"。这两句合起来是两层：

| 层 | 是什么 | 现状 |
|---|---|---|
| **分析视图** | 版位×任务、出价×任务、业务×版位的交叉表，看"哪种组合跑得动" | v1.6 已冻 `account.pivot2` |
| **可保存的方案** | 从分析里沉淀出来的一套打法，存成对象：适用哪类任务/阶段、用什么版位、什么投放方式、什么出价、RTA 人群、预算节奏、账户矩阵、商品素材规则、适用/不适用条件、历史验证样本、版本——能绑到任务上、能复制修改、能对比 | 原型 P07 策略库 / P08 策略详情画的就是它；Codex 9-5 审查也点名要"可保存复用的投放方案"；**之前没契约** |

没有第二层，策略页就只是一张透视表，优化师每次都要重新总结"上次这类任务怎么跑的"。有了它，"稳健放量-双成本控本 v1.2.3" 这种打法能沉淀、能验证、能给新人复用——这是你说的"我们比技术更懂业务"落地的地方。本版冻成 `strategies` 对象，进任务详情第九页签「投放策略」。

## 二、六个 P2 大件的功能定义（先想清楚功能，再冻 DTO）

| 项 | 回答什么问题 | 数据从哪来 | 一期边界 |
|---|---|---|---|
| **归因树**（3.7，原型 P02） | 目标差了多少？差在成本还是量还是结构？具体是哪些户/哪些广告组/哪个环节？ | 任务 pacing + 账户日 v3 + 广告组级（个人=启航 ad_realtime，团队=ka-data adgroup） | 只算有公式的节点（成本差距/量级差距/结构差距→CPA 偏高/转化不足/账户贡献/素材效率）；算不出的标 undeterminable，不臆造"可优化空间" |
| **竞情**（3.12） | 同行在投什么素材、投多久、投哪些版位？和我的任务/素材能不能对上？ | AppGrowing（账号已有，8-18）：API / 导出 CSV / 挂链接 三种接法待 OS 实证 | 一期=导入 + 挂链接 + 人工关联到任务/素材；页面先示例态 |
| **Shadow Mode**（5.9） | AI 建议和人实际怎么做，各自之后怎么样了？规则能不能升档？ | 工作项建议 vs 24h 内该账户的变更集/带外变更；T+1/T+7 观察 | 全程叫"操作后观察结果"，不叫效果/alpha；升档考试期按 v1.4.1 四门 |
| **AI 提效看板**（7.5，`/reports/ai-impact`） | 自动化跑了多少、拦了多少异常、省了多少人时、采纳组 vs 未采纳组成本差 | 规则执行记录 + 工作项 + Shadow + 动作估时表（可配） | 四象限；人时按估时表算并标"估算"；不进绩效导出、不按人排名 |
| **周报 / 任务复盘 + Deep Research**（7.2） | 本周怎么样、下周看什么；这个任务为什么达/没达标 | 现有 DTO 拼装；复盘=Agent 异步 5-10 分钟带溯源报告 | 复盘只给证据和建议，结论标"待人确认"；生成即存知识库 |
| **知悉流 + 月度推送**（7.6） | 负责人不用处理但该知道的事；高层每月一页 | 审批结果/升级关闭/大变更/里程碑 聚合；月推=文档非页面 | 知悉流进负责人视图；月推走订阅 |
