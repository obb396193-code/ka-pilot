# B13 素材拆片运行方式

> 日期：2026-08-20
>
> 决策人：老板
>
> 状态：已拍板，进入实现

## 选择

采用 **KA Worker 确定性媒体管线 + 平台字幕优先 + API Key 云 ASR 兜底 + Claude Agent SDK 多模型结构化拆解**。

- 视频来源由 B12 OS Source Bridge 提供；
- KA Worker 下载并校验媒体，调用 FFmpeg/FFprobe 做本地抽帧、镜头切点和视觉特征；
- 有平台独立字幕时直接使用；没有时调用云 ASR Provider；
- 明确禁止本地 Whisper、本地 ASR 模型下载和本地语音推理；
- 文本证据和视觉证据交给现有 Claude Agent SDK + localhost 多模型网关做结构化拆解；
- ContentRadar 只作为只读代码与 Prompt 来源，复制必要方法后在 KA 仓独立演进，不共库、不共状态、不共运行时。

### 2026-08-20 实施期安全边界补充

“视觉证据交给模型”是目标能力，不代表默认允许把真实公司素材帧发送给任意 Provider。B13a 先完成本地抽帧和证据引用，但模型只接收字幕、镜头时间边界和确定性统计；输出显式标记 `blocked_pending_trusted_multimodal_provider`，禁止声称看过图片。只有老板后续明确允许的模型/内网网关、数据使用范围和保留策略冻结后，才接入窄范围帧读取工具。不得通过 Base64 塞 Prompt、通用文件工具或外部 URL 绕过这一门禁。

## 未选择的方案

### 整条拆片交给 OS/Multica Agent

未选原因：媒体下载、抽帧、断点恢复、幂等和结构化输出会退化成对话任务，延迟、可观测性和失败恢复不足；也会让 KA 产品继续依赖 OS 对话形态。

### KA 直接调用多模态模型读取整段视频

未选为默认原因：长视频成本、时长限制、时间戳稳定性和证据可重复性较差。可在未来作为特定模型的增强工位，但不能替代确定性抽帧和字幕时间轴。

### 直接调用 ContentRadar 服务

未选原因：违反两条产品线仓库、契约和运行时隔离的既定边界，也会形成发布和故障耦合。

## 需要外部实证但不阻塞 B13a 的事项

- OS 第五轮商品、承接页和平台字幕字段；
- 素材签名 URL 的真实 TTL；
- FaaS 对 kwimgs/yximgs CDN 的真实下载；
- 云 ASR 的最终 Provider/接口契约。
