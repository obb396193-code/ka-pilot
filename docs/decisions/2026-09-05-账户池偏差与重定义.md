# 账户池偏差与重定义（2026-09-05 arch 核对）

> 触发：老板 9-5 深夜"账户池要看全量户处于哪个阶段、哪些没用、按产品名划分、哪些备用；一键开户这些原子操作——是不是做偏了？"
> 核对材料：老板原话（Codex 会话 8-13～8-25）、需求总表 REQ-040～047、PRD v1.6、功能全景 v2 域五、原型图 P09/P11（R-002）、契约 accounts/ACCOUNTS-LIST-001、F-006 页面规划 §3、前端现状 `apps/web/app/(main)/accounts`。

## 一、逐层对照

| 层 | 账户池写成什么 | 判定 |
|---|---|---|
| 老板原话 8-13 | "还应该有个账户池功能"；"CLI 可视化工具箱把查数、改价、基建、关账户做成按钮，这个要做"；"开户—充值—基建—跑量—监控算工作流"；"内置 agent 完成从开户准备到充值到基建到跑量到监控这个 SOP" | 基线 |

| PRD v1.6 | 账户池只有一行"全户状态总览"，**没有专节**（2.3.x 只写了工作台/任务详情/透视/账户详情/基建）；库存语义散落：§3 "空闲/可用筛选起步"（B 级后置）、"双层标签体系"、4.5 加/关账户 | **缺口起点** |
| 契约 | `accounts.lifecycle_stage ∈ cold_start\|ramping\|stable\|declining\|paused\|closed\|unknown`——**全是投放中的状态，没有"可用/待开户/待充值/待搭建/备用"**；无 product 字段；ACCOUNTS-LIST-001 筛选只有 stage/starred/tags/owner，响应是指标行 | 继承 PRD 缺口 |
| F-006 页面规划 §3 | DataTable 壳 + 列（账户/负责人/阶段/消耗/CPA/考核价/达标/余额倒计时/关联任务）+ 导入账户 | 指标表思路，无流水线、无产品分组、无批量→变更预览 |

**根因**：PRD 定稿时账户池没写专节，原型图 P09 的库存语义（没投的四个状态、产品归属、备用）没有回写进 PRD/契约；后面契约、页面规划、前端都从 PRD 继承，于是"账户资源"被做成了"账户数据"。原子操作没偏：CLI 工具箱在契约 v1.5 `capabilities`（自动化导航下，与原型 P11「原子能力」tab 一致），开户流程向导在 v1.4 `POST /accounts/open-flow`。

| 要的 | 现状 | 差 |

## 三、重定义提案（待老板拍板后冻 v1.5.1）

1. **账户两套状态并存**：`pool_status`（库存态，账户资源页主视角）+ `lifecycle_stage`（投放态，规则引擎用）。
   `pool_status ∈ available（可用未分配）| assigned（已分配任务未投）| pending_open（待开户）| pending_recharge（待充值）| pending_build（待搭建）| in_delivery（在投）| paused | closed | abnormal`。
   **推导规则**（系统算，人可覆盖并留记录）：无任务绑定→available；有任务无消耗且余额 0→pending_recharge；有余额无 unit→pending_build；有消耗→in_delivery；`closed_at`→closed；异常规则命中→abnormal；`pending_open` 只由开户流程向导写。in_delivery 内再用 lifecycle_stage 细分冷启动/放量/稳定/衰退。
2. **产品归属**：`accounts.product_name TEXT, product_ref TEXT`（个人空间人工/导入维护；团队空间同步 ka-data `product_name/bound_by`）；账户池按产品分组、任务详情账户页签按产品汇总。
3. **ACCOUNTS-LIST-001 扩**：筛选加 `poolStatus/product`；`groupBy=lifecycle|product|owner|task`；新增 `GET /api/v1/accounts/pipeline` → 9 态计数 + 昨日增减（原型顶部卡）。
4. **账户池页面重定义**（替换 F-006 §3）：顶部流水线 9 卡（点卡即筛）→ 分组开关（生命周期/产品/负责人）→ 表（原型 12 列，指标列走 v3 三态）→ 行内「建议下一步」（来自工作项/规则，无则空）→ 勾选批量 → **变更集组预览**（每户一条变更集，一页预览一次确认）→ 右栏：待搭建队列（P1）、容量分布、匹配建议（P1）。主按钮：**新建账户**（开户流程向导 open-flow）/ 导入认领 / 批量操作。
5. **官方工作流模板补**：「新任务开户到基建」（开户→充值→基建→冷启动观察），与 P11 一致。
6. **变更集组**：`POST /api/v1/changesets/batch {items_by_account:[...]}` → `{group_id, changesets:[...]}`，预览/确认按组，执行仍逐账户（三键不变）。

## 四、影响
