# 侧栏 vs 顶栏导航：业界定论与决策记录

> 日期：2026-08-19　决策人：老板（拍板侧栏先行）+ arch（业界研究）+ Codex（独立验证）

## 决策结论

**侧栏先行**（可折叠 240px → 64px），保留 layout 层切换能力，B1c 后出顶栏对比版给老板真页面拍板。

---

## 一、NN/g (Nielsen Norman Group) 核心观点

从 NN/g 的 tabs 文章提取到的关键点：

### Tab 适用场景（这些原则也适用导航选择）
1. **信息不平等时**：默认 tab 获得更多关注，其他 tab 可能被忽略 → 适合有主次之分的内容
2. **标签可以简短时**：短标签节省横向空间，避免横向滚动
3. **用户不需要同时看到不同 tabs 的信息时**：否则反复切换增加认知负担

### In-page tabs vs Navigation tabs 区分
- **In-page tabs**：在单页内组织展示相关内容，不做导航
- **Navigation tabs**：用于跨页面导航，需要清晰标记用户位置

→ **结论**：我们的 9 项导航是 Navigation tabs（跨页面），不是 In-page tabs

---

## 二、Ant Design 提取

### 布局模式
- **Left-Right Layout (侧栏)**："fix the left navigation bar and dynamically scale the right work area"
- **Top-Bottom Layout (顶栏)**："the intermediate main content area is dynamically scaled"

### 导航定位
- **顶部导航**：provides all the categories and functions（提供全部分类和功能）
- **侧边导航**：provides the multi-level structure（提供多层级结构）

→ **暗示**：多层级、复杂结构 → 侧栏；扁平、全局功能 → 顶栏

---

## 三、实际案例观察

### 蝉妈妈（chanmama.com）
- **形态**：纯顶栏（8 个一级导航横向排列）
- **特点**：扁平结构、每个导航下内容独立、无深层嵌套、无实时警报需求
- **用户场景**：查询式使用（来看榜单/查博主/看数据，完事就走）

### shadcn dashboard-01
- **形态**：可折叠侧栏（240px → 64px）
- **特点**：支持角标（badge/notification dot）、可容纳更多项、支持分组、适合常驻型应用
- **用户场景**：工作台类应用（长时间停留、需要实时监控、频繁切换不同域）

## 四、核心判断维度总结（从业界实践提炼）

| 维度 | 侧栏优势 | 顶栏优势 |
|---|---|---|
| **导航项数量** | 7-15 项都舒适 | 5-8 项为佳，超过挤 |
| **实时状态/角标** | 天然支持（每项旁边挂红点/数字） | 难实现（横向密集，角标挤） |
| **层级深度** | 支持分组/二级展开 | 扁平为主，二级靠 dropdown |
| **屏幕利用** | 纵向空间充裕（1080p 竖向够长） | 横向空间有限（1366/1440 宽度紧张） |
| **用户使用模式** | 常驻型工作台（长时间停留、频繁切换） | 查询式工具（快速定位、完事离开） |
| **品牌/logo** | 顶部左侧固定，视觉稳定 | 顶部居中/左侧，但导航挤压空间 |

## 五、对我们项目的判断（数据密集型 B 端）

### 我们的特征
1. **9 项一级导航** → 顶栏偏挤（尤其 1366px 屏幕）
2. **实时警报需求强** → 工作台需要红点、集成与通知需要角标（PRD §2.1 明确"警报监控区 P0/P1 滚动+值守状态一眼可见"）
3. **使用模式 = 常驻工作台** → 优化师早上 5 分钟巡检，不是"查完就走"
4. **数据密集** → 页面内已经很挤（表格/图表/筛选器），导航不应再占横向空间
5. **未来扩展** → 可能加"移动端适配"域（PRD 提到过），侧栏更灵活

### 业界数据密集型 B 端案例
- **Grafana**：侧栏（监控类，实时状态密集）
- **Metabase**：侧栏（BI 工具，多 dashboard 切换）
- **Notion**：侧栏（知识管理，多 workspace/page 树）
- **Linear**：侧栏（项目管理，issue/project/team 多维）
- **蝉妈妈**：顶栏（查询式，无实时监控，扁平结构）

→ **数据密集 + 实时监控 + 常驻工作台 = 侧栏是主流选择**

## 六、决策过程

1. **老板初问**："我们这个应该用顶栏还是侧栏好呢？站在用户角度，不只是美观，还要方便实用"
2. **老板拍板**："你按把侧栏先做好，到时候我们再看一版顶栏对比下"
3. **Codex 独立验证**：给出"左侧一级导航 + 顶部全局工具栏 + 页内横向 Tab"建议，完全命中业界最佳实践
4. **arch 业界研究**：NN/g + Ant Design + 数据密集型 B 端案例全部支持侧栏选择

---

## 七、实施方案

1. **F-001 骨架**：直接用 shadcn dashboard-01 原生 Sidebar（240px → 64px 可折叠）
2. **角标位预留**：每项导航支持 badge（工作台红点、集成与通知数字角标）
3. **保留切换能力**：layout 层抽象 nav 形态（side|top 配置切换），代码支持但先不做顶栏实现
4. **B1c 后对比**：等有真实数据页（完整数据总表/大盘/透视），arch 派 F-00x 任务出一版顶栏，老板真页面对比拍板终选
