# B1c 语义查询内核边界

> 日期：2026-08-19
> 决策者：老板

## 决定

采用“仓储内核先行”：先在后端独立工作树实现 PostgreSQL 语义查询内核，暂不接前端 API。

当前只开放数据库已经能可靠表达的任务、业务、账户维度。`tier` 和版位、出价工具、UBP、抵扣区间等维度等契约与数据源补齐后再接。

同一账户同一天多任务归属不做隐式分摊，查询任务/业务维度时明确报冲突。

## 未选方案

- 同批实现 Web API：当前会与前端工作树和未冻结 DTO 发生耦合。
- 先做通用报表 DSL：范围过大，无法先证明核心查询口径正确。
- 多任务时重复计入每个任务：会导致管理大盘总量虚增。
- 自动选择最新任务：会掩盖数据治理问题并改变历史口径。
