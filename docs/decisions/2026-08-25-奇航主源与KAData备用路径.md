# 奇航主源与 KA Data 备用路径

> 日期：2026-08-25  
> 状态：老板已拍板  
> 决策者：老板

## 决策

1. 一期业务页面继续使用原有奇航取数设计：奇航直取后进入平台 Canonical（统一格式）与 PostgreSQL，作为投放经营功能的默认数据通路。
2. KA Data 与奇航属于同一业务数据的不同获取路径。KA Data 只作为备用 Adapter（适配器）和技术诊断源，不再作为业务功能、首次内网部署或页面推进的前置条件。
3. 普通用户界面默认不展示 `ka_data / platform / reconcile` 三态切换和“对账差值”。技术诊断能力保留在代码中，由显式 feature flag（功能开关）和管理员权限控制。
4. KA Data 不可用、口径元数据缺失或两路数据不同，不得阻断奇航主路径的页面、工作流和只读联调；也不得静默把 KA Data 值覆盖成平台主数。
5. 现有双数据代码不删除。在真实奇航链路稳定前保留可回退能力；后续是否把 KA Data 升为自动故障切换源，需要单独冻结新鲜度、完整性、幂等和告警规则。

## 没选的方案

- 没选“双源对账先完成，业务页面再推进”：两条路径读取的是同源业务数据，持续把差异产品化会拖慢核心经营功能。
- 没选“立即删除 KA Data”：现有适配、契约和审计资产仍可用于诊断和备用，删除会丢失回退能力。
- 没选“KA Data 失败时浏览器自动切源”：未冻结新鲜度和一致性规则前，静默切源会让用户不知道看到的是哪份数据。

## 产品口径

对账差值只表示同一指标经两条技术路径取得后的差异，例如奇航为 100、KA Data 为 98，差值为 2。它用于排查取数、时区、截断或缓存问题，不代表业务新增了第三个指标，也不作为普通用户的经营判断入口。
