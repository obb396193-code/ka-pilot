# 双数据逐指标权威矩阵裁决

> 日期：2026-08-24  
> 裁决人：老板  
> 状态：已拍板

## 冻结原则

权威按业务用途和时效定义，不把某一数据源宣布为所有场景的唯一真相。同一字段在不同场景可以有不同默认来源，但页面、导出、Agent 和报告必须显示来源、截止时间、口径版本和完整性状态。

## 权威矩阵

| 场景/指标组 | 默认权威来源 | 使用规则 |
|---|---|---|
| 跨媒体经营、大盘与部门汇总 | KA Data | 作为运营权威版，用于部门查看、跨媒体比较和经营汇报 |
| 历史运营分析、历史趋势 | KA Data | 默认使用 KA Data 已维护的历史口径；platform 历史值保留用于对账 |
| 商品、素材、广告组、BI 分析 | KA Data | 以其现有事实表、维表和运营维护口径为默认来源 |
| 当日实时消耗、转化、CPA | platform | 使用启航实时/平台 canonical 数据；必须显示数据截止时间 |
| 小时 pacing、时段趋势 | platform | 使用已经验证的小时分片语义；截断或小时不完整时禁止全量结论 |
| 异常诊断、账户/广告下钻 | platform | 诊断证据与页面下钻使用同一版本的平台事实层 |
| 执行前检查、媒体对象状态 | platform | 写操作开放后仍必须实时复核 from value、权限和对象状态 |
| 动作效果回收、T+1/T+7 | platform | 与变更集、执行记录和实际媒体状态关联；KA Data 可在对账中作为经营结果参考 |
| 考核价、返点、赔付、现金成本 | 分来源版本化 | 两边各自按来源和生效版本计算；禁止跨来源抽字段混算 |

## 对账规则

- `reconcile` 继续采用方案 A：双边并列，不生成统一主数。
- 双方都完整且口径可比时，后端才计算差值和差异率。
- 任一侧缺失、partial、truncated、stale 或口径不可比时，保留双方原值和状态，不输出误导性的差异结论。
- LLM 只能解释已经存在的来源和规则证据，不能决定权威来源，也不能补造未知差异原因。

## 后续变更

新增指标必须先登记指标定义、业务用途、默认来源、备选来源、版本和可比条件，再进入 Contract。不得由前端或单个 Adapter 临时决定来源优先级。
