# 详情对象账户作用域持久化

## 决定

`work_items` 和 `changesets` 的账户作用域按
`(workspace_id, media, account_id)` 持久化。详情 API 只能读取与服务端批准 scope
精确匹配的对象，不得将授权降级为单独 `account_id` 集合。

## 历史数据迁移

- 工作项有 `account_id` 时，必须在同 workspace 内唯一命中一条 accounts 媒体记录，否则迁移中止。
- 关联工作项的历史变更集继承其三元组。无关联且无法证明账户归属的历史变更集保持空 scope，详情 API fail closed。
- 新变更集必须显式写入 `media + account_id`；如关联工作项，两者 scope 必须一致。

## 未选方案

- 不从 evidence JSON 推测 media：JSON 不是可依赖的对象身份列。
- 不按 account_id 独立鉴权：同 workspace 跨媒体同号会串权。
- 不给历史行填默认 `KUAISHOU`：默认值会掩盖无法证明的历史归属。
