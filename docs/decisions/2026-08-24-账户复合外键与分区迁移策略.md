# 账户复合外键与分区迁移策略

日期：2026-08-24  
状态：已实现，待 Claude/arch 复审

## 决策

所有直接持有账户身份的表统一以
`(workspace_id, media, account_id)` 外键引用 `accounts`：

- `task_accounts`
- `metrics_raw`
- `account_metrics_daily`
- `account_balance`
- `ad_metrics_hourly`
- `ad_entities`

删除账户采用 `RESTRICT`，不得留下孤儿历史或由级联删除抹掉投放证据。Raw 表也挂外键；
当前没有允许“未知账户先落 Raw、事后认领”的已冻结业务语义，因此不为它保留例外。

## 上线方式

- 普通表：`ADD CONSTRAINT ... NOT VALID` 后单独 `VALIDATE CONSTRAINT`，降低长时间强锁风险。
- 分区父表：PostgreSQL 16 不允许父表使用 `NOT VALID` 外键。迁移先在同一事务中显式扫描
  孤儿 tuple，确认无孤儿后再添加父表强制 FK；该步骤需要安排数据库迁移窗口，并在生产数据量上
  先测扫描与锁时长。
- 任一孤儿存在时整笔 migration 回滚，不自动补 media、不删除历史行、不创建占位账户。

## 验证

真实 PostgreSQL 测试必须覆盖：六个父表 FK 存在；canonical、余额、Raw 的孤儿插入均返回
`23503`；migration `up → down → up` 可重放；降级后孤儿能插入、重新升级后再次被拒。
