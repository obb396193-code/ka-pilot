# 原子能力与工作流全量范围澄清

> 日期：2026-08-24  
> 确认人：老板  
> 状态：既有范围再次确认，不是新增功能

## 产品范围不缩减

产品不是只做“修改出价”或任意单个写动作。以下能力按现有 PRD 和验收基线继续全部建设：

1. **Capability Registry（原子能力目录）**：每项能力登记参数 Schema、读写级别、权限、渠道、执行器、版本、dry-run、可用状态和 runtime verification。
2. **操作工具箱**：把查数、改价、预算、暂停/启用、改时段、基建、账户操作等已取得合法通路的原子能力表单化，供用户单点调用。
3. **工作流画布**：使用数据、计算、Agent、执行、协作、控制六类节点组合业务流程；模板与自建流程使用同一版本化数据模型。
4. **模板商店与 Agent 帮编**：官方模板可复制修改；自然语言只能生成可编辑流程草稿，必须经过 Schema 校验和模拟运行才能发布。
5. **统一执行闭环**：页面按钮、钉钉卡片、工作流节点和内置 Agent 都调用同一 Capability Registry；写节点统一经过变更集、dry-run、风险检查、确认、幂等执行、审计、UNKNOWN 对账和效果回收。

## “单能力 canary”只是什么

工程联调时可以先选一个已授权、可回滚、容易核证的能力做 canary（探路测试），用于验证产品→Registry→执行器→回执→回查整条链路。它只表示验证顺序，不代表只实现该能力，也不需要老板把产品范围缩成一个动作。

## 能力状态边界

“全部要做”不等于把未取得接口或权限的能力伪装成已可用。每项能力必须独立经过：

```text
documented → authorized → wrapped → contract_aligned → runtime_verified → product_enabled
```

未达到对应状态时可以进入目录、设计和工作流候选，但产品必须显示不可用原因或人工/深链降级，不能假执行。
