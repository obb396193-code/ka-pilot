# 双数据账户 ID 同源直连裁决

> 日期：2026-08-24  
> 事实确认人：老板  
> 状态：已确认

## 已确认事实

KA Data 与启航/platform 使用相同的快手账户 ID，不存在账户级不同命名空间。因此首轮双数据对账不建立账户 ID 映射表，不建设人工映射确认页面。

## 实现规则

- 账户对账键固定为 `(workspace_id, media, account_id)`；
- `workspace_id` 用于租户隔离，`media` 防止未来不同媒体出现同号碰撞；
- 同一键只有一侧有数据时，状态为该来源缺失/unmatched-by-presence，不得解释为 ID 待映射；
- 上线前用脱敏样本验证两侧 account ID 的格式、类型和前导零处理一致；
- 禁止仅按账户名称 join；名称只用于展示和异常核查。

## 保留边界

任务、商品、素材、广告组等其他对象是否同 ID 尚未确认。只有未来实证某类对象存在不同命名空间时，才为该对象单独设计映射关系；不得提前建设通用映射平台。
