# 前端 UI 资产复用体系决策记录

> 日期：2026-08-19  
> 决策人：老板  
> 状态：已拍板

## 决策结论

采用“**完整目录 + 按需复制官方源码 + 来源隔离 + tweakcn 多主题**”的混合体系。

1. shadcn/ui 与官方 Blocks 作为页面壳和基础结构主底座。
2. coss/ui 作为细节组件优先库；日期/范围选择、Command、组合框、字段组、弹层、按钮组和空态等先查 Components/Particles，有成品就复制源码适配。
3. ReUI 承接复杂 Data Grid/筛选/列配置；Tremor 承接 KPI 和经营看板版式。
4. React Bits 正式进入资产池，Aceternity、Magic UI、React Bits 用于克制的局部动效。
5. tweakcn 是后续运行时多风格切换的核心能力，不只作为配色参考。
6. 建立所有官方候选的完整元数据目录，但运行仓只安装实际用到的源码。

## 技术边界

- shadcn/Radix 固定在 `components/ui/`。
- coss/Base UI 固定在独立目录，显式导入，不覆盖 shadcn 同名文件。
- 两种底层可以出现在同一页面，但不把 Radix 和 Base UI 行为 API 混进同一个 primitive。
- 本地主要新增业务适配层，不重新手写官方已有的骨架和通用交互。
- 第三方源码进入仓库前必须登记来源、上游 ref、许可证、依赖和修改说明。

## 首个落地样板

使用 coss/ui 日期选择器或日期范围选择器走通完整链路：

```text
目录发现 → 官方预览 → Registry 源码检查 → 独立路径复制
→ 主题 token 与中文适配 → 业务薄封装 → 可访问性/多主题/响应式验证
```

## 没选的方案

### A. 全量下载所有第三方源码

未选原因：上千份未使用代码会增加依赖、升级、许可证和检索噪音；“知道官方有什么”由完整目录解决，不需要把所有源码装进运行仓。

### B. 只用 shadcn/ui

未选原因：基础层稳定，但日期筛选、复杂数据交互、看板组合和高级细节覆盖不够；会重新产生大量手写组件。

### C. 用 coss/ui 全量替换 shadcn

未选原因：当前项目已经以 shadcn/Radix 和 dashboard-01 为骨架，全量替换会扩大迁移面。coss 以独立 Base UI 细节层进入，能取得视觉和交互收益，同时保留现有底座。

### D. 自己再造一套统一 primitives 层屏蔽所有来源

未选原因：会隐藏 Radix/Base UI 的焦点、事件、portal 和受控状态差异，形成新的维护层。只在业务语义上做薄适配，不造万能底层。

### E. 每种风格复制一套页面

未选原因：功能修改会产生多分支。采用同一 DOM/组件树 + tweakcn token + density/motion 变量切换。

## 后续变更规则

如要更换主底座、引入有付费或强 copyleft 约束的资产、或把某个第三方库全量装入运行仓，需另立决策记录，说明迁移范围和许可证影响。
