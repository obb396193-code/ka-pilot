# 双数据对账主数语义裁决

> 日期：2026-08-24  
> 裁决人：老板  
> 状态：已拍板

## 选择

采用方案 A：

- `ka_data` 模式只展示 KA Data 数值；
- `platform` 模式只展示自建平台数值；
- `reconcile` 模式并列展示两边原值、差值、差异率、双方 lineage 和可比状态；
- `reconcile` 不生成第三个“统一主数”，也不静默选择一边覆盖另一边；
- KA Data 标记为运营权威版；当日实时诊断、小时 pacing、执行前检查和效果回收仍使用 platform。

## 没选的方案

### B. 所有场景一律 KA Data 为主

未选原因：会削弱自建实时诊断、执行前检查和动作效果回收，无法表达数据时效与用途差异。

### C. 当日自动以 platform 为主、历史自动以 KA Data 为主

未选原因：同一页面会随日期和日切自动更换主数，用户难以判断变化来自业务还是来源切换；实现和审计也更复杂。

## Contract 影响

- reconcile DTO 必须保留 `kaData` 与 `platform` 两个独立值对象；
- 两侧各自携带 lineage、availability、truncated/partial 与口径版本；
- `delta/deltaRate` 只在双方可比且完整时由后端计算；
- 任一侧缺失或不可比时保留另一侧原值，并返回明确状态，不显示伪造的 0 或统一值。
