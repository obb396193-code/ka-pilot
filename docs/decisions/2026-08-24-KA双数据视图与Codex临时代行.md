# 决策：KA 双数据视图与 Codex 临时代行

> 日期：2026-08-24  
> 状态：老板已拍板；待实现与 Claude 复审

## 选择

1. 一套产品提供 `KA Data 运营权威版 / 自建主线版 / 对账比较` 三种数据视图，不复制两套产品。
2. KA Data 先以内部共享只读通路投入试用；每用户授权治理后补，不阻塞当前价值验证。
3. 自建数据与执行闭环继续作为产品主线，KA Data 不取代奇航实时巡检、账户动作和效果回收。
4. Claude 暂不可用期间采用“可复用纵向切片”方案：Codex 临时审查 + Codex 临时前端两个可见任务并行，结果全部等待 Claude 终审。
5. Claude Code 原始会话不伪造成 Codex 原生任务，采用“原始 JSONL 保留 + 可审计上下文包 + 新 Codex 任务”的迁移方式。

## 没选的方案

### 两套独立产品

未选。会导致同一指标、筛选、页面和后续功能双份维护，数据差异也更难解释。

### 等 Claude 恢复后再动

未选。后端契约、双数据适配和纵向切片都有可隔离工作，可以先形成候选，等待终审不等于停止开发。

### Codex 一次做完整九页正式前端

未选。当前 `fe/f001` 有未整理改动，视觉与契约仍需 Claude 复审；一次铺满会扩大返工面。先验证一条完整业务链路更可控。

### 直接导入 Claude Code JSONL 为 Codex 会话

未选。两者会话协议不同，伪造会破坏工具事件、附件、权限与父子关系的可信度。

## 约束

- 当前 `fe/f001` 工作区零触碰；临时前端必须用独立 `codex/` 分支和 worktree。
- 共享读权限只属于内部试用阶段，不得下发浏览器或写进仓库。
- Codex 审查只叫“预审”，不能替代 Claude/arch 终裁。
- 对账保持两边原值和来源，禁止静默合并。
