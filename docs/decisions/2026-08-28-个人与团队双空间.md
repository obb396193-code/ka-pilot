# 一期个人与团队双空间

> 日期：2026-08-28
> 决策人：老板
> 状态：已拍板；覆盖 `2026-08-28-一期一人一工作区与个人数据隔离.md` 的个人-only 边界

## 决定

一期提供两个相互隔离、可切换的数据空间：

1. **我的工作台（personal workspace）**：默认入口。业务数据初始为空，只包含本人接入或显式
   获授的媒体账户，以及这些账户产生的任务、工作项、诊断和操作记录。本人私有的 `self`、
   `agent_question` 等无账户工作项只存在于个人空间。
2. **团队数据（team workspace）**：加入该团队的 active member 可读取团队账户、任务、指标和
   账户型异常/工作项。团队空间一期只读，不开放媒体写、跨用户派发、个人行为审计或绩效排名。

用户默认进入 personal workspace，可显式切换到自己有 active membership 的 team workspace。
“团队所有人可看”仅指该 team workspace 的成员，不是任意登录用户。

## 数据源与权限分离

KA Data 或部门级奇航通路只是 team workspace 的服务端取数 Adapter，不是授权依据。团队数据必须
先写入独立 team workspace，再由 membership 授予只读能力；禁止因为请求来自 KA Data 就跳过
workspace 隔离。服务端可按配置选择已验证的数据源，一个来源不可用不得阻断 personal workspace。

personal workspace 的媒体操作仍使用本人权限，并保持 `preview/dry-run → 风险检查 → 人工确认 →
执行 → 审计 → 效果回收`。team workspace 不得借共享凭证执行写操作；从团队视图发起动作时，
必须回到 personal context，重新验证本人对目标账户的 execute grant。

## 公共资产

官方模板、规则和教学内容是版本化公共只读资产，可在空 personal workspace 中展示；它们不属于
个人或团队业务数据，不得携带真实账户 ID、金额、诊断、工作项或用户行为。

## 未选择方案

- 未把个人与团队数据放在同一 workspace 后靠前端筛选：容易串数，且无法证明租户隔离。
- 未让 team workspace 直接继承共享媒体写权限：共享读取与可执行授权是两件事。
- 未把全部团队账户编码进浏览器或超长 account-scope header：团队范围必须由服务端 workspace
  membership 和持久化数据边界解析。
