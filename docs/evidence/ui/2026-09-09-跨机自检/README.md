# 跨机一致性自检（fe 2026-09-09）

**问题**：Mac 上看着好的界面，部署到内网、同事用别的电脑打开会不一样。
**方法**：把 Mac 上看不见的三类环境差异逐条模拟出来实测，而不是靠猜。

## 一、模拟 Windows 有效宽度 + Windows 中文字体

Windows 的滚动条**永久占约 15px**（macOS 是浮层，占 0），所以同样一台 1366×768 @125%
的机器，实际排版宽度是 1093 − 15 = **1078px**，比我们在 Mac 上量的还窄一截。
中文字体也不同：Mac 走苹方，Windows 没有苹方 → 落到我们自己打包的 MiSans。

测法：同源 iframe 钉死宽度 + 覆盖 `--font-sans` 去掉苹方，量根元素横向溢出。

| 视口宽 | 对应机器 | 结果 |
|---|---|---|
| 1078 | 1366×768 @125%（内网同事主力机）| 12 页全部 **0px** |
| 896 | 1366×768 @150%（最极端）| 全部 **0px** |

字体度量实测：MiSans 比苹方**窄 2.0%**、行高**矮 1.5px**（14px 字号）——
即 Windows 上文字只会更省地方，不会撑破。

## 二、系统深色模式

内网同事把 Windows 设成深色主题时：页面本体仍是浅色（我们的三档配色是「颜色用到哪一步」，
不是明暗主题，不跟随 `prefers-color-scheme`）——**这一点是对的，两边看到的一样**。

但发现一个漏：`color-scheme` 没声明，**原生控件会跟系统走**——日期选择器弹层、下拉、
滚动条会渲染成深色，页面浅色，两边打架。已钉死 `color-scheme: light`。

## 三、字重

我们打包的 MiSans 只生成了 **400 / 500 / 600** 三档，没有 700。
`font-bold`（700）在 Windows 上拿不到真字面，浏览器合成假粗体，发糊——Mac 上是苹方真粗体。
生产代码里只有知识库文档标题一处用了 `font-bold`，已改成 `font-semibold`（站内其他标题本来就是这档）。

⚠️ **遗留**：知识库编辑器里用户自己加粗的正文会产生 `<strong>`（700），同样会假粗。
彻底解法是把 MiSans Bold 也切片打包（npm 包里有），代价是构建产物 +约 2MB。
等接口开放、真有用户内容时再定，已写信箱问 arch。

## 四、数字对齐

金额/数量列靠 `tabular-nums` 对齐。实测数字由 **Geist** 提供（在 CJK 字体之前），
`1111111111` 与 `8888888888` 同宽 ——**与操作系统无关**，不会因为换机器而参差。

## 五、已修

| 改动 | 为什么 | Mac 上的影响 |
|---|---|---|
| `html { color-scheme: light }` | 系统深色时原生控件不再跟着变深 | 无 |
| `html { scrollbar-gutter: stable }` | Windows 滚动条来回出现会让整页横向抖 15px；预留后宽度恒定 | 无（浮层滚动条不参与布局，实测占宽仍为 0） |
| 知识库标题 `font-bold` → `font-semibold` | 700 没有真字面，Windows 上是合成假粗 | 极轻微，与站内其他标题一致 |

改完复测：1078 × 8 页、896 × 3 页，横向溢出仍全部 0px；Mac 上滚动条占宽仍为 0、观感不变。

## 六、测不了、需要确认的（最大风险）

我们的样式依赖这些较新的 CSS 特性，**最低要 Chrome / Edge 119**：

| 特性 | 最低版本 | 用途 | 不支持的后果 |
|---|---|---|---|
| `oklch()` | 111 | 全套颜色变量（Tailwind v4 基线）| **全站颜色失效** |
| `oklch(from …)` 相对颜色 | **119** | 主色派生（8 处）| 主色/按钮/选中态没颜色 |
| `color-mix()` | 111 | 边框 / hover 派生色 | 局部颜色失效 |
| 容器查询 `@container` | 105 | 8 个文件的响应式 | 布局塌 |
| `:has()` | 105 | 1 处 | 局部样式失效 |
| `field-sizing` | 123 | 文本域自动长高 | 只是不自动长高，可接受 |

内网机器如果装的是老版本 Chrome、老 Edge，或者 360 / IE 内核的浏览器，
**不是「不好看」而是「颜色和布局整个垮掉」**。需要内网同事报一下浏览器版本
（地址栏输 `chrome://version` 第一行）才能定要不要做降级兜底。
