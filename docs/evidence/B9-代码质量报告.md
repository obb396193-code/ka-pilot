## 4. TDD 与故障证据

1. Handler 测试先因旧逐行方法不存在而 5/5 RED，再改批量端口转绿。
2. 缺失复合键、重复/越界结果、非法 chunk 均 fail-closed。
3. 第二批 Upsert 中断时首批可保留，Run 记录 `aggregate:upsert` 失败，质量 Job 不派生；重试依靠同复合键 bulk Upsert 收敛。
4. Repository 真实 PG 测试覆盖多账户/多日期、有效配置、14 个非零历史日、批量 Upsert、缺账户和跨 workspace。
5. 纵向集成不使用内存数据库：Full/Raw/Job/Canonical/Quality/Semantic/WorkItem/ReportFacts 全为生产实现。
6. 同 accountId 在两个 workspace 下分别得到 5100 与 9999，语义查询无串租户。
7. 规则首次扫描创建工作项，重扫合并，外发告警 idempotent；报告 KPI/趋势/任务维度与语义查询同口径。
8. 质量 source 反例证明旧实现会把 realtime 当天误报为 Raw=0；修复后 offline/realtime 两日 total reconciliation 均通过。

## 5. 性能与资源证据

- 端口调用由 `3N+4` 降到 `3×ceil(N/250)+4`；5000 行从 15004 降为 64。
- 真实 PG 三次中位数：100/1000/5000 行为 16.818/71.545/394.974ms。
- 最终 Canonical 行数精确等于输入规模，重复 Upsert 不增行。
- 代表性账户、Canonical workspace/date 查询走 Index Scan；Raw 最新选择根为 Unique。
- benchmark 只允许 localhost/127.0.0.1/::1:55432/ka，限定规模、迭代和 chunk，并在 finally 自动清理。
- 自动测试后实查 `pg-benchmark-%` workspace 为 0。

## 6. 质检中发现并修复

1. PG benchmark 初版只有手工运行，模块覆盖率 14.13%、Worker 总覆盖 87.38%；补 100 行真实 PG 自动测试后模块 98.34%、Worker 91.69%。
2. 参数解析 complexity 15、EXPLAIN 汇总 11；拆成解析、校验和计划摘要纯函数后均 ≤10。
3. Full/Incr ETL Run scope 漏 workspaceId；纵向测试验证后补齐。
4. 数据质量只汇总 offline Raw；当天 realtime Canonical 稳定假异常，改为按 field_sources 选择对应 Raw。

## 7. 已知边界与风险

1. Raw 是 append-only 审计记录；源 Job 在 Raw 写后崩溃重试会留下重复抓取。`loadMergeInputs` 取每资源 latest，Canonical Upsert 收敛，但 Raw 物理去重尚无请求幂等键，需 arch 决定是否保留抓取历史或增加 request/run identity。
2. Full/Incremental 单次账户 ID 上限 1000；5000 行 PG benchmark 是数据库 fixture，不代表奇航单请求支持 5000 ID。
3. `ad_realtime` 极宽返回仍可能让 Raw bulk INSERT 接近 PostgreSQL 参数上限；P1-14 只完成响应/URL/ID 资源预算，生产 Raw 分片仍需补。
4. 真实规则候选 Provider、rule/report Job payload、触发器和输出存储未冻结，所以纵向测试适配器不注册 Runtime。
5. 无真实奇航字段/限流、Multica/OS、Secret、模型 Provider、钉钉 Stream、FaaS/共享 PG 联调。
6. 性能只测本机热缓存、单 workspace、无并发；不包含网络、Job SQL、质量 SQL、WAL/冷缓存或 p95/p99。

以上边界均写入 P-016，不把测试闭环冒充生产通路完成。
