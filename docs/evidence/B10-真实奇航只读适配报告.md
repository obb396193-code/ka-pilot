## 1. 证据边界

本轮真实请求由老板转交给内网 OS Agent，在当前合法身份下执行；Codex 本机不能访问阿里内网。OS 回传包含命令/源码核验、四类只读请求、脱敏字段字典、耗时和响应大小。本仓不复制原始回传，避免真实业务规模进入可能外发的文件；脱敏准入记录见 `docs/evidence/integration/2026-08-20-qihang-readonly-os-probe.md`。

因此本轮可以确认“上游协议与返回事实”，但还不能宣称“本项目 Worker/FaaS 已真实联通”：当前没有产品代码 SHA、产品 job/run ID、Raw 落库、Canonical、质量检查和共享 PostgreSQL 的同一条真实 trace。

## 3. 本批代码修复

1. Qihang Client 对 `beginDate/endDate/ds` 只接受 `YYYY-MM-DD` 或 `YYYYMMDD`，统一发送 `YYYYMMDD`；非法日历日期在网络前失败，且不重试。
2. Full ETL 从 D-1 开始有界向前查 3 日，首个非空离线分区命中后停止；Canonical 范围纳入实际命中日。该策略只解决已实证的延迟，不把跨日区间行为当成事实。
3. 历史日若离线行含 `account_real_conversion`，Canonical 优先采用并标记 `offline`；字段缺失时继续由实时行补齐。
4. 现有动态 `Record<string, unknown>` Raw 信封保持不变，未把旧文档 23 列写成固定 Schema。
