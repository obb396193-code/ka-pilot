## 1. 本批实现

1. 新增 `account` metadata Adapter：`workspaceId/media` 只取 Worker 任务中的受信范围，上游 payload 无法覆盖；只接收精确的 `account_id/account_name/status`。
2. 新增 DB 每页短事务：整页 tuple 校验 → `accounts` upsert → 同页 `metrics_raw` insert → commit。任一 SQL 失败整页回滚。
3. Full ETL 与 Backfill Coordinator 接入同一原子端口；Incr/BackfillDay 仍只处理已知账户指标，不伪造 metadata。
4. 非空 account 页在持久化前必须有分页总数；缺失时 `validate:account_page_N` fail-closed，不落主表/Raw，不派 canonical/fanout。
5. 真实 PostgreSQL 纵切片删除目标 workspace 的预置 account，验证奇航假源 → 建户 → Raw → Canonical → Quality → Semantic → Rule → WorkItem。

## 2. 事务与恢复语义

- 网络请求不放进 DB 事务，避免长事务占锁。
- 每个已拉取的 account 分页是一个短事务单元。当页 upsert 失败时，当页 `accounts/metrics_raw` 都为 0 写入。
- 前页已验证的提交可保留；Job 重试会重放分页。`accounts` upsert 幂等，Raw 依既有 append-only 语义追加，Canonical 取最新来源行，不会重复建户。
- 只有所有 account 页与指标步骤完成后才派生 canonical；Backfill 账户发现未完成时不 fanout 日任务。
- 空页可作为终止页；非空页缺 pagination 视为契约破损，禁止静默半成功。

## 3. 权限与字段边界

- 账户键固定为 `(workspace_id, media, account_id)`。`workspace_id/media` 不读取上游自报字段。
- 新建账户只写实证 metadata `account_name/status`；缺失值不覆盖已有值。
- `owner_user_id/lifecycle_stage/is_starred/tags` 等平台经营字段不从奇航 payload 派生，重放时保持不变。
- 没有删除/relax 任何账户三键 FK，没有默认 `KUAISHOU`，没有将 fixture 放入生产路径。
- 本批不解析 session、不扩大 account grant；同号跨 workspace/跨 media 的行保持隔离。
