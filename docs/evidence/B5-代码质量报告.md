## 安全审计

- Agent 内建 Bash/Read/Write/Edit/Web/Task/Skill 全部关闭，仅允许服务端闭包绑定身份的 in-process MCP 精确 allowlist。
- Agent 原子能力只开放 `read`/`preview`；`execute` 类型在注册阶段拒绝，媒体写操作继续走变更集确认门。
- `settingSources/skills/plugins=[]`、`persistSession=false`、每 Run 独立 `cwd/HOME/CLAUDE_CONFIG_DIR`；按 Claude 官方多租户说明额外强制 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`。
- SDK 子进程 env 只保留 12 个白名单键，不继承数据库、Multica、启航或 Provider 真实 AK。
- AES-256-GCM 信封最长 5 分钟，绑定 workspace/user/run/provider/model；篡改、过期和跨身份重放 fail-closed。
- sidecar 只监听 `127.0.0.1`；产品配置强制 localhost gateway；远端 Provider 强制 HTTPS，HTTP 只允许 loopback fake 测试。
- Provider raw trace、access log、MCP gateway、内置 Agent、透明工具执行、上游自动重试和调度默认关闭。
- 唯一动态进程创建是使用已锁定依赖包 bin 的 `spawn(process.execPath, [bin])`，未启用 shell；临时配置不含 AK。
- 凭证扫描只命中测试中的明确 fake/redaction 样本，生产源码和交付文档无真实 key。

## 如实边界 / 上线硬门

1. `createAgentBackend()` 已可组合，但现有 Worker main 未注册 Web/SSE 入口，也不会因 `AGENT_ENABLED=false` 改变 B1-B4 job consumer；等待 P-008 API/事件契约后接入。
2. Provider capability 目前是内存端口，用户多 Provider 凭证、事件流和 Run 扩展字段缺少冻结表结构。
3. 尚未接真实 Secret 服务、IdeaLab/Anthropic AK、额度和账单对账。
4. 尚未实现生产容器/微虚机沙箱、进程级 CPU/RAM/磁盘配额和基础设施 egress allowlist；官方文档把 SDK 定义为拥有本地状态的子进程，生产必须由部署层补齐隔离。
5. 尚未实现公开 SSE 重连、断线取消、event 持久化和并发恢复。
6. 尚未实现 Multica/OS `dispatch_os_task`、真实媒体工具回执和对话/账户绑定；只交安全端口，不发明内网协议。
7. fake upstream 未验证真实 Provider 对 Claude Code system prompt、tools、structured output、限流与错误码的完整兼容性。
