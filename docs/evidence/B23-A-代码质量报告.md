## 5. 真实 PostgreSQL 验收

- migration `up → down → up` 可重放。
- 同一 identity 可加入两个 workspace，各自解析 workspace-local user 与授权。
- 同一 `account_id` 可分别存在于两个 workspace；同 workspace 可在两个 media 下同号存在。
- 无 grant 返回 `allowedAccounts: []`；不自动继承 workspace 全账户。
- session、membership、identity、user 任一撤销/停用均拒绝；过期 session 为 401。
- membership 绑定其他 workspace 的 user 被复合 FK 以 `23503` 拒绝。
- token hash CHECK 拒绝明文形态；授权账户必须真实存在且匹配三字段键。

## 6. 安全与实现审计

- Repository 查询不选择 `token_hash/provider_subject/qihang_user_id/multica_pat_ref/idealab_ak_ref`；
  返回对象敏感词扫描为 0。

- SQL 全部参数化；无 raw SQL 出口、动态执行、shell、日志或 N+1 grant 查询。

## 7. 自审发现与修复

1. **真实 migration 链缺 `users(workspace_id,id)` 唯一约束**：Contract 已写复合身份，但旧 migration
   没有可引用键。008 显式补齐，并用跨 workspace user FK 反例验证。
2. **整合基线测试夹具与 UUID Contract 漂移**：Domain 已要求 UUID，Worker 账户日测试仍传
   `workspace-1/trusted-workspace/w`。只修测试夹具为合法 UUID，未放宽生产 Schema。
3. **新增 grant FK 使旧测试清理失败**：旧测试直接删 `accounts`，与 RESTRICT 语义冲突。
   修为先清 `account_access_grants`，并让 auth repository 每例释放自己的四表数据。
4. **空 grant 易被误作 workspace 全权**：Domain 明确把它解析为 approved empty scope；授权必须逐
   `(media,account_id)` 给出。
5. **敏感身份字段可能随 JOIN 泄漏**：Repository SELECT 白名单化，只取授权决策字段；真实测试对
   provider subject、启航 userId、Secret ref 和 token hash 做序列化扫描。
