## 实现结论

1. 账户对象身份已统一为 `(workspace_id, media, account_id)`：数据库联合键、Repository、
   Platform SQL tuple scope、KA 输出可信 workspace 注入和服务输出守卫使用同一语义；同一
   workspace 下跨媒体同号不会碰撞或串数。
2. 六个冻结 Query ID 已使用严格版本化 canonical row schema；KA 与 Platform Adapter
   输出同形，非法数值、非法 tasks、伪日历日期和契约损坏均顶层 fail closed。
3. lineage 不再用当前时间或部署默认值冒充来源事实。coverage partial 与 transport
   truncated 分离；聚合无法证明跨日对象集合时不编造 returnedObjects；对账单侧对象为零
   优先返回 source_missing。
4. migration 006 为六张账户主/业务表补复合 FK 和预检。冻结部署条件是首次部署或维护窗口
   停写、服务启动前执行；`lock_timeout=5s`、`statement_timeout=5min`，不宣称在线低锁。
5. migration 007 为 work_items/changesets 持久化账户 tuple。可确定历史行回填；跨媒体同号
   无法确定时整笔阻断。历史无 scope 的详情对象继续 fail closed。
6. 已挂载只读 `GET /api/v1/work-items/:id` 与 `GET /api/v1/changesets/:id`，返回证据、诊断、
   T+1、变更项、风险/dry-run 快照和 TTL；复用服务端认证、tuple scope 与 requestId。
7. 所有详情与 data query 共用响应大小守卫。序列化正文大于或恰好命中 16MB 均返回
   502 + `SOURCE_TRUNCATED`，不发送部分结果。
8. 未挂载 create/dry-run/confirm/execute/rollback；Runtime/Multica/媒体真实写继续关闭。
