## 5. 第一性原理自审与修复

1. **版本冒充**：初版允许调用方传任意合法格式的 `profileVersion`，会让同一算法伪装成未来版本；创建端现只接受当前 v1，比较端保留对历史/未来版本漂移的明确阻断。
2. **比较方向漂移**：比较 fingerprint 若按 left/right 直接写入会导致 A↔B 两条不同缓存键；现按画像 fingerprint 排序，完整结果对调输入严格相等。
3. **缺项伪 0 分**：缺钩子/卖点/人群/CTA 不能算“不相似”；现标 unavailable 并移出分母，过稀时直接不出总分。
4. **复刻关系混淆**：没有用相似度阈值自动生成谱系；谱系是单独的显式事实对象，并拒绝自环。
5. **Schema 演进**：谱系初版只带 fingerprint，没有显式版本；现增加独立 lineage schema v1，未来升级可保留历史解释。
6. **视觉非法组合**：`hardCutCount > visualEventCount` 会产生大于 1 的密度；输入层现 fail-closed，零事件则密度为 0。
7. **中文可复现性**：不依赖运行环境分词器；NFKC+固定字符 n-gram、去重排序和数量上限保证跨请求稳定。

## 6. Claude/arch 必审

1. 六组件名称和初始权重是否成为一期默认配置；若未来可配置，必须版本化而非覆盖历史分数。
2. `materialVersionId` 与 B15 `teardownFingerprint` 在未来公开 DTO/表中的权威来源和租户键。
3. 持久化时相似度画像、比较缓存、谱系边分别建模；不要把算法相似关系写成“复刻自”。
4. 一期候选检索是纯 PostgreSQL token/字段召回，还是引入向量库；Embedding Provider、数据外发、成本和重算策略需单独冻结。
5. 页面应展示分项与 unavailable 原因，不能只展示一个百分比；`insufficient_evidence` 不应渲染成 0%。
6. 谱系创建动作的权限、审计、撤销/纠错语义和版本对比 DTO 需由契约方冻结。
