## 1. 五层状态口径

| 层级 | 含义 |
|---|---|
| `internal_implemented` | Domain/Repository/Handler 等内部能力有代码和测试 |
| `runtime_attached` | 已注册到真实 Worker/API 启动入口 |
| `frontend_integrated` | 页面已调用稳定 BFF/API，而非占位或纯 Mock |
| `local_verified` | 本机测试、构建、启动或浏览器路径已实测 |
| `deployed_internal` | 已在内网环境部署并用真实身份、真实数据通路验证 |

## 2. 当前可实证总况

- 后端 B1-B22 的主要内部提交均已进入整合分支；这证明“底座代码已纳入”，不证明全部成为产品功能。
- 九个一级导航均有路由；工作台、数据分析、账户资源 3 个已有数据视图，任务、自动化、商品素材、报告、知识库、集成与通知 6 个仍是明确 `ModulePlaceholder`。
- Next BFF 当前仅 3 个只读入口：data query、work-item detail、changeset detail。
- Worker 生产 Runtime 当前只注册 6 类数据任务：full/incremental ETL、historical/day backfill、canonical merge、data quality check。
- 媒体写操作 API 为 0；ChangeSet 仅能查看，预览/确认/执行未接生产入口。
- 本机 Mock 九导航、双数据三态、账户/诊断详情已验证；正式登录、KA Data、内网 PG/网络、Multica/Runtime 均未完成真实联调。
- `deployed_internal = 0`：当前没有任何功能可以宣称已内网上线或生产验证。

## 4. 本批整合判断

### 已完成并可保留

- 后端、前端、知识资产已进入同一整合分支。
- 双数据 canonical、`workspaceId + media + accountId` 身份、16 MB/2k/10k 截断、只读详情和错误降级的已知 P0/P1 已在整合提交修复并有回归测试。
- 默认查询日期已改为上海时区 03:00 日切业务日，不再固定查询 `2026-08-24`。
- 本地 Mock 可用于老板逐页查看当前阶段页面，但不能用于判断真实数据正确性。

### 首次内网部署前仍需完成

1. 老板确认首次身份方案与对账口径 G1-G4。
2. 接入 approved server-side auth scope；若采用临时静态身份，只允许固定试用 workspace/account tuple，不能接受浏览器自报。
3. 配置并验证真实 KA Data origin/token/Query Registry、内网 PG 和网络出口。
4. 若首次展示 reconcile，先完成并验收真实对账引擎；否则保持 reconcile pending/入口关闭。
5. 跑脱敏 smoke：三种 data view、跨租户/跨媒体反例、exact truncation、lineage、日志无 token/SQL/上游正文。

### 下一批功能顺序建议（未派发）

1. 投放任务真实读链 + 工作台今日队列：能把现有任务/规则/诊断底座变成老板可操作页面。
2. 自动化工作流的只读预览与运行中心：先展示“为什么触发/没触发”，仍不开放媒体写。
3. 商品素材、报告、知识库、集成与通知逐个做 API + 页面垂直切片，不能只继续堆 Domain 内核。
