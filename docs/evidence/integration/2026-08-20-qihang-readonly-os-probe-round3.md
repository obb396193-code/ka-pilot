# 2026-08-20 Qihang read-only OS probe · Round 3

> 仅含脱敏协议事实；原始响应、真实 userId、账户/广告标识、名称、金额和完整请求 URL 不进入仓库。

## 环境与范围

- 环境：内网 OS Agent 当前合法身份。
- 请求：15 次只读 GET，覆盖历史 realtime、`hh` 边界、无过滤与账户分片对照、分页参数探针。
- 无写操作、无循环翻页、无越权对象；本项目代码未发起请求，因此仍不是 Worker/FaaS 产品同链 trace。

## 已确认事实

### realtime 历史日期

- `account_realtime` 和 `ad_realtime` 均以历史 `ds` 成功返回数据，行内 `ds` 回显请求日。
- 历史 realtime 行仍携带 `last_sync_time`。
- 这推翻“实时接口只支持当天”的旧表述：历史日走 offline 是 Skill 为保证结算口径做的选择，不是服务端能力边界。
- 历史 realtime 只能用于诊断回溯和同口径趋势；结算、对账、结算单继续以 offline 为准。

### hh 边界

- `hh=0`、`23`、`24` 均成功；24 与 23 在完整历史日结果一致。
- `hh=25` 也返回成功且与 23/24 一致，服务端没有错误提示，表现为静默钳制。
- 产品 Client 必须自行限制查询参数 0..24；小时差分和 `ad_metrics_hourly` 仍只允许 0..23，24 仅作全天累计查询别名。

### 2000 行静默截断

- 无过滤 `ad_realtime` 再次恰好返回 2000 行，顶层仍只有成功状态、数据、trace 与耗时等字段，无 total/hasMore/nextPage/truncated/limit。
- 同一范围按 5 个账户一批查询后，分片并集去重为 2017 行；无过滤结果的 2000 行全部包含在分片并集中，分片额外发现 17 行。
- 因此“疑似固定边界”升级为**已证实静默截断**：无过滤查询至少丢失 17 行且服务端无提示。
- 当前样本中的单账户未触及边界；若单个过滤分片恰好返回 2000 行，仍必须 fail-closed，不能声称完整。

### 分页参数

- 给 `ad_realtime` 增加 `pageNum=1&pageSize=5` 后仍返回 2000 行，响应 envelope 不变。
- 这些参数被服务端静默忽略；数组类广告接口不能依赖分页补全。

## 产品与工程结论

1. 生产 `ad_realtime` 必须先有账户清单，再按账户小批查询、合并去重；禁止无 accountIds/adIds 全量查询。
2. 默认使用已真实验证的 5 账户分片；同时保留命中 2000 行即阻断，以覆盖单账户或高密度分片风险。
3. Client 自校验 `hh` 0..24；小时表和差分仍保持 0..23，不制造第 24 小时桶。
4. 数据产品可提供历史实时诊断，但所有界面、报告和 Agent 回答必须显式标记 realtime/offline 口径。
