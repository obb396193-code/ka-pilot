## 已确认事实

### hh 累计语义

- 不传 hh 表示当日累计；文档声明 hh 范围 0..24，本轮只真实执行相邻两个已完成小时。
- 同一批共同广告的消耗、曝光、点击、回传转化和真实转化逐行满足较早 hh ≤ 较晚 hh ≤ 不传 hh，确认 hh 是“0..hh 含”的累计快照，不是独立小时值。
- 相邻快照的广告集合可能不同：较早时点尚无数据的广告整行不返回；返回行字段集合一致，本轮没有 null，缺省数值表现为 0。
- 当前时刻“不传 hh”可能与最近完整小时相同，证明当前小时存在同步延迟；必须结合 `last_sync_time` 展示数据截至时间。

### offline 跨日与产出时效

- `beginDate/endDate` 区间含首尾，每行携带 `ds`；本次两日区间同时返回两个数据日。
- 同一成熟数据日的跨日结果与单日结果逐行哈希一致。
- 第一轮午后较早时点 D-1 为空，第二轮约两小时后 D-1 已出现；离线产出在日内推进，D-2 只是第一轮时点快照，不是固定 SLA。
- 源码和 connector 没有 partition ready/complete/latest marker；离线也没有 `last_sync_time`。空数组只能表示“当前未观察到行”，非空也不能证明完整产出。

### 疑似截断

- 无 `accountIds` 的全范围 `ad_realtime` 恰好返回固定整数边界行数，且数组响应没有分页外壳或截断提示。
- 这是强截断信号但还不是硬上限实证。生产查询必须按 accountIds/adIds 分片；恰好命中该边界时 fail-closed 并标记 `suspected_truncation`。

## 产品与工程结论

1. 小时窗口值可以由相邻累计快照做差；必须按 ad_id 并集处理较早快照缺行。
2. 当前快照缺少上一时点已有广告时不能按 0，必须标不完整。
3. 离线 D-1 需跨时间重试和修订，不能一次空就落“真无数据”。
4. 多次观测稳定只能是本产品的 provisional/stable heuristic，不能冒充平台 complete。
5. `last_sync_time`、离线 availability、疑似截断和数据修正需要进入数据健康与报告证据。
