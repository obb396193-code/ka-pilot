> 分支：`codex/dual-data-backend`

## 本批实现

- Domain 可执行 Zod Contract：`DataViewMode`、`MetricValue`、单/双 source lineage、逐指标权威元数据、账户直连键、对账响应和稳定错误 envelope。
- 服务端 Query Registry：仅六个冻结 queryId；严格参数、视图、日期、行数、账户 scope、模板版本和权威策略。
- KA Data 安全 reader：服务端 Secret、固定 HTTPS origin + `/api/query`、禁止 redirect、timeout、16MB 流式上限、2,000/10,000/16MB 疑似截断、错误脱敏、token 不可序列化。
- 查询服务与可挂载 handler：`POST /api/v1/data/query` 语义；认证上下文注入 workspace/user/媒体账户 scope；三种 dataView；reconcile 双边并列且无统一主数。
- 账户事实按 `(workspace_id, media, account_id)` 直连；整源失败为 `source_unavailable`，双边查询成功但单侧无行为 `source_missing`。未外推任务、商品、素材或广告组 ID。

## 质控中发现并修复

1. 跨媒体账户计数从只按 `account_id` 改为按 `media + account_id`，避免同号碰撞。
2. 当日权威日期改用 `Asia/Shanghai`，且只有单日当天查询才标 platform 实时权威；跨日范围不误标。
3. 分页表不再用“本页 rowCount”冒充全量 total。
4. 上游整源失败与单侧无数据拆为 `source_unavailable/source_missing`。
5. Contract 强制 stale/partial/missing 不可声明 comparable；truncated 必须同时 partial；unavailable source 不得携带 rows。
6. 有效 queryId 携带额外顶层字段返回 `INVALID_REQUEST`，未知 queryId 才返回 `QUERY_NOT_ALLOWED`。
