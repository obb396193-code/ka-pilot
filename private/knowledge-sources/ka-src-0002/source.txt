一、项目背景与目标
1.1 背景
KA 媒体投放（巨量引擎、快手、腾讯广告）是核心业务渠道，日常需要对多平台投放效果进行全方位监控。当前日报依赖人工整理数据、计算衍生指标、判断异常并撰写分析，流程繁琐且容易遗漏关键问题。
1.2 目标
构建一个通用的 KA 媒体日报生成 Agent，实现以下能力：
● 数据自动获取：调用统一 MCP 数据工具，自动拉取前一日全量投放数据（含已计算的衍生指标和环比）。
● 多维度拆解：按代理/自投、业务、任务、账户、资源位、出价工具、UBP 等维度独立展示数据。
● 异常自动标记：基于可配置的规则引擎，自动识别并高亮标记各维度下的异常数据。
● 报告自动输出：生成包含数据表格和可视化图表的 HTML 日报文档，支持推送至钉钉。
1.3 渠道支持
本方案支持以下三大 KA 媒体渠道，通过统一的 MCP 工具接口获取数据：

不同渠道的字段映射和计算逻辑由 MCP 工具内部处理，Agent 层使用统一的字段名消费数据。

3.2 工具总体设计
工具名称：dailyReportData
Agent 通过不同的 query_type 参数多次调用该工具，获取日报各模块所需的数据。工具内部负责权限校验、SQL 查询、指标计算和环比计算，Agent 只需消费计算好的结果。
权限处理说明：
● Agent 调用时不需要传递用户身份信息
● MCP 工具从调用上下文自动获取当前用户身份
● MCP 内部完成权限校验和数据过滤
● 返回的数据已经是用户有权限查看的范围
3.3 入参定义

{
  // [必填] 报告日期，格式 YYYYMMDD，数据为该日全天
  "date": "20260409",

  // [条件必填] 媒体渠道，指定数据来源
  // 渠道经理：必填，必须在 managed_channels 范围内
  // 优化师：可选，MCP 自动从 authorized_accounts 推断
  "channel": "oceanengine | kuaishou | tencent",

  // [必填] 查询类型，决定返回数据的结构
  "query_type": "summary | dimension | health | tier | trend",

  // [条件必填] 当 query_type = "dimension" 时必填
  // 指定按哪个维度聚合
  "dimension_type": "agent_type | business | task | account | resource_position | bid_tool | is_ubp | deduction_rate_range",

  // [可选] 过滤条件，缩小数据范围
  // 注意：优化师指定的 account_id 必须在自己的授权列表内
  "filters": {
    "agent_type": "代理",           // 过滤投放类型
    "operator_name": "张三",        // 过滤负责人
    "business_name": "业务A",       // 过滤业务
    "task_id": "T001",             // 过滤任务ID
    "account_id": "123456",         // 过滤账户（权限校验）
    "resource_position": "信息流",   // 过滤资源位
    "bid_tool": "oCPM",            // 过滤出价工具
    "is_ubp": true                  // 过滤UBP
  }
}

2.11 Agent 调用序列
Agent 生成一份完整日报需要按以下顺序调用 MCP 工具：

调用1: { channel: "oceanengine", query_type: "summary" }                                    → 整体大盘数据
调用2: { channel: "oceanengine", query_type: "trend" }                                      → 7日趋势数据
调用3: { channel: "oceanengine", query_type: "dimension", dimension_type: "agent_type" }    → 代理/自投分析
调用4: { channel: "oceanengine", query_type: "dimension", dimension_type: "business" }      → 业务维度分析
调用5: { channel: "oceanengine", query_type: "dimension", dimension_type: "task" }          → 任务维度分析
调用6: { channel: "oceanengine", query_type: "dimension", dimension_type: "account" }       → 账户维度分析
调用7: { channel: "oceanengine", query_type: "dimension", dimension_type: "resource_position" } → 资源位分析
调用8: { channel: "oceanengine", query_type: "dimension", dimension_type: "bid_tool" }      → 出价工具分析
调用9: { channel: "oceanengine", query_type: "dimension", dimension_type: "is_ubp" }        → UBP分析
调用10: { channel: "oceanengine", query_type: "dimension", dimension_type: "deduction_rate_range" } → 扣量分析
调用11: { channel: "oceanengine", query_type: "health" }                                    → 投放健康度详情
调用12: { channel: "oceanengine", query_type: "tier" }                                      → 消耗分层统计
多渠道支持：
如需生成多个渠道的日报，对每个渠道分别执行上述 12 次调用序列：

# 巨量引擎日报
for call in sequence: call(channel="oceanengine", ...)

# 快手日报
for call in sequence: call(channel="kuaishou", ...)

# 腾讯广告日报
for call in sequence: call(channel="tencent", ...)
Agent 可根据配置选择生成单一渠道日报或合并多渠道的综合日报。

3.10 环比计算规则
所有指标均需计算日环比，公式统一为：环比变化率 = (今日值 - 昨日值) / 昨日值
特殊处理规则：
● 昨日值为 0 时：若今日值 > 0，MCP 返回 "NEW"，报告展示为"新增"；若今日值也为 0，返回 0，展示为"持平"。
● 分母为 0 导致指标无法计算时，MCP 返回 null，报告展示为 "-"。
● 比率类指标（CTR、CVR 等）：环比以百分点（pp）表示，即 今日值 - 昨日值。
● 环比展示格式：正值显示为 +X.X%（红色），负值显示为 -X.X%（绿色），零显示为 0.0%（灰色）。

五、异常标记规则框架
5.1 规则引擎设计
异常标记采用可配置的规则引擎，支持用户自定义规则。规则以 JSON/YAML 配置文件形式存储，Agent 在运行时加载并应用。
5.2 规则配置结构
具体规则可以再进行分配
anomaly_rules:
  # 规则1：消耗环比波动
  - rule_id: "cost_change"
    metric: "cost"
    type: "ratio_change"         # 环比变化率
    thresholds:
      warning: 0.20              # >=20% 变化标记为关注
      critical: 0.50             # >=50% 变化标记为异常
    direction: "both"            # both/up/down

  # 规则2：成本超出考核
  - rule_id: "cost_over_target"
    metric: "cash_cpa"
    type: "compare_to_target"    # 与目标值比较
    target_field: "target_cost"
    thresholds:
      warning: 0.10              # 超出考核成本10%
      critical: 0.30             # 超出考核成本30%

  # 规则3：GAP异常
  - rule_id: "gap_abnormal"
    metric: "gap"
    type: "absolute_value"       # 绝对值判断
    thresholds:
      warning: 0.15              # GAP绝对值 > 15%
      critical: 0.30             # GAP绝对值 > 30%

  # 规则4：空耗占比过高
  - rule_id: "empty_cost_ratio"
    metric: "empty_plan_cost_ratio"
    type: "absolute_value"
    thresholds:
      warning: 0.10              # 空耗消耗占比 > 10%
      critical: 0.20             # 空耗消耗占比 > 20%

  # 规则5：冷启动通过率过低
  - rule_id: "cold_start_low"
    metric: "cold_start_pass_rate"
    type: "below_threshold"      # 低于阈值
    thresholds:
      warning: 0.20              # 低于20%
      critical: 0.10             # 低于10%

  # ... 用户可继续追加规则

7.2 Step 1：数据获取（调用 MCP 工具）

    - 调用1~2：整体大盘 + 7日趋势
    - 调用3~10：8个维度的分维度数据
    - 调用11~12：健康度详情 + 消耗分层

    - 检查各调用返回是否正常
    - 若某次调用失败，在报告中标注"该模块数据缺失"

    - 按严重度排序
    - 生成自然语言描述

    - 使用 Python 拼装 HTML
    - 嵌入 ECharts CDN，渲染图表
    - 应用异常高亮样式
    - 生成交互式表格（排序、筛选）

KA 媒体广告投放平台面向大型广告主，提供跨媒体渠道（头条、快手、腾讯广告等）的广告投放管理、数据分析、异常监控和素材优化能力。平台通过 MCP（Model Context Protocol）数据工具与底层数据系统（ODPS/MaxCompute）连接，为渠道经理和优化师提供权限隔离的数据分析与决策支持。

●        实现权限精细化管理：渠道经理与优化师两级权限隔离，确保数据安全
●        建立实时监控能力：15 项异常检测规则，覆盖账户和广告组级别
●        支持素材深度分析：素材维度与业务维度交叉分析，优化素材策略
