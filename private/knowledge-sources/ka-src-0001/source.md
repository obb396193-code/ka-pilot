# AI 投放平台产品能力对比

## 白盒平台 vs 黑盒平台 — 定位、能力与关键差异梳理

内部对齐文档｜2026-06-29｜v0.1（持续迭代中）

## 一、一句话定位

**白盒平台** 面向优化师，提供自动化基建与规则化调控能力，帮助优化师高效完成广告投放的执行工作。策略由人定，系统帮执行。

**黑盒平台** 面向渠道管理，具备从策略理解、实验设计、智能基建到效果复盘的全流程闭环能力。渠道管理提出目标，AI 规划并执行。

两个平台相互独立、平行运行，服务不同角色、解决不同层次的问题。

## 二、产品概览

### 白盒平台

执行效率工具。

让优化师的日常操作从“手动逐一搭建”变为“模板化批量执行”，从“盯盘手动调”变为“规则自动调”。核心解决的是执行效率问题。

- 用户：优化师
- 驱动方式：人工策略 + 自动执行
- 智能程度：规则驱动

### 黑盒平台

策略智能平台。

让渠道管理从“写文档→开会→盯优化师执行”变为“说一句话→AI 规划→系统全自动跑完→看结论”。核心解决的是策略规划与实验验证问题。

- 用户：渠道管理
- 驱动方式：AI 理解目标 + 全自动执行
- 智能程度：AI 驱动

## 三、能力矩阵对比

| 能力维度 | 白盒平台 | 黑盒平台 | 差异度 |
|---|---|---|---|
| 目标用户 | 优化师（一线执行者） | 渠道管理（策略制定者） | 完全不同 |
| 策略理解 | 不具备。不理解策略含义，完全依赖优化师手动输入基建参数和调控规则。 | 核心能力。能理解自然语言的测试目标（如“测某类商品在某媒体的表现”），自动拆解为可执行的实验方案。 | 本质差异 |
| 老基建（已验证策略） | 仍需人工搭建模板。即使商品、素材风格、版位、出价策略已经验证效果好，优化师仍需手动创建基建模板并配置参数后执行投放。系统不会自动识别“什么跑得好”。 | 自动识别 + 长期托管。系统能充分理解哪些策略方向已经被验证（效果好的商品、素材风格、版位、出价组合等），自动维持这些成熟策略的长期稳定投放，无需人工干预。 | 人工维持 vs AI 托管 |
| 新基建（新方向测试） | 人工从头搭建。优化师自行判断新方向怎么测，手动设计模板参数（选什么商品、素材、版位、出价等），系统按模板批量创建。 | 智能方案设计。AI 理解本次测试的策略方向后，自动生成基建方案——在测试新变量（如新品类商品）的同时，其他维度（素材风格、版位、出价等）优先选用已验证的成熟策略，确保测试结论的纯净度。 | 人工设计 vs AI 设计 |
| 调控能力 | 规则执行 + 人工指令执行。两种模式并存：（1）优化师预设 if-then 规则（如“成本超 X 降预算 Y%”），系统按条件自动触发；（2）优化师直接下达操作指令（如“现在把这个账户出价降 10%”），系统即时执行。两种方式均无 AI 判断成分，由人决定“做什么”和“何时做”。 | AI 实时调控与自优化。系统根据实时投放数据智能判断——自动追加预算、关停表现差的实验组、调整出价策略等，无需人工预设规则或下达指令。 | 规则+指令 vs AI |
| 实验设计 | 无。不区分实验/对照，不涉及流量分配。 | 核心能力。自动设计实验分组、流量分配、对照组设置，确保实验结论的统计有效性。 | 有 vs 无 |
| 效果分析 | 人工驱动的数据拉取。优化师可以指定要看什么数据（如“拉取某账户近7日的转化成本”），系统按要求拉取并展示。但平台不具备自主判断“这个实验应该看什么数据”的能力，分析维度和指标均由人决定。 | 内建效果回收与复盘。实验结束后自动回收数据、对比各实验组表现、生成结论报告，供下一轮策略迭代参考。系统能根据实验设计自动选择正确的分析维度。 | 被动 vs 主动 |
| 人机协作模式 | 人主导 + 机器执行。所有决策由优化师完成，系统负责提效。 | 人定目标 + 机器决策。渠道管理只负责“要测什么”，how 的部分全部交给 AI。 | 协作深度不同 |
| 闭环程度 | 执行闭环。覆盖“基建搭建→规则/指令调控→人工指定数据分析”的执行链路，但策略制定（做什么、为什么做）在平台外由渠道管理或优化师自行完成。 | 策略全闭环。覆盖“目标理解→策略规划→基建搭建→智能调控→效果回收→结论复盘”全链路，从目标到结论一站式完成。 | 链路长度不同 |
| 覆盖媒体 | 全渠道：快手、巨量引擎、腾讯广告、钉钉、厂商媒体等 | 全渠道：快手、巨量引擎、腾讯广告、钉钉、厂商媒体等 | 一致 |

## 四、典型场景流程对比

场景：“测试某新品类商品在快手的投放效果”

### 白盒平台的工作方式

1. 渠道管理下发测试需求：通过会议/文档告知优化师“要测这个品类”。
2. 优化师手动设计方案：决定建几个计划、出价多少、用什么素材、怎么分组。
3. 在白盒中批量搭建：配置模板参数，系统批量创建广告计划和广告组。
4. 设置调控规则或直接下指令：配置 if-then 规则（成本超阈值降预算等），或直接下达操作指令（如“降出价10%”），系统执行。
5. 人工指定数据分析：优化师告诉系统“拉取XX指标”，系统按要求拉取并展示数据，优化师自行判断并汇报。

### 黑盒平台的工作方式

1. 渠道管理输入测试目标：用自然语言描述：“我要测XX品类在快手的投放效果”。
2. AI 理解目标并生成策略方案：自动拆解测试目标，规划实验分组、素材方向、流量分配。
3. 系统自动搭建基建：根据策略方案自动创建广告计划、广告组和创意。
4. AI 实时调控与自优化：根据实时数据自动调整预算/出价、关停低效组、追加高效组。
5. 自动回收效果并生成结论：实验结束后自动对比数据、生成复盘报告，指导下一轮策略。

## 五、关键差异总结

1. **决策权归属不同**

   白盒的决策权在人（优化师），系统只是执行器。黑盒的决策权在 AI，人只负责定义目标。这是两个平台最本质的区别——一个是“人脑 + 机械臂”，一个是“AI 大脑 + 机械臂”。

2. **能力链路长度不同**

   白盒覆盖投放执行段（基建 + 调控），是“工具”。黑盒覆盖策略全链路（理解→规划→执行→复盘），是“平台”。白盒是锤子，黑盒是会自己找钉子的机器人。

3. **智能化层次不同**

   白盒的智能化停留在“自动化”层次——按预设规则重复执行。黑盒的智能化达到了“自主决策”层次——能理解意图、设计方案、动态调优、总结结论。

4. **服务的管理层次不同**

   白盒服务执行层（优化师的日常操作效率），解决“怎么做更快”。黑盒服务管理层（渠道管理的策略验证效率），解决“做什么更有价值”。
