# 商品域·铺货·选品与搜索

## 概述

巴拿马（淘系海外 OVS 供给侧 / 跨境分销）商品域，负责把国内大淘宝 / 天猫 / 1688 的货源商品，经过**国际化 / 铺货**加工，供给给海外分销商用于选品、铺货、搜索与采购。整个链路以货通平台（GSP / 全球铺货中心）为商品数据主干，分销侧应用 `ovs-pnm-item` 作为商品域核心，在其之上构建撞库寻源、选品中心、导购搜索、图搜拍立淘、消息订阅、商品 ID 加解密等能力。

**三段铺货模型**（贯穿全域的核心概念）：

| 段位 | 转化 | 说明 |
| --- | --- | --- |
| 一段铺货 | gsp → gp（国际化商品池） | 货源商品生成 GP（gpId） |
| 二段铺货 | gp → cp（渠道商品） | GP 铺到 "PANAMA" 渠道生成 CP，搜索/选品底池基于二段 |
| 三段铺货 | cp → dp（分销商） | 也叫**品商关系**，记录分销商与 CP 的关系；**客户视角的"铺货" = 完成三段铺货** |

关键 ID 体系：`itemId`（淘宝商品）、`gpId`（国际化商品）、`mpId`（分销/供销商品 ID，对外主 ID）、`miId`（加密后对外 ID）。

商品域应用与上下游关系（详见 [[巴拿马跨境分销业务与产品总览.md]]、[[账号体系与开放平台.md]]）：
- `ovs-pnm-item`：商品域核心应用（Aone appId 222630），提供商品查询、撞库、选品、铺货任务、搜索、消息等能力。
- `ovs-pnm-open`：开放平台应用（appId 151744），对外 API 网关侧，调用 item / distributor。
- `ovs-pnm-distributor`：分销工作台应用，承载 mtop 导购能力。
- `ovs-pnm-xt`：搜索接入应用，集成 TPP（拍立淘）二方包。
- `ovs-pnm-account`：账号 / 分层分级 / 白名单配置。
- 货通侧：`gsp-supply`（商品基础信息/优惠价）、`gsp-assortment`（铺货/品商关系）、全球铺货中心。

### 撞库（寻源）链路与依赖

撞库指按淘宝商品找可售供销商品并按需铺货。依赖梳理（来源：商品域链路&依赖梳理）：

**现状问题**：全部跨单元调用，最小 6 次 / 最大 8 次 RPC，存在淘宝商品信息、铺货信息重复调用。可优化点：减少跨单元、IC/UMP 直调、移除国际化素材调用。

### 铺货详情查询优化专项

批量查询性能瓶颈（来源：铺货详情查询优化专项）：
- 跨单元链路：SG52 → OS30（开放网关→分销）、OS30 → NA610（分销→货通）均有跨单元损耗。
- **中台底层无真正批量查询能力**，货通用线程池伪批量并发，流量对中台放大；线程池积压导致 RT 迅速增大（示例：单品 100ms、批量 10 个时单机上限约 100 TPS）。
- API 无请求数量约束（东森 100 / KC 20 / Dsers 1），成功率与 RT 视角波动大。
- 优化策略（方案二）：减少跨单元 + HSF 改异步移除线程池 + 限制并发数 + 货通提供透传详描 KEY 与 CP 状态的新接口，由分销做渲染查询。

## 图片存储治理

来源：巴拿马图片存储治理。底层依赖 mediacenter（`com.taobao.media.client.hsf.HsfMediaClientImpl#addFile/getFile`、`DefaultFetchImageManager#fetchFile`）。

- **现状**：巴拿马图片 2.65 亿，实际存储仅 1.1w（成本合理，本财年可不动）。
- **上传接口** `/upload/image`、**图搜**、**相似推荐** 均依赖 mediacenter。域名白名单配置 `user.traffic.service.config`（group `pnm-open`）：img/gw/heic/picasso.alicdn.com 等；支持 `.jpg/.jpeg/.png/.webp`。
- **已知问题**：同 url 图片按 userId 隔离区分文件名，会被反复存储。
- **长期方案**：低热数据 archive 归档，避免月累增长。归档执行前产品优化：老 imageId 读取需报错提示重传；老 picUrl 读取需系统自动重新上传补 imageId。
- **异常错误码**（读图）：`NO_RIGHT_READ_IMAGE`（403 授权不足）、`ILLEGAL_IMAGE_URL`（400 非法/不存在域名）、`UN_REACHED_IMAGE_URL`（握手中断，如需翻墙图片）。

## 商品消息

来源：分销商品消息中心（ovs-pnm-item）。消息模型与解析方法沉淀在二方库 `ovs-pnm-item-api`。

### 消息协议

| 消息类型 | TOPIC | Tag | Key |
| --- | --- | --- | --- |
| 商品状态变更 | `PANAMA_ITEM_UPDATE` | ITEM_STATUS | `${分销商品ID}_${TAG}` |
| 商品信息变更 | 同上 | ITEM_INFO | |
| 商品价格变更 | 同上 | ITEM_PRICE | |
| 商品库存变更 | 同上 | ITEM_STOCK | |
| SKU 状态/信息变更 | 同上 | SKU_STATUS / SKU_INFO | |
| 品商关系变更 | `PANAMA_ITEM_RELATION_UPDATE` | BIND / UNBIND | `${BIND/UNBIND}_${分销商品ID}_${分销商ID}` |

消息体：`ItemUpdateDTO{mpId, type, content}`、`ItemRelationUpdateDTO{mpId, distributorId, action}`。

### 国际化素材（外模图）消息链路

来源：分销已铺货商品国际化素材信息更新链路。目标：新增国际化素材消息大类，含外模图消息。
- **外模图 → item**：`eventType=SPU_OVS_MODEL_PHOTO`，`marketCode=PANAMA`，`status=ACCEPTED/REJECTED`。
- **item → open**：`TOPIC=OVS_INTERNATIONAL_MATERIAL_MSG`，`TAGS=foreign_model_audit_update`，`KEYS=MPID_TAGS`，body 含 mpId/itemId/status/fields/time。
- **open → 分销商**：仅在前后状态变化时发送（NULL→ACCEPTED/REJECTED 发；ACCEPTED↔REJECTED 互相发；相同状态不发）。

### 品商关系变更链路（现状与优化）

- 分销商视角无"品商关系"概念，对应"铺货上新"；收到变更消息基本按铺货处理，不做解除。
- 品商关系查询三模式（部分基于 OpenSearch）：判断单商品-单分销商关系、按分销商 ID 批量查商品、按 mpId 批量查分销商（用于发变更消息）。
- 技术问题：分销侧自建品商关系搜索引擎，数据仍在货通侧，一致性完全依赖货通消息、无补偿。优化方向：统一创建/删除接口、查询能力转交货通、尽量不走 opensearch。

## 铺货能力

### 两条铺货链路（重要区分，来源：AI 版铺货优化一期）

代码中铺货存在两条独立链路：

**链路 A｜选品集铺货（批量任务式）**
- HSF：`DistributionTaskServiceImpl`（`createTask → doCreateTask`；Tair 重入锁 `createTask_+mainUserId`；`accountAdapter.checkDistributePermission`）。
- 规则校验：`DistRuleManager.distRuleChecker` 构造 `MultiRuleMatchRequest`，主能力 `AbilityCodeEnum.SUBMIT_GOODS_RULES`，子能力 `SubAbilityCodeEnum.MAX_SUBMIT_GOODS`。
- 规则引擎：`RuleCheckerServiceImpl.queryDosage`，maxCanUse 取 `SubAbilityConstraint`，**额度计数存 Tair**（key = `RuleDosageResultUtils.getDosageKey(leads, abilityCode, subAbilityCode, timeUnit)`）。
- 任务状态：`DistributionStatusEnum` CREATED(1)/EXECUTING(2)/SUCCESS(3)/FAILED(4)/USER_CANCEL(5)。
- 落库：外部 transformer-supply（`DistTaskAdapterImpl → AutomaticJobManageFacade`），本仓无任务表。

**链路 B｜寻源实时铺货（单品式）**
- `OvsPnmItemRealtimeDistributeRecordApplication`：`addWaitDistribution`（上限硬编码 `ItemSwitcher.WAIT_DISTRIBUTION_MAX_VALUE=1000`）、`batchDistribution`（selectAll / itemIdList）、`immediatelyDistribution`。
- 本地表 `ovs_pnm_item_realtime_distribute_record`（`OvsPnmItemRealtimeDistributeRecordDO`）。

### 寻源铺货二期（来源：寻源铺货2期-技术方案）

- **待铺货列表**：加入 / 取消 / 批量铺货；发起铺货只创建任务不同步调用（防超时），额外 SchedulerX 任务每分钟扫描待调度任务执行铺货；货通失败无品商关系时，用超时策略置失败。取消铺货直调 `GspAssortmentService.updateProductLevelRelation`。
- **banner 推荐商品**：复用分销商品主题推荐，banner 与主题一一对应，传主题 id；商品 T+1 同步需剔除失效商品。banner 与 u+ 选品集映射（美妆海外热销 109524694、家具海外热销 109525527、东南亚热卖 109525858、中国台湾热卖 109526157、日韩热卖 109526226、更多推荐 109546928）。
- 依赖接口：铺货 `GspProductService.joinProductPool`、取消 `GspAssortmentService.updateProductLevelRelation`、详情 `ItemApi#batchQuerySupplyItem`、多语言素材 `DistMaterialReadService#queryMaterialSummary`（materialVersion 固定 "OVS"）。
- 商品状态判定：可售（`ItemSaleableChecker.check`）+ 签约（商品上是否有 IC 标）+ 已铺货（查品商关系）。

### 大 SKU 商品铺货成功率优化（来源：km1hk79ukea58izx）

目标：大 SKU 撞库成功率提升到 99%。核心改动：
- 撞库链路仅查一段 GP 信息、不依赖 CP；接入异步编排组件简化流程。
- 铺货识别 "PANAMA_DG" 市场，仅铺一段 GP、不触发 CP 段铺货。
- 交易侧替换铺货商品查询接口，"PANAMA_DG" 链路仅查一段 GP 防流程报错。
- 是否重铺 `isNeedReDistribute`：剔除 CP 有效性检查，比对商品状态与 SKU 一致性。
- item 层接口：`GspProductAdapter#queryDGProductBySupplyItemId`；货通接口 `GspAssortmentOpenApi#queryDistributionGspProduct` 传参剔除 CP 市场。
- 1688 撞库链路同步调整（`MarketEnum.CBU_MARKET`）。

### 铺货管理（来源：【详细设计】分销铺货管理）

- 铺货任务模型 + 任务状态机（最终以海外铺货任务中心状态为准）。前台状态 `DistStatusEnum` CREATED(1)/EXECUTING(2)/SUCCESS(3)/FAILED(4)。
- 铺货关系模型：商品状态枚举 `["active","inoutage","inactive","deleted","delete"]`；铺货状态 1 正常 / 3 已取消。
- 菜单数量从接口读取：`mtop.alibaba.ovs.panama.distributor.product.relation.count`（正常/已失效/已取消）。
- 选品集数据导出到 ODPS `odps.tmall_ovs.ovs_pnm_distributor_collection`（分区为选品集 ID）。
- 铺货任务承载介质：OSS csv / ODPS 表 / 接口直连（≤5000 个）。

### 换供一期（来源：换供一期技术方案）

- 所有商品接口新增返回 taoworld 商详链接 `twItemUrl`、标准化商品状态 `itemStatus`、叶子类目 `itemCateId`。
- 拍立淘图搜 `OpenProductSearchService#querySimilarProducts`：优先取 skuUrl，支持 skuUrl/itemUrl/itemId/itemCateId；新增 `sameShop`（是否同店）；itemOptions 支持 sortBy（PRICE/COMMISION_AMOUNT/SIMILIAR）、skipSame、topNum。

## 选品中心

### 概要（来源：分销工作台选品铺货 概要设计）

面向零售类 KA 和中小 ds。核心工作是 0-1 构建**规则圈品**能力，在**分层分级**管控下让分销商自主创建圈品规则形成**选品集**，调用在线**铺货任务**把已签约货源商品批量转化成分销渠道商品同步到分销商系统。
- 选品方式：**搜索选品**（关键词/图片 + 筛选排序，挑少量）与 **规则圈品**（类目/价格带/风格等指标组合，圈批量）。
- 指标分：筛选/排序指标、展示指标（如 30 天模糊化销量）。
- 外部依赖：铺货系统（创建/查询/执行/停止任务、任务状态消息）、海外商品管理系统 OIM（按指标表达式查询商品/创建实体/OTS 查询/导出）。

### 选品引擎选型（OpenSearch vs OTS）

概要设计做过选型对比：
- OpenSearch（智能检索标准版）：全年约 8.85 万元；新增指标需重建索引（约 13.88h 延迟，用户 T+18h 可见）；无法复用海外已有指标。
- OTS（TableStore，预留模式）：全年约 2~4 万元，成本优势；支持 key:value 嵌套查询、指标以 kv 存储时无需重建索引；可复用海外指标；4 VCU 支持 9000~12000 QPS。
- **最终二期落到 OTS 引擎**（增量更新，见下）。

### 详细设计模型（来源：【详细设计】分销选品中心）

- 领域模型：选品用户、选品指标、筛选规则（元信息含 valueType 单值/多值/区间、matchType EQUAL/NOT_EQUAL/CONTAIN/NOT_CONTAIN/GREATER_THAN_OR_EQUAL、多值逻辑 AND/OR）、排序规则、选品集。
- 存储：库 `tmw_panama`，表 `ovs_pnm_collection`（`user_id, name, type, select_rule, preview_info, engine_info, rel_obj_type_id, export_info`）。
- **规则与规则之间都是"与"关系**。筛选规则示例：

| 前台 | 规则 KEY | 关联指标 | 设值/匹配/逻辑 |
| --- | --- | --- | --- |
| 商品素材语言 | lang | has_material_en | 单值/相等 |
| 商品类目 | category | cate_level1_id/cate_level2_id/cate_id | 多值/相等/OR（下划线拍平多级） |
| 商品标题(含) | titleInclude | title | 多值/包含/OR |
| 商品标题(排除) | titleExclude | title | 多值/不包含/AND |
| 店铺名称(含/排除) | shopNameInclude/Exclude | shop_name | 多值/包含或不包含 |
| 价格区间 | priceUpper/priceLower | promotion_price | 单值/≥、≤ |
| 商品销量 | salesQuantity | tb_sold_quantity_30d | 单值/≥ |
| 店铺 DSR | dsr | dsr | 单值/≥ |
| 热卖趋势 | trend | trend_tag_list | 多值/包含/OR |
| 服饰风格 | clothingStyle | fashion_style_list | 多值/包含/OR |
| 家居场景 | homeScene | residence_type_list | 多值/包含/OR |
| 商品黑名单 | itemExclude | item_id | 多值/不相等/AND（反选） |

## 商品 ID 加解密

来源：商品 ID 加解密技术方案（开放平台）。

- **目标**：对开放 API 返回值中的 itemId 加密生成 `miId`，按灰度置空原始 itemId；入参新增 `miId/taoPassword/itemUrl`，按优先级解析为 itemId，按灰度拦截直传 itemId。
- **入参解析优先级**：miId（最高，解密）> itemId > itemUrl（`resolveItemUrl`）> taoPassword（淘口令解析，返回 bizId 即 itemId）。
- **切面** `ItemIdCryptoAspect`：入参实现 `ItemIdCryptoRequest`、返回值实现 `ItemIdCryptoResponse`；灰度服务 `ItemIdCryptoGrayService`（`shouldClearItemId` 阶段一置空 / `shouldInterceptItemId` 阶段二拦截）；核心 `ItemIdCryptoService`。
- **灰度策略**：白名单跳过 → openAll 全开命中 → 黑名单命中 → 灰名单且 `itemId%100 <= 阈值` 命中。
- **接口分类**：A 类（入参+返回值，5 个）`/product/get`、`/batch/src/products/check`、`/product/recommend`、`/traffic/item/batchGetSourceItemLogisticPrice`、`/traffic/item/get`；B 类（仅返回值，3 个）`/traffic/item/search`、`/traffic/item/imgsearch`、`/traffic/theme/getThemeDetail`。
- **依赖**：SDK `com.alibaba.security:bx-x5-sdk-crypto`（LTK 服务端加密）、`com.taobao.sharepassword:sharepassword-client`（淘口令）。
- **加密 type**（AI 版铺货优化一期）：寻源 144 / toc 208 / 采购 176。
- itemId→mpId：`ProductQueryFacadeImpl.queryMpIdByItemId → SpuDTO{mpId, itemId, List<SkuIdDto>}`（错误码 `NONE_MMP_ID`）；缺 mpId→itemId 反查与详情页 URL 构建器（后续补）。
