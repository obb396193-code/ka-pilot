# AI能力建设

## 概述

本页汇总巴拿马跨境分销（淘系海外 OVS 供给侧，平台品牌为 **Taoworld / 淘天跨境供货平台**）在 AI 方向的能力建设，覆盖五条主线：

1. **AI Coding 研发范式**：以 OpenSpec（SDD 规范驱动开发）为底座，融合 Glue Coding 领域知识体系，落地后端 SDD SOP、前端 AI Coding SOP（`sdd-fe-all-in-one` skill）、IM 群聊版 AI Native 研发流程，实现"需求→设计→澄清→生码→测试→归档"的自动化闭环。
2. **AI 答疑 Agent**：以 Multi-Agent + Flow 架构构建"知识问答 + 智能排查"双引擎（TaoWorld 智能运营助手 / 答疑机器人），目标将技术支持每周约 60% 的答疑工时降本提效 66%（约省 4 人日/周）。
3. **AI 智能外呼**：入驻审核场景的 Taoworld 外呼助手，基于阿里云"通信智能引擎 + 百炼大模型（Qwen）"自研 AI 对话，替代人工坐席回访、识别黑产。
4. **AI 选品**：面向海外流量的差异化搜推 + AIGC 素材处理 + 轻量选品工程框架。
5. **能力总览与规划**：分销 skill 能力总览、运营 SKILL、智能知识库、天机兽智能体，以及 FY26/FY27 AI 建设规划与 Q1 汇报。

> ⚠️ **内容分歧（提效口径）**：不同文档对答疑提效表述略有出入——《可复用答疑Agent落地实践》测算周工作量 6 人日、节省 4 人日、整体提效 66%（在线客户答疑提效 60%、运营技术支持 100%）；《FY26 规划》给出答疑响应时长 90min→10min、准确率 ≥90%、人力 4 人日/周→0.5 人日/周。两者数据基准不同，引用时需注明来源。

**上下游依赖关系**：AI Coding 范式与 [[技术架构与研发规范.md]] 强相关；答疑 Agent / 天机兽依赖 [[账号体系与开放平台.md]]、[[采购交易与履约链路.md]]、[[佣金结算与资损防控.md]] 的业务数据与 MCP 工具；AI 外呼落地于入驻审核链路；AI 选品对接 [[商品域·铺货·选品与搜索.md]]。

## AI Coding 研发范式

### 1. TMW SDD AI Coding SOP（后端五阶段）
围绕 **初始化 → 需求澄清 → 提案与设计 → AI 编码 → 完结归档** 五阶段建设配套能力，共涉及 **7 个命令、6 个智能体、5 个原子技能**，整体完成率约 30%。

| 阶段 | 目标 | 关键 Agent / 产物 |
| --- | --- | --- |
| 初始化 | 建立知识基座 | 从 Aone 拉取各域领域知识（导购/营销/供给/交易/支付/多语言/TMF 扩展点），扫描 master 分支 → 产出 `Code Wiki`、`Project.md` |
| 需求澄清 | 结构化解析 PRD | PRD 检测 Agent、PRD 澄清 Agent、DDD 拆解 → `openspec/changes/<id>/intake.md` |
| 提案生成 | 实现路径/影响范围 | 提案生成 Agent → `proposal.md`；大需求补 `design.md`、`tasks.md` |
| AI 编码 | 逐任务生码 | 编码 Agent + 单测生成 Agent，人工验证与修正，走 CR Agent / Aone AI CR |
| 完结归档 | 知识沉淀闭环 | 归档 Agent 整合 Spec 产物，推送 Aone 远端更新领域知识与 Code Wiki |

**技术选型**：IntelliJ IDEA + AoneCopilot；模型优先级 **Claude-4.6-Opus > Claude 其他系列 > Kimi2.5 > 内部模型**；知识库 = Aone 远程知识库 + Code Wiki + 本地 OpenSpec 规格；SDD 框架选用 **OpenSpec**（轻量、棕地优先）。已落地 AI 全栈场景：AI 生成技术方案、技术方案生码、AI 改 Bug（案例：缺陷 80275342 自动定位 `handleTabChange`/`handleFilterSearch`）、AI 生成接口文档、AI 生成提测文档。

### 2. 后端 AI Coding 范式：OpenSpec + Glue
在业界四层范式（L1 Vibe Coding → L2 Agentic → L3 SDD → L4 Multi-Agent Orchestration）基础上，融合 **Glue Coding 四层领域知识体系**，形成"分层混合式"范式：

| 领域知识层 | 解决问题 | 加载方式 | 效果数据 |
| --- | --- | --- | --- |
| 任务规格（SPEC） | 这次做什么 | 动态生成 | 规范意图 |
| 开发规范（`AGENTS.md`） | 规矩是什么 | 静态注入 | 通过率 53%→**100%** |
| 代码模式（最佳实践 `.showcase/`） | 有没有类似代码可抄 | 按业务域路由 | CR 直接通过 |
| 领域知识（知识库） | 该用什么组件 | 动态检索（MCP） | 采纳率 18%→**35%** |

核心洞察："一个精准的 300 token 上下文，胜过混杂的 113,000 token 上下文"。三层执行模型：**L1 轻量**（<3 天/单文件，Vibe + `AGENTS.md`）、**L2 标准**（OpenSpec 五阶段 + 最佳实践）、**L3 深度**（多 Agent 编排，大需求/新领域）。SDD 框架对比中 OpenSpec 契合度最高（已选用），BMAD/Intent 作理念借鉴。

### 3. 前端 AI Coding SOP（B 端供给域）
基于 `sdd-fe-all-in-one` skill（[open.aone.alibaba-inc.com/skill/sdd-fe-all-in-one]），在 IDEA（AoneCopilot 插件）/ Qoder 内即可完成"创建迭代→生码→部署→CR→发布"。以 `panama-main` 仓库为例，工程含 `.agents/`（agents/openspec/rules/skills）、`AGENTS.md`（OpenSpec 入口）。

- **两种模式**：全流程模式 `ff`（提需求→预发部署一键直达）；原子能力模式（单独调用某能力）。
- **依赖 MCP**：`o2`（创建迭代/CR/发布）、`coop`（关联 Aone 工作项）、`aone-km`（读语雀/钉钉 PRD）、`super-d2c`（设计稿 D2C 生码）、`tmw-ai-coding-mcp`（美杜莎多语言文案）。
- **原子能力**（提示词触发）：安装前端环境、创建迭代、解析 PRD、生成技术方案（产出 `.agents/proposals/design.md`+`tasks.md`）、D2C 生码 / 调优、生成 mock、上传美杜莎文案、更新 changelog、提交代码、部署预发（`o2 p -d`）、提交 CR、线上发布、生成提测文档。
- 覆盖仓库：巴拿马-跨境供销平台（`panama-main`）、采购插件（`taoworld-extension`）、开放平台官网（`panama-open`）。联系人：简柒。

### 4. IM 版 AI Native 研发流程（SOP V2.1）
以 **IM 群聊为协作中枢**，Agent 作为群内 7x24 助手串联 业务方 / PD / 开发。八步闭环：Step 1 项目初始化（拉 Agent 入群、角色识别、生成知识库）→ Step 2 需求提出（问答式录入）→ Step 3 MRD 评审（模板比对/冲突检测）→ Step 4 Demo 澄清（覆盖率检查）→ Step 5 知识同步（30 分钟自动扫描/每日 18:00 摘要）→ Step 6 需求澄清 → Step 7 Coding 方案 → Step 8 研发交付（自动生码/CI-CD 预发/AI 测试/分级验收/CR/发布/归档）。常用指令：`@Agent 需求初始化`、`@Agent 开始需求澄清`、`@Agent 开始生码`、`@Agent 开始测试`、`@Agent 归档`。

> ⚠️ **适用性提示**：Agent 目前仅适用于标准化程度较高的需求，复杂架构改造/创新性需求需人工干预；服务端核心业务逻辑当前以 `TODO` 框架标注待人工补充，自动化测试也在补齐中。

### 5. 全栈视角前端 AI Coding 工具
面向供给团队重构的轻量全栈工具（区别于终端团队的重工具）：研发链路交给 MCP、开发视角基于 SDD、测试链路接入 browser-agent；接入方式为"一键 skill 安装 MCP+skill"。两种入口——编译器 Agent（`ff` 快速 / `normal` 标准 SDD）与 IM 端（钉群 @工作助手 输入 Aone ID + 需求描述，自动完成预发代码编写+发布）。数据统计通过 hooks 上报调用记录。预计 6 月下旬完成并内部宣讲。

## AI 答疑 Agent

### 背景与目标
天猫淘宝海外分销覆盖除物流履约外的电商全链路，技术支持每周约 **60%** 工时消耗在高频重复答疑（客户答疑 + 运营技术支持）。目标：自动化响应、7x24 即时、释放研发，实现"提效+降本+提质"。

### 双引擎与 Case 分类
- **客户答疑**：分 **问答类**（API 文档/业务规则/错误码，可标准化，走 RAG）与 **排查类**（线上异常，需日志/DB/接口交叉诊断，重人工）。
- **运营技术支持**：分 **读数据**（账号状态/业务配置/订单红包查询）与 **写数据**（权限增删、黑白名单、功能开关、大促氛围标等，高风险）。可工具化场景如：开通收货功能、ToC 权限、去地址附加码、API 限流配置、商品池权限增删（`MatrixDataSetFacade`）、下单地址限制（`DatasetFacade`）等。

### 答疑 Agent 框架（1.0）
采用 **能力组件化、策略配置化、流程编排化** 的 Multi-Agent + Flow，构建于知识库管理平台、评测平台、上下文管理平台、提示词管理平台、Agent 注册中心之上。只需提供知识库文档链接 + 配置意图识别/工具路由提示词即可快速落地新领域答疑。全链路：用户提问（群机器人/钉钉 AI 助理/API）→ 业务身份权限校验（`ovs_agent_setting` 配置表 / Diamond，type=权限/流量/提示词）→ 限流管控（并发校验 + 异步排队回调）→ 记忆读取 → 问题改写 Agent → 意图识别 Agent → 分流（`business_qa` 走 RAG / `business_problem` 走工具路由 SLS·HSF / `business_operation` / `other`）→ 结果聚合 → 异步写记忆。

- **意图识别基模**：对比后选 **Qwen Turbo**（约 500ms，准确度 100%，快于 Qwen3-max ~1200ms / Qwen3-30B ~600ms / Qwen-plus ~600ms）。提示词遵循 Role→Rules→Few-shot，输出严格 JSON `{"intent":"business_qa|business_problem|other","confidence":0.xx}`；排查类判定强规则：仅当含订单号（约 20 位）/traceId（约 30 位数字字母）/商品 id（12 或 16 位）且不含错误码时判为排查类。
- **问题改写 / 工具路由**：均用 Qwen Turbo；工具依赖 HSF/SLS 分组、遵守单一职责，工具描述与 `tool_name` 写入路由配置表供基模关键词匹配。
- **技术难点**：多场景意图识别、群聊记忆维护与上下文瘦身、高并发限流可用性、Function Call 误调用风险（如错误退款工具引发客诉）。

### 答疑 Agent 2.0（930 规划）
从"静态知识库 + 一次性回答"升级为 **Action 类知识库 + 跟进式迭代答疑**：
- **Action 类知识库**：每条知识升级为可执行动作单元（触发条件、输入参数、执行步骤、工具 key 与调用示例、输出模板、风险等级与人工确认点），支持 T+1 语雀同步、聊天记录高频 Q&A 自动提取升级、版本管理灰度回滚。
- **跟进式迭代**：追问澄清 → 草稿确认 → 执行/回答（写操作走风险管控二次校验）→ 沉淀迭代（人工修正自动回写）。
- **时间节奏**：2026-07 Action 基线 → 08 跟进式 Agent → 09 运营与身份隔离 → 10 评测与规模化。评测指标：Action 命中率、追问有效率、人工确认准确率。负责人：简柒。
- **近期知识库建设进展**：已收集 104 条历史群聊有效记录去重；接入 `panamabff`、`global-seller-common-s` 等应用 SLS 日志（`gsp-order` 日志量大易超时暂缓）；接入 errorCode/订单 ID 查询、前端日志、截图问题定位；问题转人工机制待接入。

### 答疑 Skill（排查工具链）
沉淀为可执行 skill，排查流程"拿到问题→分类→定位应用→三角取证→给结论"。
- **覆盖仓库（本地 clone 7 个）**：`ovs-pnm-account`（账号/鉴权/白名单/AI 外呼）、`ovs-pnm-matrix`（流控/权益）、`ovs-pnm-open`（商品/流量/价格混淆/口令解析）、`ovs-pnm-purchase`（下单/收货/售后）、`ovs-pnm-incentive`（结算/提现/发票）、`ovs-pnm-distributor`（前后台/订单聚合）、`ovs-pnm-data`（数据导出）。
- **三角取证**：① 代码（本地 grep + Read 定位 file:line）② 日志（SLS 多 project/logstore）③ 数据（DMS 双库 + ODPS 离线表），至少凑齐两条互相印证；配 **反幻想复查**（证据推翻初判则换归属重走）。
- **MCP 工具**：读类 `dms-mcp-server`、`ovs-pnm-account`、`sls-mcp`、`skylark`（语雀）、`ovs-pnm-matrix`；写类走 `createDataChangeOrder`（DMS 工单审批），如 `set_api_rate_limit`、`add_whitelist_leadsId`、`initiate_ai_call` 等，**写操作强制走 DataChangeOrder，禁止 executeScript 直改**。
- **配套 skill**：`ali-middleware`、`guard-apply`（ODPS 表权限）、`panama-crm-export(-odps)`、`theme-oauth-manage`、`ovs-pnm-skill`、`fbi-skill`、`skylark`。`FAQ_HIGH_FREQ.md` 沉淀 70+ 条对外口径。
- **关键坑位**：两库勿串（`tmw_panama` dbId=5183113 结算/提现/绑定 vs `global_tmalloversea_panama` dbId=1738569 CRM 主库）；外层 `code=0/success=true` 不代表 goods_info 内层成功；mpId（19-20 位）vs 淘宝 itemId（约 12 位）以长度秒判。

> **关系**：答疑 Skill 是 [[技术架构与研发规范.md]] 排查 SOP 的 AI 化落地，也是天机兽/答疑 Agent 排查能力的底层工具集。

## AI 智能外呼

### 场景与定位
Taoworld 外呼助手面向**新用户入驻审核回访**场景。原由 3 名外包人工外呼，人手不足常跳过导致垃圾客户混入。目标：在原有证件审核 Agent 基础上增加**智能外呼 Agent**，识别黑产（无效号码/无效回答/拒绝接通）并基于语音回复明确入驻意图、自动回流 CRM。整体业务耗时目标控制在 1200ms 内。

### 方案选型
对比三类语音产品：**通信智能引擎**（仅底层通信/媒体，对话逻辑自研，灵活度最高）、**通信智能体**（内置大模型配知识库，灵活性不足）、**智能联络机器人**（纯规则拖拉拽，上限低）。**最终选用通信智能引擎**（内置 ASR/TTS，450ms 内响应）。服务层放弃百炼工作流（黑盒、无法流式拦截）转 **高代码自研**。

### 系统架构
两大核心：**实时对话引擎（ActorAgent）** + **离线评测引擎**。
- **对话引擎**：CRM 下发外呼任务 → 通信智能引擎 ASR/TTS/打断 → 开场白/首轮规则匹配/六步状态机推进/动态模型选择/SSE 流式推送/敏感词过滤；每轮动态 Prompt 组装融入知识库与模板。
- **评测引擎**：录音异步回传，下挂 **信息提取子 Agent**（结构化审核意见回流 CRM）、**质量评估子 Agent**（多维评分）、**Prompt 优化子 Agent**（对比效果迭代 Prompt），形成持续改进闭环。
- **四层架构**：业务层（CRM + 运营后台）、接入层（通信智能引擎）、服务层（阿里云 FC，FastAPI + AgentScope + Python asyncio，SSE 流式）、模型层（**Qwen-Plus/Turbo + Qwen-Max**，同 Region 部署）。
- **接口链路**：`CreateAiCallTask`（创建任务骨架，绑定 AgentId、虚拟号、重试策略）→ `ImportTaskNumberDatas`（导入被叫号码 + 上下文变量，单次 ≤1000 条）。CRM 侧新增 `ovs_ai_call_task`（外呼任务主表）、`ovs_ai_call_record`（通话记录明细，含 ASR 转写/审核结论/录音 OSS 地址）。

### 六步审核状态机
渠道来源 → 采购意图 → 物流能力 → 核心信息（主营类目/目标市场/团队规模/采购规模）→ 支付确认（港台日韩新泰马主体追问万里汇 WorldFirst）→ 审核结论。驳回条件：销售/代销/上架意图、无法自处理跨境物流、渠道来源可疑（ERP 不在 30+ 官方认证厂商列表）、关键信息 3 次模糊缺失。流程骨架由代码控制（杜绝跳步/遗漏），LLM 仅处理语义理解。

### 核心优化与效果
| 问题 | 方案 | 关键指标 |
| --- | --- | --- |
| 首字符延迟 >1s（挂断率高） | 自研 FastAPI+AgentScope + SSE 句子级逐句推送 + 多层去重（temperature=0.7/top_p=0.9） | 首轮响应 1.05s→<0.1s（90%↓） |
| 40% 首轮仍调 LLM | LLM 前置**首轮极速响应规则引擎**（8 类关键词命中即返回：拒绝/转人工/情绪/否认注册/销售/1688/模糊/有效渠道） | LLM 调用 100%→60%（40%↓）、成本降 40% |
| 单模型难兼速度与精度 | **动态模型选择**：简单步骤（渠道/ERP/采购意图，40%）用 Qwen-Plus，关键步骤（物流/核心信息/结论/支付，60%）用 Qwen-Max | 零切换成本 |
| 幻觉/重复提问/误判 | 规则+LLM 混合决策 + 六步状态机 + ERP 模糊匹配（去 "ERP" 后缀）+ ASR 容错（Prompt 注入误识别示例）+ 语气承接 | 重复提问 15%→<2%（87%↓）、ERP 识别 85%→98%、审核通过率 78%→92% |

**综合效果**：平均响应 1.05s→0.68s（35%↓）、首轮 <0.1s（90%↓）、LLM 调用 100%→36%（64%↓）、API 成本降 49%、审核准确率 85%→96%。

> **数据资产复用**：历史人工外呼录音经"对话清洗→知识提取→知识验证→知识入库"4 步法转化为三层知识库（核心规则层/业务知识层/对话技巧层），用于 Prompt 动态注入与 RAG，同一套语音交互通路（ASR→意图识别→多轮对话→自动判定）可复用于客户答疑、CRM 智能化。相关业务规则详见 [[账号体系与开放平台.md]] 入驻审核。

## AI 选品

### 必要性与海外优势
AIGC 将重塑流量入口，AI 选品较传统搜索选品显著提效，算法能力可迁移至海外 ToC 搜推导购与凑单。海外已建成的差异化能力：
- **禁限售/运标签识别模型**：覆盖近 20 亿淘系商品，药品/纯电/食品等标签准确率接近 100%。
- **海外搜索召回&排序模型**：基于海外人群行为差异化建模（人群样本、稀疏性建模、物流因子、DANN 扩充样本、"确认订单页"辅助目标），相对手淘主站 **搜索场 UV 价值 +8%、推荐 L-P +30%**。
- **商品素材国际化全链路**：标题优化 + 图片 OCR-翻译-合图，累计处理翻译 **7KW（7000 万）商品**；对接塔基平台外模图能力（6 月初灰度）。
- **轻量可扩展 AI 选品工程框架**：选品任务管理 + 流程编排调度 + 提示词管理，多模型接入（GPT3.5/GPT4/ChatGLM，当前依托 GPT3.5 调优）。

### 成本
基于 GPT3.5：单次选品 token 约 10550，千次约 21.1 美元；分销选品全年机器成本 **117.8 万**（大模型 107.8 万 + 工程 10 万），支持每天 2 万次选品。私有化模型效果与 GPT 差距较大暂未计成本。需求资源：稳定可控大模型基础设施（海外不可自建，考虑复用 AIDC 底层大模型）、Java 版 langchain 工程框架。

> **关系**：AI 选品与 [[商品域·铺货·选品与搜索.md]] 深度耦合；FY26 规划进一步扩展为国别化趋势商品清单、商品素材智能优化、语义识别智能搜索、商品智能同款推荐、智能凑单等场景。

## 分销 Skill 与智能知识库

### 巴拿马分销 Skill 能力总览
面向运营/技术支持的自然语言驱动 skill，覆盖 **13 项能力**，统一执行规则：能力检查 → 信息收集（缺参主动追问）→ 写前二次确认（高风险操作）→ 先查后写（取基线→变更→复查）→ 结果回写。

## 智能体天机兽

分销智能体"天机兽"是**线上问题排查与答疑 SOP AI 助手**的早期形态（AI Studio ideaTALK 应用），面向研发提效与运营数据自助。目标功能：解决运营问题（待开发）、答疑问题（搭建中）、技术问题排查（持续升级）、智能报表（待开发）。

**详细功能**：① 一键排查线上问题（按 trace/关键词并发查询分销系统日志、组装出入参、主动分析错因）② 匹配线上问题 SOP 并输出 ③ 分销业务数据查询（订单/CRM/激励/对账单）。已支持常见技术问题排查、交易问题全链路排查（当前支持 buy2，tp/pp 待接入）、答疑 SOP、问题定位+解决方案输出。

**核心工作**：对接分销系统 SLS 日志（系统 10+ 个、logStore 30+ 个）；SOP 知识库生成挂载（采购交易/账号/商品 SOP）；HSF 接口接入（CRM/激励/订单）；报表接入。

> **演进关系**：天机兽 → 答疑 Skill（本地化 7 仓库排查工具链）→ 答疑 Agent 1.0（Multi-Agent+Flow）→ 2.0（Action 知识库 + 跟进式迭代），是同一条"智能排查/答疑"能力主线的迭代。

## AI 能力建设规划

### FY26 巴拿马 AI 解决方案
**业务输入**：S2 因数据安全策略调低 GMV 目标（30 亿→26 亿，全年 Ebita 3000 万不变），运营策略聚焦高净值客户、风险防控升级、Ebita 优化。AI 应用集中在**商品搜推、趋势供给、客户成长、客服答疑**。从用户经营动线（入驻→选品铺货→搜索撞库→采购下单→答疑）出发拆解：
- 客户入驻智能审核（证件 OCR 实人实证 + 智能外呼挖掘高潜力客户）
- 客户智能运营（Agent 周期打标分层推送运营跟进）
- 国别化趋势商品清单、商品素材智能优化
- 语义识别智能搜索（精准 query→自然短语→切割多 query）、商品智能同款推荐（同款簇+质量打分）
- 智能凑单（拆合单降本）
- 客户答疑（知识库 + 智能答复）

**S2 落地计划**：智能外呼 Agent（26.01 投入/26.02 发布，外呼 7 个/天→70 个/天，人力 5 人日/周→2 人日/周）；客户答疑 Agent（26.02 投入/26.03 发布，响应 90min→10min，准确率 ≥90%，人力 4 人日/周→0.5 人日/周）。

### FY27 AI 能力建设规划
以 **AI Native（skill）新交付形式** 转变业务迭代方式（采用 OpenClaw/QoderWorker 等本地 AI Native 而非云端部署，控制落地成本）。
- **目标**：端到端 AI Native 覆盖率 80%、核心场景 90%、分销链路 100%；客户覆盖度 50%、skill 建设量 40+；运营单用例人日降 80%；单品议价时长缩 80%、单次选品采购时长缩 50%。
- **客户侧 12 类 skill 用例**：Taoworld 入驻、海外电商平台入驻、消息接收解析（WhatsApp/Ins/Telegram/FB/微信）、商品撞库（图搜+词搜）、议价（IM 买卖家沟通）、下单（支付人工）、选品铺货、一键开店（云实例创建+代码部署，商业化）、多平台铺货（Amazon/Shopify/TikTok Shop/eBay）、订单同步、发货识别与履约、子账号管理。
- **运营侧 10 类用例**（含节降与进度）：入驻审核（22→4 人日/月）、客户状态推进（12→3）、客户反馈收集分析（4→1）、国内转售风险客户识别处置（4→1）、层级归佣核对（18→3，嘉宁 100%）、结算佣金对账（18→3，缀明 90%）、支付比/用量考核（10→2，嘉宁 80%）、权限开通（3→1，嘉宁 60%）、采购账号转移（3→1，仲劭 20%）、归佣调整（3→1，嘉宁 100%）。
- **时间计划**：运营侧 5-7 月；客户侧 8 月 AI 智能入驻、9-11 月 E2E 智能采购议价、12-3 月 AI 选品铺货多店运营。

> ⚠️ **风险提示**：FY27 文档标注 IM 自动议价可能触发淘宝风控；全自动"类 SaaS 跨平台 ERP"模式可能有法务风险。

### Q1 巴拿马 AI 汇报
**核心痛点**：运营事务碎片化、客户接入技术门槛高、业务知识散落。**优先级**：技术答疑机器人（P0/复杂度最低）> 一体化智能客服数字运营 Agent（复杂度最高）> 海外采购选品助手（次高）。

**当前进展（数据）**：
- **招商入驻**：近一个月（6.3~7.3）入驻申请 2656 笔，AI 参与审核 1455 笔，**覆盖率 54.8%**；AI 外呼发起 335 通，通过率 75.3%，接通后判定不通过率 60.3%。沉淀"智能对话能力"（ASR→意图→多轮→自动判定）与"客户画像能力"（信息采集→画像生成→智能分发）。
- **客户管理**：运营 SKILL 自然语言驱动客户数据查询与操作，新上线试用中。
- **智能答疑**：技术答疑机器人 630 启用内测，每 2 日迭代；知识库路线 答疑历史→日志接入→代码知识库→KBASE 荟萃(830)→自动更新(930)。

**里程碑**：运营提效 630（P0/P1 MCP&SKILL）/930（P2+全链路异常主动外呼）/1030（业务知识库）；技术提效 815（技术答疑）/930（业务答疑+排查定位占比 50%）；客户提效 双十一后 AI Native 一站式接入、1230 采购选品助手第一版。

**终极目标**：一体化智能客服运营 Agent（入口 IM/外呼/Taoworld 助手，售前→售中→售后）+"最懂客户和市场的"采购选品助手。
