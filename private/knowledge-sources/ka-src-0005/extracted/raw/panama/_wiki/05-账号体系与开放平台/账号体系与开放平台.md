# 账号体系与开放平台

## 概述

本页汇总巴拿马跨境分销（淘系海外 OVS 供给侧）的**账号域**建设：主子账号体系、UserRelation、入驻与国际支付宝绑定、分层分权/分层分级 API 调用管控、开放平台（OpenAPI）授权链路，以及 1688 采购对接（聚石塔）与 leads/CRM。

账号域是整个分销业务的基础设施：商品铺货、交易履约、佣金结算、IM 等一切上层能力都依赖它提供的账号识别、权限校验与授权 token。核心设计原则（见 [[技术架构与研发规范.md]]）是把历史分散在 `global-uic`、`gsp-order`、`gsp-merchant` 中的分销商用户逻辑，**收敛**到独立的账号域工程 `ovs-pnm-account`，向上被业务层依赖，而非反向被中台/平台依赖。

**核心应用矩阵**：

| 应用 | 职责 | 数据库 / TDDL APP |
| --- | --- | --- |
| `ovs-pnm-distributor` | 分销平台 portal：跨境供销平台（`distributor.taobao.global`）+ 采购管理系统（`distributor-management.taobao.global`） | `global_tmalloversea_panama` / `GLOBAL_TMALLOVERSEA_PANAMA_APP` |
| `ovs-pnm-open` | Open API 开放平台 | - |
| `ovs-pnm-account` | 巴拿马账号域工程（账号 / 客户 / 角色 / CRM / 入驻） | `global_tmalloversea_panama` / `GLOBAL_TMALLOVERSEA_PANAMA_APP` |
| `ovs-pnm-gateway` | 网关，目前只对接 1688 三方接口 | `tmw_panama` / `TMW_PANAMA_APP` |

**上下游生产关系**：
- **国际会员（global-uic，HK 租户）**：提供登录态 session、主账号/子账号创建；数据隔离以不同 `site` 值区分（巴拿马、采购管理系统、国际开放平台共用 HK 租户）。
- **货通平台（gsp-merchant）**：分销商基础信息（目前只写不读）。
- **开放平台**：主子账号授权开放平台账号链路。

## 账号域与主子账号体系

### 演进脉络

1. **用户体系升级（2022，`egwq`）** —— 提出问题与架构方向：历史单账号模式下分销商需注册“一堆”账号（20 个采购账号需 20 个淘客账号才能 CPS 返佣），能力不收敛且分散在 global-uic/gsp-order/gsp-merchant。提出自建分销商用户应用，收敛领域基础能力。
2. **采购管理系统（主子账号分离）一期（2022.11，`wnd7oe`）** —— 最早的主子账号尝试，在 `ovs-pnm-distributor` + `global-uic-s`（分支 `20221117-panama-purchanse-account`）落地，引入 `purchase`（采购账号）、`purchaseAdmin`（采购管理账号）、`purchaseAdminId` 角色概念。
3. **账号建设 V1/V2（2023，`qmuqzwiy`/`znff3y1`）** —— 明确领域模型与两种设计思路选型。
4. **主子账号 + 工作台升级（2023，`wm3yiw`）** —— 新建 `ovs-pnm-account` 应用，落地 RBAC 权限模型与工作台改版。

### 账号模型（V2 采用方案）

以 KA 入驻主体为核心，主子账号同属一个 `distributor_id`：

- **巴拿马主账号（PnmMainAccount）**：KA 入驻的核心主体，原有入驻链路迁移到主账号入驻流程。
- **巴拿马子账号（PnmSubAccount）**：即分销商采购员。**只能分配、不能注册**。
- **海外联盟账号（ovsAffiliateAccount）**：绑定主账号，用于下单 CPS 返佣结算（详见 [[佣金结算与资损防控.md]]）。
- **淘宝买手账号**：真正在淘宝天猫下单的账号，附属在主账号下，同时绑定子账号；采购账号与买手账号是"弱链接"（可形成账号池）。
- **国际支付宝 AB 户 / 1688 账号 / 开放平台开发者账号**：外部绑定账号。

> ⚠️ **内容分歧**：账号建设 V1（`qmuqzwiy`）曾并列两种思路——「思路一：子账号拥有全部数据+主账号拥有子账号所有权限」与「思路二：子账号只拥有操作权限不拥有数据」。**最终采用思路二**（V2 及主子账号+工作台升级方案确认）：子账号只拥有下单、支付等操作权限，不拥有数据；OpenAPI 支持授权子账号；子账号操作可溯源（订单写入子账号 ID）；子账号支付时选择主账号绑定的支付宝。

**痛点 → 解法对照**（V2）：
- 分销商账号过多需一一绑定联盟账号 → **采购主账号统一绑定联盟账号**；
- 账号分散无明确主体 → **主账号作为入驻主体，可选生成 n 个子账号**；
- 授权过期需手动重授 → **自动生成开放平台账号并自动授权主账号**。

### RBAC 权限模型

`ovs-pnm-account` 采用 RBAC：**账号 → 角色 →（权限 = 权限点集合）→（资源 = 菜单/按钮/接口，最小单元为资源点）**。

- **权限点**：最细粒度控制单元，如 `order:pay`（订单支付）、`order:create`（采购创单）。
- **资源点**：资源最小实例，如商品撞库接口 `com.alibaba.pnm.open.facade.ProductQueryFacade#queryProductById` 对应资源点 `itemDistribution`。
- 子账号权限 RBAC 存储在 **diamond**（应用 `ovs-pnm-account`）：`account.resource.config`（资源）、`account.permission.config`（权限）、`account.menu.config`（菜单）。
- 权限枚举按页面 uri + 资源点 name + mtop API + 所属权限组织，覆盖：选品铺货（`selectionDistribute:*`）、订单支付、采购创单、售后逆向（`refund:*`）、对账单、账号管理、岗位/角色管理、IM。子账号管理相关 mtop：`mtop.alibaba.ovs.panama.account.sub.create/resetPwd/updateStatus`、`mtop.alibaba.ovs.panama.account.role.create/edit/delete`。

### 存储与代码结构

**核心表**（`global_tmalloversea_panama`）：`ovs_pnm_account`（主子账号表，含 `role_code`、`is_admin`）、`ovs_pnm_account_detail`、`ovs_pnm_account_bind`（支付宝/1688 等绑定关系）、`ovs_pnm_account_address`、`ovs_pnm_role`、`ovs_pnm_distributor_apply`（入驻记录）、`ovs_pnm_customer`（客户）。

`ovs-pnm-account` 分层模块：
- `ovs-pnm-account-api`：`AccountAdminApi`（小二运营后台）、`AccountAuthApi`（账号授权，主为 1688 授权链路）、`AccountManageApi`（子账号管理）、`AccountMerchantApi`（入驻、支付绑定、实名、旧采购系统账号绑定）、`AccountReadApi`（核心对外读，内含缓存）、`AddressManageApi`；客户 `CustomerManageApi`/`CustomerReadApi`；角色 `RoleManagerApi`。
- `ovs-pnm-account-client`：`AccountAPIClient` 富客户端，用 tair 缓存账号↔客户映射。
- `ovs-pnm-account-application`：因 `ovs-pnm-account` 与 `ovs-pnm-matrix`（权益/分层）存在双向依赖而新增，承载入驻/CRM 业务流程，含 `MatrixFuncPermissionListener`（监听入驻成功写功能权限到 matrix）、`MatrixLeadsIdRefreshTask`。
- `ovs-pnm-account-adapter`：防腐层，二方服务 uic、alipay、guic、division（地址库）、distributor（gsp-merchant），中间件 odps、cache、diamond、dingtalk。

### UserRelation（用户关系，`gf7uz0`）

描述分销商 ID 与其他信息的对应关系，为支持高 QPS **直接存储在 tair**（KV 方式）：
- key = `distributorId`；
- value = `{leads, userType, userLevel, status}`；
- `userType`：`dai_gou`（代购）/ `retailer`（零售商）/ `service_provider`（服务商）；
- `userLevel`：`normal`/`ka`/`ska`；`status`：`testing`/`online`。
- tair 实例：name `3c95397f3ccb401a`，namespace `708`，unit `center`。

## 用户入驻与国际支付宝绑定

入驻链路由 `ovs-pnm-account`（`DistributorOnboardingService`）+ BPMS 审批流驱动，含多个审批节点：

1. **采购账号注册与资料提交** → 灰度期需配置白名单（diamond `platform-config` / group `panama-distributor`）。
2. **入驻资料审批**（BPMS `panama_settle_audit`）。
3. **绑定国际支付宝 AB 户**（ipay AB 户 = Alipay for Global Business / alipay business，B 端账号）：BPMS `panama_alipay_bind_flow`；提交接口 `mtop.alibaba.ovs.panama.distributor.settle.alipayIntl.submit` → HSF `DistributorOnboardingService#submitAlipayIntl`；审批通过回调后接入 ipay SDK 绑定，并把余额/企业名称/营业执照信息更新到 `global_distributor`。
4. **实名审批**（BPMS `panama_realname_flow`）：`DistributorOnboardingService#submitRealNameMaterial` / `renderRealNameData`；清除实名走 `AccountMerchantApi#clearRealName`（需先提 ione 工单）。
5. **World First（跨境宝）绑定**：`AccountWFService`，依赖淘宝开放平台 top API。
6. **小蜜服务入口**：`AccountSettleService#getAliMeLink`（阿里小蜜 / XP 智能客服平台）。

绑定验证闭环（`vniaagtxf6tubsia`）：采购账号创建订单并支付 → 国际支付宝账号有扣款记录；申请退款 → 支付宝账号收到退款记录。

**自动入驻（新增主账号 leads，`kz8t0`）**：HSF `AccountSettleService#bindEmailForAutoSettle(userId, email)` 先绑定邮箱（写入 `pnm_auto_settle_email_{ID}`，有效期 30 天），再由 `autoSubmitMaterial` 自动提交入驻材料；邮箱未绑定/不匹配返回 `AUTO_SETTLE_EMAIL_NOT_BOUND` / `AUTO_SETTLE_EMAIL_NOT_MATCH`。

> 支付绑定与创单支付的完整交易侧链路见 [[采购交易与履约链路.md]]。

## 分层分权与 API 调用管控

面向不同**客户层级（普通/KA/SKA）**与**分销商类型（代购/零售/服务商）**，对能力做分层分级授权与用量管控。

### 能力项模型（`gav`/`odx`/`qt8`）

- **能力**分主能力/子能力，也分 **API 能力**与自定义能力。能力分类涵盖：选品铺货、账单查询、物流、订单售后、订单售中、商品查询、商品素材、流量承接（2C 搜索/2C 详情/撞库寻源）。
- **API 能力属性**：`abilityId`、`abilityCode`、`abilityName`、`abilityApiPath`（开放平台 API 路径）、`abilityClazzPath`（类方法路径）、`enableFastFail`、`failDuration`、`waitDuration`、`canUse`/`notCanUseReason`、`whiteList`、`abilityType`（`api`|`self`）。
- **控制维度**：分销商主账号（如铺货量）或分销商 APPKEY（如 QPS/调用量）。**规则量化**示例——零售铺货 `submit_goods_rules`/`max_submit_goods`：每日发起铺货 ≤ 2W、总铺货 ≤ 50 万；流量承接类按 QPS/每日调用量/总调用量约束。

### 调用管控与用量统计（`fk39nm`/`oopa1y`/`ha7tbw`）

- **管控 = 能力 + 调用策略**，两个维度：方法维度（对应权益配置）、用户维度（对应特殊解决方案配置）。
- **能力校验**：`com.alibaba.ovs.panama.facade.PnmRuleCheckerFacade#check`，按 leads 维度校验是否有权限。
- **用量统计**：每天统计各 API 能力接口调用量并存储回流；FBI 报表按（leadsId、api、日期、当日调用总量、当日余量）展示。
- **调用预警**：odps 加工超限预警底表 → 回流账号 mysql 表 `ovs_pnm_customer_warn` → 接入阿里钉机器人预警（`CustomerWarnTask`）。
- **富客户端查客户**：`AccountAPIClient`（`ovs-pnm-account-client`）封装 `CustomerReadApi#get`，返回 `CustomerDTO`（`leadsId`、`level` KA/SKA/NORMAL、`type`）。
- 权益模板存于 matrix 应用离线表：`s_hierarchy_rule_template_tb_app`、`s_hierarchy_rule_tb_app`、`s_hierarchy_rule_constraint_tb_app`。

### 解决方案与收佣控制（账号域技术方案，`rkkeotq`）

分销商 leads 可配置**解决方案**，控制收佣范围：
- 枚举：零售铺货 `retailSolutionA`（全收佣）、推广赚佣 `agentSolutionA`（全收佣）、推广赚佣非退货宝 `agentSolutionB`、纯采购 `agentSolutionC`（仅淘客）。
- 收佣三模式：全收佣 / 保退货宝收佣（不收全球增长计划、大件出海）/ 仅淘客。
- 存储：`ovs_pnm_customer_solution`（leads_id、solution_code）+ diamond 配置；接口 `CustomerSolutionApi#updateCustomerSolution(Definition)`、`CustomerManageApi#queryCustomerSolution`。
- Open API 侧：`/customer/distributor/list`（服务商查下游分销商）、`/customer/distributor/solution/update/solution`。

> **分层开放平台能力建设（`lk7`）** 规划以 MVP 框架接入核心接口，目标覆盖 90% 核心开放接口；结合选品工作台升级集成上线。限流与降级治理详见 [[限流与服务治理.md]]。

## 开放平台 OpenAPI 与授权

### 平台与账号

- 分销商 ISV 注册平台 `open.taobao.global`；ISV 管理/控制台 `iopadmin-hk.alibaba-inc.com` / `iopconsole-tbgl.alibaba-inc.com`。
- 账号模型（`ssqm1a`）：开放平台账号（注册于 global-uic）、开放平台应用（新建于开放平台）、appkey↔分销商授权关系（授权链接产生，存开放平台）。

### 授权链路

标准 OAuth 授权码流程：
1. 先登录分销平台账号（分销商 session）；
2. 访问授权链接 `https://api.taobao.global/oauth/authorize?response_type=code&redirect_uri=<回调>&force_auth=true&client_id=<appkey>` 拿到 code；
3. 调 `/auth/token/create` 换取 token 与 refresh_token；
4. 携带 token 请求业务 API（示例 AppKey `500018`）。

**授权链路优化方向（`ssqm1a`）**：把 appkey↔分销商多次授权改为**只授权一次**（ucc 关系记录 appkey + 分销商 userId，后续国际会员自动登录换 token）；统一会员绑定关系入口；巴拿马侧自助管理开放平台文档。

### 接口盘点（`hx40yp`/`wf3nts`/`ntxwpn`）

Open API 由 `ovs-pnm-open` 承载，业务实现均在 `com.alibaba.pnm.open.facade.*`，共约 **49 个接口**，主要门类：
- **商品**：`ProductQueryFacade`（`/product/get`、`/item/get`、`/mpId/get`、`/batch/src/products/check`、`/product/recommend`、`/promotion/query`）、`DistributeFacade`（`/product/relation/build` 建立品商关系、`/product/relation/cancel` 取消）、`ProductCategoryFacade`（`/product/categories/get`）、`SellerProductsFacade`（`/product/details/query`、`/product/spus/get`）、`SearchItemFacade`（`/product/selection/` 导购搜索）、`SimilarItemFindFacade`（`/product/similar/get` 同款图搜）。
- **交易/售后/物流/供应链**：`PurchaseOrderFacade`（下单渲染/创单/取消/批量支付/查询采购单）、`RefundOrderFacade`（逆向单渲染/提交/查询/取消/留言/物流单）、`LogisticsServiceFacade`、`SupplychainServiceFacade`（`/supplychain/price/get` 报价）。
- 调用量 TOP 集中在 `/product/details/query`、`/purchase/orders/query`、`/product/get`、`/product/relation/build`、`/supplychain/price/get`。商品接口细节见 [[商品域·铺货·选品与搜索.md]]。
- OpenAPI 描述与代码对应关系通过 `open.taobao.global/handler/share/apidoc/getApi.json` 自动采集维护。

### 现存问题（`obv09z`/`ve1hk9`）

- **平台可用性差**：应用控制台 API 测试工具不可用、API 消息推送日志无数据、消息服务/订阅无法展示、多处链接跳转未知页面；文档目录树无编辑权限、维护成本高、存在年久失修与干扰文档；工单系统未真正用起来。
- **对接体验**：开放平台账号从注册到上线经过 3 次审核（注册由分销侧审、创建应用与上线由开放平台侧审），周期常被拉长；分销工作台账号与开放平台账号**登录态混乱**易导致授权 code 拿错、连锁报错；错误码不够显性化导致反复答疑。
- **结论/优化**：代购模式接入成本显著小于导购模式；建立大客户对接准入准出标准；推动**代购/导购方案对客户黑盒化**（下单接口不再显式传渠道参数，撞库/铺货商品可混合下单）。

## 1688 采购对接与聚石塔

将货通采购（gsp-order）已对接的**二方接口切换为三方接口**，在 1688 开放平台采用「跨境 ERP 对接解决方案」对接；三方接口统一封装到网关应用 `ovs-pnm-gateway`（二方库 `ovs-pnm-gateway-cbu-api`）。

### 聚石塔接入（`ik0599`/`tlbmgzk`）

1688 OpenAPI 上线要求调用方为**聚石塔内应用 IP**，故在聚石塔申请代理应用：
- 架构：弹内 `ovs-pnm-gateway` → 聚石塔巴拿马 VPC（公网 SLB → `ovs-pnm-jst-open-api-proxy-server`（Nginx 反向代理）→ NAT/EIP）→ 1688 OpenAPI；WebSocket 消息通知切换为 **URL 回调模式**。
- 网关实例 IP：集群公网 IP `39.99.245.86`（对外提供）、弹性公网 IP `39.98.181.217`（SNAT 出口，调 1688 用）。
- Nginx 关键配置：`proxy_pass http://gw.open.1688.com`（转发 1688）、`/cbu-open-callback/` 回调 `distributor.taobao.global`、`/websocket` 代理 `message.1688.com`。
- 成本：约 **19307 元/年**（2 台 4 核 8G 互备集群 + 带宽）+ 约 15 个开发测试人日。
- 1688 侧应用：AppKey `3382576`（跨境供货 erp，关联「跨境 ERP 对接解决方案」）。

### 账号授权链路（`pd5xwg`）

- 采购主账号与 1688 主账号绑定为 **1:1**；绑定时校验对方是否为 1688 主账号。
- token 生命周期：code 有效期 2min、token 10h、refresh_token 半年（refresh 期间若 token 未过期则不返回新 token）；**scheduleX 每小时刷新 token**。
- 子账号授权 MTOP（`ovs-pnm-distributor`）：`mtop.alibaba.ovs.panama.account.authorization.get/cancel`、`subAccount.authorization.get/cancel`、`account.subPurchaseAccount.list`、`account.subPurchase.authorize`、`account.purchase.authorize`。HSF（`ovs-pnm-account`）：`AccountAuthApi#pageQueryAuthSubAccount` / `#unAuthSubAccount`。

### 创单链路（`ftwxxl`/`mro7fv`）

- 三方 API：商品 `alibaba.cross.productInfo`、创单 `alibaba.trade.createCrossOrder`；HSF `CrossProductService`（`getByProductId`）、`CrossOrderCreateService#createOrder`。
- **主子账号的 1688 订单 buyerId 都归属主账号**（与淘宝货源不同），扩展属性记录子账号 ID。
- 货源市场 `purchaseMarket`：`TAOBAO`（淘宝货源）/`CBU_MARKET`（1688 货源）/`GONGXIAO`（供销线下货源）。
- 支付：1688 订单支付走 `mtop.alibaba.ovs.panama.purchase.getPayUrl`（返回 1688 收银台 payUrl），淘宝订单仍走 `mtop.alibaba.ovs.panama.purchaseorder.batchpay`；下拉筛选 `mtop.alibaba.ovs.panama.purchase.getPurchaseMarket`。
- GSP 采购创单同步/异步开关：`PANAMA_ENABLED_SYNC_PURCHASE`。

> 1688 采购交易的履约、退款等完整链路见 [[采购交易与履约链路.md]]。

## leads / CRM

CRM 系统内建于 `ovs-pnm-account`（customer 领域），后台 `tmallworld.alibaba-inc.com/supply/visual/crm`；小二侧角色权限配置在 `ovs-operationcenter` 的 ACL 后台，代码按角色硬编码判权。

**客户模型**：`leadsId`（对应国际会员 userId）、`name`、`status`、`level`（KA/SKA/NORMAL）、`type`（`disRetail` 零售 / `disPurchaseAgent` 代购 / 服务商）。客户表 `ovs_pnm_customer`（含 `leads_id`）。

**客户状态机**（`initial`=Leads → `negotiating` → `negotiate_success` / `collaborate_fail` → `open_api`（API 对接中）→ `test_operation`（测试运营）→ `normal_operation`（正式运营）/ `discarded`），意向层级 `willingnessLevel` P0/P1(KA)/P2。状态推进由 scheduleX 任务 `CustomerStatusSystemTask` 驱动（API 对接中→测试运营、测试运营→正式运营）。

**leads 接口**：
- `/customer/render`（CRM Leads 渲染接口，返回状态/意向/技术能力枚举）；
- 客户读写 `CustomerManageApi` / `CustomerReadApi`；
- 新增主账号 leads 自动入驻见上文 `bindEmailForAutoSettle`；
- UserRelation（tair）负责按 distributorId 获取 leads 及分销商分层信息。

**账号域技术方案（`rkkeotq`）** 还规划：CRM 针对不同分销商类型配置可选解决方案，开放平台增加 leads 查询/设置 API 供服务商查改其下游 leads 的解决方案设置。
