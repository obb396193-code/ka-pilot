# 佣金结算与资损防控

## 概述

本页面沉淀「巴拿马跨境分销（淘系海外 OVS 供给侧）」的**资金域**知识：从平台向淘宝商家收取佣金（收佣/收入链路），到平台向分销商/服务商返佣（返佣/支出链路），再到提现、支付、对账、结算 SOP 与资损防控的端到端体系。

核心资金模型（贯穿全域的第一性原理，来自《分销激励返佣一期概要设计》）：

- **收佣是平台向淘宝商家收钱，返佣是平台给分销商发钱**；平台能给分销商返多少，取决于能从商家收到多少。
- 当前业务采用**「收支完全分离」**模式：返佣率是基于商品「应收佣金」的**估算**，系统无法 100% 保证「返佣金额 ≤ 收佣金额」（实收可能收不到、实收与应返规则不完全一致）。
- 返佣表达与交易返佣**无因果关系**：有表达不一定生效，无表达也可能返佣。
- 平台收佣率 = 商品佣金率 × 90%（预留 10% 排除交易资损）；客户返佣率 = 平台收佣率 × 客户层级返佣比例。

因此资金域是**典型的资损防控重点场景**，围绕「收/返/提/支」四条链路建立在线扣退佣、离线补偿、离线对账、账期重跑、调账 SOP 的多层保障。

## 一、资金四链路总览

资金域由四条链路构成（源自《资金链路》《佣金链路》《提现链路》《支付链路》，其中总览页仅有骨架，细节散落在各专项文档）：

| 链路 | 方向 | 说明 | 关键系统 |
| --- | --- | --- | --- |
| **佣金链路（收佣）** | 收入 | 向淘宝商家收取佣金，确认收货时从货款中扣佣，退款时按比例退佣 | ovs-base / ovs-base-charging（结算）、汇金 |
| **返佣链路（返佣记账）** | 支出准备 | 计算分销商/服务商返佣率，记录到订单快照，离线清算生成账单 | ovs-pnm-incentive |
| **提现链路（返佣支出）** | 支出 | 返佣账单 → 提现单 → 发票/扣税 → 智付打款 | ovs-pnm-incentive、智付、BPMS |
| **支付链路** | 交易资金 | 交易单支付/二次支付/支付失败回传、提现打款、理赔 | 智付、简柒（前端） |

> ⚠️ **内容分歧/说明**：`资金链路`、`佣金链路`、`提现链路`、`支付链路` 四个总览页在 KBase 中大多仅有标题或极简骨架（如提现链路仅列「返佣记账 / 返佣提现」，支付链路仅列「支付/提现/理赔」三点）。具体的技术细节均落在下文各专项文档，本页以专项文档为准综合。

### 1.1 收佣规则（佣金类型体系）

收佣以**子单**为结算维度，`最终佣金 = max(商品佣金金额, 类目最低佣金金额)`。基础规则（`跨境供货平台商家海外特邀发展计划服务规则`）：

- `佣金金额 = 订单金额 − 成本价`
- `预估佣金 = 券后价或原价 − 成本价`，或 `= 券后价或原价 × 兜底佣金费率`
- `应收佣金 = 商品实际确认收货价格（不含运费）× 兜底佣金费率`
- **结算节点**：订单确认收货时从货款扣佣；退款/部分退款时在退款成功时按退款比例退佣。

平台在同一订单上通过多种佣金类型区分（通过淘宝卖家 DomainTag / 商品 ItemTag 判断，映射到不同的汇金 bizType）：

| 佣金类型 | 系统判断标准 | 汇金 bizType |
| --- | --- | --- |
| 巴拿马基础佣金 | DomainTag `panama＿business＿growth＿buyer`；成本价取 SKU/商品 Feature 上的 `brokerCostPrice` | `PANAMA_BUSINESS_GROWTH_BUYER_STD_PROCESS` |
| 3 佣金（跨境全托管 3+X） | DomainTag `ovs_cross_border_trusteeship` | `TMALL_OVS_POST_V3_REDUCTION_STD_PROCESS` / `..._REFUND_STD_PROCESS` |
| X 佣金 | DomainTag `ovs_panama_growth_buyer` | — |
| 全球推广-全球包邮（大服饰/中小件） | 商品标 `containsAll([3225218, 637185])` | `TMALL_OVS_POST_DFS_SHARE_REDUCTION_STD_PROCESS` / `..._REFUND` |
| 全球推广-大件出海 | — | `TMALL_OVS_DFS_ZDJ_SHARE_STD_PROCESS` |
| **定向高佣（TIC）** | 商品标 `containsAll(712001, 3409218)`；水平标 `_F_pnm_comm = "TIC"` | `OVS_PANAMA_SPECIAL_DEVELOPMENT_PROGRAM_STD_PROCESS` / `..._REFUND_STD_PROCESS` |
| 淘客佣金 | 依赖联盟报名数据 | — |

成本价存储：端内订单取订单垂直属性 `ovsTicCostAmt`；端外分销订单取 `gspExt.commission.factors.COST_AMT`（`"COST_AMT"`）。

## 二、佣金中心与结算（佣金规则封闭）

**佣金中心（ovs-commission-center）** 是佣金费率查询与佣金计算规则的收敛点，设计原则「**佣金规则封闭**」——计算规则与设置规则收拢到佣金中心，外部系统不感知具体实现；同时提供**本地化运行能力**以减少批量场景下的远程并发量（详见《定向高佣佣金率变更-佣金中心技术方案》）。

对外提供两类接口：

1. **折扣率和最低佣金率查询接口** `CmcItemCommissionRateQueryService#queryItemCommissionRate`（支持批量）
   - 返回折扣率、最低佣金率**底层数据**（不含计算规则），主要供营销价格域设价/计算，以提升设价性能。
   - 业务类型枚举：`CmcBusiCodeEnum#CBS_DST_TARGETED_INDUSTRY_COMMISSION`（定向高佣）。
   - 入参 `CmcItemCommissionRateQueryParam`：sellerId/cateId/itemId/skuId（可选）+ `itemSellerType`（天猫/淘宝）+ `busiSourceType`（端内/端外分销），批量结果按 `getUniqueKey()` 拼接返回。
2. **佣金计算接口** `CmcItemCommissionCalculationService`（`CmcCommissionCalculationService#calculateCommission`）
   - 用于设价预估、预估佣金、结算佣金计算等；**若佣金率与成本金额都传入则走本地计算**。

二方库坐标：`com.alibaba.ovs.commissioncenter:ovs-commission-center-client(-starter):1.1.2`；富客户端按 byName 注入 `cmcCommissionCalculationServiceLocalManager` / `cmcCommissionRateBatchQueryServiceLocalManager`。

**费率规则存储**：
- 白名单商家佣金率：基于 diamond 直配，`DATA-ID/GROUP-ID = TIC_SELLER_COMMISSION_CONFIG / OVS-COMMISSION-CENTER-TIC`。
- 类目兜底佣金率：底层基于海外类目标签能力，通过 switch 切换标签 ID（`TIC_COMMISSION_RATE_CAT_TAG_ID`、`TIC_COST_PRICE_DISCOUNT_RATE_CAT_TAG_ID`）。

**结算侧变更（《定向高佣佣金率变更-佣金结算技术方案》）**：设计原则「**结算规则收敛**」——结算费率规则收拢到结算节点处理，规则变更不牵涉交易创单环节。端内端外结算共用一套链路，本次改造仅将「最低佣金率读取」改为动态服务获取（`OvsTicCommissionDeductManager` 收佣逻辑修改点）。基础计算公式：

```
收佣金额 = 子订单确认收货金额 − 子订单商品成本价
最低收佣金额 = 子单确认收货金额 × 最低佣金费率（按商家白名单和类目配置）
最终收佣金额 = max(收佣金额, 最低收佣金额)
（确认收货金额 = 不含运费的实付金额，需扣除退款金额按实际确收比例）
```

系统协作：`ovs-sellercenter`（签约打标）→ `uic`（卖家服务标）→ `ovs-pnm-marketing`（成本价 Feature）→ `itemcenter`；`buy2/oversea-ip-product` 创单打标（依赖 IC 结算因子）；`ovs-base` 订阅确认收货/售后成功消息、查 `ovs-affiliate`（归因）、查 `ovs-commission-center`（最低佣金率）、发起 `settle-center`（扣/退佣）。

## 三、TIC 定向高佣（收佣/退佣核心链路）

定向高佣（TIC，Targeted Industry Commission）是巴拿马最重要的商业化佣金，涉及商家商品报名、交易、佣金规则中心、结算多域，是资损防控必须覆盖的场景。链路包括**正向扣佣**（确认收货后收佣）、**逆向退佣**（售后退款后退佣）、**DTS 补偿**与**汇金回调**。

### 3.1 老系统实现（ovs-base，《TIC 结算流程分析与代码迁移方案》）

分层：消息入口层 → 服务层（`OvsTicCommissionHandleService` → `AbstractOvsOrderCommissionManager`(模板方法) → `OvsTicOrderCommissionDeductManager` → `OrderCommissionService` → `CommissionRepoV2`(汇金交互)）→ DTS 补偿层 → 汇金回调层（`HJCommissionConsumer`）。

**正向扣佣触发**：消息 `TRADE_ORDER_PART_CONFIRM`（部分确认收货）。条件：已确认收货 + TIC 订单标（`_F_pnm_comm="TIC"`）+ 不在实时黑名单 + 与 DFS/QTG/大件互斥。

**端内 vs 分销订单差异**：

| 维度 | 端内订单 | 分销订单 |
| --- | --- | --- |
| 判断依据 | `outBizCode != "lazada_buyer"` | `outBizCode == "lazada_buyer"` |
| 商家白名单 | 必须在收佣白名单 | 不需要 |
| 导购归因（CPS） | 必须有导购归因记录 | 不需要 |
| 成本金额来源 | `ovsTicCostAmt` 属性 | `gspExt.commission.factors.COST_AMT` |
| 垂直标类型 | `OVERSEA_ORDER`(2) | `PNM_DETAIL_ORDER`(1) |
| 不满足条件 | 作废交易分账规则 | — |

**佣金金额计算**：`confirmedAmount = actualFeeAmount − refundedAmount`，调用佣金中心 `calculateCommissionAmount()`（业务码 `CBS_DST_TARGETED_INDUSTRY_COMMISSION`），单位分→元 `movePointLeft(2)` + `HALF_UP`。

**逆向退佣触发**：消息 `TRADE_ORDER_REFUND_SUCCESS`（售后退 `DISPUTE_AFTER_SELL_REFUND`）。端内订单必须有导购归因命中标（`ovsTicCpsFlag=1`，只有正向收过佣才退），分销订单直接退。

**状态机（正向）**：`WAIT_TO_DEDUCT(10)` → `DEDUCT_SUBMIT_SUCCESS(30)` →(汇金回调)→ `DEDUCT_SUCCESS(100)`；提交失败 `DEDUCT_SUBMIT_FAIL(20)`，回调失败 `DEDUCT_FAIL(40)` → `INVALID_BILL_SUCCESS(70)` → `TRANSFER_BOND_SUCCESS(90)`。逆向用 `commissionRefundStatus` 独立管理。

**订单垂直标（biz_attribute 存储）**：`commissionSettleKey`(扣佣状态)、`commissionDeductAmount`(分)、`receivableCommissionAmount`(元)、`ovsTicSeller`(白名单 1/0)、`ovsTicCpsFlag`(CPS 归因 1/0)、`commissionSellerId`、`commissionCategoryId` 等。

**DTS 补偿**：
- 定时退佣 `OvsTicOrderCommissionRefundProcessor`（SchedulerX，从 ODPS 读昨日退佣数据，分页 100）。
- 手动扣/退佣 `OvsTicOrderCommissionDeductManualProcessor` / `...RefundManualProcessor`（参数 `orderId|sellerId,...`）。
- 佣金补偿 `CommissionCompensateService`：比对汇金状态，按状态重提交/作废账单/转保证金。

**ODPS 数据表**（《定向行业佣金结算开发文档》）：
- 扣佣：`tmall_ovs.ovs_pnm_tic_commission_deduct_fail_order`（未扣佣底表）、`ovs_pnm_tic_commission_deduct_compensate_order`（补偿）。
- 退佣：`ovs_pnm_tic_commission_refund_fail_order`、`ovs_pnm_tic_commission_refund_compensate_order`。
- 逆向因分销消息无属性标无法过滤，自 3.x 起仅有 T+1 离线链路。

### 3.2 新系统迁移（ovs-base-charging）

TIC 结算逻辑从老系统（`_pending_migration`）迁移到新系统 **ovs-base-charging**，采用「消息驱动 + Handler 模板方法」重构（《扣佣结算链路迁移技术设计》《TIC 迁移变更与灰度方案》）。

**分层**：消息入口(`AbstractMessageListener`) → 结算处理器(`AbstractSettlementHandler`, 模板方法 `deductHandle`：preFilter→initContextInfo→calculateCommission→updateCommissionInfo→submitToHj→updateCommissionInfo) → 业务服务(`TicCommissionService`) → 适配器(`HuijinAdapter`/`CommissionCenterAdapter`/`TicCommissionAdapter`/`AdCpxEffectAdapter`)。

- **正向入口** `TicSettlementPartConfirmMsgListener`：Topic `OVS_ORDER`，ConsumerGroup `CID_OVS_TRADE_PART_CONFIRM_CONSUMER_NEW`。
- **逆向入口** `TicRefundMsgListener`：Topic `OVS_REFUND_DISPUTE`，Tag `REFUND_SUCCESS`，ConsumerGroup `CID_OVS_CHARGING_ORDER_REFUND_CONSUMER`。
- **正逆向复用**：都走 `deductHandle` 模板方法，通过 `SettleBizTypeEnum.OVS_TIC` 路由；差异在汇金提交（正向 `submitTradeShareDeductCommission` 交易分账 vs 退佣 `submitDeductCommission` 普通扣佣 + aliPayId）与退佣金额计算（退佣直接取 `disputeOrder.getApplyPrice()`，不调佣金中心）。
- 汇金模板码：正向 `TIC_DEDUCT = OVS_PANAMA_SPECIAL_DEVELOPMENT_PROGRAM_STD_PROCESS`；退佣 `TIC_REFUND = ..._REFUND_STD_PROCESS`。BizTypeId `2930`（跨境定向行业佣金结算）。
- 退佣状态扩展：`WAIT_TO_REFUND(110)`/`REFUND_SUBMIT_FAIL(120)`/`REFUND_SUBMIT_SUCCESS(130)`/`REFUND_FAIL(140)`/`REFUND_SUCCESS(200)`。不退佣时打阻断标 `TIC_REFUND_BLOCK_TYPE` 防 T+1 重复处理。

**关键开关**：`needTicSettle`(总开关,默认 true)、`ticSubmitHJDowngrade`(降级,true 时跳过汇金提交仅走流程)、`ticSellerWhiteListQueryEnabled`(白名单查询,false 降级全通过)、`ticBlockShotAmount`(计佣封顶 200000 分)、`ticDeductScheduleTaskClose`/`ticRefundScheduleTaskClose`(补偿任务开关)、`ticOrderRealTimeProcessBlackList`(订单黑名单)。

**离线补偿**：`TicSettlementCompensateProcessor`(正向)、`TicRefundCompensateProcessor`(逆向)，ODPS 源 `ovs_pnm_tic_commission_{deduct,refund}_compensate_order`，分页 100，默认前一天分区。

**灰度方案**（`MigrateScheduleConfig#isHitMigrateGraySchedule`，Diamond `DEFAULT_GROUP/ovs_settlement_migrate_schedule`）：
- 粒度 `buyerId % 10000`，`gray` 为万分比（500=5%）；多配置按 `effectTime` 降序，支持按订单创建时间分段灰度。
- 阶段一「影子验证」：`ticSubmitHJDowngrade=true`（不实际扣佣），老系统真实扣佣，逐步开到 100% 影子跑；MCP 对账比对新旧垂直标差异（`ovsTicSeller`/`ovsTicCpsFlag`/`ovsTicCostAmt`），通过标准差异率 <0.1%。
- 阶段二「真实扣佣灰度」：`ticSubmitHJDowngrade=false`，5%→10%→30%→80%→100%；**每次先缩小老系统处理范围再扩大新系统比例，保证同一订单只被一个系统真实提交，避免双扣/漏扣**。
- 回滚：将灰度值置 0 或 `needTicSettle=false`，老系统兜底；已提交订单用手工补偿任务修正。

## 四、返佣与激励体系（分销激励域）

### 4.1 业务价值与阶段成果（《激励体系系统方案设计梳理》）

以平台佣金收入为资金池，按订单对分销商激励。分销商按 GMV 层级分层（T0–T4），阶梯返佣。截至运营验证：2024.10 返佣表达+API 上线后，10–12 月合计 GMV 超 2600 万（超预期），约 60 家分销商开白，粗估实际返佣约 150W；引入妙手、聚水潭等服务商间接引入 1000+ 家分销商。分销价格优惠模式（渠道价/供货价）于 2025.1.15 下线，全面转「后返模式」。

### 4.2 返佣率计算（《返佣计算技术方案》《返佣一期概要设计》）

术语与公式：
- **商品佣金率** = 佣金 / 预估成交价 × 100%（分销佣金 or 淘客佣金）。
- **平台收佣率** = 商品佣金率 × 90%（90% 排除交易资损）。
- **客户返佣率** = 平台收佣率 × 客户层级返佣比例。

客户等级返佣比例（一期固定配置，业务每月 2 号更新层级；CRM 一期未参与，策略暂放激励域）：T1 30% / T2 35% / T3 40% / T4(分销商) 40% / T4(服务商) 70%。

领域划分：
- **海外供给域**：`招商运营-佣金信息查询`，查询商品命中的全量招商活动收佣规则（3+X、全球包邮、定向高佣、全托管）。
- **分销域（激励返佣子域）**：返佣率计算、返佣率记录、分佣查询 API。

接口 `IncentiveQueryService#rebateRateCalculate`（`ovs-pnm-incentive-client`）：入参 `RebateRequest`(distributorId + estimatePrice + rebateItem)，出参 `IncentiveDTO`(rebateRate + `CalculationProcessInfo` 计算过程)。外部依赖：淘客佣金查询（按最大佣金率收取）、海外招商佣金查询、用户管控 `MatrixCheckerFacade#check`（`ovs-pnm-matrix-client`，主能力=分销返佣）。

**计算过程结构化存档**：在线用 Lindorm 表 `incentive_rebate_calc_record`（返佣成功发异步消息自发自收，TOPIC `PANAMA_INCENTIVE_REBATE_CALC_TOPIC`）；离线表 `tmall_ovs_se.s_pnm_incentive_rebate_calc_record`。

### 4.3 返佣率记录（订单打标，《返佣率记录技术方案》）

最终方案：**异步打标**（不改 buy2，上线不依赖 buy2）。监听创单成功消息（`GSP_TAOBAO_ORDER` tag `200-trade-created-done`）/支付成功（tag `200-trade-paid-done`），在淘宝子订单上打**创单时刻的返佣率快照**。打标经 `batchUpdateBizOrderAttribute`，`@Retryable(maxAttempts=3)`。

### 4.4 返佣客户侧表达（《返佣率客户侧表达技术方案》）

返佣率在工作台多场景展示：购物车列表、下单渲染页、再来一单、订单列表（子单维度 `_F_rebate` 标）、采购插件商品详情、商品寻源（`itemRebateRatio`）。订单标配置 diamond：`query.order.tag.configured`(gsp-order)、`purchase-order-tag`(ovs-pnm-distributor)。相关二方库 `ovs-pnm-purchase-client`。

### 4.5 返佣清算与对账（服务商体系，《返佣解决方案-计算和对账》）

基于 CRM 服务商体系对服务商分层、返佣率计算，对分销商/服务商订单计算预估返佣金额，输出对账单。核心 ODPS 表（离线离转 Hologres 供在线分页/筛选）：
- `ovs_pnm_order_rebate_detail`（子单返佣明细，含 `rebate_rate`/`super_rebate_rate`/`own_leads_id`）。
- `ovs_pnm_distributor_day_commission`（分销商账号维度日结）、`ovs_pnm_main_distributor_day_commission`（主账号维度）、`ovs_pnm_distributor_commission_stat`（分销商总表）。
- `ovs_pnm_provider_day_commission`（服务商日结，含自采/下游分账）、`ovs_pnm_provider_commission_stat`（服务商总表）。
- 数据流：明细表 →group by 日 日结表 → 累加 总表；服务商层 group by `own_leads_id`。
- 看板接口 `RebateDashboardService#getCommissionOrderStats` / `queryCommissionOrderDetails`（`ovs-pnm-incentive`）。

### 4.6 费率查询接口切换与规则引擎演进

- **费率查询统一收拢佣金中心**（《返佣中心佣金费率查询接口切换》）：新方法替换 `CommissionService#queryCommissionRate`，配灰度对账方案。
- **规则引擎化**（《垂直行业返佣-激励域技术方案》《分销激励规则运营能力提升》）：构建激励返佣规则引擎，抽象返佣因子并支持动态配置，目标将新增规则迭代工时从平均 **7 人日降到 1 人日**（后台配置即可）。数据表：`calculation_rule_factor`(因子)、`calculation_rule`(规则,含 `rule_expression`/`priority`)、`calculation_rule_instance`(实例)、`calculation_rule_operate_log`(操作日志)。规则引擎横向支持收佣结算、返佣预估、发佣计算多场景。
- **分销商解决方案一期**（《分销商解决方案一期》）：按客户类型（type a/b/c）细化解决方案，收佣/返佣范围配置化（如「除退货宝佣金」「仅淘客」），涉及 `gsp-order-panama` 扩展包、`global-seller-common-s`、`ovs-pnm-account`、`ovs-pnm-incentive` 规则引擎。

## 五、提现链路（返佣支出，ovs-pnm-incentive）

（《提现单生命周期流转分析》，基于源码分析）

### 5.1 核心模型

- **结算账单 SettlementLedger**（`SettlementLedgerStatusEnum`）：-1 已关闭 / 0 待处理 / 1 可提现 / 2 提现中 / 3 已提现 / 4 审批通过 / 5 审批中。
- **提现单 WithdrawRecords**（`ON_` + 12位 MD5 大写，`BillNoUtil.generateWithdrawNo`）：1 待确认提现信息 / 2 待上传发票 / 3 发票核验中 / 4 发票核验成功 / 6 待打款 / 7 打款成功 / 8 打款失败 / 9 已关闭。
- **账单-提现单映射 BillWithdrawMapping**；**预费用单 CaijingFeeBillRecord**（财经侧，`PreFeeBillStatusEnum`）。

### 5.2 主流程

账单生成：佣金计算完成 → `SettlementCheckFinishHandler` 生成账单 → 发起 BPMS 审批(状态 5) → `BpmsFinishEventHandler` 通过(4) → `PreFeeBillCreateResultHandler` 创建预费用单 → 可提现(1)。
用户提现：`confirmWithdrawInfo` 生成 `ON_` 单号 → 取消旧预费用单 → 判断主体 → 保存提现单(1)，账单→提现中(2)。
发票/扣税 → 待打款(6)：智付 `SmartPayPaymentExtensionApiImpl` 查收款信息 → `PaymentResultConsumer`/`PaymentResultHandler` 处理打款结果回调。

### 5.3 三种提现主体差异（资损/合规关键）

| 维度 | 国内个人 | 国内企业 | 海外 |
| --- | --- | --- | --- |
| 发票处理 | 无需发票，走扣税确认 `confirmTaxInfo` | 上传→异步解析→登记→校验→匹配(4步) | 上传→邮件人工审核→验证(2步) |
| 费用单/结算单创建时机 | 扣税确认后 | 确认提现时立即 | 确认提现时立即 |
| 打款失败终态 | 已关闭(9)+关费用/结算单+重建预费用单+账单回退可提现 | 已关闭(9)+账单回退可提现 | **打款失败(8)+发邮件，账单不回退（仍提现中2），需人工介入** |
| 打款成功后续 | 提交报税 `taxCalculateAndSubmit`+校验重复支付；同一身份证每月仅一次 | — | — |

**统一失败回退机制**（发票失败/打款失败/用户取消）：关闭费用单+结算单 `cancelFeeAndSettlementOrder` → 重建预费用单 `createNewPreFeeOrder` → 提现单→已关闭(9) → 账单回退→可提现(1)，允许重新发起。海外打款失败为例外（状态 8，需人工）。

## 六、对账单与账单迁移（FBI）

### 6.1 客户对账单升级演进

- **对账单升级**（《对账单升级技术方案》，2023）：客户仅能页面下载、多采购账号需人工汇总、ipay 仅 SFTP 交付。方案：ODPS 数据集成同步蚂蚁 SFTP 账单到 `distributor_ant_bills_data` → 关联采购单/淘宝数据生成临时结果 → 同步 **Open Search**。选型对比 MySQL(慢 SQL)/ADB(~2.3W/年)/Hologres(~3W/年)/Open Search(~0.89W/年)，最终选 **Open Search**（SCROLL 导出）。历史+一年预估约 2690W 数据。接口 `mtop.alibaba.ovs.panama.distributor.statement.query` → `OvsPanamaDistributorStatementService#list`。
- **对账单导出升级**（《对账单导出升级技术方案》，2023）：实时导出慢，改为**预生成**。方案：ODPS(`tmall_ovs.ovs_panama_distributor_statement_v2`) 经 SQLTask 建临时表 + Tunnel 下载生成 EXCEL → 上传 OSS → distributor 提供下载 mtop 接口，按月粒度下载。

### 6.2 正向账单迁移至 FBI（《正向账单数据迁移至FBI技术方案》）

目标：正向账单数据迁移到 **FBI 开放能力**，减少数据处理流程与错误，**下掉 OSS excel 账单存储和 Open Search 存储**（透出数据与之前保持一致）。
- 场景码 `order_bills`（reportId=1381417）。
- Diamond 配置 `fbi-data-config-query-data-id / fbi-data-config-query-group-id`（namespace `ovs-pnm-data`）。
- 接口 `DataSearchFacade#getData`（内部）、`DistributorBillsFacade#queryPurchaseBill`（开放 `com.alibaba.pnm.open`）。字段含 `purchase_pay_amount`/`purchase_refund_amount`/`pay_channel`(如 `THIRD_PARTY_ALIPAY_AGREEMENT`) 等。

> 演进脉络：**页面下载 → Open Search 升级 → OSS 预生成导出 → FBI 开放能力（下掉 OSS/Open Search）**。这是同一对账单能力的三次迭代，后者逐步替代前者。

### 7.1 结算调账 SOP（《结算调账SOP》）

> ⚠️ **红线**：客户数据必须**线上**操作，严禁预发操作客户数据。

- 创建调账记录：`SettlementBillService#createSettlementBill`（单个）/ `batchCreateSettlementBill`（批量）。**注意 `deductAmount` 抵扣字段为正数**（单个接口注释有误）。billItem 含 `addAmount`/`deductAmount`/`leadsId`，ds 账期如 `202506`。

### 7.2 分销结算账期重跑 SOP（《分销结算账期重跑SOP》）

DataWorks project 31022。**严格按顺序执行**：
- **批次 0**：`301035375` 巴拿马佣金客户详情表（必须先生成本月客户配置表，账期次月 18 号）。
- **批次 1**（次月 19 号）：海外佣金结算表 `300564672`、淘客佣金结算表 `301813457`、海外/淘客/全佣金返佣结算明细、分销商签约有效 GMV `304433689`、服务商 GMV `303520091` 等。
- **批次 2**：分销商/服务商返佣订单结算明细与账单、财务维度汇总 `302796476` 等。
- **批次 3**：结算返佣客户配置/订单明细/账单同步 Holo。
- **最终账单同步**（业务财务核对通过后才可执行，写 DB + 发起资金审批流）：`303727347` 结算佣金总额对账（**执行完必须检查对账通过，否则发送无效**）→ `303721701` 对账完成发送消息（触发审批流）。
- 核对：DB `ovs_pnm_settlement_ledger`(period) 总量 = 离线 `ovs_pnm_distributor_rebate_settle` + `ovs_pnm_provider_settle_bill`。
- 审批后校验：状态应全为 1/2/3；若存在 **4（审批通过但未生效）** 说明智付预费用单创建失败或被限流（SLS 关键词 `createFeeOrder error`），需线上 HSF 重跑 `SettlementWashService#processSettlementApproved`。

### 7.3 智付-财务侧数据一致性 SOP（《智付-财务侧数据一致性保障SOP》）

清理测试账号单据与未正常关闭的客户单据，保障智付侧与财务侧一致。能力：
- 关智付单：`SettlementWashService#cancelFeeOrder`（费用单）、`cancelSettlementOrder`（结算单）。
- 补预费用单：`SettlementWashService#insertPreWithdraw`。
- 场景：测试账号提现单/预费用单全关；客户已关闭提现单(status=9)对应智付单全关；账单审核通过/可提现但预费用单不存在时补预费用单；所有关闭预费用单(status=0)同步关智付侧。
- 关键表：`ovs_pnm_withdraw_records`(提现单 `ON_`)、`ovs_pnm_caijing_fee_bill_record`(预费用单 `PRE_`)、`ovs_pnm_settlement_ledger`(账单)。

## 八、资损防控

### 8.1 定向行业佣金对账（《巴拿马定向行业佣金-对账技术方案》）

三个关键节点及资损防控定位：
1. **成本价获取并落订单快照**——强依赖操作，取不到成本价直接报错阻断，杜绝资损。
2. **计算佣金金额**——费率配置、计算规则综合体现，正确性受应用变更影响，**资损防控重点覆盖场景**。
3. **资金结算**——调汇金实现，分账/结算由汇金体系保障，汇金结算结果作为数据核查对象。

**离线核对方案**：用基础数据在离线链路重新推导应收佣金金额，与已产出的佣金结算账单核对，发现在线系统潜在问题/逻辑错误。
- 基础表：`dim_ovs_planning_cate_operation_df`(定向行业佣金率)、`ods_ovs_tag_meta_df`(类目兜底,id=55 default_val)、`dim_ovs_cate_group`(类目层级)、`dwd_ovs_trd_ord_df`(端内订单)、`r_tbcdm_dwd_tb_trd_panama_ord_flow_di`(端外)、`dwd_ovs_vertical_key_df`(端外垂直属性)、`ovs_panama_huijin_hj_bill`(汇金账单)。
- 对账表：`ovs_tic_order_df`(TIC 订单端内外,近200天)、`ovs_tic_order_settle_df`(结算数据,近31天)、`ovs_tic_order_settle_amount_df`(带应收金额计算,关联类目)。
- **类目费率向上回溯**：叶子类目无费率时逐级向上取（cat5→cat1），最终兜底 default。
- **关键规则**：佣金按实际确收（订单金额−退款金额）比例收取；佣金重算与在线链路允许 **±0.01 分**误差。
- 对账脚本：`WHERE comm_amt_aucual <> comm_amt_expected AND ABS(diff) > 0.01`。
- **M.A.C. 任务**：`mac.alibaba-inc.com/dashboard/caseanalysis/136118`。

### 8.2 资损风险场景清单（《巴拿马资损风险场景》）

| 业务场景 | 描述 | 已监控 | 相关监控 |
| --- | --- | --- | --- |
| X 佣金分账 | 分销佣金签约打标规则影响多收/漏收 | 是 | 汇金平台错误检查(`OVS_PANAMA_CHANNEL_PROMOTION_COMM_STD_PROCESS`) + MAC 对账(case 87587) |
| 渠道一口价（划线） | 一口价设置正确性影响结算价 | 否 | 需强一致性对账，用户暂无强感知 |
| 淘客联盟佣金 | 联盟系统问题致佣金收不到 | 否 | 技术主体在海外联盟，暂未定为资损 |
| 售后卡单赔付 | 淘宝系统/商家保证金问题致无法逆向，平台赔付（月均几千元） | 否 | 产品优化点 |

### 8.3 多层防控体系（综合）

- **在线强依赖阻断**：成本价快照取不到直接报错，杜绝无成本价扣佣。
- **在线补偿**：DTS 定时/手动补偿任务兜底漏扣/漏退。
- **离线核对**：ODPS 重算应收 vs 汇金账单，±0.01 分精度，MAC 平台监控。
- **灰度平滑**：新老系统迁移用降级开关 + buyerId%10000 灰度，保证同单不双扣。
- **账期对账门禁**：账期重跑「结算佣金总额对账」不通过则消息无效、不触发审批流。
- **数据一致性 SOP**：智付侧与财务侧单据（提现单/预费用单/结算单）人工比对与清理。
