# 技术架构与研发规范

## 概述

本页沉淀巴拿马跨境分销（淘系海外 OVS 供给侧）的**整体技术架构、历年架构演进、研发通用规范、公共库/工具能力与 AI 研发规范**，是研发同学日常开发、CR、联调、治理的规范性索引。

分销侧核心应用以 `ovs-pnm-*` 为前缀（分销域自建），依赖大量 `gsp-*`（全球供给平台）与国内交易中台（buy2、tradeplatform）等外部系统。公共能力统一沉淀在 `ovs-pnm-common` 库与一系列 spring-boot starter（`ovs-pnm-*-starter`）中，通过 `ovs-pnm-dependencies-bom` 统一管理版本。

业务/产品视角见 [[巴拿马跨境分销业务与产品总览.md]]，各子域详情见 [[采购交易与履约链路.md]]、[[佣金结算与资损防控.md]]、[[商品域·铺货·选品与搜索.md]]、[[账号体系与开放平台.md]]。稳定性/治理相关见 [[限流与服务治理.md]]、[[安全生产与稳定性保障.md]]。

## 整体技术架构与应用列表

### 领域分层
技术架构按**领域分层**组织（对应 `ovs-pnm-common` 的领域划分）：

- **基础域（0 层）**：账号域。
- **独立业务域（1 层）**：商品域、商家域（供应商）、客户域（分销商）。
- **互联域（2 层）**：
  - 交易域/采购域：商品从「商家 → 客户」的流转；
  - IM 域：商家↔客户、运营↔客户 的消息互联。

### FY2024 核心模型
FY2024 系统设计规划中定义的核心模型：**分销商、IM消息、分销商品、品商关系、采购单**。

## 架构规划与演进历程

### FY2024 系统设计规划
- 确立核心模型（分销商、IM消息、分销商品、品商关系、采购单）；
- 首版应用分层架构 + 全链路系统架构（图）。

### FY2025 架构演进目标
- 明确 FY25 的应用分层架构与全链路系统架构目标（图，沿用 FY24 全链路底图迭代）。

### FY2025 分销架构总结（实际落地）
业务领域重点建设：
- **用户域**：分销商-服务商关系模型建设；CRM/客户等级分层与权益模型建设。
- **商品&导购**：商品价格模型升级（丰富价格、优惠表达）；统一业务商品池建设（不同客户/场景的特定商品池诉求）。
- **选品域**：批量选品；工作台搜索寻源（搜索+采购）；商品主题榜单（结合商品企划）。
- **采购收单**：分销结算佣金体系建设，新增**定向行业佣金模式**（联动供给价格域 + 商家佣金中心）；返佣激励子领域建设；线下店导购收佣模式。
- **供给商品中心**：海外标签中心（统一类目/商品基础标签、属性）；海外类目运营平台（支撑佣金费率、海外包邮）。

系统架构变化：
- 用户域：新增客户归属关系库表、用户等级/权益库表；
- 采购域：对接订单结算与佣金率管理，**复用 `ovs-base` 结算基础能力**；新增 `ovs-pnm-incentive`，对接 `ovs-commission`；
- 选品投放域：复用词搜/图搜能力建设搜索寻源；新建主题榜单数据表，复用类目运营平台打标能力；
- 商品域：统一商品价格模型；商品池模型、商品断供能力。

### FY2026 分销架构规划
业务重点：
- **用户域**：打通流量管控模型与权益模型，用**分销商标签模型**统一数据表达；
- **选品域&导购**：支持单个/多个商品**实时铺货**并展示**券后价**；落地全链路营销信息表达；选品指标增加**俄/韩/日**语种支持；
- **采购收单**：线下店/导购模式佣金结算切到**海外佣金协议**，剥离端内端外交叉链路；
- **返佣激励**：建立返佣计算规则模型（订单维度佣金预估/计算/账单报表）；**返佣因子和规则配置化**，同一底层模型支撑预估与结算。

关联海外商家商品域变化：
- 供给价格域支持 **UMP 接入**（统一商品价格模型对接淘系优惠表达）；
- 供给佣金域增加**出海增长-大件交易佣金**收取；
- 线下店链路通过佣金模式切换，**统一切到端内闭环**。

## 研发通用规范（巴拿马技术通用规范）

### 超时（timeout）设置
- 简单服务：1000ms（无批量、无非常规下游 RT）；
- 常规服务：3000ms（常规复杂逻辑 + 一般链路依赖）；
- 略超长：5000ms（大量数据或下游超长 RT）——**需单独 Review**；
- **> 10000ms 必须单独核对决策**。
- 正确超时 = 预估本服务 99 分位 RT × 1.3（先看核心下游 99 分位 RT，再叠加本服务中间件调用次数×RT）；不好评估的设为配置项，上线后按 1.3~1.5 倍调整。

### 多线程处理
- 并发线程数设计**必须是技术方案与人工 CR 的一部分**；
- 线程任务统一用 `guide-calf` 的 async 包提交（micro/pkg/1004861）；
- 线程池队列大小**必须设置**（反例：`new LinkedBlockingQueue<>()` 无界队列）。

### Exception 与关键日志
- 来自外部调用/中间件的原始 Exception **不要吃掉且不打日志**。

### 外部依赖 package 隔离
- package 必须独立，module 按业务复杂度自定：`infra -> adapter`（已有）、`infra -> external`、`biz -> external`。

### HSF 服务限流
- 被 ODPS/MQ 调度或具备重试的服务反向 call 的 HSF 服务**必须限流**（自我保护）；
- ODPS 调度 UDF（HSF）里适度加 sleep（5ms/10ms/100ms）；
- 若 ODPS 来源为非核心应用流量，限流**不超过 50**。
- 详见 [[限流与服务治理.md]]。

### 重试（有数据变更）
- 前端防重复提交（用户点击）；后端**幂等**设计（DTS 任务重试、MQ 重试）。

### 各类资源上限（任何资源都不是无限）
- 输入数组/List 必须校验最大；查询条件起始日期限制（常规最大 3 年内、默认最近 1 个月）、最大 1W（尤其 DB）；队列长度、timeout、扩展字段 varchar 最大值都需约束。

## 日志与埋点规范

### 日志接入（ovs-pnm-log-starter）
- **技术栈**：slf4j-api + logback + spring starter（`@ConfigurationProperties`）+ maven bom。
- **接入**：pom 引入 `ovs-pnm-dependencies-bom` + `ovs-pnm-log-starter`。
- **配置**（application.properties）：
  ```
  panama.logging.modules[0].moduleName=item
  panama.logging.separator=|          # 默认 <|>
  panama.logging.modules[0].subModuleNames=gsp,supply,ump,shop,uic
  panama.logging.modules[0].level=info
  panama.logging.modules[0].async=true # 不设置默认同步
  ```
- **使用**：`DefaultLogger`（如 `Logger.UMP.info/error/monitor(...)`）；`@Monitor(moduleName=..., ignoreResult=false)` 注解自动打印规范日志与监控。
- **关闭开关**：diamond 配置 `dataId=log.switch.config`，`groupId=应用名`，true 表示关闭。
- 监控日志切面：`com.alibaba.ovs.panama.common.log.aop.ApiAspect`，路径 `/home/admin/{appName}/logs/monitor/`。
- Logger 配置控制：diamond `dataId=pnm.common.logger.config`、`group=ovs-pnm-common`、`namespaceId=ovs-pnm-open`（JSON 数组，含 loggerScene/directory/fileName/level/async/maxHistoryDays/maxFileSize/totalSizeCap）。
- 公共库仓库：`git@gitlab.alibaba-inc.com:ovs-pnm/ovs-pnm-common.git`。

### 后端业务事件埋点
- **MQ Topic：`PANAMA_USER_TRACK`**，事件类 `com.alibaba.ovs.panama.common.log.event.BizTrackLogEvent`。
- 关键字段：`trackId`、`time`、`appKey`（分销商 appKey）、`leadsId`（商家/leads 标识）、`platform`、`deviceId`、`userId`、`page`、`block`、`type`、`event`、`args`、`fromSpm`、`linkedSpm`、`expose`、`success`、`errCode`、`mqId`、`otherParams`。
- 日志目录 `/home/admin/{appName}/logs/track`，以 `|` 分隔字段打印。
- **治理方向**：前后端事件统一规范（产品/业务/技术三方一致）；`其他 → data`、`account → 逐步下线`；`leads_id` 必有。版本2 兼容表 `tmall_ovs_se.user_track_source_data_record`（旧 sub_scene → 新版 block，如 `getSupplyItemDetail→已取代`、`itemSearch→已兼容`）。

### 业务事件规范一览（type/event）
- `type` 取值：`PAGE`、`OPEN`、`TAOWORLD` 等（用户回传具体类型）；`event` **前后端统一且巴拿马全局唯一可识别**。
- OPEN 类事件示例：`ITEM_EXPOSE_SPECIFY_ID`（指定商品ID撞库）、`ITEM_EXPOSE_SPECIFY_URL`、`ITEM_EXPOSE_SPECIFY_TaoPassword`、`ITEM_EXPOSE_SEARCH_Kewword`（词搜）、`ITEM_EXPOSE_SEARCH_Img`（图搜）、`ITEM_RELATION_BUILD`（铺货）、`ITEM_ORDER_RENDER`（下单渲染）、`ITEM_ORDER_PAY`（支付）、`ITEM_EXPOSE_SPECIFY_MPID`（下单前 mpId 撞库）、`ITEM_EXPOSE_RCMD`（推荐）、`ITEM_EXPOSE_THEME`（榜单）。

### 前端埋点（SPM）
- **spmA 位为站点标识**，巴拿马当前为 `a1zlqa`；spmB 位为业务标识；统一附加参数 `spmEvent`（取「业务事件规范一览」对应值）。
- 典型 SPM 事件（`/a1zlqa.source_search.*` / `/a1zlqa.orderDetail.*` 等），覆盖：榜单/推荐/词搜/图搜/拍立淘商品卡曝光点击、加购（点击/成功）、立即购买、再次采购、订单支付（`btn_order_pay` / `order_pay_result`）、申请退款、加入待铺货 / 立即铺货 / 取消铺货、加入选品、找相似、选品集铺货等。
- 埋点要素通常含：商品ID、skuId、数量、位置、来源场景、搜索类型、是否成功、失败原因、themeId、selectionId、spmEvent。

## DB 与错误码规范

### DB 设计规范
> ⚠️ **待补**：「DB设计规范」页正文为空。通用约束参见上文「各类资源上限」（varchar 最大、查询日期范围、单次最大 1W）与幂等设计要求。

### 错误码规范
- **格式**：`PNM-{模块}-{级别}-{类别}-{编码}`，采用**字母方式**。
  - 固定位：`PNM`；
  - 模块（4-8 位）：`search` / `order` / 铺货（待定）等；
  - 严重程度（9 位，忽略数字）：1 INFO / 3 WARN / 5 ERROR / 7 FATAL；
  - 错误类别（10 位）：0 `SYS`（系统，如 DB/系统间调用/缓存异常）、1 `BIZ`（业务，如商品不存在）、2 `THIRD`（第三方）；
  - 编码（11-20 位）：限 2 个单词，格式「名词-动作」。
  - 示例：数字式 `PNM-SEARCH-5-0-PLT-TIMEOUT`；字母式 `PNM-SEARCH-SYS-PLT-TIMEOUT`（**采用**）。
- **枚举定义**：`PnmCodeConstants`（PNM/SEPARATOR/Module 枚举/ErrorLevel 枚举）+ 各模块枚举（如 `SearchCodeEnum`，`getCode(ErrorLevel)` 拼装完整码）。
- **多语言**：错误码以美杜莎 key 方式配置进 `messages.properties`，接入 `mcms-spring-boot-starter`。

- **交易/退款订正**：使用集团**数据修复平台 DRP2**；如「强制退款给买家」工具（keycode `disburse_rest_fee_to_buyer`）。

### 业务开发手册（调试/回放）
- 国内交易 Buy2（Sar 包化后）开发手册；
- **请求回放**：星环运维「线上请求线下回放（debug）」，用 `bsp` 按 traceId 捞取线上接口回放；
- 项目环境回放可能被防刷拦截，需推 diamond 配置 `dataId=safety.anti.brush.rule`（group=safety）关闭防刷（参考 `AntiBrushUtils`）；
- 常用工具：星环开发者工具、星环运维 bsp、tpConsole 订单查询、GSP 订单信息查询；
- 资源：`gsp-order`（货通交易平台）、`china-tmall-buyer-app`、`tbc-buyer-product` 等。

### 开发联调环境配置
- **DPATH 强制指定环境隔离**：云原生机器不支持交易预发天擎环境路由，调用方**强制指定被调用服务 DPATH** 可路由到隔离环境。diamond 预发 `ENV_D_PATH_ROUTER_CONFIG`（group/namespace 均为 `global-seller-common-s`）。
- **HSF 版本号隔离**（备选，较麻烦）：`global-seller-common-s` 云原生不支持 HSF 路由时，用独立 HSF 版本号隔离。Buy2 渲染服务 `com.alibaba.buy.client.service.BuyServiceClient`、创单服务 `com.alibaba.trade.client.service.TradeOrderService`，autoconfig 如 `buy2.provide.service.version=1.0.0.buy2.PANAMA`。
- 天擎「绑定路由」可路由到指定独立预发环境做联调。

### HSF 异步工具（ovs-pnm-tools-starter）
- **原理**：利用 HSF 自身异步化实现方法调用异步（对比 Bean 异步工具在业务系统开辟线程池）。实测 20 次调用：异步 ~2756ms vs 同步 ~21806ms。
- **接入**：bom + `ovs-pnm-tools-starter`；在 HSF 配置类的 `HSFSpringConsumerBean` 上加 `@HsfAsyncCall(interfaceClass=..., originInvokerBeanName="...")`。
- **使用**：
  - 方式一：`HsfAsyncCallContext.asyncInvoke("beanName","method",args)` 触发，`HsfAsyncCallContext.getHsfAsyncResponse().getResult(2000L)` 取结果；注入的同步对象仍是同步调用。
  - 方式二：`AsyncBizNodeBuilder` 构建 `AsyncNode`（`hsfBeanInvoker` / `methodName` / `paramList` / `timeOut` / `resultConvert`），`start()` 后 `getResult()`。
- 底层用 HSF `HSFFuture` 获取结果。

### Bean 组件异步执行工具（ovs-pnm-tools-starter）
- 让本地对象/HSF 对象方法执行异步化；3 个角色：服务提供者、业务逻辑者、服务提供者异步接口。
- 有返回值 `T` → 改为 `Future<T>`，无返回值 → `void`；可用公共线程池或自定义线程数。

### 重试工具 RetryUtils（ovs-pnm-tools-starter）
- 方法一：`RetryUtils.doRetry(retryTimes, param, fn, predicate)`（带参，免 final）；
- 方法二：`RetryUtils.doRetry(retryTimes, supplier, predicate)`（需 final 参数）；
- 超限抛 `ReachedRetryTimesExceptions`，`getOriginExceptions()` 获取各轮异常（每轮异常可能不同）。

### 分布式锁（ovs-pnm-tools-starter，基于 Tair）
- 配置：`panama.distributed.lock.tair-name/tair-namespace/tair-unit/enabled`；
- 用法：注入 `DistributedLock`，`lock(key, time, TimeUnit)` / `unlock(key)`；常配合 `@HSFMethodSecurity(maxQps=..., waitTimeOut=..., canUse=true)` 使用。

### Hologres 工具接入（ovs-pnm-hologres-starter，版本 ≥ 1.0.9）
- 引入 `ovs-pnm-hologres-starter` + `org.postgresql:postgresql`；
- 数据源配置 `panama.hologres.datasource.*`（host/db-name/port/username=AccessId/password=[secret_ref:removed]），支持多数据源 `datasources[i].*`；`panama.hologres.base-packages` 指定 mapper 包；
- Mapper：`@HoloMapper(dataSourceName=...)` 接口 + `@HoloSelect(mappingClass=..., sql=...)` 方法；参数 `@HoloParam("x")`；分页方法以 `ByPageResult` 结尾（默认 pageNo=1、pageSize=10）返回 `PageResult<List<T>>`；
- 结果映射 `@HoloFieldMapping("列名")`（日期默认 `yyyy-MM-dd HH:mm:ss`，浮点默认保留 4 位）。

### AuraFlow 框架
- 用于编排类场景，应用于**图搜接口** `/traffic/item/imgsearch` 等。（源文档「背景」为空，细节待补。）

### MtopResult 美杜莎-国际化方案（ovs-pnm-i18n-starter，版本 ≥ 1.0.14-SNAPSHOT）
