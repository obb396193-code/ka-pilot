ka-data 取数指南（接口用法 + 核心数据怎么取）
一份自洽文档：怎么调取数接口 + 有哪些核心数据 / 怎么取 / 易错口径。 接口读车程拥有的全部数据：Hologres / ODPS / 本地 sqlite dwd。只读 SQL 透传，持 reader token 即可。

一、接口用法
1. 先设两个环境变量（设一次，所有 curl 通用）
1export KA_DATA_BASE="https://c9fa2f-sandbox-session4112318d76d046149d-7105.agent.alibaba-inc.com"
2export KA_DATA_READER_TOKEN="<你的 reader token>"
● KA_DATA_BASE（服务地址）：沙箱会话地址，沙箱重启会变。连不上重取： curl -s "http://localhost:58596/api/port-mapping?port=7105" | jq -r .url，更新 KA_DATA_BASE。
    ● 同沙箱内进程也可直用 http://localhost:7105。
    ● 端口是 7105，不是 7005（7005 被沙箱端口映射占；7005 返 {"ok":true,"ts":...} 是映射代理，不是本服务）。
● KA_DATA_READER_TOKEN：reader 及以上 token。取法三选一：
    a. 已发你的 token（环境变量 KA_DATA_READER_TOKEN）；
    b. ka-data/token-registry.md（gitignored 台账，含已发 token）；
    c. 没有就找车程发：python3 ka-data/issue_token.py <名> reader。
    ● reader=只读；editor/admin 也能调（reader+）。
2. 调用契约
POST $KA_DATA_BASE/api/query
Authorization: Bearer $KA_DATA_READER_TOKEN
Content-Type: application/json

{
  "backend": "holo | odps | sqlite",     # 必填
  "sql":     "<单条 SELECT 或 WITH ...>", # 必填
  "project": "<odps project>",            # 可选，仅 odps；默认 dt_fbi_public_center_dev
  "limit":   10000                        # 可选，1~1000000，超 10000 自动截断
}

成功响应：
1{"backend":"sqlite","rowCount":5,"rows":[{...}],"truncated":false,"limit_clamped":false}
● truncated=true＝结果超 10000 行或 16MB 被截断 → 用 WHERE 自分批。
● limit_clamped=true＝你传的 limit > 10000，被截到 10000。
● note：附加说明（如有）。
错误码：400=SQL 被护栏拒/参数错（看 error）｜401=无 token/无效｜500=后端执行错（error+backend）。
3. 三后端 · 可直接跑的例
1# sqlite dwd 本地表（毫秒级，最稳）—— 0817 KUAISHOU 各 biz 转化
2curl -s -X POST "$KA_DATA_BASE/api/query" \
3  -H "Authorization: Bearer $KA_DATA_READER_TOKEN" -H "Content-Type: application/json" \
4  -d '{"backend":"sqlite","sql":"SELECT biz, SUM(conv) AS s FROM fact_conv_daily WHERE ds=20260817 AND media=\"KUAISHOU\" GROUP BY biz ORDER BY biz"}'
5
6# Hologres（秒级）—— 列 public schema 表
7curl -s -X POST "$KA_DATA_BASE/api/query" \
8  -H "Authorization: Bearer $KA_DATA_READER_TOKEN" -H "Content-Type: application/json" \
9  -d "{\"backend\":\"holo\",\"sql\":\"SELECT table_name FROM information_schema.tables WHERE table_schema='public' LIMIT 10\"}"
10
11# ODPS（CTAS，慢，受权限/槽位）—— 真实表行数
12curl -s -X POST "$KA_DATA_BASE/api/query" \
13  -H "Authorization: Bearer $KA_DATA_READER_TOKEN" -H "Content-Type: application/json" \
14  -d "{\"backend\":\"odps\",\"sql\":\"SELECT COUNT(*) AS c FROM dt_fbi_public_center_dev.fact_conv_daily WHERE ds='20260820'\"}"
4. 不知道有哪些表？用 SQL 自己列
1# sqlite 本地表
2... -d '{"backend":"sqlite","sql":"SELECT name FROM sqlite_master WHERE type=\"table\" ORDER BY name"}'
3# Hologres 表
4... -d "{\"backend\":\"holo\",\"sql\":\"SELECT table_name FROM information_schema.tables WHERE table_schema='public' ORDER BY table_name LIMIT 50\"}"
5# ODPS：列 project 下表（部分 schema 无 List 权限，列不出=无权限读）
6... -d "{\"backend\":\"odps\",\"sql\":\"SHOW TABLES IN dt_fbi_public_center_dev\"}"
7# sqlite 表结构
8... -d '{"backend":"sqlite","sql":"PRAGMA table_info(\"dwd_account_daily\")"}'
5. 只读护栏（写不进去，别试）
● 只接受单条 SELECT 或 WITH(CTE)；拒多语句（分号隔开多条）。
● 拒一切写/DCL/DDL 关键词：INSERT/UPDATE/DELETE/MERGE/DROP/CREATE/ALTER/TRUNCATE/GRANT/REVOKE/INTO/EXPORT/VACUUM/CALL/SET/COPY/EXEC/PRAGMA/ATTACH/DETACH/REPLACE。
● 双保险：sqlite 连接 mode=ro、ODPS 走 CTAS（只写自有临时表，不碰用户源表）。SELECT ... INTO 会被拦。
● 硬上限：行数 10000（env KA_DATA_QUERY_MAX_ROWS）、字节 16MB（env KA_DATA_QUERY_MAX_BYTES）、ODPS 超时 120s、sqlite busy 30s。要更多行用 WHERE/LIMIT ... OFFSET 自分批。

三、核心口径（必读，否则数值会错）
1. 现金公式（媒体系数，cash_formulas.json）
cash = (消耗 − 赔付) × 系数：
媒体
系数
KUAISHOU
(消耗-赔付)*0.7812
TENCENT
(消耗-赔付)/1.045
TOUTIAO
(消耗-赔付)/1.09
BAIDU
(消耗-赔付)/1.51
dwd 表的 cash_yuan 已按此公式算好（聚合点计算，非 fund 表预存）。直接 SUM(cash_yuan) 即可。BAIDU/TENCENT 赔付≈消耗→现金贡献≈0（rebate 已按赔付处理）。
2. 转化 fact_conv 5 biz ⚠️ 最易踩的坑
● 对齐官方 xlsx 必须加 WHERE media='KUAISHOU'：fact_conv 存全媒体（召回/闲鱼 conv 按 ad_space→media 分到 BAIDU/TENCENT/TOUTIAO，致全媒体 SUM 远大于 xlsx）。xlsx 只含媒体KA=KUAISHOU。
    ● 例：召回 0817 全媒体 614024 vs KUAISHOU-only 49828（对齐 xlsx）。

● account_id = ODPS 源 ad_space_id（闪购/CVR/CVR预流失/召回）或 ad_id（闲鱼）。
3. account_id 两套 namespace ⚠️
● dwd_adgroup（ODPS 体系）的 account_id ≠ dwd_account/fact_conv（Hologres/ODPS account 体系）的 account_id。
● 赔付 JOIN 必须带 media（不带则腾讯 0 命中）。
● 闲鱼 ad_id(7917xxx) 与媒体消耗账户 ID 两套 namespace 不可 JOIN（6 小 task 归并到主 task，总计对得上，低优不修）。
4. 考核口径
● 现金考核 cash_assessment，账面成本 = cash/(1−扣量比) 反推。budget = cash_budget/ratio。
● 考核 SSOT 在 ka-knowledge 仓 catalog/assessment_catalog.json（53 条，sub_biz×media）；本地 business_rules.json 考核段已退役为 skeleton。编辑考核走 ka-knowledge，不走本接口。
5. "全部"聚合
● 成本达成率 = Σ成本 / Σ(考核 × 转化)；预算按 card_id 去重、支持"不限"。
